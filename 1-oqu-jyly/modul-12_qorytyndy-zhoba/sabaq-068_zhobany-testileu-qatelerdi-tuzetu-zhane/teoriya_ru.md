## 1. Что такое тестирование?

**Тестирование** (testing) – процесс проверки того, что программа работает в соответствии с требованиями, и **поиска** ошибок.

**Отладка** (debugging) – определение **причины** найденной ошибки и её **исправление**.

> Цель тестирования – не «доказать, что программа работает», а **найти ошибки**. Хорошие тесты – это тесты, которые пытаются программу «сломать».

### Виды тестирования

| Вид | Что проверяет | Пример в викторине |
|---|---|---|
| Функциональное | Выполняется ли каждое требование из ТЗ | Игра задаёт 8 вопросов, правильно считает баллы |
| Граничное | Значения на границах условий | 0 баллов, все ответы верные, ровно 85% |
| Негативное | Неверный, неожиданный ввод | Ввод «а» в меню, пустое имя, нет файла |
| Пользовательское | Удобство, понятность | Сможет ли друг играть без инструкций? |
| Регрессионное | Не сломались ли прежние части после исправления | После исправления рекордов игра всё ещё работает? |

## 2. Тест-кейс

**Тест-кейс** – конкретное описание одной проверки: **что делаем** → **что ожидаем** → **что получилось**.

| № | Действие (ввод) | Ожидается | Фактически | Пройден? |
|---|---|---|---|---|
| 1 | В меню `1`, имя `Дана`, все ответы верные | `8/8`, оценка 5 | `8/8`, оценка 5 | ✔ |
| 2 | В меню `5` | «Возможные варианты: 1, 2, 3, 0» | Так и есть | ✔ |
| 3 | В меню `абв` | Спрашивает снова | Так и есть | ✔ |
| 4 | Оставить имя пустым (Enter) | «Не должно быть пусто!» | Так и есть | ✔ |
| 5 | Ответ заглавными: `АСТАНА` | Засчитывается как верный | Так и есть | ✔ |
| 6 | Ответ с пробелами: `  тенге ` | Засчитывается как верный | Так и есть | ✔ |
| 7 | «Рекорды», когда нет `results.txt` | «Результатов пока нет» | **Программа упала** | ✘ |
| 8 | «Играть», когда нет `questions.txt` | Сообщение «Вопросов нет» | Так и есть | ✔ |
| 9 | Добавить вопрос и сыграть | Новый вопрос есть в игре | Так и есть | ✔ |
| 10 | Повреждённая строка в `results.txt` | Строка пропускается | Так и есть | ✔ |

Тест 7 **не пройден** – найден баг, его нужно исправить (см. раздел 4).

### Как выбирать граничные значения?

Если условие `if percent >= 85:`, проверяем: **84**, **85**, **86** – обе стороны границы и саму границу. А также «особые» значения: **0**, **пустая строка**, **пустой список**, **очень большое число**, **отрицательное число**.

```python
def grade(score, total):
    percent = score / total * 100
    if percent >= 85:
        return 5
    elif percent >= 65:
        return 4
    elif percent >= 40:
        return 3
    return 2

# граничные тесты
print(grade(17, 20), grade(16, 20), grade(13, 20), grade(0, 20))
```

Результат:
```text
5 4 4 2
```

17/20 = 85% → 5 ✔; 16/20 = 80% → 4 ✔; 13/20 = 65% → 4 ✔; 0 → 2 ✔. А `grade(0, 0)`? → `ZeroDivisionError`! Может ли количество вопросов быть 0? Если да – нужна защита.

## 3. assert – автоматическая проверка

`assert условие` – если условие ложно, программа останавливается с ошибкой `AssertionError`. Это самый простой способ **автоматически** проверять функции логики:

```python
def check_answer(user_answer, correct_answer):
    return user_answer.strip().lower() == correct_answer.strip().lower()

assert check_answer("Астана", "астана") == True
assert check_answer("  тенге ", "тенге") == True
assert check_answer("Алматы", "астана") == False
print("Все тесты пройдены!")
```

Результат:
```text
Все тесты пройдены!
```

Профессиональное развитие этой идеи – модуль стандартной библиотеки `unittest` и сторонняя библиотека `pytest`: они сами находят и запускают все тесты проекта.

## 4. Алгоритм исправления ошибки

```text
1. ВОСПРОИЗВЕДИ   – найди действия, которые стабильно повторяют ошибку
2. НАЙДИ МЕСТО    – Traceback (номер строки), print, отладчик
3. ПОЙМИ ПРИЧИНУ  – «Почему эта переменная получила такое значение?»
4. ИСПРАВЬ        – с минимальными изменениями
5. ПЕРЕПРОВЕРЬ    – тот же тест + все прежние тесты (регрессия)
```

### Пример по тесту 7

Программа упала:

```text
Traceback (most recent call last):
  File "quiz.py", line 58, in load_results
    with open(file_name, encoding="utf-8") as f:
FileNotFoundError: [Errno 2] No such file or directory: 'results.txt'
```

Причина: игру ещё ни разу не запускали, файла нет. Исправление – `try...except`:

```python
def load_results(file_name):
    results = []
    try:
        with open(file_name, encoding="utf-8") as f:
            for line in f:
                parts = line.strip().split(";")
                if len(parts) == 4:
                    results.append(parts)
    except FileNotFoundError:
        pass                     # файла ещё нет – возвращаем пустой список
    return results

print(load_results("нет_файла.txt"))
```

Результат:
```text
[]
```

### Инструменты отладки

| Инструмент | Когда используем |
|---|---|
| Traceback | Если программа упала – какая строка, какая ошибка |
| Временный `print` | Наблюдение за значениями переменных (не забудь потом удалить!) |
| Отладчик Thonny | Построчное выполнение кода и просмотр переменных (🐞, F6/F7) |
| Метод «резиновой уточки» | Объясни свой код построчно вслух кому-нибудь (даже игрушке) – чаще всего ошибку найдёшь сам |
| «Разделение» кода | Временно закомментировать часть (`#`), чтобы найти, в какой части ошибка |

### Баг-репорт

В команде (например, в разделе Issues на GitHub) сообщение об ошибке пишется так:

```text
Название: Меню рекордов роняет программу
Шаги: 1) удалить файл results.txt; 2) запустить программу; 3) выбрать «2»
Ожидалось: сообщение «Результатов пока нет»
Фактически: FileNotFoundError, программа закрылась
Важность: высокая
```

## 5. Оформление кода: качество кода

Код пишется не только для компьютера, но и для **людей** (коллеги, команда, ты сам через месяц). Официальные рекомендации по стилю написания кода на Python – **PEP 8**.

### Основные правила

| Правило | Плохо | Хорошо |
|---|---|---|
| Осмысленные имена | `a`, `x1`, `f()` | `score`, `total_price`, `load_questions()` |
| Имя переменной/функции – строчные буквы + `_` | `TotalPrice`, `LoadQ` | `total_price`, `load_questions` |
| Константы – ЗАГЛАВНЫЕ БУКВЫ | `file = "q.txt"` | `QUESTIONS_FILE = "questions.txt"` |
| Отступ – 4 пробела | 2 или 8 | 4 |
| Пробелы вокруг операций | `x=a+b*2` | `x = a + b * 2` |
| 2 пустые строки между функциями | без пустых строк | 2 пустые строки |
| Длина строки | 150 символов | ≤ 79–99 символов |
| Нет «магических чисел» | `if p >= 85:` непонятно | `EXCELLENT = 85` |
| Нет повторяющегося кода | одинаковые 5 строк в 3 местах | одна функция |

### Комментарии и docstring

```python
def grade(score, total):
    """Переводит баллы в проценты и возвращает оценку от 2 до 5.

    score – количество правильных ответов, total – всего вопросов (> 0).
    """
    percent = score / total * 100
    if percent >= 85:
        return 5
    elif percent >= 65:
        return 4
    elif percent >= 40:
        return 3
    return 2


help(grade)
```

Результат:
```text
Help on function grade in module __main__:

grade(score, total)
    Переводит баллы в проценты и возвращает оценку от 2 до 5.

    score – количество правильных ответов, total – всего вопросов (> 0).
```

- **docstring** (`"""..."""`) – описывает, **что делает** функция; `help()` его показывает.
- **комментарий** (`#`) – объясняет, **почему** написано именно так (а не очевидные вещи!):

```python
total = 0
total += 1         # плохо: «прибавляем 1 к total» – это и так видно из кода
total -= 1         # хорошо: «не учитываем строку заголовка»
print(total)
```

В начале файла напиши **заголовочный комментарий** проекта:

```python
"""
Викторина о Казахстане – консольная игра-викторина.
Автор: Дана Абилова, 2027
Запуск: python quiz.py (рядом должен лежать файл questions.txt)
"""
```

## Частые ошибки

**1. Тестировать только «счастливый путь».** Проверка только правильным вводом – при неверном вводе программа упадёт. Для каждого ввода напиши хотя бы один негативный тест.

**2. Исправить одну ошибку и сломать другое.** После исправления заново прогони **все** тест-кейсы (регрессия).

**3. «Прятать» ошибку через `except:`.** Программа не падает, но и правильно не работает. Указывай конкретный тип ошибки и сообщай пользователю.

**4. Оставить временные `print`.** Пользователь увидит на экране `DEBUG: i = 3`.

**5. Большие изменения в последнюю минуту.** Перед выпуском не добавляй новых возможностей – только исправляй и оформляй.

**6. Не сохранить версию.** Обязательно скопируй версию, прошедшую тестирование: `quiz_final.py`.

## Основные понятия

| Понятие | Пояснение |
|---|---|
| Тестирование | Проверка программы и поиск ошибок |
| Отладка (debugging) | Поиск причины ошибки и её исправление |
| Тест-кейс | Описание «действие → ожидаемый результат → фактический результат» |
| Граничный тест | Проверка значений на границе условия |
| Негативный тест | Проверка неверных, неожиданных данных |
| Регрессионный тест | Повторная проверка прежнего после исправления |
| `assert` | Оператор, вызывающий ошибку, если условие ложно |
| Баг-репорт | Структурированное сообщение об ошибке |
| PEP 8 | Официальные рекомендации по стилю кода на Python |
| docstring | Описание функции (`"""..."""`) |
| README | Файл с описанием проекта и инструкцией |

## Примечание

- `assert` можно отключить: при запуске `python -O` все проверки `assert` пропускаются. Поэтому `assert` подходит для тестов, но не для проверки пользовательского ввода – там нужны `if` и исключения.
- Сравнивать с `True`/`False` через `==` в `assert` необязательно: PEP 8 рекомендует писать `assert check_answer(...)` и `assert not check_answer(...)`.
- Дробные числа нельзя проверять на точное равенство: `0.1 + 0.2 == 0.3` → `False`. Используй `math.isclose()` или `round()`.
- Стиль кода проверяют автоматически: `flake8`, `pylint`, `ruff` находят нарушения PEP 8, а `black` форматирует код сам.
- В Python 3.11+ Traceback показывает точное место ошибки в строке (подчёркивание `^^^^`), что ускоряет отладку.
- Документация: [PEP 8](https://peps.python.org/pep-0008/), [unittest](https://docs.python.org/3/library/unittest.html), [pdb – отладчик](https://docs.python.org/3/library/pdb.html).
