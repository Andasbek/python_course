## 1. Что такое основная логика?

Любую программу можно разделить на слои:

| Слой | Что делает | Пример в викторине |
|---|---|---|
| **Основная логика** (бизнес-логика, «мозг») | Вычисляет, проверяет, принимает решения | Проверка ответа, подсчёт баллов, оценка |
| **Интерфейс** («лицо») | Общается с пользователем | Меню, `input`, `print`, красивое оформление |
| **Хранение данных** («память») | Записывает в файл, читает | `questions.txt`, `results.txt` |

Разработку обычно начинают с **логики** («мозга»), а **интерфейс и хранение** добавляют поверх неё.

**Аналогия.** У автомобиля есть двигатель (логика) и руль/сиденья (интерфейс). Сначала делаем двигатель и проверяем, что он работает, – и только потом устанавливаем красивый салон.

Польза от того, чтобы писать логику **отдельно** от интерфейса:
- функции легко проверять (не дожидаясь `input`);
- если поменять интерфейс (например, консоль заменить на окно Tkinter), логика останется прежней.

## 2. Стратегия разработки: маленькими шагами

```text
  +------------------+     +-------------+     +------------+
  | Напиши 1 функцию | --> | Запусти,    | --> | Работает?  |
  | (5-15 строк)     |     | проверь     |     |            |
  +------------------+     +-------------+     +------------+
         ^                                       |      |
         |                 да: переходи к след.  |      | нет: исправь
         +---------------------------------------+      v
                                                 (найди ошибку,
                                                  проверь снова)
```

**Правила:**
1. Работай одновременно только с **одной** функцией.
2. Сразу после написания функции **проверь её отдельно**: вызови в конце файла и выведи результат через `print`.
3. Каждые 10–15 минут **запускай** программу. Если написать 50 строк и только потом запустить – столкнёшься с 10 ошибками.
4. Если не получается – прочитай текст ошибки (Traceback), проверь значения переменных через `print` или отладчик, загляни в документацию.
5. **Сохрани** работающую версию (копию) – и только потом добавляй что-то новое.

### Метод «сверху вниз»

Сначала пишется «каркас»: функции есть, но внутри пусто (заглушки). Затем они заполняются **одна за другой**. Программа всё время остаётся в рабочем состоянии.

```python
def play(questions):
    """Пока заглушка: заполним позже."""
    print("[play ещё не написана]")
    return 0

print(play({}))
```

Результат:
```text
[play ещё не написана]
0
```

## 3. Демо-проект: логика «Викторины о Казахстане»

### Шаг 1. Данные

Чтобы проверить логику, на первом шаге данные можно хранить прямо в коде (позже их выносят в файл):

```python
QUESTIONS = {
    "Какой город – столица Казахстана?": "астана",
    "Национальная валюта Казахстана?": "тенге",
    "В каком году Казахстан провозгласил независимость?": "1991",
    "Одно из крупнейших озёр Казахстана – Балхаш или Байкал?": "балхаш",
    "Высокогорный каток в Алматы?": "медеу",
}
print("Количество вопросов:", len(QUESTIONS))
```

Результат:
```text
Количество вопросов: 5
```

(`QUESTIONS`, написанное заглавными буквами, – **константа**: данные, которые не меняются во время работы программы.)

### Шаг 2. Самая маленькая функция – проверка ответа

```python
def normalize(text):
    """Готовит ответ к сравнению: убирает пробелы и регистр."""
    return text.strip().lower()


def check_answer(user_answer, correct_answer):
    """Возвращает True, если ответ верный."""
    return normalize(user_answer) == normalize(correct_answer)


# проверка
print(check_answer("  Астана ", "астана"))
print(check_answer("Алматы", "астана"))
```

Результат:
```text
True
False
```

Внутри `check_answer` нет ни `input`, ни `print` – это **чистая логика**. Поэтому её легко проверить.

### Шаг 3. Перевод баллов в оценку

```python
def grade(score, total):
    """Переводит баллы в оценку."""
    percent = score / total * 100
    if percent >= 85:
        return "5 – отлично!"
    elif percent >= 65:
        return "4 – хорошо"
    elif percent >= 40:
        return "3 – неплохо"
    return "2 – готовься ещё"


print(grade(5, 5), "|", grade(3, 5), "|", grade(1, 5))
```

Результат:
```text
5 – отлично! | 3 – неплохо | 2 – готовься ещё
```

Проверь **граничные значения**: что будет ровно при 85%? А при 0 баллов?

### Шаг 4. Один вопрос и вся игра

```python
import random


def normalize(text):
    return text.strip().lower()


def check_answer(user_answer, correct_answer):
    return normalize(user_answer) == normalize(correct_answer)


def ask_question(number, question, answer):
    """Задаёт один вопрос и возвращает результат (True/False)."""
    user = input(f"{number}. {question} ")
    if check_answer(user, answer):
        print("Верно!")
        return True
    print("Неверно. Правильный ответ:", answer)
    return False


def play(questions):
    """Игра: задаёт вопросы в случайном порядке, возвращает баллы."""
    items = list(questions.items())
    random.shuffle(items)
    score = 0
    number = 1
    for question, answer in items:
        if ask_question(number, question, answer):
            score += 1
        number += 1
    return score


QUESTIONS = {"Какой город – столица Казахстана?": "астана", "Национальная валюта?": "тенге"}
result = play(QUESTIONS)
print(f"Результат: {result}/{len(QUESTIONS)}")
```

Результат (пример):
```text
1. Национальная валюта? Тенге
Верно!
2. Какой город – столица Казахстана? Алматы
Неверно. Правильный ответ: астана
Результат: 1/2
```

MVP готов! Теперь это работающая программа. Следующие шаги – меню, файлы и оформление.

## 4. «Основная логика» в разных проектах

| Проект | Основная логика (функции) |
|---|---|
| Виселица | `choose_word()`, `mask_word(word, guessed)`, `is_won(word, guessed)` |
| Карманные деньги | `add_operation(...)`, `balance(operations)`, `by_category(operations)` |
| Тамагочи | `feed(pet)`, `play_with(pet)`, `tick(pet)` (течение времени), `is_alive(pet)` |
| Дневник | `add_task(...)`, `overdue(tasks, today)`, `mark_done(...)` |
| Тренажёр | `make_example(level)`, `check(...)`, `statistics(results)` |
| Квест | словарь `rooms`, `move(room, direction)`, `take(item, inventory)` |

Пример – ядро логики «Виселицы»:

```python
def mask_word(word, guessed):
    """Скрывает неотгаданные буквы знаком _."""
    result = ""
    for ch in word:
        if ch in guessed:
            result += ch + " "
        else:
            result += "_ "
    return result.strip()


def is_won(word, guessed):
    """True, если отгаданы все буквы слова."""
    for ch in word:
        if ch not in guessed:
            return False
    return True


print(mask_word("python", {"p", "o"}))
print(is_won("кот", {"к", "о", "т", "а"}))
```

Результат:
```text
p _ _ _ o _
True
```

## 5. Передача данных между функциями

Избегай изменения глобальных переменных внутри функции (через `global`). Правильный путь – **передавать через параметры** и **возвращать через `return`**:

```python
def add_points(score, points):
    return score + points

score = 0
score = add_points(score, 10)
score = add_points(score, 5)
print("Баллы:", score)
```

Результат:
```text
Баллы: 15
```

Если нужно хранить несколько значений вместе (например, состояние тамагочи), используй **словарь** – его можно передать в функцию и изменить внутри:

```python
def feed(pet):
    pet["hunger"] = max(0, pet["hunger"] - 30)
    pet["mood"] = min(100, pet["mood"] + 5)

pet = {"name": "Котик", "hunger": 70, "mood": 50}
feed(pet)
print(pet)
```

Результат:
```text
{'name': 'Котик', 'hunger': 40, 'mood': 55}
```

## 6. Сохранение версий и документирование кода

Работающую версию нужно сохранять до того, как начинаешь её менять:
- простейший способ – **копия проекта с датой**: `quiz_2027-05-03.py`, папка проекта в облаке или на флешке;
- профессиональный способ – система контроля версий **Git**: `git init` (создать репозиторий), `git add .` и `git commit -m "Добавлена проверка ответа"` (сохранить снимок), `git log` (история).

Незаконченные места в коде отмечают комментарием `# TODO:`, а назначение каждой функции описывают в **docstring**:

```python

    # TODO: добавить ограничение по времени

```

## Частые ошибки

**1. Писать всё сразу.** Написать 100 строк и впервые запустить – гора ошибок. Маленький шаг + проверка!

**2. Функция делает `print` вместо `return`.**

```python
def total_price(prices):
    print(sum(prices))     # результат не сможет использовать другая функция

def total_price_ok(prices):
    return sum(prices)     # правильно: возвращает значение

bill = total_price_ok([500, 1200, 300])
print("Итого:", bill, "тенге")
```

**3. Вызов функции до её объявления.** Python читает код сверху вниз: вызов функции должен быть **после** строки `def` (или внутри `main()`, а `main()` вызывается в конце файла).

**4. «Потерянный» `return` внутри цикла.** `return` сразу останавливает и цикл, и функцию. Если цикл должен пройти до конца, вынеси `return` за пределы цикла.

**5. «Украшательство» без проверки.** Пока логика не работает, не трать время на цвета и оформление – сначала MVP!

**6. Не сохранять копию.** Сломать работающую версию, «улучшая» её, – самое частое сожаление. Сохраняй после каждого удачного шага.

## Основные понятия

| Понятие | Пояснение |
|---|---|
| Основная логика | Часть программы, которая вычисляет и принимает решения |
| Интерфейс | Часть взаимодействия с пользователем |
| Заглушка (stub) | Временная, ещё не заполненная функция |
| Инкрементная разработка | Написание кода маленькими шагами с проверкой каждого шага |
| Константа | Неизменяемое значение, имя пишется ЗАГЛАВНЫМИ БУКВАМИ |
| Граничное значение | Значение на границе условия (0, 85%, пустой список) |
| Docstring | Строка документации в начале функции |

## Примечание

- Разделение «логика / интерфейс / хранение» – основа архитектуры большинства программ (в больших проектах это паттерны MVC, слоистая архитектура). Чистые функции без `input`/`print` легко проверять с помощью `assert` или модуля `unittest`.
- Константы по PEP 8 пишутся `UPPER_CASE` и объявляются в начале модуля; Python не запрещает их изменять – это лишь соглашение.
- Изменяемые объекты (список, словарь), переданные в функцию, изменяются «на месте» – вызывающий код увидит изменения. Если это нежелательно, передавай копию: `dict(pet)` или `pet.copy()`.
- Не используй изменяемые значения по умолчанию: `def f(items=[])` – список создаётся один раз и «накапливает» данные между вызовами. Правильно: `def f(items=None)` и внутри `if items is None: items = []`.
- `random.shuffle()` работает только со списком; для словаря сначала получи список пар: `list(d.items())`.
- Документация: [Defining Functions](https://docs.python.org/3/tutorial/controlflow.html#defining-functions), [PEP 257 – Docstring Conventions](https://peps.python.org/pep-0257/).
