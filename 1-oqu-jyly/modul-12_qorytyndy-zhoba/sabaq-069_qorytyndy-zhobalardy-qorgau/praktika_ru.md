# Урок 69. Практические задания: защита проекта и выставка

## Базовый уровень (обязательно для каждого ученика)

**Задание 1. Подготовка к защите (до начала урока).**
- Финальная версия проекта открыта на компьютере, шрифт увеличен.
- Сценарий демонстрации (какие действия в каком порядке показываешь) записан на бумаге.
- Слайды или плакат (при необходимости) и запасные скриншоты готовы.

**Задание 2. План презентации.** Заполни образец (его можно использовать как опору во время защиты):

```text
ПЛАН ПРЕЗЕНТАЦИИ
1. Вступление (20 с): Здравствуйте! Меня зовут ______. Мой проект называется «______».
2. Цель (30 с): Эта программа предназначена для ______. Идея пришла, когда ______.
3. Демонстрация (90 с):
   а) ______ (например: меню → играть → ответ на 3 вопроса)
   б) ______ (например: неверный ввод → программа не падает)
   в) ______ (например: таблица рекордов, файл)
4. Техническая часть (60 с): Использованные темы: ______.
   Самая интересная функция: ______ – она делает ______.
5. Трудность (20 с): Была проблема ______, я решил её с помощью ______.
6. Итоги (20 с): Я научился ______. В будущем хочу добавить ______.
   Спасибо за внимание! Готов ответить на ваши вопросы.
```

**Задание 3. Защита.** Представь свой проект по регламенту (4 мин) и ответь на вопросы (2 мин).

**Задание 4. Оценивание в роли слушателя.** Оцени защиту каждого одноклассника по «Листу слушателя» ниже и задай хотя бы один вопрос.

```text
ЛИСТ СЛУШАТЕЛЯ                   Оценивал: ______________
| Автор | Идея (1-5) | Программа (1-5) | Презентация (1-5) | Сильная сторона | Предложение |
|-------|------------|-----------------|-------------------|-----------------|-------------|
|       |            |                 |                   |                 |             |
```

## Продвинутый уровень

**Задание 5. «Прогулка по галерее».** На выставке сам попробуй не менее 4 проектов. Каждому напиши «две звезды и одно пожелание» (две похвалы + одно предложение) и отдай свои 3 «звёздочки» самым понравившимся проектам.

**Задание 6. «Следующая версия» проекта.** На основе полученной обратной связи напиши список улучшений для версии 2.0 своего проекта (не менее 3 пунктов) и для каждого укажи, какая тема следующего года поможет (например: «графическое окно – Tkinter», «база данных – SQLite», «онлайн-погода – API»).

## ★ Олимпиадная / творческая задача

**7. «Пресс-релиз» о проекте.** Напиши новостную заметку из 5–7 предложений о своём проекте для странички/сайта кружка: название, кто сделал, что делает, чем интересен, скриншот.

**8. Подготовка к конкурсу.** Проанализируй, чего не хватает, чтобы представить твой проект на городской/республиканский конкурс юных программистов (например, конкурс научных проектов или IT-олимпиады), и составь план.

## Домашнее задание

1. Заполни лист рефлексии (ниже).
2. Сохрани папку проекта (код, данные, README, слайды) в папку «Портфолио» – в следующем году загрузим её на GitHub.
3. Покажи проект семье и запиши их мнение.

```text
ЛИСТ РЕФЛЕКСИИ
1. Самое удачное в моём проекте: ________________________________
2. Проблема, на которую ушло больше всего времени, и решение: ____
3. Если бы начал заново, по-другому сделал бы: ___________________
4. После проекта я оцениваю себя как программиста на (1-10): ____
5. В следующем году хочу научиться: _____________________________
```

### Уточнение критериев (для выставления баллов)

| Критерий | Высокий | Средний | Низкий |
|---|---|---|---|
| Идея (20) | 17–20: самостоятельная, полезная, с особенностью | 10–16: известная идея, но со своими дополнениями | 0–9: полное повторение образца |
| Техническое исполнение (25) | 21–25: уместно объединены 6+ тем (функции, словарь/список, файлы, try, модуль, цикл, условие) | 13–20: 4–5 тем | 0–12: 1–3 темы |
| Стабильность (20) | 17–20: не упала на демо, устойчива к неверному вводу, есть тест-кейсы | 10–16: есть мелкие ошибки | 0–9: упала на демо |
| Качество кода (15) | 13–15: разбит на функции, docstring, README, красивый интерфейс | 7–12: частично | 0–6: один блок, непонятные имена |
| Презентация (20) | 17–20: структурированно, вовремя, свободно объясняет код | 10–16: частично структурированно, ответы неполные | 0–9: без подготовки, не может объяснить код |

Уровни: **85–100** – высокий; **60–84** – средний; **40–59** – начальный.

**Образец ответа (викторина, «почему словарь?»):** «У каждого вопроса один правильный ответ – это соответствие ключа и значения. В словаре ответ можно сразу найти по вопросу, а через `items()` я получаю все пары. Чтобы перемешать, я сделал `list(questions.items())` и использовал `random.shuffle`.»

**Советы по организации защиты:**
- Состав комиссии: руководитель кружка + 1–2 приглашённых специалиста (педагог другого кружка, представитель администрации, родитель из IT-сферы).

- Хорошо, если каждый ученик может получить какую-либо номинацию (мотивация).
- Объяви результаты на следующем уроке (или в конце этого урока) и внеси их в таблицу мониторинга.
