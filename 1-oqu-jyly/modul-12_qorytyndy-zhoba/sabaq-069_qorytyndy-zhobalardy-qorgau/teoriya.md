## 1. Дайын Python жобасының құрылымы

Жобаны көрсетуге, іске қосуға және түсінуге болатындай етіп, оның файлдары түсінікті сызба бойынша орналастырылады:

```text
quiz_kazakhstan/
├── main.py            – кіру нүктесі: мәзір және іске қосу
├── quiz.py            – негізгі логика (функциялар)
├── storage.py         – файлдарды оқу және жазу
├── data/
│   ├── questions.txt  – бағдарлама деректері
│   └── results.txt    – автоматты құрылады
├── tests.py           – assert тексерулері
├── requirements.txt   – сыртқы кітапханалар (болса)
└── README.md          – жоба сипаттамасы
```

| Бөлік | Не үшін керек |
|---|---|
| Кіру нүктесі (`main.py`) | Қай файлды іске қосу керегі бірден түсінікті |
| Мағынасы бойынша модульдер | Логиканы, интерфейсті және файлмен жұмысты табу мен тексеру оңай |
| `data/` папкасы | Деректер кодтан бөлінген |
| `tests.py` | Функциялардың дұрыс жұмыс істейтінін тез көрсетеді |
| `README.md` | Жобаны алғаш көрген адамға түсіндіреді |

Кіру нүктесі былай рәсімделеді:

```python
def main():
    print("Қазақстан викторинасы")
    # мұнда мәзірдің басты циклі


if __name__ == "__main__":
    main()
```

`__name__` файл тікелей іске қосылғанда ғана `"__main__"`-ге тең. Файл импортталса (мысалы, `tests.py`-дан), мәзір іске қосылмайды.

## 2. README.md – Markdown форматындағы жоба сипаттамасы

**Markdown** – мәтінді белгілеудің қарапайым тілі: GitHub, GitLab және көптеген редакторлар оны әдемі безендірілген түрде көрсетеді.

| Белгілеу | Нәтиже |
|---|---|
| `# Тақырып`, `## Тақырыпша` | Әр деңгейдегі тақырыптар (немесе жолдың астын `===` / `---` таңбаларымен сызу) |
| `**қалың**`, `*көлбеу*` | Мәтінді ерекшелеу |
| `- пункт` | Таңбаланған тізім |
| `1. пункт` | Нөмірленген тізім |
| `` `код` `` | Жол ішіндегі код |
| Үш кері апостроф | Код блогы |
| `[мәтін](https://...)` | Сілтеме |

`README.md` мысалы:

```text
Қазақстан викторинасы
=====================

Консольдік викторина ойыны: кездейсоқ ретпен 10 сұрақ, рекордтар кестесі.

Мүмкіндіктері
-------------
- сұрақтар `data/questions.txt` файлынан жүктеледі
- нәтижелер күні мен уақытымен сақталады
- қате енгізуден қорғау

Іске қосу
---------
    python main.py

Python 3.10 немесе жаңарағы қажет, сыртқы кітапханалар керек емес.

Қолданылған Python құралдары
----------------------------
функциялар, сөздіктер, файлдар, try...except, random, datetime
```

(Markdown-да 4 бос орын шегінісі бар жол код блогы ретінде көрсетіледі.)

## 3. Жобаны басқа компьютерде іске қосу

Тек «автордың компьютерінде» жұмыс істейтін бағдарлама – жиі кездесетін мәселе. Нені ескеру керек:

1. **Python нұсқасы.** README-де ең төменгі нұсқаны көрсет. Нұсқаны кодтан тексеру:

```python
import sys

print(sys.version)
if sys.version_info < (3, 10):
    print("Python 3.10 немесе жаңарағы керек")
```

2. **Файл жолдары.** `"questions.txt"` салыстырмалы жолы ағымдағы жұмыс папкасынан ізделеді, ал ол жоба папкасынан өзгеше болуы мүмкін. Сенімді тәсіл – жолды скрипттің өз орнынан құру:

```python
from pathlib import Path

BASE_DIR = Path(__file__).parent
QUESTIONS_FILE = BASE_DIR / "data" / "questions.txt"
print(QUESTIONS_FILE.name)
```

3. **Кодтау.** Файлдарды ашқанда әрқашан `encoding="utf-8"` – әйтпесе басқа компьютерде қазақ әріптері «бұзылуы» мүмкін.

4. **Сыртқы кітапханалар.** Жоба сыртқы пакеттерді қолданса, олар `requirements.txt`-те тізіліп, `pip install -r requirements.txt` командасымен орнатылады. Әр жобаның пакеттері бір-біріне кедергі жасамауы үшін **виртуалды орта** қолданылады: `python -m venv .venv`.

## 4. Бағдарламаны көрсету

Тірі демонстрация бағдарламаның шынымен жұмыс істейтінін көрсетеді. Техникалық тәсілдер:
- барлық мүмкіндіктер көрінуі үшін **тест деректерін** дайында (рекордтар файлында бірнеше жазба);
- **қате енгізуге** реакцияны көрсет – бұл `try...except` пен тексерулердің жұмыс істейтінін дәлелдейді;
- автоматты тексерулерді көрсету үшін `tests.py`-ды іске қос:

```python
def check_answer(user_answer, correct_answer):
    return user_answer.strip().lower() == correct_answer.strip().lower()


assert check_answer("  Астана ", "астана")
assert not check_answer("Алматы", "астана")
print("Барлық тестілер өтті!")
```

- кодты көрсету үшін редактор қаріпін үлкейт (Thonny: **View → Increase font size**).

## 5. Өз кодыңды қалай түсіндіру керек

Жобаны талқылағанда (code review) әдетте техникалық сұрақтар қойылады. Жақсы жауап тілдің ұғымдарына сүйенеді:

| Сұрақ | Жауап мысалы |
|---|---|
| Неге тізім емес, сөздік? | Сұрақ бойынша жауапты тез табу керек: сөздікте кілт бойынша іздеу толық аралап шығуды талап етпейді |
| Санның орнына әріп енгізсе не болады? | `int()` `ValueError` тудырады, оны `try...except` ұстайды да, бағдарлама қайта сұрайды |
| Деректер қайда сақталады? | Мәтіндік файлда, бір жолда бір жазба, өрістер `;` арқылы, UTF-8 кодтауы |
| `main()` функциясы не үшін? | Бұл – кіру нүктесі; `if __name__ == "__main__"` арқасында модульді тестілер үшін импорттауға болады |
| Бағдарлама қалай тексерілді? | Қалыпты, шекаралық және қате деректерге арналған тест-кейстер, логика функцияларына `assert` |
| Нені жақсартуға болады? | Деректерді JSON-да сақтау, графикалық интерфейс қосу (Tkinter), кодты `unittest`-пен қамту |

Функцияны мына сызба бойынша түсіндіру ыңғайлы: **не қабылдайды → не істейді → не қайтарады → қателерді қалай өңдейді**.

## 6. Жобаны жариялау

| Тәсіл | Қалай | Ерекшелігі |
|---|---|---|
| Мұрағат | Жоба папкасын `.zip`-ке салу | Қарапайым; алушыда Python болуы керек |
| GitHub | Репозиторий: код + README + өзгерістер тарихы | Бағдарламашы портфолиосының стандарты |
| Орындалатын файл | `pip install pyinstaller`, содан кейін `pyinstaller --onefile main.py` | Python орнатылмаған компьютерде іске қосылады (тек сол ОЖ-де) |
| Онлайн-орта | Replit, Google Colab т.б. | Браузерде іске қосу |

Жарияламас бұрын уақытша `print`-терді, жөндеу кодын, жеке деректерді және артық файлдарды (`__pycache__`, ескі көшірмелер) өшір.

## Жиі кездесетін қателер

**1. Кодтағы абсолюттік жолдар.** `open("C:/Users/Dana/Desktop/questions.txt")` басқа компьютерде жұмыс істемейді. `Path(__file__).parent`-тен бастап салыстырмалы жолдар қолдан.

**2. Кіру нүктесі жоқ.** Папкада бес `.py` файл бар, қайсысын іске қосу керегі түсініксіз. Басты файлды `main.py` деп ата және мұны README-де көрсет.

**3. Код импорт кезінде орындалады.** `if __name__ == "__main__":`-сіз `main()` шақыруы модуль тестілерге импортталғанда да мәзірді іске қосады.

**4. Деректер файлдарын ұмыту.** `questions.txt` мұрағатқа түспегендіктен бағдарлама `FileNotFoundError`-мен құлайды. Жобаны мұрағатты жаңа папкаға ашып тексер.

**5. Соңғы нұсқадағы жөндеу шығысы.** Пайдаланушы экранындағы `DEBUG: i = 3` сияқты жолдар – аяқталмаған жұмыстың белгісі.

## Ескерту

- `Path(__file__)` интерактивті қабықшада (REPL) және кейбір онлайн-орталарда анықталмаған – онда `__file__` жоқ; скриптті қалыпты іске қосқанда ол әрқашан жұмыс істейді.
- PyInstaller орындалатын файлды тек өзі іске қосылған ОЖ үшін жинайды: Windows `.exe`-ін Windows-та жинау керек. Антивирустар кейде мұндай файлдарға қате әрекет етеді.
- `requirements.txt` файлын `pip freeze > requirements.txt` командасымен алуға болады, бірақ ол ортадағы **барлық** пакеттерді тізеді – сондықтан оны жобаның виртуалды ортасы ішінде іске қосады.
- `.gitignore`-ға `__pycache__/`, `.venv/` және жеке деректері бар файлдарды қосу қабылданған – олар репозиторийге түспеуі керек.
- Заманауи жобалар метадеректер мен тәуелділіктерді `pyproject.toml` файлында сипаттайды ([PEP 621](https://peps.python.org/pep-0621/)).
- Құжаттама: [`__main__`](https://docs.python.org/3/library/__main__.html), [venv](https://docs.python.org/3/library/venv.html), [pathlib](https://docs.python.org/3/library/pathlib.html).
