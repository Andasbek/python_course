## 1. Структура готового Python-проекта

Чтобы проект можно было показать, запустить и понять, его файлы раскладывают по понятной схеме:

```text
quiz_kazakhstan/
├── main.py            – точка входа: меню и запуск
├── quiz.py            – основная логика (функции)
├── storage.py         – чтение и запись файлов
├── data/
│   ├── questions.txt  – данные программы
│   └── results.txt    – создаётся автоматически
├── tests.py           – проверки assert
├── requirements.txt   – внешние библиотеки (если есть)
└── README.md          – описание проекта
```

| Часть | Зачем нужна |
|---|---|
| Точка входа (`main.py`) | Сразу понятно, какой файл запускать |
| Модули по смыслу | Логику, интерфейс и работу с файлами легко найти и проверить |
| Папка `data/` | Данные отделены от кода |
| `tests.py` | Быстро показывает, что функции работают правильно |
| `README.md` | Объясняет проект человеку, который видит его впервые |

Точка входа оформляется так:

```python
def main():
    print("Викторина о Казахстане")
    # здесь главный цикл меню


if __name__ == "__main__":
    main()
```

`__name__` равно `"__main__"` только при прямом запуске файла. Если файл импортируют (например, из `tests.py`), меню не запустится.

## 2. README.md – описание проекта в формате Markdown

**Markdown** – простой язык разметки текста: GitHub, GitLab и многие редакторы показывают его красиво оформленным.

| Разметка | Результат |
|---|---|
| `# Заголовок`, `## Подзаголовок` | Заголовки разных уровней (или подчёркивание строки знаками `===` / `---`) |
| `**жирный**`, `*курсив*` | Выделение текста |
| `- пункт` | Маркированный список |
| `1. пункт` | Нумерованный список |
| `` `код` `` | Код внутри строки |
| Три обратных апострофа | Блок кода |
| `[текст](https://...)` | Ссылка |

Пример `README.md`:

```text
Викторина о Казахстане
======================

Консольная игра-викторина: 10 вопросов в случайном порядке, таблица рекордов.

Возможности
-----------
- вопросы загружаются из файла `data/questions.txt`
- результаты сохраняются с датой и временем
- защита от неверного ввода

Запуск
------
    python main.py

Требуется Python 3.10 или новее, внешние библиотеки не нужны.

Использованные средства Python
------------------------------
функции, словари, файлы, try...except, random, datetime
```

(Строка с отступом в 4 пробела в Markdown отображается как блок кода.)

## 3. Запуск проекта на другом компьютере

Программа, которая работает только «у автора», – частая проблема. Что нужно учесть:

1. **Версия Python.** Укажи минимальную версию в README. Проверить версию из кода:

```python
import sys

print(sys.version)
if sys.version_info < (3, 10):
    print("Нужен Python 3.10 или новее")
```

2. **Пути к файлам.** Относительный путь `"questions.txt"` ищется в текущей рабочей папке, которая может отличаться от папки проекта. Надёжно – строить путь от расположения самого скрипта:

```python
from pathlib import Path

BASE_DIR = Path(__file__).parent
QUESTIONS_FILE = BASE_DIR / "data" / "questions.txt"
print(QUESTIONS_FILE.name)
```

3. **Кодировка.** Всегда `encoding="utf-8"` при открытии файлов – иначе на другом компьютере кириллица может «сломаться».

4. **Внешние библиотеки.** Если проект использует сторонние пакеты, их перечисляют в `requirements.txt`, а устанавливают командой `pip install -r requirements.txt`. Чтобы пакеты разных проектов не мешали друг другу, используют **виртуальное окружение**: `python -m venv .venv`.

## 4. Демонстрация программы

Живая демонстрация показывает, что программа действительно работает. Технические приёмы:
- подготовь **тестовые данные** (несколько записей в файле рекордов), чтобы были видны все возможности;
- покажи реакцию на **неверный ввод** – это доказывает, что `try...except` и проверки работают;
- запусти `tests.py`, чтобы показать автоматические проверки:

```python
def check_answer(user_answer, correct_answer):
    return user_answer.strip().lower() == correct_answer.strip().lower()


assert check_answer("  Астана ", "астана")
assert not check_answer("Алматы", "астана")
print("Все тесты пройдены!")
```

- для показа кода увеличь шрифт редактора (Thonny: **View → Increase font size**).

## 5. Как объяснить свой код

При обсуждении проекта (code review) обычно задают технические вопросы. Хороший ответ опирается на понятия языка:

| Вопрос | Пример ответа |
|---|---|
| Почему словарь, а не список? | Нужно быстро находить ответ по вопросу: поиск по ключу в словаре не требует перебора |
| Что будет, если ввести букву вместо числа? | `int()` вызовет `ValueError`, его перехватывает `try...except`, и программа спрашивает снова |
| Где хранятся данные? | В текстовом файле, одна запись на строку, поля через `;`, кодировка UTF-8 |
| Зачем функция `main()`? | Это точка входа; благодаря `if __name__ == "__main__"` модуль можно импортировать для тестов |
| Как проверялась программа? | Тест-кейсы для обычных, граничных и неверных данных, `assert` для функций логики |
| Что можно улучшить? | Хранить данные в JSON, добавить графический интерфейс (Tkinter), покрыть код `unittest` |

Объяснять функцию удобно по схеме: **что принимает → что делает → что возвращает → как обрабатывает ошибки**.

## 6. Публикация проекта

| Способ | Как | Особенность |
|---|---|---|
| Архив | Папка проекта в `.zip` | Просто; у получателя должен быть Python |
| GitHub | Репозиторий: код + README + история изменений | Стандарт для портфолио программиста |
| Исполняемый файл | `pip install pyinstaller`, затем `pyinstaller --onefile main.py` | Запускается без установленного Python (только на той же ОС) |
| Онлайн-среда | Replit, Google Colab и т.п. | Запуск в браузере |

Перед публикацией удали временные `print`, отладочный код, личные данные и лишние файлы (`__pycache__`, старые копии).

## Частые ошибки

**1. Абсолютные пути в коде.** `open("C:/Users/Dana/Desktop/questions.txt")` не сработает на другом компьютере. Используй относительные пути от `Path(__file__).parent`.

**2. Нет точки входа.** В папке пять `.py`-файлов, и непонятно, какой запускать. Назови главный файл `main.py` и укажи это в README.

**3. Код выполняется при импорте.** Вызов `main()` без `if __name__ == "__main__":` запускает меню даже при импорте модуля в тесты.

**4. Забыли файлы данных.** Программа падает с `FileNotFoundError`, потому что `questions.txt` не попал в архив. Проверяй проект, распаковав архив в новую папку.

**5. Отладочный вывод в финальной версии.** Строки вида `DEBUG: i = 3` на экране пользователя – признак незаконченной работы.

## Основные понятия

| Понятие | Пояснение |
|---|---|
| Точка входа | Файл/функция, с которой начинается выполнение программы |
| `__name__ == "__main__"` | Условие «файл запущен напрямую, а не импортирован» |
| README | Файл с описанием проекта и инструкцией по запуску |
| Markdown | Простой язык разметки текста (`.md`) |
| `requirements.txt` | Список внешних библиотек проекта |
| Виртуальное окружение (venv) | Изолированный набор пакетов для одного проекта |
| Code review | Обсуждение и проверка кода другими людьми |
| Демонстрация (демо) | Запуск программы с показом её возможностей |

## Примечание

- `Path(__file__)` не определён в интерактивной оболочке (REPL) и в некоторых онлайн-средах – там `__file__` отсутствует; в обычном запуске скрипта он работает всегда.
- PyInstaller собирает исполняемый файл только для той ОС, на которой запущен: для Windows `.exe` нужно собирать на Windows. Антивирусы иногда ложно реагируют на такие файлы.
- Файл `requirements.txt` можно получить командой `pip freeze > requirements.txt`, но она перечисляет **все** пакеты окружения – поэтому её запускают внутри виртуального окружения проекта.
- В `.gitignore` принято добавлять `__pycache__/`, `.venv/` и файлы с личными данными – они не должны попадать в репозиторий.
- Современные проекты описывают метаданные и зависимости в файле `pyproject.toml` ([PEP 621](https://peps.python.org/pep-0621/)).
- Документация: [`__main__`](https://docs.python.org/3/library/__main__.html), [venv](https://docs.python.org/3/library/venv.html), [pathlib](https://docs.python.org/3/library/pathlib.html).
