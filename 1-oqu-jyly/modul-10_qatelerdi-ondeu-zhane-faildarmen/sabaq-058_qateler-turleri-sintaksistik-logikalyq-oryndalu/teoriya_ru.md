## 1. Что такое ошибка и откуда она берётся?

Программисты называют ошибку **багом** (bug – «жук»). А процесс поиска и исправления ошибок называется **отладкой** (debugging). Даже самый опытный программист ошибается – важно уметь быстро найти и исправить ошибку.

Ошибки в Python делим на три большие группы:

| Вид ошибки | Когда обнаруживается? | Сообщает ли Python? | Пример |
|---|---|---|---|
| Синтаксическая (syntax error) | До запуска программы | Да, `SyntaxError` | Забыто двоеточие |
| Ошибка времени выполнения (runtime error, exception) | Во время работы программы | Да, `ValueError`, `ZeroDivisionError` и др. | Деление на ноль |
| Логическая (logic error) | Программа «работает», но ответ неверный | Нет! | Вместо `+` написан `-` |

**Аналогия.** Представь программу как кулинарный рецепт:
- *синтаксическая ошибка* – рецепт написан безграмотно, повар не может его прочитать («соль 2 ложки в посуду положи ;;;»);
- *ошибка выполнения* – рецепт правильный, но в холодильнике не оказалось яиц – остановились посреди работы;
- *логическая ошибка* – рецепт прочитан, блюдо готово, но вместо сахара положили соль – результат «неправильный».

## 2. Синтаксические ошибки

Синтаксис – правила записи языка. Если правило нарушено, Python **не выполнит ни одной строки** программы.

Код с ошибкой (этот код намеренно не запускается):

```text
age = 15
if age > 10
    print("Ты принят в кружок!")
```

Результат:
```text
  File "main.py", line 2
    if age > 10
               ^
SyntaxError: expected ':'
```

Часто встречающиеся синтаксические ошибки:
- забытое `:` в конце `if`, `for`, `while`, `def`, `else`;
- незакрытые скобки и кавычки: `print("Привет)`;
- неправильный отступ – `IndentationError`;
- путаница `=` (присваивание) и `==` (сравнение): `if x = 5:`;
- использование ключевого слова как имени переменной: `for = 3`.

Правильный код:

```python
age = 15
if age > 10:
    print("Ты принят в кружок!")
```

Результат:
```text
Ты принят в кружок!
```

> **Подсказка.** Проверяй не только строку, которую указал Python, но и строку **перед** ней: незакрытая скобка часто остаётся на строку выше.

## 3. Ошибки времени выполнения (исключения)

Синтаксис правильный, программа запустилась, но какую-то строку выполнить оказалось невозможно. Такую ситуацию Python называет **исключением** (exception).

```python
a = 10
b = 0
print("Начинаем деление...")
print(a / b)
print("Эта строка никогда не выведется")
```

Результат:
```text
Начинаем деление...
Traceback (most recent call last):
  File "main.py", line 4, in <module>
    print(a / b)
ZeroDivisionError: division by zero
```

Обрати внимание: первый `print` выполнился, а в месте ошибки программа **остановилась**.

### Как читать Traceback?

Читай сообщение об ошибке **снизу вверх**:
1. Самая последняя строка – **тип ошибки** (`ZeroDivisionError`) и её **описание** (`division by zero`).
2. Над ней – **строка кода**, где произошла ошибка (`print(a / b)`).
3. Ещё выше – **имя файла и номер строки** (`line 4`).

### Часто встречающиеся исключения

| Исключение | Когда возникает | Пример |
|---|---|---|
| `ValueError` | Значение не подходит для типа | `int("десять")` |
| `ZeroDivisionError` | Деление на ноль | `5 / 0`, `5 % 0` |
| `TypeError` | Операция с несовместимыми типами | `"5" + 3` |
| `NameError` | Необъявленная переменная | `print(sco)` |
| `IndexError` | Индекса нет в списке | `[1, 2][5]` |
| `KeyError` | Ключа нет в словаре | `{"a": 1}["b"]` |
| `AttributeError` | У объекта нет такого метода | `[1, 2].upper()` |
| `FileNotFoundError` | Файл не найден | `open("нет.txt")` |

```python
cities = ["Алматы", "Астана", "Шымкент"]
print(cities[3])
```

Результат:
```text
Traceback (most recent call last):
  File "main.py", line 2, in <module>
    print(cities[3])
IndexError: list index out of range
```

## 4. Логические ошибки

Самая «хитрая» ошибка – программа работает без всяких сообщений, но **результат неверный**. Python её найти не может, только ты – с помощью тестирования.

Пример: среднее трёх оценок.

```python
a, b, c = 5, 4, 3
average = a + b + c / 3   # логическая ошибка!
print("Средняя оценка:", average)
```

Результат:
```text
Средняя оценка: 10.0
```

Средняя оценка не может быть 10! Причина – порядок действий: сначала `c / 3`, затем сложение. Правильно:

```python
a, b, c = 5, 4, 3
average = (a + b + c) / 3
print("Средняя оценка:", average)
```

Результат:
```text
Средняя оценка: 4.0
```

Способы найти логическую ошибку:
- **Сравнение с ответом, посчитанным вручную** – подать программе данные с известным ответом.
- **Промежуточный `print`** – выводить значения переменных на каждом шаге.
- **Проверка граничных значений** – 0, отрицательное число, пустой список, максимальное значение.
- **Отладчик (Debugger) в Thonny** – выполнять код построчно и следить за переменными (кнопка 🐞, F7 – следующий шаг).

```python
# Проверка цикла с помощью промежуточного print
total = 0
for i in range(1, 5):
    total = total + i
    print("i =", i, "total =", total)   # временная строка для проверки
print("Сумма от 1 до 4:", total)
```

Результат:
```text
i = 1 total = 1
i = 2 total = 3
i = 3 total = 6
i = 4 total = 10
Сумма от 1 до 4: 10
```

## 5. Конструкция try...except

Ошибку выполнения можно заранее «перехватить» и не дать программе упасть.

```text
try:
    # код, в котором может возникнуть ошибка
except ТипОшибки:
    # код, который выполнится при ошибке
```

**Аналогия.** Когда акробат идёт по канату, под ним натянута **страховочная сетка**. `try` – идти по канату, `except` – сетка. Если упадёт – сетка поймает, представление продолжится.

```python
try:
    age = int(input("Введи свой возраст: "))
    print("В следующем году тебе будет", age + 1)
except ValueError:
    print("Ошибка! Возраст нужно писать цифрами.")
print("Программа завершена.")
```

Результат (ввод `пятнадцать`):
```text
Введи свой возраст: пятнадцать
Ошибка! Возраст нужно писать цифрами.
Программа завершена.
```

Порядок работы:
1. Выполняется код внутри `try`.
2. Если ошибки нет – блок `except` **пропускается**.
3. Если ошибка есть – оставшиеся строки внутри `try` не выполняются, управление сразу переходит в соответствующий блок `except`.
4. После этого программа продолжает работу.

### Несколько блоков except

```python
try:
    a = int(input("Первое число: "))
    b = int(input("Второе число: "))
    print("Частное:", a / b)
except ValueError:
    print("Нужно было ввести число!")
except ZeroDivisionError:
    print("На ноль делить нельзя!")
```

Результат (ввод `12` и `0`):
```text
Первое число: 12
Второе число: 0
На ноль делить нельзя!
```

### Получение сведений об ошибке: `as`

```python
try:
    number = int("12а")
except ValueError as e:
    print("Произошла ошибка:", e)
```

Результат:
```text
Произошла ошибка: invalid literal for int() with base 10: '12а'
```

### else и finally

- `else` – выполняется, если ошибки **не было**;
- `finally` – выполняется **всегда**, была ошибка или нет (например, для закрытия файла или освобождения ресурса).

```python
try:
    price = float(input("Цена товара (тенге): "))
except ValueError:
    print("Цена должна быть числом.")
else:
    print("Цена с НДС:", round(price * 1.12, 2), "тенге")
finally:
    print("Расчёт завершён.")
```

Результат (ввод `1000`):
```text
Цена товара (тенге): 1000
Цена с НДС: 1120.0 тенге
Расчёт завершён.
```

### Спрашивать, пока не введут правильно (while + try)

Самый полезный шаблон – повторно спрашивать, пока пользователь не введёт правильное значение:

```python
while True:
    try:
        grade = int(input("Введи свою оценку (1-5): "))
        if 1 <= grade <= 5:
            break
        print("Оценка должна быть от 1 до 5.")
    except ValueError:
        print("Это не число, попробуй ещё раз.")
print("Твоя оценка:", grade)
```

Результат:
```text
Введи свою оценку (1-5): пять
Это не число, попробуй ещё раз.
Введи свою оценку (1-5): 7
Оценка должна быть от 1 до 5.
Введи свою оценку (1-5): 5
Твоя оценка: 5
```

### try...except внутри функции

Обработку ошибок удобно прятать внутрь функции – получается «безопасная» функция:

```python
def safe_int(text, default=0):
    """Преобразует строку в число, иначе возвращает default."""
    try:
        return int(text)
    except ValueError:
        return default

print(safe_int("25"))
print(safe_int("двадцать"))
print(safe_int("", -1))
```

Результат:
```text
25
0
-1
```

> **Правило.** Писать `except:` (без указания типа) – плохая привычка: так скрываются **все** ошибки, даже твои собственные логические. Всегда указывай конкретный тип ошибки.

## Частые ошибки

**1. Неверно указан тип ошибки.**

```python
try:
    x = int("abc")
except ZeroDivisionError:      # должно было быть ValueError
    print("Ошибка")
```

Этот код не перехватывает `ValueError` – программа всё равно упадёт. Правильно:

```python
try:
    x = int("abc")
except ValueError:
    print("Введён текст, а не число")
```

**2. Слишком много кода внутри try.** Становится непонятно, где именно произошла ошибка. Оставляй внутри `try` только строки, которые могут вызвать ошибку, остальное выноси в `else`.

**3. Попытка перехватить синтаксическую ошибку через try.** Файл с синтаксической ошибкой вообще не запускается, поэтому `try` не поможет – её нужно просто исправить.

**4. Ничего не делать внутри except.**

```python
try:
    n = int(input("Число: "))
except ValueError:
    pass   # плохо: пользователь не знает, что произошло
```

Всегда выводи пользователю понятное сообщение.

**5. Перекладывать на try то, что проверяется условием.** Например, наличие ключа в словаре проще и понятнее проверить через `if key in d:`.

## Основные понятия

| Понятие | Пояснение |
|---|---|
| Баг (bug) | Ошибка в программе |
| Отладка (debugging) | Поиск и исправление ошибок |
| Синтаксическая ошибка | Нарушение правил языка, программа не запускается |
| Ошибка выполнения / исключение (exception) | Ошибка, возникшая во время работы, программа останавливается |
| Логическая ошибка | Программа работает, но результат неверный |
| Traceback | Сообщение Python о месте и типе ошибки |
| `try` | Блок кода, в котором может возникнуть ошибка |
| `except` | Блок, перехватывающий и обрабатывающий ошибку |
| `else` | Блок, выполняемый при отсутствии ошибки |
| `finally` | Блок, выполняемый всегда |

## Примечание

- Синтаксическую ошибку `try` не перехватит: файл с ней не компилируется целиком. Исключение – код, выполняемый через `eval()`/`exec()` или импортируемый модуль.
- Начиная с Python 3.10–3.12 сообщения об ошибках стали подробнее: `SyntaxError: expected ':'`, подсказки вида `Did you mean: 'score'?` для `NameError` и `AttributeError`. В старых версиях текст сообщений другой.
- Все стандартные исключения образуют иерархию: например, `ZeroDivisionError` – наследник `ArithmeticError`, а почти всё – наследники `Exception`. Порядок `except` важен: более общий тип, указанный первым, «перехватит» и более частные.
- Несколько типов можно перехватить одним блоком: `except (ValueError, TypeError):`.
- Сгенерировать исключение самому можно оператором `raise ValueError("сообщение")` – это пригодится при проверке аргументов функции.
- Документация: [Errors and Exceptions](https://docs.python.org/3/tutorial/errors.html) и [Built-in Exceptions](https://docs.python.org/3/library/exceptions.html).
