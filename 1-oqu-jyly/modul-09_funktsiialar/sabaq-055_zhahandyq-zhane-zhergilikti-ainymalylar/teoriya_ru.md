## 1. Что такое область видимости?

**Область видимости (scope)** — часть программы, в которой **можно обратиться** к переменной.

Аналогия: **школа и класс**.
- Доска объявлений в фойе школы — **глобальная**: её может увидеть ученик, вышедший из любого класса.
- Надпись на доске внутри класса — **локальная**: её видят только те, кто в этом классе, после урока её стирают.

| Область | Где создаётся | Где видна | Когда уничтожается |
|---|---|---|---|
| **Локальная (local)** | внутри функции | только внутри этой функции | когда функция завершается |
| **Глобальная (global)** | в основной части файла (вне функций) | во всём файле, в том числе внутри функций (для чтения) | когда программа завершается |
| **Встроенная (built-in)** | в самом Python | везде | — (`print`, `len`, `sum` ...) |

## 2. Локальные переменные

Каждая переменная, которой присваивается значение внутри функции, — **локальная**. Она создаётся при вызове функции и уничтожается при её завершении.

```python
def make_tea():
    water = 250        # локальная
    sugar = 2          # локальная
    print(f"Чай: {water} мл воды, {sugar} ложки сахара")


make_tea()
make_tea()             # при каждом вызове переменные создаются заново
```

Результат:
```text
Чай: 250 мл воды, 2 ложки сахара
Чай: 250 мл воды, 2 ложки сахара
```

### Параметры тоже локальные

```python
def double(n):         # n — локальная переменная
    n = n * 2
    return n


x = 10
print(double(x))
print(x)               # x не изменился!
# print(n)             # NameError: n существует только внутри функции
```

Результат:
```text
20
10
```

При вызове происходит присваивание вида `n = x`: `n` — отдельная переменная, её изменение не влияет на `x` (для чисел и строк).

### У каждой функции своя «комната»

Одноимённые переменные в двух разных функциях не мешают друг другу:

```python
def morning():
    message = "Доброе утро!"
    print(message)


def evening():
    message = "Добрый вечер!"
    print(message)


morning()
evening()
```

Результат:
```text
Доброе утро!
Добрый вечер!
```

Это одно из главных преимуществ функций: каждая функция **изолирована** внутри себя и не портит случайно переменные других.

## 3. Глобальные переменные

Переменная, созданная вне функций, — **глобальная**. Функция может её **читать**:

```python
school = "Школа №120"     # глобальная
year = 2027                # глобальная


def print_badge(name):
    print(f"{name} | {school} | {year}")


print_badge("Айгерим")
print_badge("Бекзат")
```

Результат:
```text
Айгерим | Школа №120 | 2027
Бекзат | Школа №120 | 2027
```

Это удобно для постоянных значений (констант). По соглашению их пишут **ЗАГЛАВНЫМИ БУКВАМИ**: `PI = 3.14159`, `MAX_SCORE = 100`.

## 4. Порядок поиска переменной

Встретив имя переменной, Python ищет его в следующем порядке:

```
1. Локальная (Local)      — внутри самой функции
2. Глобальная (Global)    — в основной части файла
3. Встроенная (Built-in)  — среди готовых имён Python
Не найдено → NameError
```

```python
x = "глобальная"


def show():
    x = "локальная"
    print("Внутри функции:", x)


show()
print("Вне функции:", x)
```

Результат:
```text
Внутри функции: локальная
Вне функции: глобальная
```

`x = ...` внутри функции создало **новую локальную** переменную, она «затеняет» (shadowing) глобальную `x`, но не изменяет её.

### Затенение встроенных имён — опасно!

```python
numbers = [3, 5, 7]
# sum = 0                      # теперь sum — число, встроенная функция «закрыта»
# print(sum(numbers))          # TypeError: 'int' object is not callable
total = 0                      # правильно: другое имя
print(sum(numbers))
```

Результат:
```text
15
```

## 5. Изменение глобальной переменной внутри функции

```python
counter = 0


def add_one():
    # counter = counter + 1   # UnboundLocalError: cannot access local variable 'counter'
    pass
```

Почему ошибка? Внутри функции есть присваивание `counter = ...`, поэтому Python считает `counter` **локальной**. А когда вычисляется правая часть `counter + 1`, у локальной `counter` ещё нет значения.

### Ключевое слово global

`global` говорит Python: «эта переменная глобальная, не создавай новую»:

```python
counter = 0


def add_one():
    global counter
    counter = counter + 1


add_one()
add_one()
add_one()
print("Счётчик:", counter)
```

Результат:
```text
Счётчик: 3
```

### Почему global нужно использовать редко?

Результат функции с `global` зависит не только от параметров, но и от **внешнего состояния**. Когда программа разрастается, искать «кто и когда изменил переменную?» очень трудно. Поэтому рекомендация: **данные входят в функцию через параметры, результат выходит через `return`.**

Пример выше — правильным способом:

```python
def add_one(value):
    return value + 1


counter = 0
counter = add_one(counter)
counter = add_one(counter)
counter = add_one(counter)
print("Счётчик:", counter)
```

Результат:
```text
Счётчик: 3
```

| | через `global` | через параметр + `return` |
|---|---|---|
| От чего зависит функция | от внешней переменной | только от аргументов |
| Тестирование | трудно | легко: вход → выход |
| Повторное использование | только с этой переменной | с любым значением |
| Поиск ошибок | трудно | легко |

## 6. Замечание об изменяемых объектах

Чтобы **изменять** список или словарь внутри функции **с помощью методов**, `global` не нужен — потому что мы не переприсваиваем переменную, а меняем содержимое объекта:

```python
cart = []


def add_to_cart(item):
    cart.append(item)       # global не нужен


add_to_cart("хлеб")
add_to_cart("молоко")
print(cart)
```

Результат:
```text
['хлеб', 'молоко']
```

Но это тоже зависимость от глобального состояния. Чистый способ — передавать список как параметр: `def add_to_cart(cart, item):`.

## 7. Наблюдение за областью видимости в отладчике

При пошаговом выполнении программы в отладчике (debugger) области видимости хорошо видны. Например, в Thonny при открытом окне **View → Variables** в пошаговом режиме (F7) при входе в функцию появляется новое окно — **локальная область** функции, а при выходе из функции оно закрывается.

Области можно посмотреть и из самого кода: `locals()` возвращает словарь локальных переменных, `globals()` — словарь глобальных.

```python
def demo(a):
    b = a * 2
    print(locals())


demo(5)
```

Результат:
```text
{'a': 5, 'b': 10}
```

## Частые ошибки

**1. Чтение локальной переменной снаружи**

```python
def get_name():
    name = "Дана"
    return name

# print(name)          # NameError
name = get_name()      # правильно: получить через return
print(name)
```

**2. Попытка изменить глобальную переменную без global**

```python
score = 10

def bonus():
    # score += 5       # UnboundLocalError
    return 5

score += bonus()
print(score)           # 15
```

**3. Думают, что изменение параметра изменило внешнюю переменную**

```python
def reset(x):
    x = 0

a = 100
reset(a)
print(a)               # 100 — не изменилась
```

**4. Встроенное имя дают переменной**

```python
# list = [1, 2, 3]     # функция list() теперь недоступна
items = [1, 2, 3]
print(list("абв"))
```

## Основные понятия

| Понятие | Пояснение |
|---|---|
| Область видимости (scope) | часть программы, в которой можно обратиться к переменной |
| Локальная переменная | переменная, созданная внутри функции и видимая только там |
| Глобальная переменная | переменная, созданная вне функций и видимая во всём файле |
| Встроенные имена | имена Python, такие как `print`, `len`, `sum` |
| Затенение (shadowing) | одноимённая переменная во внутренней области «закрывает» внешнюю |
| `global` | ключевое слово, разрешающее изменять глобальную переменную внутри функции |
| Константа | неизменяемое значение, имя пишется заглавными буквами: `MAX_SCORE` |

## Примечание

- В Python блоки `if`, `for`, `while` не создают новую область видимости: переменная, созданная в цикле, доступна и после него (в отличие от C и Java).
- Полный порядок поиска — **LEGB**: Local → Enclosing (внешняя функция) → Global → Built-in. Чтобы изменить переменную внешней функции из вложенной, используется `nonlocal`.
- `UnboundLocalError` — подвид `NameError`; он возникает потому, что если переменной где-либо в функции присваивается значение, она считается локальной во всей функции.
- По PEP 8 константы записываются на уровне модуля в виде `UPPER_CASE`; Python не запрещает их изменять — это лишь соглашение.
- Если встроенное имя случайно затенено, его можно вернуть, удалив переменную: `del sum`.
- Документация: https://docs.python.org/3/tutorial/classes.html#python-scopes-and-namespaces
