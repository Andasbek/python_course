## 1. Структура программы «Обо мне»

Программа «Обо мне» — «цифровая визитка»: она выводит на экран сведения об авторе. Даже небольшую программу удобно сначала **спланировать**: разбить на разделы и для каждого выбрать инструмент Python.

| № | Раздел | Содержание | Инструмент Python |
|---|---|---|---|
| 1 | Описание | Название, автор, дата, что делает программа | `"""..."""` (строка документации) |
| 2 | Заголовок | «ОБО МНЕ» в рамке | `print("=" * 40)` |
| 3 | Основные сведения | Имя, возраст, школа, город | `print()` с несколькими значениями |
| 4 | Интересы | Хобби, любимый предмет, игра | `print()`, `sep` |
| 5 | Интересные числа | Сколько месяцев я прожил(а)? | вычисление `12 * 12` без кавычек |
| 6 | Расписание на неделю | Кружок, спорт, музыка | `\t` для выравнивания столбцов |
| 7 | Рисунок | Кошка / ракета / ноутбук | многострочная строка в тройных кавычках |
| 8 | Прощание | «Спасибо!» | `end` |

С точки зрения блок-схемы это **линейный алгоритм**: «Начало → вывод → вывод → ... → Конец».

Признаки аккуратно оформленной программы:
- в начале файла — описание в тройных кавычках;
- логические части отделены **пустыми строками** и подписаны **комментариями**-разделителями;
- хотя бы часть данных **вычисляется** Python, а не считается вручную;
- код соответствует PEP 8 (пробелы после запятых и вокруг операторов);
- программа запускается **без ошибок**.

## 2. Пример программы

```python
"""
Программа: Обо мне
Автор: Айдана Серикова
Дата: 23.09.2026
Описание: красиво выводит на экран сведения обо мне.
"""

# ----- Заголовок -----
print("=" * 40)
print("               ОБО МНЕ")
print("=" * 40)
print()

# ----- Основные сведения -----
print("Фамилия и имя:", "Айдана Серикова")
print("Возраст:", 12)
print("Город:", "Алматы")
print("Школа:", "школа-гимназия №125, 6 класс")
print()

# ----- Мои интересы -----
print("Хобби:", "рисование", "шахматы", "Python", sep=" | ")
print("Любимый предмет: математика")
print("Мечта: стать разработчиком игр")
print()

# ----- Интересные числа -----
# так как мне полных 12 лет, примерно считаем месяцы, умножая на 12
print("Я прожила примерно", 12 * 12, "мес.")
print("Это примерно", 12 * 365, "дней!")
print()

# ----- Моё расписание на неделю -----
print("День\t\tДела")
print("Понедельник\tкружок Python")
print("Среда\t\tкружок Python")
print("Пятница\t\tшахматы")
print()

# ----- Рисунок -----
print("""
   /\\_/\\
  ( ^.^ )   Мой кот — Барсик
   > ^ <
""")

# ----- Прощание -----
print("Спасибо за", end=" ")
print("знакомство!")
print("=" * 40)
```

Результат:
```text
========================================
               ОБО МНЕ
========================================

Фамилия и имя: Айдана Серикова
Возраст: 12
Город: Алматы
Школа: школа-гимназия №125, 6 класс

Хобби: | рисование | шахматы | Python
Любимый предмет: математика
Мечта: стать разработчиком игр

Я прожила примерно 144 мес.
Это примерно 4380 дней!

День		Дела
Понедельник	кружок Python
Среда		кружок Python
Пятница		шахматы


   /\_/\
  ( ^.^ )   Мой кот — Барсик
   > ^ <

Спасибо за знакомство!
========================================
```

**Обратите внимание:** в строке «Хобби: | рисование» разделитель поставлен и после заголовка. Это небольшая **логическая ошибка**: `sep` ставится между всеми значениями. Как её исправить? Например, вывести заголовок отдельно через `print("Хобби:", end=" ")`, а остальное — с `sep=" | "`. Вот почему так важно постоянно проверять результат!

## 3. Пошаговая разработка программы

Профессиональные программисты пишут код **небольшими шагами** и проверяют каждый шаг (инкрементальная разработка):

1. **План.** Определите разделы программы и инструменты для каждого (таблица выше).
2. **Каркас.** Напишите описание и комментарии-разделы (`# ----- ... -----`) — это «каркас» программы. Такой файл уже можно запустить: комментарии не выполняются.
3. **Наполнение.** Постепенно заполняйте каждый раздел. **Запускайте и проверяйте после каждых 3–4 строк** — ошибку легче найти, пока изменённого кода мало.
4. **Оформление.** Добавьте рамку, пустые строки, таблицу, рисунок.
5. **Тестирование.** Сравните фактический вывод с ожидаемым: правильные ли вычисления, ровные ли столбцы, нет ли лишних разделителей.

Каркас программы:

```python
"""
Программа: Обо мне
Автор: ...
"""

# ----- Заголовок -----

# ----- Основные сведения -----

# ----- Интересные числа -----
```

## 4. Code review — проверка кода

**Code review** (ревью кода) — практика, при которой код читает другой программист и предлагает улучшения. На что обращают внимание:
- работает ли программа и верен ли результат;
- понятны ли комментарии и имена;
- соблюдён ли PEP 8: пробел после запятой, пробелы вокруг операторов, нет пробела перед `(`;
- нет ли повторяющегося кода, который можно упростить (например, `"=" * 40` вместо сорока символов `=`).

Замечания формулируют конкретно («в строке 12 нет пробела после запятой»), а исправления вносит автор кода.

## Частые ошибки
**1. Число в кавычках «отключает» вычисление.**
```python
print("Я прожил примерно", "12 * 12", "мес.")
```
Результат:
```text
Я прожил примерно 12 * 12 мес.
```
Правильно — выражение без кавычек:
```python
print("Я прожил примерно", 12 * 12, "мес.")
```

**2. Символ `\` в рисунке в тройных кавычках.** `\` — специальный символ, поэтому в рисунке пишем его дважды: `\\` (или рисуем без `\`).

**3. Запуск кода только один раз, в самом конце.** Если написать 40 строк и сразу получить 5 ошибок, найти их трудно. Запускайте почаще!

**4. Файл не сохранён.** IDLE перед запуском требует сохранить файл («Source Must Be Saved»), а несохранённые изменения в других редакторах не попадут в запуск из терминала. Сохраняйте файл (Ctrl+S) перед каждым запуском.

**5. Отступ.** Все `print` пишутся с начала строки; лишний пробел вызывает `IndentationError`.

## Основные понятия

| Понятие | Определение |
|---|---|
| Линейная программа | Программа, команды которой выполняются по порядку сверху вниз, по одному разу |
| Планирование | Определение содержания и структуры до написания кода |
| Каркас программы | Начальная структура из комментариев, обозначающих разделы |
| Тестирование | Запуск программы и сравнение результата с ожидаемым |
| Code review (ревью кода) | Чтение кода другим программистом и предложения по его улучшению |
| ASCII-рисунок | Рисунок, составленный из текстовых символов |

## Примечание

- Строку можно умножать только на целое число: `"=" * 40` работает, а `"=" * 2.5` вызывает `TypeError`; `"=" * 0` даёт пустую строку.
- Табуляция `\t` выравнивает текст по позициям, кратным 8 символам (в большинстве консолей), поэтому для длинных слов нужен второй `\t`, а для коротких — нет. Точнее выравнивать можно с помощью f-строк: `f"{'Среда':<12}"`.
- В обычной строке `\` начинает спецпоследовательность; для ASCII-рисунков удобны «сырые» строки `r"""..."""`, в которых `\` пишется один раз.
- Строку документации модуля можно прочитать из программы: `print(__doc__)`.
- Текст программы и сообщений можно писать на любом языке (Python 3 работает с Unicode), но имена файлов лучше давать латиницей: `men_turaly.py`.
