## 1. Почему важна культура кода?

Программист **пишет** код **один раз**, а **читает** его **десятки раз** — и сам, и его коллеги. В неаккуратно написанном коде трудно найти ошибку, на его понимание уходит много времени.

> «Код пишется для человека, а не для компьютера; компьютер его только выполняет.»

Аналогия: аккуратный почерк. Неряшливую, исчёрканную запись трудно прочитать, даже если в ней всё написано правильно.

## 2. PEP 8 — стиль кода Python

**PEP 8** — официальный сборник рекомендаций о том, как писать код на Python красиво и единообразно (Python Enhancement Proposal 8). Основные правила, касающиеся команд, которые мы уже знаем:

| Правило | Правильно | Неправильно |
|---|---|---|
| Нет пробела между именем функции и скобкой | `print("A")` | `print ("A")` |
| После запятой — один пробел | `print(1, 2, 3)` | `print(1,2,3)` |
| По одному пробелу с обеих сторон знаков операций | `print(5 + 3 * 2)` | `print(5+3*2)` |
| Нет пробелов у краёв внутри скобок | `print(10)` | `print( 10 )` |
| В имени параметра нет пробелов вокруг `=` | `sep="-"` | `sep = "-"` |
| Длина строки — не более 79 символов | Длинный текст разбит | Строка, выходящая за экран |
| Одна пустая строка между логическими частями | Разделы отделены пустой строкой | Всё в одной куче |
| Единообразное использование кавычек | Во всём файле `"..."` | Вперемешку `'...'` и `"..."` |

Пример. Неряшливый код:

```python
print ("ЧЕК МАГАЗИНА")
print("Хлеб:",2*180,"тенге")
print( "Молоко:" , 3*520 , "тенге" )
print("Итого:",2*180+3*520,'тенге')
```

Приведённый в порядок по PEP 8:

```python
print("ЧЕК МАГАЗИНА")
print("Хлеб:", 2 * 180, "тенге")
print("Молоко:", 3 * 520, "тенге")
print("Итого:", 2 * 180 + 3 * 520, "тенге")
```

Результат (в обоих случаях одинаковый):
```text
ЧЕК МАГАЗИНА
Хлеб: 360 тенге
Молоко: 1560 тенге
Итого: 1920 тенге
```

Результат не изменился, но второй код читать гораздо легче.

## 3. Комментарии (түсініктемелер, comments)

**Комментарий** — запись внутри кода, предназначенная для человека. Python её **игнорирует** (не выполняет).

### 3.1. Однострочный комментарий: `#`
Текст от символа `#` до конца строки — комментарий.

```python
# Эта программа выводит чек магазина
# Автор: Айдана Серикова, 21.09.2026

print("ЧЕК МАГАЗИНА")  # заголовок
print("Хлеб:", 2 * 180, "тенге")  # 2 хлеба, каждый по 180 тенге
```

Результат:
```text
ЧЕК МАГАЗИНА
Хлеб: 360 тенге
```

Правила PEP 8:
- после символа `#` — один пробел: `# комментарий`;
- перед комментарием в конце строки кода — не менее **двух** пробелов: `print(1)  # один`.

### 3.2. Многострочный комментарий
Используются несколько строк с `#` или текст в тройных кавычках (`"""..."""`). Текст в тройных кавычках принято писать в начале файла — как описание программы:

```python
"""
Программа: Дни недели
Автор: Ерлан Касымов
Описание: выводит на экран рабочие дни недели.
"""

print("Понедельник, Вторник, Среда, Четверг, Пятница")
```

Результат:
```text
Понедельник, Вторник, Среда, Четверг, Пятница
```

### 3.3. Использование комментария для временного «отключения»
Чтобы временно не выполнять строку кода, не удаляя её, ставим перед ней `#` (в IDLE: **Format → Comment Out Region**, Alt+3; в VS Code/Thonny: **Ctrl+/**).

```python
print("Эта строка выполняется")
# print("Эта строка временно отключена")
print("Эта тоже выполняется")
```

Результат:
```text
Эта строка выполняется
Эта тоже выполняется
```

### 3.4. Хороший и плохой комментарий
| Плохой (бесполезный) | Хороший (полезный) |
|---|---|
| `print(60 * 60)  # умножаем 60 на 60` — код и так это говорит | `print(60 * 60)  # количество секунд в часе` — объясняет, **зачем** |

Правило: комментарий должен объяснять не **что** делает код, а **зачем** он это делает.

## 4. Ошибки в программе

Ошибку в программе по-английски называют **bug** («жук»), а поиск и исправление ошибок — **debugging** (отладка). В 1947 году внутри компьютера Mark II в Гарвардском университете была найдена настоящая моль, которую вклеили в журнал с надписью «First actual case of bug being found», — с тех пор это название и распространилось.

### 4.1. Виды ошибок

| Вид | Когда возникает? | Пример |
|---|---|---|
| **Синтаксическая ошибка** (SyntaxError, IndentationError) | До запуска программы; Python не может «прочитать» код | Не закрыта кавычка |
| **Ошибка времени выполнения** (runtime error: NameError, TypeError, ZeroDivisionError) | Во время работы программы, когда она доходит до строки с ошибкой | `print(10 / 0)` |
| **Логическая ошибка** | Python не выдаёт никакой ошибки, но результат неверный | Вычисление площади вместо периметра |

Логическая ошибка — самая опасная, потому что компьютер её не показывает. Её находят только проверкой результата: трассировкой и сравнением с заранее известным правильным ответом.

### 4.2. Чтение сообщения об ошибке (traceback)

Программа:

```text
print("Первая строка")
print("Вторая строка)
print("Третья строка")
```

Ответ Python:

```text
  File "C:\Python_Uyirme\test.py", line 2
    print("Вторая строка)
          ^
SyntaxError: unterminated string literal (detected at line 2)
```

Как читаем:
1. **`line 2`** — ошибка во 2-й строке (или чуть раньше!).
2. **`^`** — указывает предполагаемое место ошибки.
3. **`SyntaxError`** — вид ошибки.
4. **`unterminated string literal`** — причина: «незакрытая строка (текст)».

Сообщение об ошибке времени выполнения:

```text
Traceback (most recent call last):
  File "C:\Python_Uyirme\test.py", line 3, in <module>
    prnt("Привет")
NameError: name 'prnt' is not defined. Did you mean: 'print'?
```

Здесь Python даже даёт подсказку: «Did you mean: 'print'?» — «Вы имели в виду 'print'?» Всегда внимательно читайте **последнюю строку** сообщения!

Обратите внимание: при синтаксической ошибке **не выполняется ни одна строка** программы. А при ошибке выполнения строки до ошибки успевают выполниться.

### 4.3. «Словарь» частых сообщений об ошибках

| Сообщение | Значение по-русски | Возможная причина |
|---|---|---|
| `SyntaxError: invalid syntax` | Неверный синтаксис | Лишний/недостающий символ, неправильное слово |
| `SyntaxError: unterminated string literal` | Строка (текст) не закрыта | Нет кавычки |
| `SyntaxError: '(' was never closed` | Скобка не закрыта | Нет `)` |
| `SyntaxError: unmatched ')'` | Лишняя закрывающая скобка | Лишняя `)` |
| `SyntaxError: invalid character '«'` | Недопустимый символ | Кавычки «», кириллическая «с» и т.п. |
| `SyntaxError: invalid syntax. Perhaps you forgot a comma?` | Может, вы забыли запятую? | Нет запятой между значениями |
| `IndentationError: unexpected indent` | Неожиданный отступ | Лишний пробел в начале строки |
| `NameError: name '...' is not defined` | Это имя не определено | Команда написана с ошибкой, текст без кавычек |
| `TypeError` | Ошибка типа | Сложение текста и числа: `"5" + 3` |
| `ZeroDivisionError: division by zero` | Деление на ноль | `print(5 / 0)` |

### 4.4. Стратегия поиска ошибок (5 шагов)
1. **Успокойся** — сообщение об ошибке не ругает, оно помогает!
2. **Прочитай последнюю строку** — вид и причина ошибки.
3. **Перейди к номеру строки** — проверь эту строку и **предыдущую** (незакрытая скобка может проявиться на следующей строке).
4. **Проверь типичные причины:** кавычки, скобки, запятые, раскладка, заглавные/строчные буквы, пробел в начале строки.
5. **Исправь и запусти снова.** Вноси одно изменение и проверяй результат. Если ошибок несколько — исправляй постепенно, сверху вниз.

Дополнительные приёмы:
- **Метод «резиновой уточки»** — объясните свой код вслух строка за строкой кому-нибудь (или игрушечной уточке!). Объясняя, вы часто сами находите ошибку.
- Временно отключите подозрительную строку с помощью `#` и проверьте, исчезла ли ошибка.

## Частые ошибки
**1. `#` внутри кавычек.**
```python
print("Привет # это не комментарий")
```
Результат:
```text
Привет # это не комментарий
```
`#` внутри кавычек — часть текста. Комментарий пишется вне кавычек:
```python
print("Привет")  # это — комментарий
```

**2. Комментарий через `//` (как в других языках).**
```text
// это комментарий
SyntaxError: invalid syntax
```
В Python — только `#`:
```python
# это комментарий
```

**3. Нет запятой между значениями.**
```text
print("Мне лет" 12)
SyntaxError: invalid syntax. Perhaps you forgot a comma?
```
Правильно:
```python
print("Мне лет", 12)
```

**4. «Исправление» не той строки, а следующей.** Если скобка не закрыта в 3-й строке, Python иногда указывает на 4-ю. Всегда проверяйте и предыдущую строку.

**5. Кириллическая буква внутри латинского слова.** Если в слове `print` буква «р» набрана русской раскладкой, внешне всё выглядит одинаково, но возникает `NameError`. Решение — заново набрать слово в английской раскладке.

## Основные понятия

| Понятие | Определение |
|---|---|
| Культура кода | Правила читаемого, единообразного написания кода |
| PEP 8 | Официальные рекомендации по стилю кода на Python |
| Комментарий (түсініктеме, comment) | Запись для человека, которую Python игнорирует (`#`) |
| Баг (bug) | Ошибка в программе |
| Отладка (debugging, жөндеу) | Процесс поиска и исправления ошибок |
| Синтаксическая ошибка | Нарушение правил языка; программа вообще не запускается |
| Ошибка времени выполнения | Ошибка, возникающая во время работы программы |
| Логическая ошибка | Программа работает, но результат неверный |
| Traceback | Сообщение Python, показывающее место и вид ошибки |

## Примечание

- Полный текст PEP 8 (на английском): https://peps.python.org/pep-0008/ . Правила стиля проверяются автоматически инструментами `flake8`, `pycodestyle`, `ruff`, а автоформатер `black` сам приводит код к единому виду.
- Строка в тройных кавычках в начале файла — это не комментарий, а **строка документации** (docstring, PEP 257): Python сохраняет её в `__doc__` модуля, и её показывает `help()`.
- Подсказки вида `Did you mean: 'print'?` и более точные сообщения об ошибках появились в Python 3.10–3.12; в старых версиях часто выводится просто `invalid syntax`.
- Первая строка вида `# -*- coding: utf-8 -*-` в Python 3 не нужна: исходные файлы по умолчанию читаются в кодировке UTF-8.
- Комментарии, расходящиеся с кодом, хуже, чем их отсутствие: при изменении кода обновляйте и комментарии (правило из PEP 8).
