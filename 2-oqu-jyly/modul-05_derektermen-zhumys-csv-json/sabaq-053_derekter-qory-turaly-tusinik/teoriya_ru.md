## 1. Что такое база данных?

**База данных (БД, database)** — совокупность данных, относящихся к определённой теме, хранящихся в организованном виде, в которой легко искать и изменять данные.

Примеры из повседневной жизни:
- **kundelik.kz** — ученики, классы, предметы, оценки;
- **Kaspi.kz** — клиенты, товары, заказы, платежи;
- **egov.kz** — граждане (ИИН), документы, адреса;
- **школьная библиотека** — книги, читатели, выданные книги;
- **игра** — игроки, уровни, рекорды.

**Аналогия:** база данных — большая библиотека. Книги (данные) не свалены где попало: они разложены по отделам и полкам (таблицы), у каждой книги есть номер (ключ) и каталожная карточка (запись). Поэтому библиотекарь находит любую книгу за несколько секунд.

### СУБД — система управления базами данных

С базой данных мы не работаем напрямую — работаем через специальную программу.

**СУБД (DBMS)** — программная система для создания базы данных, хранения, поиска, изменения и защиты данных.

| СУБД | Особенность | Где используется |
|---|---|---|
| **SQLite** | один файл, не нужен сервер, встроена в Python | мобильные приложения, браузеры, небольшие проекты |
| PostgreSQL | мощная, бесплатная, сервер | веб-сайты, крупные системы |
| MySQL / MariaDB | широко распространена, сервер | веб-сайты |
| Microsoft SQL Server, Oracle | коммерческие | банки, крупные компании |

**SQLite** входит в стандартную библиотеку Python как модуль `sqlite3`, вся база — один файл `.db`. WhatsApp и Telegram на смартфоне, история браузера тоже хранятся в SQLite.

### Почему база данных, а не файл?

| Проблема | Файлы (txt, CSV, JSON) | База данных |
|---|---|---|
| Поиск | прочитать весь файл и искать циклом | мгновенно через индекс (SQL-запрос) |
| Изменение одной записи | перезаписать весь файл | меняется только эта запись |
| Несколько пользователей | стирают изменения друг друга | СУБД регулирует очерёдность |
| Корректность данных | запишется и оценка `"пять"` | проверяются тип и ограничения |
| Повторы | один ученик может быть записан несколько раз | ключи не допускают повторов |
| Связи | поиск вручную | таблицы связаны через ключи |
| Объём | мегабайты | гигабайты, терабайты |

## 2. Модели данных

Есть несколько способов организации данных:

| Модель | Структура | Пример |
|---|---|---|
| Иерархическая | дерево (родитель → потомок) | папки файловой системы, JSON |
| Сетевая | граф (любые связи) | друзья в социальной сети |
| **Реляционная** | **связанные между собой таблицы** | школьный журнал, банк, магазин |
| Документная (NoSQL) | набор JSON-подобных документов | MongoDB |

Самая распространённая — **реляционная модель**. Её предложил в 1970 году английский математик **Эдгар Кодд** (Edgar F. Codd, IBM). «Relation» по-английски — «отношение», в математике — таблица.

## 3. Реляционная модель: таблица, поле, запись

**Реляционная база данных** — база данных, в которой данные хранятся в виде **таблиц**, а таблицы связаны между собой через **ключи**.

Таблица `students` (ученики):

| id | last_name | first_name | birth_date | class | city |
|---|---|---|---|---|---|
| 1 | Нурланкызы | Айгерим | 2011-03-15 | 9А | Алматы |
| 2 | Сеитов | Бауыржан | 2011-07-02 | 9А | Алматы |
| 3 | Оспанов | Даулет | 2010-11-20 | 9Б | Конаев |
| 4 | Алиева | Сымбат | 2011-01-09 | 9Б | Алматы |

### Основные понятия

| Понятие | Другие названия | Значение | Пример |
|---|---|---|---|
| **Таблица (table)** | отношение (relation) | данные об объектах одного типа | `students` |
| **Поле (field)** | столбец, атрибут, column | одна характеристика объекта; столбец таблицы | `birth_date` |
| **Запись (record)** | строка, кортеж, row | полные сведения об одном объекте; строка таблицы | строка о Даулете |
| **Значение (value)** | ячейка | данные на пересечении записи и поля | `9Б` |
| **Схема (schema)** | структура | поля таблицы и их типы | `students(id, last_name, ...)` |

Правила реляционной таблицы:
1. У каждой таблицы есть **уникальное имя**.
2. В одной таблице **имена полей не повторяются**.
3. Все значения в одном поле **одного типа** (например, в столбце `birth_date` — только даты).
4. В каждой ячейке **только одно значение** (атомарность): нельзя записать в одну ячейку два кружка «Python, Робототехника».
5. **Одинаковых записей нет** — есть ключ, однозначно определяющий каждую запись.
6. Порядок записей и полей не важен.

**Сравнение с Python:** таблица — как список словарей, запись — один словарь, поле — ключ словаря.

```python
# Моделируем таблицу структурой Python
students = [
    {"id": 1, "last_name": "Нурланкызы", "first_name": "Айгерим", "class": "9А", "city": "Алматы"},
    {"id": 2, "last_name": "Сеитов", "first_name": "Бауыржан", "class": "9А", "city": "Алматы"},
    {"id": 3, "last_name": "Оспанов", "first_name": "Даулет", "class": "9Б", "city": "Конаев"},
    {"id": 4, "last_name": "Алиева", "first_name": "Сымбат", "class": "9Б", "city": "Алматы"},
]

fields = list(students[0].keys())
print("Поля:", fields)
print("Количество полей:", len(fields), "| Количество записей:", len(students))
print("3-я запись:", students[2])
print("Значение (3-я запись, поле city):", students[2]["city"])
```

Результат:

```text
Поля: ['id', 'last_name', 'first_name', 'class', 'city']
Количество полей: 5 | Количество записей: 4
3-я запись: {'id': 3, 'last_name': 'Оспанов', 'first_name': 'Даулет', 'class': '9Б', 'city': 'Конаев'}
Значение (3-я запись, поле city): Конаев
```

## 4. Типы данных полей

Тип каждого поля определяется заранее. Основные типы SQLite:

| Тип SQLite | Значение | В Python | Примеры полей |
|---|---|---|---|
| `INTEGER` | целое число | `int` | `id`, `age`, `quantity` |
| `REAL` | дробное число | `float` | `price`, `average`, `temperature` |
| `TEXT` | текст | `str` | `name`, `email`, `phone` |
| `BLOB` | двоичные данные | `bytes` | изображение, файл |
| `NULL` | пустое значение («неизвестно») | `None` | ещё не заполненное поле |

Дата и время в SQLite обычно хранятся как `TEXT` в формате ISO: `'2011-03-15'`, `'2027-01-11 14:30:00'`. Логическое значение — `INTEGER` (0 или 1).

**Номер телефона** хранится как `TEXT`! Потому что в `+7 701 ...` есть `+` и пробелы, ведущие нули не должны теряться, а арифметику с номером не делают. ИИН — тоже `TEXT` (12 цифр, может начинаться с нуля).

### Ограничения (constraints)

| Ограничение | Значение |
|---|---|
| `NOT NULL` | поле не должно быть пустым |
| `UNIQUE` | значения не должны повторяться (например, email) |
| `DEFAULT 0` | если значение не задано — значение по умолчанию |
| `CHECK (score BETWEEN 0 AND 100)` | значение должно соответствовать условию |
| `PRIMARY KEY` | первичный ключ (см. ниже) |

## 5. Ключи

### Первичный ключ (PRIMARY KEY)

**Первичный ключ** — поле (или группа полей), **однозначно** определяющее каждую запись в таблице.

Требования:
- **уникальность** — не совпадает у двух записей;
- **непустота** — не бывает `NULL`;
- **неизменность** — не меняется со временем.

Какое поле может быть ключом? Проверим таблицу `students`:

| Поле | Может быть ключом? | Причина |
|---|---|---|
| `first_name` | Нет | Может быть две Айгерим |
| `last_name` + `first_name` | Нет | Встречаются полные тёзки |
| `class` | Нет | В одном классе много учеников |
| ИИН | Да, но... | Уникален, но это персональные данные, распространять его повсюду как ключ небезопасно |
| `id` | **Да** | Уникальный номер, который присваивает сама система |

**Аналогия:** если в классе две «Айгерим», в журнале их различают по порядковому номеру. В банке — номер счёта, в библиотеке — инвентарный номер, в школе — номер ученического билета.

| Вид ключа | Описание | Пример |
|---|---|---|
| **Естественный ключ** | уникальные данные, существующие в реальной жизни | ИИН, госномер, ISBN |
| **Суррогатный ключ** | искусственный номер, созданный системой | `id` = 1, 2, 3, ... (`AUTOINCREMENT`) |
| **Составной ключ** | совокупность нескольких полей | (`student_id`, `subject_id`, `date`) |

На практике чаще всего используется **суррогатный ключ** `id INTEGER PRIMARY KEY`.

### Внешний ключ (FOREIGN KEY) и связь таблиц

Если хранить всё в одной таблице, данные **повторяются**:

| id | student | class | teacher | teacher_phone |
|---|---|---|---|---|
| 1 | Айгерим | 9А | Ермекова Г.С. | +7 701 111 11 11 |
| 2 | Бауыржан | 9А | Ермекова Г.С. | +7 701 111 11 11 |
| 3 | Даулет | 9Б | Оспанова А.Б. | +7 702 222 22 22 |

Если изменится телефон классного руководителя — нужно менять десятки строк, а если одну забудем — возникнет противоречие. Решение — разделить данные на **две таблицы** и связать их через **ключ**:

Таблица `classes`:

| id | name | teacher | teacher_phone |
|---|---|---|---|
| 1 | 9А | Ермекова Г.С. | +7 701 111 11 11 |
| 2 | 9Б | Оспанова А.Б. | +7 702 222 22 22 |

Таблица `students`:

| id | name | class_id |
|---|---|---|
| 1 | Айгерим | 1 |
| 2 | Бауыржан | 1 |
| 3 | Даулет | 2 |

`students.class_id` — **внешний ключ**: он ссылается на первичный ключ другой таблицы (`classes`).

```text
classes                      students
+----+------+---------+      +----+-----------+----------+
| id | name | teacher |      | id | name      | class_id |
+----+------+---------+      +----+-----------+----------+
| 1  | 9А   | Ермекова| <----| 1  | Айгерим   |    1     |
| 2  | 9Б   | Оспанова| <-+  | 2  | Бауыржан  |    1     |
+----+------+---------+   +--| 3  | Даулет    |    2     |
   PRIMARY KEY               +----+-----------+----------+
                                              FOREIGN KEY
```

Правило внешнего ключа — **ссылочная целостность** (referential integrity): нельзя записать `class_id = 7`, если в таблице `classes` нет записи с `id = 7`.

```python
# «Вручную» находим связь по внешнему ключу в Python
classes = {1: {"name": "9А", "teacher": "Ермекова Г.С."},
           2: {"name": "9Б", "teacher": "Оспанова А.Б."}}
students = [{"id": 1, "name": "Айгерим", "class_id": 1},
            {"id": 2, "name": "Бауыржан", "class_id": 1},
            {"id": 3, "name": "Даулет", "class_id": 2}]

for s in students:
    cls = classes[s["class_id"]]          # внешний ключ → первичный ключ
    print(f"{s['name']}: класс {cls['name']}, руководитель {cls['teacher']}")

# Проверка ссылочной целостности
new_student = {"id": 4, "name": "Сымбат", "class_id": 7}
if new_student["class_id"] not in classes:
    print("Ошибка: такого класса нет, запись не добавляется!")
```

Результат:

```text
Айгерим: класс 9А, руководитель Ермекова Г.С.
Бауыржан: класс 9А, руководитель Ермекова Г.С.
Даулет: класс 9Б, руководитель Оспанова А.Б.
Ошибка: такого класса нет, запись не добавляется!
```

Такие проверки СУБД выполняет **сама** — поэтому база данных надёжна. Связи между таблицами бывают трёх видов: один-к-одному, один-ко-многим и многие-ко-многим.

## 6. SQL — язык баз данных

**SQL (Structured Query Language)** — язык структурированных запросов для работы с реляционными базами данных. Он общий для всех реляционных СУБД (SQLite, PostgreSQL, MySQL). Из Python SQL-запросы выполняются через модуль `sqlite3`. Первое знакомство:

```sql
-- Создание таблицы
CREATE TABLE students (
    id INTEGER PRIMARY KEY,
    name TEXT NOT NULL,
    class_id INTEGER REFERENCES classes(id)
);

-- Добавление записи
INSERT INTO students (name, class_id) VALUES ('Айгерим', 1);

-- Поиск: все ученики класса 1
SELECT name FROM students WHERE class_id = 1;
```

Обратите внимание: в SQL мы говорим не **«как»** искать, а **«что»** нужно — цикл организует сама СУБД.

| Команда SQL | Что делает |
|---|---|
| `CREATE TABLE` | создание таблицы |
| `INSERT` | добавление записи |
| `SELECT` | чтение данных, поиск |
| `UPDATE` | изменение записи |
| `DELETE` | удаление записи |
| `JOIN` | объединение таблиц |

## Частые ошибки

**1. Запись нескольких значений в одну ячейку.**

| id | name | clubs |
|---|---|---|
| 1 | Айгерим | Python, Шахматы, Домбра |

Ошибка: трудно найти «тех, кто ходит на шахматы», трудно удалить кружок. Правильно: вынести кружки в отдельную таблицу и связать её с учениками через ключи.

**2. Использование имени в качестве ключа.** Если придут ученики-тёзки — ключ нарушится. Правильно: `id`.

**3. Хранение вычисляемого значения.** Если хранить поле `age` (возраст), оно каждый год устаревает. Правильно: хранить `birth_date` и вычислять возраст.

**4. Хранение телефона, ИИН, индекса в виде числа** → теряются ведущие нули и `+`. Правильно: `TEXT`.

**5. Путаница между полем и записью.** Поле — **столбец** (характеристика: «имя»), запись — **строка** (конкретный ученик).

**6. Смешивание всего в одной таблице.** Ученики, преподаватели, оценки, расписание — в одной большой таблице. Правильно: для каждой «смысловой сущности» (entity) — отдельная таблица.

## Основные понятия

| Понятие | Объяснение |
|---|---|
| База данных (БД) | Совокупность данных, хранящихся в организованном виде |
| СУБД | Программа, создающая, управляющая и защищающая БД (SQLite, PostgreSQL) |
| Реляционная модель | Хранение данных в виде связанных между собой таблиц |
| Таблица | Данные об объектах одного типа (отношение) |
| Поле (столбец) | Одна характеристика объекта; имеет имя и тип |
| Запись (строка) | Полные сведения об одном объекте |
| Первичный ключ (PK) | Поле, однозначно определяющее запись |
| Внешний ключ (FK) | Поле, ссылающееся на первичный ключ другой таблицы |
| Ссылочная целостность | Правило: FK должен ссылаться только на существующую запись |
| Схема | Описание таблиц, полей, типов |
| SQL | Язык для работы с реляционными БД |

## Примечание

- SQLite использует **динамическую типизацию**: тип столбца — лишь «рекомендация» (type affinity), и в столбец `INTEGER` можно записать строку `'abc'`. Строгую проверку типов включает объявление `CREATE TABLE ... STRICT` (SQLite 3.37+).
- В SQLite проверка внешних ключей по умолчанию **выключена**; её включают командой `PRAGMA foreign_keys = ON` для каждого нового соединения.
- `NULL` — это «неизвестно», а не ноль и не пустая строка: сравнение `NULL = NULL` даёт не истину, а `NULL`; для проверки используется `IS NULL`.
- Версию SQLite, встроенную в ваш Python, показывает `import sqlite3; print(sqlite3.sqlite_version)` — от неё зависят доступные возможности SQL.
- Имена таблиц и полей принято писать латиницей в `snake_case` (`birth_date`, `class_id`), таблицы — во множественном числе (`students`).
- Документация: https://docs.python.org/3/library/sqlite3.html и https://www.sqlite.org/datatype3.html
