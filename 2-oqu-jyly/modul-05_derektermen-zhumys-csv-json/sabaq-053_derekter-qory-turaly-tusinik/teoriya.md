## 1. Деректер қоры дегеніміз не?

**Деректер қоры (ДҚ, база данных, database)** — белгілі бір тақырыпқа қатысты, ұйымдасқан түрде сақталған және оңай іздеуге, өзгертуге болатын деректер жиынтығы.

Күнделікті өмірдегі мысалдар:
- **kundelik.kz** — оқушылар, сыныптар, пәндер, бағалар;
- **Kaspi.kz** — клиенттер, тауарлар, тапсырыстар, төлемдер;
- **egov.kz** — азаматтар (ЖСН), құжаттар, мекенжайлар;
- **мектеп кітапханасы** — кітаптар, оқырмандар, берілген кітаптар;
- **ойын** — ойыншылар, деңгейлер, рекордтар.

**Аналогия:** деректер қоры — үлкен кітапхана. Кітаптар (деректер) кез келген жерге үйіліп жатпайды: олар бөлімдерге, сөрелерге бөлінген (кестелер), әр кітаптың нөмірі (кілт) және каталог карточкасы (жазба) бар. Сондықтан кітапханашы кез келген кітапты бірнеше секундта табады.

### ДҚБЖ — деректер қорын басқару жүйесі

Деректер қорымен тікелей жұмыс істемейміз — арнайы бағдарлама арқылы жұмыс істейміз.

**ДҚБЖ (СУБД, DBMS)** — деректер қорын құруға, деректерді сақтауға, іздеуге, өзгертуге және қорғауға арналған бағдарламалық жүйе.

| ДҚБЖ | Ерекшелігі | Қайда қолданылады |
|---|---|---|
| **SQLite** | бір файл, сервер керек емес, Python-ға кірістірілген | мобильді қосымшалар, браузерлер, шағын жобалар |
| PostgreSQL | қуатты, тегін, сервер | веб-сайттар, ірі жүйелер |
| MySQL / MariaDB | кең тараған, сервер | веб-сайттар |
| Microsoft SQL Server, Oracle | коммерциялық | банктер, ірі компаниялар |

**SQLite** Python-ның стандартты кітапханасына `sqlite3` модулі ретінде кірген, бүкіл қор — бір `.db` файлы. Смартфондағы WhatsApp, Telegram, браузердің тарихы да SQLite-та сақталады.

### Неге файл емес, деректер қоры?

| Мәселе | Файлдар (txt, CSV, JSON) | Деректер қоры |
|---|---|---|
| Іздеу | бүкіл файлды оқып, циклмен іздеу | индекс арқылы лезде (SQL сұранысы) |
| Бір жазбаны өзгерту | бүкіл файлды қайта жазу | тек сол жазба өзгереді |
| Бірнеше пайдаланушы | бір-бірінің өзгерісін өшіріп жібереді | ДҚБЖ кезекті реттейді |
| Деректердің дұрыстығы | `"бес"` деген баға да жазыла береді | тип пен шектеулер тексеріледі |
| Қайталану | бір оқушы бірнеше рет жазылуы мүмкін | кілттер қайталануға жол бермейді |
| Байланыстар | қолмен іздеу | кестелер кілттер арқылы байланысады |
| Көлем | мегабайттар | гигабайттар, терабайттар |

## 2. Деректер модельдері

Деректерді ұйымдастырудың бірнеше тәсілі бар:

| Модель | Құрылымы | Мысал |
|---|---|---|
| Иерархиялық | дарақ (ата → бала) | файлдық жүйе папкалары, JSON |
| Желілік | граф (кез келген байланыс) | әлеуметтік желідегі достар |
| **Реляциялық** | **өзара байланысқан кестелер** | мектеп журналы, банк, дүкен |
| Құжаттық (NoSQL) | JSON-тәрізді құжаттар жиыны | MongoDB |

Ең кең тарағаны — **реляциялық модель**. Оны 1970 жылы ағылшын математигі **Эдгар Кодд** (Edgar F. Codd, IBM) ұсынған. «Relation» — ағылшынша «қатынас», математикада — кесте.

## 3. Реляциялық модель: кесте, өріс, жазба

**Реляциялық деректер қоры** — деректері **кестелер** түрінде сақталатын және кестелері өзара **кілттер** арқылы байланысатын деректер қоры.

`students` (оқушылар) кестесі:

| id | last_name | first_name | birth_date | class | city |
|---|---|---|---|---|---|
| 1 | Нұрланқызы | Айгерім | 2011-03-15 | 9А | Алматы |
| 2 | Сейітов | Бауыржан | 2011-07-02 | 9А | Алматы |
| 3 | Оспанов | Дәулет | 2010-11-20 | 9Ә | Қонаев |
| 4 | Әлиева | Сымбат | 2011-01-09 | 9Ә | Алматы |

### Негізгі ұғымдар

| Ұғым | Басқа атаулары | Мағынасы | Мысал |
|---|---|---|---|
| **Кесте (table)** | қатынас (relation) | бір типтегі объектілер туралы деректер | `students` |
| **Өріс (field)** | бағана, баған, атрибут, column | объектінің бір сипаттамасы; кестенің бағаны | `birth_date` |
| **Жазба (record)** | жол, кортеж, row | бір объект туралы толық мәлімет; кестенің жолы | Дәулет туралы жол |
| **Мән (value)** | ұяшық | жазба мен өрістің қиылысындағы дерек | `9Ә` |
| **Схема (schema)** | құрылым | кестенің өрістері мен олардың типтері | `students(id, last_name, ...)` |

Реляциялық кестенің ережелері:
1. Әр кестенің **бірегей атауы** бар.
2. Бір кестеде **өріс атаулары қайталанбайды**.
3. Бір өрістегі барлық мәндер **бір типті** (мысалы, `birth_date` бағанында тек күндер).
4. Әр ұяшықта **бір ғана мән** (атомарлық): «Python, Робототехника» деп бір ұяшыққа екі үйірме жазуға болмайды.
5. **Бірдей жазбалар болмайды** — әр жазбаны бірегей анықтайтын кілт бар.
6. Жазбалар мен өрістердің реті маңызды емес.

**Python-мен салыстыру:** кесте — сөздіктер тізімі сияқты, жазба — бір сөздік, өріс — сөздік кілті.

```python
# Кестені Python құрылымымен модельдейміз
students = [
    {"id": 1, "last_name": "Нұрланқызы", "first_name": "Айгерім", "class": "9А", "city": "Алматы"},
    {"id": 2, "last_name": "Сейітов", "first_name": "Бауыржан", "class": "9А", "city": "Алматы"},
    {"id": 3, "last_name": "Оспанов", "first_name": "Дәулет", "class": "9Ә", "city": "Қонаев"},
    {"id": 4, "last_name": "Әлиева", "first_name": "Сымбат", "class": "9Ә", "city": "Алматы"},
]

fields = list(students[0].keys())
print("Өрістер:", fields)
print("Өріс саны:", len(fields), "| Жазба саны:", len(students))
print("3-жазба:", students[2])
print("Мән (3-жазба, city өрісі):", students[2]["city"])
```

Нәтижесі:

```text
Өрістер: ['id', 'last_name', 'first_name', 'class', 'city']
Өріс саны: 5 | Жазба саны: 4
3-жазба: {'id': 3, 'last_name': 'Оспанов', 'first_name': 'Дәулет', 'class': '9Ә', 'city': 'Қонаев'}
Мән (3-жазба, city өрісі): Қонаев
```

## 4. Өрістердің деректер типтері

Әр өрістің типі алдын ала анықталады. SQLite-тың негізгі типтері:

| SQLite типі | Мағынасы | Python-да | Мысал өрістер |
|---|---|---|---|
| `INTEGER` | бүтін сан | `int` | `id`, `age`, `quantity` |
| `REAL` | бөлшек сан | `float` | `price`, `average`, `temperature` |
| `TEXT` | мәтін | `str` | `name`, `email`, `phone` |
| `BLOB` | екілік деректер | `bytes` | сурет, файл |
| `NULL` | бос мән («белгісіз») | `None` | әлі толтырылмаған өріс |

Күн мен уақыт SQLite-та әдетте `TEXT` ретінде ISO форматында сақталады: `'2011-03-15'`, `'2027-01-11 14:30:00'`. Логикалық мән — `INTEGER` (0 немесе 1).

**Телефон нөмірі** `TEXT` ретінде сақталады! Себебі `+7 701 ...` ішінде `+` және бос орын бар, бастапқы нөлдер жоғалмауы керек, ал нөмірмен арифметика жасалмайды. ЖСН (ИИН) де — `TEXT` (12 цифр, нөлден басталуы мүмкін).

### Шектеулер (constraints)

| Шектеу | Мағынасы |
|---|---|
| `NOT NULL` | өріс бос болмауы керек |
| `UNIQUE` | мәндер қайталанбауы керек (мысалы, email) |
| `DEFAULT 0` | мән берілмесе — әдепкі мән |
| `CHECK (score BETWEEN 0 AND 100)` | мән шартқа сай болуы керек |
| `PRIMARY KEY` | бастапқы кілт (төменде) |

## 5. Кілттер

### Бастапқы кілт (PRIMARY KEY)

**Бастапқы кілт** — кестедегі әр жазбаны **бірегей** анықтайтын өріс (немесе өрістер тобы).

Талаптары:
- **бірегей** — екі жазбада бірдей болмайды;
- **бос емес** — `NULL` болмайды;
- **тұрақты** — уақыт өте өзгермейді.

Қай өріс кілт бола алады? `students` кестесін тексерейік:

| Өріс | Кілт бола ма? | Себебі |
|---|---|---|
| `first_name` | Жоқ | Екі Айгерім болуы мүмкін |
| `last_name` + `first_name` | Жоқ | Аттас-тектес оқушылар кездеседі |
| `class` | Жоқ | Бір сыныпта көп оқушы |
| ЖСН (ИИН) | Иә, бірақ... | Бірегей, бірақ — жеке дерек, оны кілт ретінде жан-жаққа тарату қауіпсіз емес |
| `id` | **Иә** | Жүйе өзі беретін бірегей нөмір |

**Аналогия:** сыныпта екі «Айгерім» болса, журналда оларды реттік нөмірі бойынша ажыратады. Банкте — шот нөмірі, кітапханада — инвентарлық нөмір, мектепте — оқушы билетінің нөмірі.

| Кілт түрі | Сипаттамасы | Мысал |
|---|---|---|
| **Табиғи кілт** | нақты өмірде бар бірегей дерек | ЖСН, мемлекеттік нөмір, ISBN |
| **Суррогат кілт** | жүйе жасаған жасанды нөмір | `id` = 1, 2, 3, ... (`AUTOINCREMENT`) |
| **Құрама кілт** | бірнеше өрістің жиынтығы | (`student_id`, `subject_id`, `date`) |

Тәжірибеде көбіне **суррогат кілт** `id INTEGER PRIMARY KEY` қолданылады.

### Сыртқы кілт (FOREIGN KEY) және кестелер байланысы

Бір кестеде бәрін сақтасақ, деректер **қайталанады**:

| id | student | class | teacher | teacher_phone |
|---|---|---|---|---|
| 1 | Айгерім | 9А | Ермекова Г.С. | +7 701 111 11 11 |
| 2 | Бауыржан | 9А | Ермекова Г.С. | +7 701 111 11 11 |
| 3 | Дәулет | 9Ә | Оспанова А.Б. | +7 702 222 22 22 |

Сынып жетекшісінің телефоны өзгерсе — ондаған жолды өзгерту керек, біреуін ұмытсақ — қайшылық пайда болады. Шешім — деректерді **екі кестеге** бөліп, оларды **кілт** арқылы байланыстыру:

`classes` кестесі:

| id | name | teacher | teacher_phone |
|---|---|---|---|
| 1 | 9А | Ермекова Г.С. | +7 701 111 11 11 |
| 2 | 9Ә | Оспанова А.Б. | +7 702 222 22 22 |

`students` кестесі:

| id | name | class_id |
|---|---|---|
| 1 | Айгерім | 1 |
| 2 | Бауыржан | 1 |
| 3 | Дәулет | 2 |

`students.class_id` — **сыртқы кілт**: ол басқа кестенің (`classes`) бастапқы кілтіне сілтейді.

```text
classes                      students
+----+------+---------+      +----+-----------+----------+
| id | name | teacher |      | id | name      | class_id |
+----+------+---------+      +----+-----------+----------+
| 1  | 9А   | Ермекова| <----| 1  | Айгерім   |    1     |
| 2  | 9Ә   | Оспанова| <-+  | 2  | Бауыржан  |    1     |
+----+------+---------+   +--| 3  | Дәулет    |    2     |
   PRIMARY KEY               +----+-----------+----------+
                                              FOREIGN KEY
```

Сыртқы кілттің ережесі — **сілтемелік тұтастық** (referential integrity): `class_id = 7` деп жазуға болмайды, егер `classes` кестесінде `id = 7` жазба жоқ болса.

```python
# Сыртқы кілт бойынша байланысты Python-да «қолмен» табу
classes = {1: {"name": "9А", "teacher": "Ермекова Г.С."},
           2: {"name": "9Ә", "teacher": "Оспанова А.Б."}}
students = [{"id": 1, "name": "Айгерім", "class_id": 1},
            {"id": 2, "name": "Бауыржан", "class_id": 1},
            {"id": 3, "name": "Дәулет", "class_id": 2}]

for s in students:
    cls = classes[s["class_id"]]          # сыртқы кілт → бастапқы кілт
    print(f"{s['name']}: {cls['name']} сыныбы, жетекшісі {cls['teacher']}")

# Сілтемелік тұтастықты тексеру
new_student = {"id": 4, "name": "Сымбат", "class_id": 7}
if new_student["class_id"] not in classes:
    print("Қате: мұндай сынып жоқ, жазба қосылмайды!")
```

Нәтижесі:

```text
Айгерім: 9А сыныбы, жетекшісі Ермекова Г.С.
Бауыржан: 9А сыныбы, жетекшісі Ермекова Г.С.
Дәулет: 9Ә сыныбы, жетекшісі Оспанова А.Б.
Қате: мұндай сынып жоқ, жазба қосылмайды!
```

ДҚБЖ мұндай тексерулерді **өзі** жасайды — сондықтан деректер қоры сенімді. Кестелер арасындағы байланыс үш түрлі болады: бір-бір, бір-көп және көп-көп.

## 6. SQL — деректер қорының тілі

**SQL (Structured Query Language)** — реляциялық деректер қорымен жұмыс істейтін құрылымдық сұраныстар тілі. Ол барлық реляциялық ДҚБЖ-да (SQLite, PostgreSQL, MySQL) ортақ. Python ішінен SQL сұраныстары `sqlite3` модулі арқылы орындалады. Алғашқы танысу:

```sql
-- Кесте құру
CREATE TABLE students (
    id INTEGER PRIMARY KEY,
    name TEXT NOT NULL,
    class_id INTEGER REFERENCES classes(id)
);

-- Жазба қосу
INSERT INTO students (name, class_id) VALUES ('Айгерім', 1);

-- Іздеу: 1-сыныптың барлық оқушылары
SELECT name FROM students WHERE class_id = 1;
```

Байқаңыз: SQL-да **«қалай»** іздеу керектігін емес, **«не»** керектігін айтамыз — циклды ДҚБЖ өзі ұйымдастырады.

| SQL командасы | Не істейді |
|---|---|
| `CREATE TABLE` | кесте құру |
| `INSERT` | жазба қосу |
| `SELECT` | деректерді оқу, іздеу |
| `UPDATE` | жазбаны өзгерту |
| `DELETE` | жазбаны жою |
| `JOIN` | кестелерді біріктіру |

## Жиі кездесетін қателер

**1. Бір ұяшыққа бірнеше мән жазу.**

| id | name | clubs |
|---|---|---|
| 1 | Айгерім | Python, Шахмат, Домбыра |

Қате: «Шахматқа қатысатындарды» табу қиын, үйірмені өшіру қиын. Дұрыс: үйірмелерді бөлек кестеге шығарып, оны оқушылармен кілттер арқылы байланыстыру.

**2. Атауды кілт ретінде алу.** Аттас оқушылар келсе — кілт бұзылады. Дұрыс: `id`.

**3. Есептелетін мәнді сақтау.** `age` (жасы) өрісін сақтасақ, ол жыл сайын ескіреді. Дұрыс: `birth_date` сақтап, жасты есептеу.

**6. Кестеде бәрін араластыру.** Оқушы, оқытушы, баға, сабақ кестесі — бір үлкен кестеде. Дұрыс: әр «мән-мағыналық объектіге» (entity) — бөлек кесте.

## Ескерту

- SQLite **динамикалық типтеуді** қолданады: бағана типі — тек «ұсыныс» (type affinity), және `INTEGER` бағанасына `'abc'` жолын жазуға болады. Типтерді қатаң тексеруді `CREATE TABLE ... STRICT` жариялауы қосады (SQLite 3.37+).
- SQLite-та сыртқы кілттерді тексеру әдепкі бойынша **өшірулі**; оны әр жаңа қосылым үшін `PRAGMA foreign_keys = ON` командасымен қосады.
- `NULL` — «белгісіз» дегенді білдіреді, нөл де, бос жол да емес: `NULL = NULL` салыстыруы ақиқат емес, `NULL` береді; тексеру үшін `IS NULL` қолданылады.
- Python-ға кірістірілген SQLite нұсқасын `import sqlite3; print(sqlite3.sqlite_version)` көрсетеді — қолжетімді SQL мүмкіндіктері соған байланысты.
- Кесте мен өріс атауларын латынша `snake_case` түрінде жазу қабылданған (`birth_date`, `class_id`), кестелер — көпше түрде (`students`).
- Құжаттама: https://docs.python.org/3/library/sqlite3.html және https://www.sqlite.org/datatype3.html
