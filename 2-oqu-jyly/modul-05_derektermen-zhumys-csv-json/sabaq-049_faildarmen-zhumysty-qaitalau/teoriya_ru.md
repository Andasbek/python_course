## 1. Что такое файл?

**Файл** — последовательность байтов, сохранённая на диске под определённым именем. Для компьютера любой файл — это просто числа (байты от 0 до 255). Как их интерпретировать, определяет **формат**.

**Аналогия:** оперативная память (RAM) — надпись мелом на доске: выключили компьютер — её стёрли. Файл — запись в тетради: на следующий день её можно открыть и прочитать.

| Вид | Что внутри | Примеры | Если открыть в Блокноте |
|---|---|---|---|
| **Текстовый** | Символы (буквы, цифры, переводы строк) в определённой кодировке | `.txt`, `.py`, `.csv`, `.json`, `.html`, `.ini` | Читается |
| **Двоичный (бинарный)** | Произвольные байты по правилам формата | `.png`, `.jpg`, `.mp3`, `.exe`, `.db`, `.zip` | «Кракозябры» |

## 2. Открытие файла: `open()` и режимы

```python
f = open("notes.txt", "r", encoding="utf-8")
```

| Режим | Значение | Если файла нет | Если файл есть |
|---|---|---|---|
| `"r"` | чтение (по умолчанию) | `FileNotFoundError` | читает с начала |
| `"w"` | запись | создаёт новый | **полностью стирает содержимое!** |
| `"a"` | дозапись в конец (append) | создаёт новый | пишет в конец |
| `"x"` | только создание нового файла | создаёт | `FileExistsError` |
| `"b"` | двоичный режим (`"rb"`, `"wb"`, `"ab"`) | — | — |
| `"+"` | чтение и запись (`"r+"`, `"w+"`) | — | — |

### Кодировка (encoding)

В текстовом файле каждый символ **кодируется** байтами. Для кириллицы и казахских букв (ә, ғ, қ, ң, ө, ұ, ү, һ, і) всегда используем **UTF-8**:

```python
with open("salem.txt", "w", encoding="utf-8") as f:
    f.write("Сәлем, Қазақстан!")
```

Если `encoding` не указан, в Windows может использоваться системная кодировка (например, `cp1251`) — тогда буквы «ә», «ң» испортятся или возникнет `UnicodeEncodeError`.

## 3. Оператор `with` — сам закрывает файл

```python
# Старый способ
f = open("data.txt", "w", encoding="utf-8")
f.write("первая строка\n")
f.close()          # если забудешь — данные могут не записаться

# Правильный способ
with open("data.txt", "w", encoding="utf-8") as f:
    f.write("первая строка\n")
# при выходе из блока файл закрывается автоматически (даже при ошибке)
```

`with` — **менеджер контекста**: он гарантирует «открыть, поработать и обязательно закрыть».

## 4. Запись и чтение текстового файла

### Запись

```python
cities = ["Алматы", "Астана", "Шымкент", "Актобе"]

with open("cities.txt", "w", encoding="utf-8") as f:
    f.write("Крупные города Казахстана\n")
    for city in cities:
        f.write(city + "\n")

with open("cities.txt", "a", encoding="utf-8") as f:
    f.writelines(["Караганда\n", "Тараз\n"])   # запись списка строк

print("Файл записан")
```

Результат:

```text
Файл записан
```

`write()` сам не добавляет перевод строки (`\n`) — его пишешь ты. Можно использовать и `print(..., file=f)`: он сам добавляет `\n`.

### Четыре способа чтения

| Метод | Результат | Когда использовать |
|---|---|---|
| `f.read()` | весь файл — одна строка (`str`) | небольшой файл |
| `f.readline()` | следующая одна строка | отдельно прочитать строку заголовка |
| `f.readlines()` | список всех строк | если нужно обращаться к строкам по индексу |
| `for line in f:` | строки по одной | **большие файлы** — экономит память |

```python
with open("cities.txt", encoding="utf-8") as f:
    title = f.readline().strip()        # первая строка — заголовок
    cities = [line.strip() for line in f]  # остальное

print(title)
print(cities)
print("Количество городов:", len(cities))
```

Результат:

```text
Крупные города Казахстана
['Алматы', 'Астана', 'Шымкент', 'Актобе', 'Караганда', 'Тараз']
Количество городов: 6
```

`strip()` — убирает `\n` и пробелы в конце строки.

### Хранение чисел

В текстовом файле всё — **текст**. При записи числа — `str()`, при чтении — `int()` / `float()`:

```python
scores = [85, 92, 78, 100]
with open("scores.txt", "w", encoding="utf-8") as f:
    for s in scores:
        f.write(f"{s}\n")

with open("scores.txt", encoding="utf-8") as f:
    numbers = [int(line) for line in f if line.strip()]

print("Средний балл:", sum(numbers) / len(numbers))
```

Результат:

```text
Средний балл: 88.75
```

## 5. Пути к файлам: `os.path` и `pathlib`

Программа ищет файл в **текущей рабочей папке**. Если в VS Code запустить программу из другой папки, файл может «не найтись». Решение — строить путь относительно папки, в которой находится скрипт.

```python
from pathlib import Path

BASE_DIR = Path(__file__).parent            # папка, где лежит скрипт
data_dir = BASE_DIR / "data"                # оператор / объединяет пути
data_dir.mkdir(exist_ok=True)               # если папки нет — создаёт

path = data_dir / "log.txt"
path.write_text("Программа запущена\n", encoding="utf-8")

print(path.name)        # имя файла
print(path.suffix)      # расширение
print(path.exists())    # существует ли?
print(path.read_text(encoding="utf-8").strip())
```

Результат:

```text
log.txt
.txt
True
Программа запущена
```

| `os.path` (старый) | `pathlib` (новый) |
|---|---|
| `os.path.join("data", "a.txt")` | `Path("data") / "a.txt"` |
| `os.path.exists(p)` | `p.exists()` |
| `os.path.basename(p)` | `p.name` |
| `os.path.getsize(p)` | `p.stat().st_size` |
| `os.listdir("data")` | `Path("data").iterdir()` |

## 6. Обработка ошибок работы с файлами

```python
filename = "jok_fail.txt"
try:
    with open(filename, encoding="utf-8") as f:
        print(f.read())
except FileNotFoundError:
    print(f"Файл «{filename}» не найден")
except PermissionError:
    print("Нет разрешения на открытие файла")
except UnicodeDecodeError:
    print("Файл не в кодировке UTF-8 (возможно, это двоичный файл)")
```

Результат:

```text
Файл «jok_fail.txt» не найден
```

## 7. Двоичные файлы и тип `bytes`

В двоичном режиме (`"rb"`, `"wb"`) Python не кодирует текст, а отдаёт байты файла **как есть**. Тип результата — не `str`, а **`bytes`**.

```python
text = "Сәлем"
data = text.encode("utf-8")       # str → bytes
print(data)
print(len(text), "символов,", len(data), "байт")
print(list(data))                 # каждый байт — число 0..255
print(data.decode("utf-8"))       # bytes → str
```

Результат:

```text
b'\xd0\xa1\xd3\x99\xd0\xbb\xd0\xb5\xd0\xbc'
5 символов, 10 байт
[208, 161, 211, 153, 208, 187, 208, 181, 208, 188]
Сәлем
```

Буквы кириллицы (в том числе казахские) в UTF-8 занимают **2 байта**, латинские буквы — 1 байт. Поэтому «количество символов» и «размер файла» различаются.

| | `str` | `bytes` |
|---|---|---|
| Внутри | Символы Unicode | Числа 0–255 |
| Запись | `"текст"` | `b"text"` |
| Режим открытия | `"r"`, `"w"` + `encoding` | `"rb"`, `"wb"` (без encoding) |
| Преобразование | `.encode("utf-8")` → bytes | `.decode("utf-8")` → str |

### Запись и чтение двоичного файла

```python
data = bytes([137, 80, 78, 71, 13, 10, 26, 10])  # 8 байт

with open("test.bin", "wb") as f:
    f.write(data)

with open("test.bin", "rb") as f:
    content = f.read()

print(content)
print(content[1:4])
print("Размер:", len(content), "байт")
```

Результат:

```text
b'\x89PNG\r\n\x1a\n'
b'PNG'
Размер: 8 байт
```

Эти 8 байт — **сигнатура** любого PNG-изображения («магические числа», magic numbers). Расширение файла можно изменить, но сигнатура показывает его настоящий формат.

| Формат | Первые байты |
|---|---|
| PNG | `89 50 4E 47` (`\x89PNG`) |
| JPEG | `FF D8 FF` |
| GIF | `47 49 46 38` (`GIF8`) |
| ZIP, DOCX, XLSX | `50 4B 03 04` (`PK`) |
| PDF | `25 50 44 46` (`%PDF`) |
| SQLite | `SQLite format 3\x00` |

```python
def detect_format(path):
    """Определяет формат файла по его первым байтам."""
    signatures = {
        b"\x89PNG": "Изображение PNG",
        b"\xff\xd8\xff": "Изображение JPEG",
        b"GIF8": "Анимация GIF",
        b"PK\x03\x04": "Архив ZIP (или DOCX/XLSX)",
        b"%PDF": "Документ PDF",
    }
    with open(path, "rb") as f:
        head = f.read(8)
    for sign, name in signatures.items():
        if head.startswith(sign):
            return name
    return "неизвестный формат"


print(detect_format("test.bin"))
```

Результат:

```text
Изображение PNG
```

### Копирование большого двоичного файла по частям

Видео может занимать несколько гигабайт — загружать его в память одним `read()` опасно. Читаем по частям (chunk):

```python
def copy_file(src, dst, chunk_size=64 * 1024):
    """Копирует файл частями по 64 КБ, возвращает количество скопированных байтов."""
    total = 0
    with open(src, "rb") as fin, open(dst, "wb") as fout:
        while True:
            chunk = fin.read(chunk_size)
            if not chunk:          # пустые bytes — файл закончился
                break
            fout.write(chunk)
            total += len(chunk)
    return total


print("Скопировано:", copy_file("test.bin", "test_copy.bin"), "байт")
```

Результат:

```text
Скопировано: 8 байт
```

## 8. Систематизация способов хранения данных

| Способ | Вид | Преимущество | Недостаток | Когда |
|---|---|---|---|---|
| `.txt` | текст | простой, читается человеком | нет структуры | лог, заметки, одно число |
| `.csv` | текст | таблица, открывается в Excel | только «плоская» таблица | журнал оценок, списки |
| `.json` | текст | вложенная структура списков/словарей | медленный на больших объёмах | настройки, ответы API |
| `.ini` / `.toml` | текст | удобен для настроек | только параметры | настройки программы |
| `pickle` | двоичный | любой объект Python | только Python; **опасен** | временный кэш |
| SQLite `.db` | двоичный | поиск, фильтрация, тысячи записей | нужно изучить SQL | база учеников, магазин |

Для каждого способа в Python есть свой инструмент: встроенные `open()`, модули стандартной библиотеки `csv`, `json`, `configparser`, `tomllib` (Python 3.11+), `pickle` и `sqlite3`.

### Предупреждение о `pickle`

`pickle` сохраняет объекты Python в двоичном виде:

```python
import pickle

player = {"name": "Айдана", "level": 3, "items": ["меч", "щит"]}
with open("save.pkl", "wb") as f:
    pickle.dump(player, f)

with open("save.pkl", "rb") as f:
    loaded = pickle.load(f)
print(loaded)
```

Результат:

```text
{'name': 'Айдана', 'level': 3, 'items': ['меч', 'щит']}
```

> **Безопасность:** **никогда** не открывай через `pickle.load` файл `.pkl`, полученный от постороннего человека, — внутри может быть вредоносный код. Для обмена данными используют JSON.

## Частые ошибки

**1. Режим `"w"` стирает данные.**

```python
# Ошибка: при каждом запуске прежние записи теряются
with open("diary.txt", "w", encoding="utf-8") as f:
    f.write("Сегодняшняя запись\n")
```

Правильно: чтобы добавить запись — режим `"a"`.

**2. Забывают `encoding`** → в Windows казахские буквы портятся. Правильно: для текстового файла всегда `encoding="utf-8"`.

**3. Запись `bytes` в текстовом режиме или наоборот.**

```python
# Ошибка: TypeError: write() argument must be str, not bytes
# with open("a.txt", "w") as f:
#     f.write(b"abc")
with open("a.bin", "wb") as f:
    f.write(b"abc")            # правильно: двоичный режим
with open("a.txt", "w", encoding="utf-8") as f:
    f.write("abc")             # правильно: текст
```

**4. Чтение двоичного файла как текста** → `UnicodeDecodeError`. Изображения, звук — только `"rb"`.

**5. Остаётся `\n`.** Результат `readlines()` — `['Алматы\n', ...]`, поэтому условие `"Алматы" == line` будет `False`. Правильно: `line.strip()`.

**6. Запись числа:** `f.write(100)` → `TypeError`. Правильно: `f.write(str(100))` или `f.write(f"{100}\n")`.

## Основные понятия

| Понятие | Объяснение |
|---|---|
| Файл | Последовательность байтов, сохранённая на диске под именем |
| Текстовый файл | Файл, символы которого записаны в определённой кодировке (UTF-8) |
| Двоичный файл | Файл из произвольных байтов (изображение, звук, db) |
| Кодировка (encoding) | Правило превращения символов в байты |
| `bytes` | Неизменяемый тип, хранящий последовательность байтов |
| Режим | Способ открытия файла: `r`, `w`, `a`, `x`, `b`, `+` |
| Менеджер контекста | `with` — конструкция, автоматически закрывающая ресурс |
| Сигнатура | Первые байты, определяющие формат файла |
| Chunk | Часть, по которой читается большой файл |
| `pathlib.Path` | Современный класс для работы с путями к файлам |

## Примечание

- Начиная с Python 3.15 (PEP 686) кодировкой по умолчанию в `open()` станет UTF-8 во всех ОС; до этого результат зависит от системы, поэтому `encoding="utf-8"` указывают явно. Включить такое поведение заранее можно флагом `python -X utf8`.
- `newline` управляет переводом строк: в текстовом режиме Python при чтении превращает `\r\n` (Windows) в `\n`, а при записи — обратно в системный вариант. В двоичном режиме никаких преобразований нет.
- Файл с BOM (часто сохраняется Блокнотом/Excel) начинается с невидимого символа `\ufeff`; читайте его с `encoding="utf-8-sig"`, тогда BOM отбросится автоматически.
- Запись буферизуется: данные попадают на диск при закрытии файла или `f.flush()`. Поэтому без `with`/`close()` последние строки могут потеряться.
- `Path.read_text()`, `Path.write_text()`, `Path.read_bytes()`, `Path.write_bytes()` сами открывают и закрывают файл — удобно для небольших файлов.
- Документация: https://docs.python.org/3/library/functions.html#open и https://docs.python.org/3/library/pathlib.html
