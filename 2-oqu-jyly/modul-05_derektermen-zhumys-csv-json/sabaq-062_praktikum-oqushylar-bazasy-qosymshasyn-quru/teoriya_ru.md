## 1. Техническое задание (ТЗ) проекта

**Пользователь:** руководитель кружка или классный руководитель.
**Цель:** хранение, просмотр, изменение и поиск данных об учениках через графический интерфейс.

## 2. Архитектура приложения

Самая частая ошибка — «разбрасывать» SQL-код по функциям кнопок. Тогда код нечитаем, повторяется, его трудно тестировать. Мы разделим его на **два слоя**:

```text
┌───────────────────────────┐
│  app.py  (Tkinter GUI)     │  ← часть, которую видит пользователь
│  кнопки, форма, таблица    │
└────────────┬──────────────┘
             │ вызывает методы: add(), get_all() ...
┌────────────▼──────────────┐
│  db.py  (класс StudentDB)  │  ← только SQL и sqlite3
└────────────┬──────────────┘
             │
        students.db
```

**Польза:** если завтра заменим Tkinter веб-интерфейсом, `db.py` не изменится. А если заменим SQLite другой СУБД, не изменится `app.py`. Это принцип **разделения ответственности** (separation of concerns).

Структура проекта:
```text
student_base/
├── db.py          # слой данных
├── app.py         # GUI
├── students.db    # создаётся автоматически
└── .gitignore     # students.db, __pycache__/
```

## 3. Слой данных: класс `StudentDB`

```python
import sqlite3


class StudentDB:
    """Класс для работы с базой данных учеников."""

    def __init__(self, path="students.db"):
        self.conn = sqlite3.connect(path)
        self.conn.execute("""
            CREATE TABLE IF NOT EXISTS students (
                id INTEGER PRIMARY KEY AUTOINCREMENT,
                name TEXT NOT NULL,
                grade INTEGER NOT NULL CHECK (grade BETWEEN 1 AND 11),
                city TEXT,
                phone TEXT,
                score REAL CHECK (score BETWEEN 0 AND 100)
            )
        """)
        self.conn.commit()

    def add(self, name, grade, city, phone, score):
        cur = self.conn.execute(
            "INSERT INTO students (name, grade, city, phone, score) VALUES (?, ?, ?, ?, ?)",
            (name, grade, city, phone, score),
        )
        self.conn.commit()
        return cur.lastrowid

    def get_all(self):
        return self.conn.execute(
            "SELECT id, name, grade, city, phone, score FROM students ORDER BY name"
        ).fetchall()

    def count(self):
        return self.conn.execute("SELECT COUNT(*) FROM students").fetchone()[0]

    def close(self):
        self.conn.close()


if __name__ == "__main__":
    db = StudentDB(":memory:")          # база в памяти для теста
    db.add("Айгерім Сәрсенова", 9, "Алматы", "+77011234567", 92.5)
    db.add("Ержан Бекұлы", 11, "Астана", "", 81)
    for row in db.get_all():
        print(row)
    print("Всего:", db.count())
```

Результат:
```text
(1, 'Айгерім Сәрсенова', 9, 'Алматы', '+77011234567', 92.5)
(2, 'Ержан Бекұлы', 11, 'Астана', '', 81.0)
Всего: 2
```

Обратите внимание:
- **Ограничения `CHECK`** — сама база данных не примет ошибочное значение (например, 15-й класс). Это «вторая линия обороны».
- **`if __name__ == "__main__":`** — позволяет проверить модуль отдельно, без GUI.
- **`":memory:"`** — временная база, которая не записывается на диск; очень удобна для тестов.

## 4. Макет интерфейса

Прежде чем писать код, нарисуем схему на бумаге (wireframe):

```text
┌───────────────── База учеников ──────────────────┐
│ ФИО:      [____________]   Класс: [__]            │
│ Город:    [____________]   Телефон: [_______]     │
│ Балл:     [____]                                  │
│ [Добавить] [Очистить]                             │
├───────────────────────────────────────────────────┤
│ ID │ ФИО             │ Класс │ Город │ ... │ Балл │
│  1 │ Айгерім ...     │   9   │Алматы │     │ 92.5 │
│  2 │ ...                                          │
├───────────────────────────────────────────────────┤
│ Всего учеников: 2                                 │
└───────────────────────────────────────────────────┘
```

Для размещения используются вместе `grid` (форма) и `pack` (крупные блоки), но **внутри одного контейнера** — только один из них. Поэтому для формы создаём отдельный `Frame` (или `ttk.LabelFrame`).

## 5. `ttk.Treeview` — виджет таблицы

```python
import tkinter as tk
from tkinter import ttk

root = tk.Tk()
cols = ("id", "name", "grade")
tree = ttk.Treeview(root, columns=cols, show="headings", height=5)
tree.heading("id", text="ID")
tree.heading("name", text="ФИО")
tree.heading("grade", text="Класс")
tree.column("id", width=40, anchor="center")
tree.column("name", width=200)
tree.column("grade", width=60, anchor="center")
tree.insert("", "end", values=(1, "Айгерім", 9))
tree.pack(fill="both", expand=True)
root.mainloop()
```

Основные методы:

| Метод | Что делает |
|---|---|
| `tree.insert("", "end", values=(...))` | Добавляет строку в конец |
| `tree.get_children()` | Идентификаторы всех строк |
| `tree.delete(*tree.get_children())` | Полностью очищает таблицу |
| `tree.selection()` | Выбранные строки |
| `tree.item(iid, "values")` | Значения строки |

Шаблон обновления таблицы — «удалить всё и заполнить заново»:

```python
def refresh(tree, rows):
    tree.delete(*tree.get_children())
    for row in rows:
        tree.insert("", "end", values=row)
```

## 6. Валидация: проверка ввода

Пользователь может написать что угодно. Выносим проверку в отдельную функцию — её можно тестировать и без GUI:

```python
def validate(name, grade, score):
    """При ошибке возвращает текст ошибки, если всё верно — None."""
    if not name.strip():
        return "ФИО не должно быть пустым"
    if not grade.isdigit() or not 1 <= int(grade) <= 11:
        return "Класс должен быть целым числом от 1 до 11"
    try:
        s = float(score.replace(",", "."))
    except ValueError:
        return "Балл должен быть числом"
    if not 0 <= s <= 100:
        return "Балл должен быть в диапазоне 0–100"
    return None

print(validate("Дана", "9", "88,5"))
print(validate("", "9", "88"))
print(validate("Дана", "15", "88"))
```

Результат:
```text
None
ФИО не должно быть пустым
Класс должен быть целым числом от 1 до 11
```

`score.replace(",", ".")` — принимаем значение, даже если пользователь написал «88,5» с запятой.

## 7. Связываем GUI и БД: кнопка «Добавить»

Цепочка событий:

```text
нажата [Добавить] → получить текст из полей → validate() → есть ошибка?
     ├─ да  → messagebox.showerror(...) → остановка
     └─ нет → db.add(...) → refresh() → очистить поля → обновить строку статуса
```

Основная идея: класс GUI хранит внутри себя объект `self.db = StudentDB()` и вызывает только его методы.

## 8. Пошаговая разработка и Git

- После каждого шага запускайте и проверяйте программу — написать 100 строк и проверить один раз опасно.
- После каждого завершённого шага делайте коммит в Git: `git commit -m "Добавлен класс StudentDB"`.
- Добавьте файл `students.db` в `.gitignore` — в репозиторий кладётся код, а личные данные (телефоны!) не кладутся.

## Частые ошибки

**1. Смешивание `grid` и `pack` в одном контейнере** — программа «зависает» или выдаёт `TclError`.
```python
# Неправильно:
# tk.Label(root, text="Имя").grid(row=0, column=0)
# tree.pack()
# Правильно: отдельный Frame для формы
# form = tk.Frame(root); form.pack()
# tk.Label(form, text="Имя").grid(row=0, column=0)
```

**2. `command=self.add_student()` — со скобками** — функция выполняется сразу при запуске программы, а не при нажатии кнопки. Правильно: `command=self.add_student`.

**3. Забытый `commit()`** — строка видна в таблице, но при повторном открытии программы её нет.

**4. Не удаляются старые строки при обновлении таблицы** — при каждом добавлении список удваивается. Сначала `tree.delete(*tree.get_children())`.

**5. `int(grade_entry.get())` без проверки** — при пустом поле возникает `ValueError`, и приложение падает. Сначала `validate()`.

## Основные понятия

| Понятие | Объяснение |
|---|---|
| Техническое задание (ТЗ) | Список требований к проекту |
| Слой данных | Код, работающий только с базой данных (`db.py`) |
| Слой интерфейса | Код, взаимодействующий с пользователем (`app.py`) |
| Wireframe (макет) | Простая схема интерфейса |
| `ttk.Treeview` | Виджет Tkinter в виде таблицы/дерева |
| Валидация | Проверка правильности введённых данных |
| `CHECK` | Ограничение на значение в SQL |
| `":memory:"` | Временная база SQLite в оперативной памяти |

## Примечание

- Нельзя смешивать `pack` и `grid` в одном контейнере — Tkinter зависнет или выдаст `TclError`. Для каждой группы виджетов создавайте отдельный `Frame`.
- В `sqlite3` всегда используйте параметризованные запросы с `?`, а не f-строки — это защищает от SQL-инъекций (https://docs.python.org/3/library/sqlite3.html).
- SQLite по умолчанию не проверяет внешние ключи: для каждого подключения нужно выполнить `PRAGMA foreign_keys = ON`.
- Блок `with sqlite3.connect(...) as con:` управляет транзакцией (commit/rollback), но **не закрывает** подключение — `con.close()` вызывается отдельно.
- По PEP 8 имена модулей пишутся строчными буквами (`db.py`, `app.py`), имена классов — в стиле CapWords (`StudentDB`). Документация `ttk`: https://docs.python.org/3/library/tkinter.ttk.html.
