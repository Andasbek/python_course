## 1. Что такое полиморфизм?

**Полиморфизм (polymorphism)** — по-гречески «многообразие форм». В программировании: **одноимённое действие у разных объектов выполняется по-разному**, а код, который его вызывает, остаётся одинаковым.

Жизненная аналогия: кнопка «Воспроизвести» (▶). Нажимаете её на телевизоре — начинается фильм, на музыкальной колонке — играет песня, на игровой консоли — запускается игра. Кнопка одна, действие зависит от устройства.

### В Python полиморфизм окружает нас давно

```python
print(len("Алматы"))          # длина строки
print(len([1, 2, 3]))         # количество элементов списка
print(len({"a": 1, "b": 2}))  # количество ключей в словаре

print(5 + 3)                  # сложение чисел
print("Привет, " + "мир")     # объединение строк
print([1, 2] + [3])           # объединение списков
```

Результат:
```text
6
3
2
8
Привет, мир
[1, 2, 3]
```

Функция `len()` и оператор `+` — одни и те же, но работают по-разному в зависимости от типа объекта. Это и есть полиморфизм.

## 2. Полиморфизм в классах

Полиморфизм в классах основан на переопределении методов (override): в родительском классе — общий метод, в дочерних — своя версия. Затем всё обрабатываем **в одном цикле**:

```python
class Shape:
    def __init__(self, name):
        self.name = name

    def area(self):
        return 0


class Rectangle(Shape):
    def __init__(self, a, b):
        super().__init__("Прямоугольник")
        self.a = a
        self.b = b

    def area(self):
        return self.a * self.b


class Circle(Shape):
    def __init__(self, r):
        super().__init__("Круг")
        self.r = r

    def area(self):
        return round(3.14159 * self.r ** 2, 2)


class Triangle(Shape):
    def __init__(self, a, h):
        super().__init__("Треугольник")
        self.a = a
        self.h = h

    def area(self):
        return self.a * self.h / 2


shapes = [Rectangle(4, 5), Circle(3), Triangle(6, 4)]
total = 0
for s in shapes:
    print(f"{s.name}: площадь = {s.area()}")
    total += s.area()
print("Общая площадь:", round(total, 2))
```

Результат:
```text
Прямоугольник: площадь = 20
Круг: площадь = 28.27
Треугольник: площадь = 12.0
Общая площадь: 60.27
```

**Важно:** код внутри цикла **не проверяет** вид фигуры (нет `if`!). Если добавим новую фигуру (например, `Square`), цикл менять не нужно. В этом главная польза полиморфизма.

### Как было бы без полиморфизма?

```python
shapes = [("rect", 4, 5), ("circle", 3), ("tri", 6, 4)]
for s in shapes:
    if s[0] == "rect":
        print(s[1] * s[2])
    elif s[0] == "circle":
        print(round(3.14159 * s[1] ** 2, 2))
    elif s[0] == "tri":
        print(s[1] * s[2] / 2)
```

Для каждой новой фигуры нужно добавлять `elif` — код удлиняется, ошибок становится больше.

## 3. Полиморфная функция

Одна функция может принимать любую «фигуру»:

```python
class Dog:
    def speak(self):
        return "Гав-гав"

class Cat:
    def speak(self):
        return "Мяу"

class Cow:
    def speak(self):
        return "Му-у"

def concert(animals):
    for a in animals:
        print(type(a).__name__, "->", a.speak())

concert([Dog(), Cat(), Cow()])
```

Результат:
```text
Dog -> Гав-гав
Cat -> Мяу
Cow -> Му-у
```

Обратите внимание: у этих классов **нет общего родительского класса**! Для Python главное — чтобы у объекта был метод `speak()`.

## 4. «Утиная типизация» (duck typing)

> «Если оно ходит как утка и крякает как утка — значит, это утка».

Python смотрит не на тип объекта, а на то, **что он умеет делать**. Это **утиная типизация (duck typing)**.

```python
class Duck:
    def swim(self):
        print("Утка плывёт")

class Robot:
    def swim(self):
        print("Подводный робот плывёт")

class Stone:
    pass

def go_swimming(obj):
    if hasattr(obj, "swim"):
        obj.swim()
    else:
        print(f"{type(obj).__name__} не умеет плавать :(")

for thing in [Duck(), Robot(), Stone()]:
    go_swimming(thing)
```

Результат:
```text
Утка плывёт
Подводный робот плывёт
Stone не умеет плавать :(
```

`hasattr(obj, "имя")` — проверяет, есть ли у объекта такой атрибут/метод.

## 5. Абстракция

**Абстракция (abstraction)** — выделение только существенных свойств объекта и сокрытие мелких деталей. Когда мы водим машину, мы знаем руль, педали, тормоз, но не знаем устройства двигателя — это абстракция.

В программе абстракция — это определение того, «**что нужно сделать**», а то, «**как это сделать**», оставляется конкретным классам.

Например, «Фигура» — абстрактное понятие. Площадь «просто фигуры» вычислить невозможно — площадь есть только у конкретного круга, квадрата. Поэтому создавать объект `Shape()` не имеет смысла.

### Модуль abc: абстрактный класс

В Python абстрактный класс создаётся с помощью модуля `abc` (Abstract Base Classes):

```python
from abc import ABC, abstractmethod


class Shape(ABC):                 # абстрактный класс
    @abstractmethod
    def area(self):
        pass                      # реализации нет — только «договорённость»

    @abstractmethod
    def perimeter(self):
        pass

    def info(self):               # может быть и обычный метод
        print(f"Площадь: {self.area()}, периметр: {self.perimeter()}")


class Square(Shape):
    def __init__(self, a):
        self.a = a

    def area(self):
        return self.a ** 2

    def perimeter(self):
        return 4 * self.a


sq = Square(5)
sq.info()

try:
    s = Shape()
except TypeError as e:
    print("Ошибка:", e)
```

Результат:
```text
Площадь: 25, периметр: 20
Ошибка: Can't instantiate abstract class Shape without an implementation for abstract methods 'area', 'perimeter'
```

(В версиях Python 3.10–3.11 текст ошибки немного другой: `... with abstract methods area, perimeter`.)

Правила:
- **нельзя создать объект** класса, который унаследован от `ABC` и имеет метод с `@abstractmethod`;
- дочерний класс должен реализовать **все** абстрактные методы, иначе его объект тоже не создастся;
- абстрактный класс — это «договор» (интерфейс) для потомков: «У вас обязательно должны быть `area()` и `perimeter()`».

```python
from abc import ABC, abstractmethod

class Payment(ABC):
    @abstractmethod
    def pay(self, amount):
        pass

class Kaspi(Payment):
    def pay(self, amount):
        print(f"Оплачено {amount} тг через Kaspi QR")

class Cash(Payment):
    def pay(self, amount):
        print(f"Оплачено наличными {amount} тг")

class Card(Payment):
    pass     # забыли написать pay!

for method in [Kaspi(), Cash()]:
    method.pay(1500)

try:
    Card()
except TypeError:
    print("Класс Card не реализовал метод pay!")
```

Результат:
```text
Оплачено 1500 тг через Kaspi QR
Оплачено наличными 1500 тг
Класс Card не реализовал метод pay!
```

Абстрактный класс показывает ошибку **раньше** — уже в момент создания объекта.

## 6. Четыре принципа ООП — общий обзор

| Принцип | Суть | Средство в Python | Аналогия |
|---|---|---|---|
| Инкапсуляция | Сокрытие данных, доступ только через методы | `_attr`, `__attr`, `@property` | Банкомат: деньги получаешь только по карте |
| Наследование | Повторное использование возможностей родительского класса | `class B(A):`, `super()` | Ребёнок получает черты от родителей |
| Полиморфизм | Один интерфейс — разные реализации | override, duck typing | Кнопка «Воспроизвести» |
| Абстракция | Показывать только важное, скрывать детали | `ABC`, `@abstractmethod` | Вождение машины без знания устройства двигателя |

## Частые ошибки

**1. Писать проверки `if type(...)` вместо полиморфизма**

```python
class Dog:
    pass

class Cat:
    pass

def speak(animal):
    if type(animal) == Dog:
        print("Гав-гав")
    elif type(animal) == Cat:
        print("Мяу")

speak(Dog())
```

Правильно — написать в каждом классе метод `speak()` и просто вызывать `animal.speak()`.

**2. Другое имя метода в дочернем классе** — `get_area` вместо `area`. Тогда общий цикл вызовет версию родительского класса или выдаст `AttributeError`.

**3. Создание объекта абстрактного класса** — `Shape()` → `TypeError`. Создаём объекты только конкретных дочерних классов.

**4. Поставить декоратор `@abstractmethod`, но не унаследовать от `ABC`**

```python
from abc import abstractmethod

class Shape:              # нет ABC — проверка не работает!
    @abstractmethod
    def area(self):
        pass

s = Shape()               # ошибки не будет
print("Объект создан, но это неправильно")
```

Правильно: `class Shape(ABC):`.

**5. Реализовать не все абстрактные методы** — даже если остался один метод, дочерний класс тоже останется абстрактным.

## Основные понятия

| Понятие | Объяснение |
|---|---|
| Полиморфизм | Выполнение одноимённого действия каждым объектом по-своему |
| Duck typing | Ориентация не на тип, а на наличие у объекта нужных методов |
| `hasattr(obj, "x")` | Проверка, есть ли у объекта атрибут `x` |
| Абстракция | Выделение существенных свойств, сокрытие мелких деталей |
| Абстрактный класс | Класс, объект которого не создаётся; служит образцом для потомков |
| `ABC`, `@abstractmethod` | Средства модуля `abc` для абстрактного класса и абстрактного метода |
| Интерфейс | Набор методов, которые обязательно должны быть в классе |

## Примечание

- `isinstance(obj, Class)` лучше, чем `type(obj) == Class`: `isinstance` учитывает наследование (объект дочернего класса тоже считается экземпляром родителя).
- Абстрактный метод может содержать реализацию по умолчанию — потомок обязан его переопределить, но может вызвать исходную версию через `super()`.
- `@abstractmethod` сочетается с `@property`, `@classmethod`, `@staticmethod`; при этом `@abstractmethod` пишется **самым нижним** (ближе к `def`).
- Модуль `collections.abc` содержит готовые абстрактные классы: `Iterable`, `Sized`, `Sequence`, `Mapping` и др.
- Для утиной типизации со статической проверкой есть `typing.Protocol` (Python 3.8+): класс подходит, если у него есть нужные методы, наследование не требуется.
- Документация: https://docs.python.org/3/library/abc.html
