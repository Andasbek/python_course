## 1. Что такое наследование?

**Наследование** (inheritance) — механизм создания нового класса на основе существующего: новый класс получает в наследство **все атрибуты и методы** существующего класса и может **добавить к ним свои**.

| Термин | Синонимы | Значение |
|---|---|---|
| **Родительский класс** | базовый класс, суперкласс, класс-предок, parent | общий класс, в котором описаны общие свойства |
| **Дочерний класс** | производный класс, подкласс, класс-потомок, child, subclass | уточнённый класс, наследующий от родительского |

Аналогии:
- **Биология:** цвет глаз и рост ребёнка передаются от родителей, но у него есть и собственные особенности.
- **Классификация:** «Животное» → «Млекопитающее» → «Кошка». Каждая кошка — млекопитающее, каждое млекопитающее — животное.
- **Шаблон документа:** официальный бланк школы (логотип, адрес) — родительский класс; созданные на его основе справка, приказ, объявление — потомки.

Основная идея: **общее** пишем один раз в родительском классе, **особенное** — в потомках.

## 2. Синтаксис

```text
class ДочернийКласс(РодительскийКласс):
    ...новые атрибуты и методы...
```

Пример — игровые персонажи:

```python
class Hero:
    """Родительский класс для всех игровых персонажей."""

    def __init__(self, name):
        self.name = name
        self.hp = 100
        self.level = 1

    def take_damage(self, amount):
        """Получает урон."""
        self.hp = max(0, self.hp - amount)

    def is_alive(self):
        """Жив ли?"""
        return self.hp > 0

    def info(self):
        """Краткая информация."""
        return f"{self.name}: {self.hp} HP, {self.level}-й уровень"


class Warrior(Hero):
    """Воин — один из видов персонажа."""

    def strike(self):
        return f"{self.name} рубит мечом!"


class Mage(Hero):
    """Маг — один из видов персонажа."""

    def cast(self):
        return f"{self.name} бросает огненный шар!"


batyr = Warrior("Батыр")
merlin = Mage("Мерлин")

print(batyr.strike())          # собственный метод
print(merlin.cast())           # собственный метод
merlin.take_damage(30)         # унаследованный метод
print(batyr.info())            # унаследованный метод
print(merlin.info())
print(merlin.is_alive())
```
Результат:
```text
Батыр рубит мечом!
Мерлин бросает огненный шар!
Батыр: 100 HP, 1-й уровень
Мерлин: 70 HP, 1-й уровень
True
```

В классах `Warrior` и `Mage` нет `__init__` — но `Warrior("Батыр")` работает: конструктор унаследован **от родительского класса**. Весь общий код — только в `Hero`. Исправим `take_damage` — исправятся сразу все персонажи.

### Наследование в UML
```text
              ┌──────────────────────┐
              │        Hero          │
              ├──────────────────────┤
              │ name, hp, level      │
              ├──────────────────────┤
              │ take_damage(amount)  │
              │ is_alive()           │
              │ info()               │
              └──────────▲───────────┘
                         │  (стрелка с пустым треугольником = «наследник»)
           ┌─────────────┴─────────────┐
┌──────────┴──────────┐     ┌──────────┴──────────┐
│      Warrior        │     │        Mage         │
├─────────────────────┤     ├─────────────────────┤
│ strike()            │     │ cast()              │
└─────────────────────┘     └─────────────────────┘
```
Стрелка направлена от потомка **к родительскому классу**: «Warrior — разновидность Hero».

## 3. Что наследует дочерний класс?

| В родительском классе | Есть ли у потомка? |
|---|---|
| Открытые атрибуты и методы | да |
| Атрибуты класса | да (общие, но в потомке их можно «перекрыть») |
| Конструктор `__init__` | да, если у потомка нет собственного `__init__` |
| Свойства `@property` | да |
| `_защищённые` атрибуты | да — именно это и означает «внутреннее, для потомков» |
| `__закрытые` атрибуты | есть, но имя искажено до `_РодительскийКласс__x`, из методов потомка через `self.__x` **обратиться нельзя** |

Последняя строка важна: для внутренних данных, которыми должны пользоваться потомки, лучше использовать **одно** подчёркивание (`_hp`).

```python
class Base:
    def __init__(self):
        self._shared = "доступно потомкам"
        self.__secret = "только внутри Base"


class Child(Base):
    def show(self):
        print(self._shared)
        # print(self.__secret)  # AttributeError: 'Child' object has no attribute '_Child__secret'


Child().show()
```
Результат:
```text
доступно потомкам
```

## 4. Расширение дочернего класса

В потомок можно добавлять новые **атрибуты класса** и **методы**. Методы потомка свободно используют атрибуты родительского класса (`self.name`, `self.hp`):

```python
class Archer(Hero):
    """Лучник."""
    max_arrows = 10                      # атрибут класса, присущий только лучникам

    def shoot(self, target):
        """Стреляет в цель (количество стрел ограничено)."""
        if not hasattr(self, "arrows"):
            self.arrows = self.max_arrows
        if self.arrows == 0:
            return f"{self.name}: стрелы закончились!"
        self.arrows -= 1
        target.take_damage(15)
        return f"{self.name} → {target.name}: -15 HP (осталось стрел: {self.arrows})"


arman = Archer("Арман")
print(arman.shoot(batyr))
print(arman.shoot(batyr))
print(batyr.info())
```
Результат:
```text
Арман → Батыр: -15 HP (осталось стрел: 9)
Арман → Батыр: -15 HP (осталось стрел: 8)
Батыр: 70 HP, 1-й уровень
```

Заметь: атрибут `arrows` мы добавили «потом» через `hasattr` — это неудобно. Потомок должен добавлять **новые атрибуты** (количество стрел, ману) в своём конструкторе, но при этом **сохранять** и конструктор родительского класса. Для этого потомок объявляет свой `__init__` и вызывает в нём конструктор родителя через `super().__init__(...)`. Кроме того, потомок может **переопределить** (override) метод родительского класса — например, чтобы `info()` у мага показывал и ману:

```python
class ManaMage(Hero):
    """Маг с запасом маны."""

    def __init__(self, name, mana=50):
        super().__init__(name)      # name, hp, level задаёт Hero
        self.mana = mana

    def info(self):                 # переопределение метода родителя
        return f"{super().info()}, мана: {self.mana}"


print(ManaMage("Мерлин").info())
```
Результат:
```text
Мерлин: 100 HP, 1-й уровень, мана: 50
```

## 5. Иерархия классов

Наследование может быть **многоуровневым**:

```python
class Animal:
    """Животное."""

    def __init__(self, name):
        self.name = name

    def breathe(self):
        return f"{self.name} дышит"


class Mammal(Animal):
    """Млекопитающее."""

    def feed_milk(self):
        return f"{self.name} кормит детёнышей молоком"


class Cat(Mammal):
    """Кошка."""

    def meow(self):
        return f"{self.name}: Мяу!"


class Bird(Animal):
    """Птица."""

    def fly(self):
        return f"{self.name} летит"


murzik = Cat("Мурзик")
print(murzik.meow())        # Cat
print(murzik.feed_milk())   # из Mammal
print(murzik.breathe())     # из Animal
burkit = Bird("Беркут")
print(burkit.fly(), "|", burkit.breathe())
# burkit.meow()             # AttributeError — птица не мяукает
```
Результат:
```text
Мурзик: Мяу!
Мурзик кормит детёнышей молоком
Мурзик дышит
Беркут летит | Беркут дышит
```

```text
             Animal
            /      \
        Mammal     Bird
          |
         Cat
```

### Порядок поиска атрибутов (MRO)
При вызове `murzik.breathe()` Python ищет метод **снизу вверх**: сначала в `Cat`, если не найден — в `Mammal`, затем — в `Animal`, и наконец — в `object`. Этот порядок называется **MRO** (Method Resolution Order, порядок разрешения методов):

```python
print([cls.__name__ for cls in Cat.__mro__])
```
Результат:
```text
['Cat', 'Mammal', 'Animal', 'object']
```

### `object` — «прародитель» всех классов
В Python 3 каждый класс, у которого не указан родительский класс, автоматически наследует от класса **`object`**. `class Animal:` ≡ `class Animal(object):`. Поэтому у любого объекта есть методы `__init__`, `__str__`, `__eq__` и т.п. — они приходят из `object` (их можно переопределять в своих классах).

## 6. `isinstance()` и `issubclass()`

```python
print(isinstance(murzik, Cat))       # True
print(isinstance(murzik, Mammal))    # True — кошка ещё и млекопитающее
print(isinstance(murzik, Animal))    # True
print(isinstance(murzik, Bird))      # False
print(issubclass(Cat, Animal))       # True — проверка на уровне классов
print(issubclass(Bird, Mammal))      # False
print(type(murzik) == Mammal)        # False — type показывает только точный класс
```
Результат:
```text
True
True
True
False
True
False
False
```

Объект потомка — одновременно и объект родительского класса. Поэтому там, где ожидается родительский класс, можно использовать потомка:

```python
heroes = [Warrior("Батыр"), Mage("Мерлин"), Archer("Арман")]
for hero in heroes:
    hero.take_damage(20)          # метод, который есть у любого Hero
    print(hero.info(), "| маг" if isinstance(hero, Mage) else "")
```
Результат:
```text
Батыр: 80 HP, 1-й уровень 
Мерлин: 80 HP, 1-й уровень | маг
Арман: 80 HP, 1-й уровень 
```
Это — основа **полиморфизма**.

## 7. «Является» (is-a) и «имеет» (has-a)

Контрольный вопрос для **правильного** применения наследования:

> «Является ли потомок **разновидностью** родительского класса?» (is-a)

| Отношение | Вопрос | Правильное решение | Пример |
|---|---|---|---|
| **is-a** («является») | Кошка — животное? Да | **наследование** | `class Cat(Animal)` |
| **has-a** («имеет») | У машины есть двигатель? Да. Машина — это двигатель? Нет | **композиция** (атрибут) | `self.engine = Engine()` |

Неправильные примеры:
- `class Car(Engine)` — машина не разновидность двигателя → композиция.
- `class Library(Book)` — библиотека не разновидность книги, в ней **есть** книги → `self.books = []`.
- `class Student(Classroom)` — ученик не разновидность класса.

Правильные примеры:
- `class Teacher(Person)`, `class Student(Person)` — и преподаватель, и ученик — люди.
- `class SavingsAccount(BankAccount)` — сберегательный счёт — разновидность банковского счёта.
- `class EBook(Book)` — электронная книга — разновидность книги.

## 8. Школьный пример: `Person` → `Student`, `Teacher`

```python
class Person:
    """Человек в школе."""
    school = "Школа-гимназия №35"

    def __init__(self, name, birth_year):
        self.name = name
        self.birth_year = birth_year

    def age(self, current_year=2026):
        return current_year - self.birth_year

    def introduce(self):
        return f"Я — {self.name}, мой возраст — {self.age()}."


class Student(Person):
    """Ученик."""

    def study(self, subject):
        return f"{self.name} изучает предмет «{subject}»."


class Teacher(Person):
    """Преподаватель."""

    def teach(self, subject, grade):
        return f"{self.name} ведёт урок по предмету «{subject}» в {grade}-м классе."


people = [Student("Әлия", 2012), Teacher("Гүлнар Серікқызы", 1985)]
for p in people:
    print(p.introduce(), p.school)
print(people[0].study("информатика"))
print(people[1].teach("информатика", 7))
```
Результат:
```text
Я — Әлия, мой возраст — 14. Школа-гимназия №35
Я — Гүлнар Серікқызы, мой возраст — 41. Школа-гимназия №35
Әлия изучает предмет «информатика».
Гүлнар Серікқызы ведёт урок по предмету «информатика» в 7-м классе.
```

## 9. Множественное наследование (краткий обзор)

В Python класс может наследовать от **нескольких** родительских классов: `class FlyingCar(Car, Airplane):`. Это мощный, но легко запутывающий инструмент (если метод есть в обоих родительских классах, какой из них будет взят? — решает MRO). На практике чаще всего применяют **одиночное** наследование. Самый частый случай — наследование от готового класса библиотеки, например `class Player(pygame.sprite.Sprite):` в Pygame.

## 10. Преимущества наследования

1. **Повторное использование кода** — общий код пишется один раз (DRY).
2. **Лёгкое исправление** — исправил ошибку в родительском классе — она исправлена во всех потомках.
3. **Лёгкое расширение** — новый вид персонажа = несколько строк.
4. **Логическая структура** — иерархия классов отражает классификацию реального мира.
5. **Использование готовых библиотек** — наследуешь от классов Tkinter, Pygame, unittest и добавляешь свои возможности.

## Частые ошибки

**1. Забыли указать родительский класс в скобках.**
```python
class Hero:
    def is_alive(self):
        return True


class Warrior:               # нет (Hero) — нет наследования!
    pass


# Warrior().is_alive()       # AttributeError: 'Warrior' object has no attribute 'is_alive'
```

**2. Родительский класс объявлен после потомка.**
```text
class Warrior(Hero): ...   ← Hero ещё не объявлен
class Hero: ...
→ NameError: name 'Hero' is not defined
```
Родительский класс должен быть в файле **выше** (или импортирован).

**3. Не переданы аргументы конструктора родительского класса при создании потомка.**
```text
Warrior()  →  TypeError: Hero.__init__() missing 1 required positional argument: 'name'
```
Потомок унаследовал конструктор родительского класса — нужно передать его параметры.

**4. Обращение из потомка к `__закрытому` атрибуту родительского класса.** `AttributeError: ... '_Child__x'`. Для данных, предназначенных потомкам, используй `_x`.

**5. Использование наследования в случае «has-a»** (`class Car(Engine)`). Задай вопрос: «является ли потомок разновидностью родительского класса?»

**6. Слишком глубокая иерархия.** `A → B → C → D → E → F` — трудно понять. Обычно достаточно 2–3 уровней.

## Основные понятия

| Понятие | Объяснение |
|---|---|
| Наследование (inheritance) | Создание нового класса на основе существующего |
| Родительский класс (parent, суперкласс) | Класс, в котором описаны общие атрибуты и методы |
| Дочерний класс (child, подкласс) | Класс, наследующий от родительского |
| Иерархия классов | «Дерево» наследования классов |
| `object` | Родительский класс всех классов в Python |
| MRO | Порядок поиска методов и атрибутов |
| `isinstance(obj, C)` | Принадлежит ли объект классу C (или его потомку) |
| `issubclass(A, B)` | Является ли класс A потомком B |
| is-a | «является» — признак наследования |
| has-a | «имеет» — признак композиции |

## Примечание

- Если в потомке написан собственный `__init__`, конструктор родителя автоматически **не вызывается** — забыв `super().__init__(...)`, ты останешься без атрибутов родителя.
- Вместо `type(obj) == Parent` используй `isinstance(obj, Parent)`: он учитывает потомков. Вторым аргументом `isinstance` принимает кортеж: `isinstance(x, (Warrior, Mage))`.
- Наследовать можно и от встроенных типов (`class MyList(list):`), но для переопределения методов `dict` и `list` надёжнее `collections.UserDict` / `UserList`.
- По PEP 8 и родитель, и потомок называются в стиле `PascalCase`; имя потомка обычно уточняет имя родителя (`SavingsAccount(BankAccount)`).
- Официальная документация: https://docs.python.org/3/tutorial/classes.html#inheritance.
