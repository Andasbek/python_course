## 1. Что такое инкапсуляция?

**Инкапсуляция** (encapsulation; от лат. *in capsula* — «в капсуле») — один из основных принципов ООП. У неё две стороны:

1. **Объединение:** данные (атрибуты) и методы, которые их обрабатывают, находятся в одном объекте («капсуле»).
2. **Сокрытие:** внутреннее устройство объекта скрыто от внешнего мира; внешний код работает с объектом только через **открытый интерфейс** — специальные методы.

Аналогии:
- **Банкомат.** Ты не имеешь доступа к сейфу с деньгами — только через экран и кнопки (интерфейс): «посмотреть баланс», «снять деньги». Банкомат проверяет PIN-код и не выдаёт больше, чем на балансе.
- **Капсула лекарства.** Порошок внутри защищён, ты просто глотаешь капсулу.
- **Телевизор.** Ты не вскрываешь внутренние схемы — управляешь пультом. Пульт не позволяет поднять громкость выше 100.

```text
             ВНЕШНИЙ КОД
                 │
                 ▼  только через методы
 ┌─────────────────────────────────────┐
 │  Открытый интерфейс (public):       │
 │   deposit(), withdraw(),            │
 │   get_balance()                     │
 ├─────────────────────────────────────┤
 │  Внутренняя реализация (скрыта):    │
 │   __balance, __pin, _log(),         │
 │   _check_pin()                      │
 └─────────────────────────────────────┘
```

**Что даёт инкапсуляция?**
- **Целостность данных** — объект никогда не окажется в «бессмысленном» состоянии (отрицательный баланс, возраст 150 лет, пустое имя).
- **Безопасность** — секретные данные (PIN, пароль) не выходят наружу.
- **Свобода изменений** — если изменить внутреннее устройство (например, хранить баланс в тиынах), внешний код не сломается, потому что он использует только интерфейс.
- **Простота** — пользователю класса нужны лишь несколько понятных методов.

## 2. Уровни доступа в Python

В языках вроде Java, C++ есть ключевые слова `public`, `protected`, `private`. В Python строгих запретов нет — вместо них используется **соглашение об именовании**: «Мы все здесь взрослые люди» (we are all consenting adults).

| Уровень | Запись | Значение | Доступ извне |
|---|---|---|---|
| Открытый (public) | `self.name` | можно использовать где угодно | `obj.name` — нормально |
| Защищённый (protected) | `self._name` | «внутреннее, не трогай» — для класса и его потомков | возможен, но по соглашению **не трогаем** |
| Закрытый (private) | `self.__name` | только внутри класса | `obj.__name` → `AttributeError` |

```python
class Demo:
    """Демонстрация уровней доступа."""

    def __init__(self):
        self.public = "открытый"
        self._protected = "защищённый"
        self.__private = "закрытый"

    def show(self):
        """Изнутри класса доступно всё."""
        print(self.public, self._protected, self.__private)


d = Demo()
d.show()
print(d.public)
print(d._protected)      # работает, но — плохой стиль!
# print(d.__private)     # AttributeError: 'Demo' object has no attribute '__private'
```
Результат:
```text
открытый защищённый закрытый
открытый
защищённый
```

- `_` (одно подчёркивание) — **сигнал** программистам: «это внутренняя часть, не меняй её напрямую, она может измениться». VS Code тоже опускает такие имена вниз в автодополнении.
- `__` (два подчёркивания) — Python скрывает такой атрибут с помощью **искажения имени**.

Методы тоже могут быть защищёнными/закрытыми: `_log()`, `__check_pin()` — внутренние вспомогательные методы класса.

## 3. Искажение имён (name mangling)

Атрибут `__balance` на самом деле никуда «не исчезает» — Python переименовывает его в **`_ИмяКласса__balance`**:

```python
class Safe:
    """Сейф."""

    def __init__(self, code):
        self.__code = code


s = Safe("1234")
print(vars(s))
print(s._Safe__code)     # «взломать» можно — но НИКОГДА так не делай
```
Результат:
```text
{'_Safe__code': '1234'}
1234
```

То есть закрытость в Python — **не замок, а табличка «Не входить»**: она защищает от случайных ошибок, но не от намеренного взломщика. Этого достаточно, потому что цель инкапсуляции — защита от **ошибок** программистов и понятность кода.

Будь внимателен: если снаружи класса написать `obj.__x = 5`, ошибки не будет — просто создастся **новый**, другой атрибут:
```python
s.__code = "0000"         # создан новый атрибут '__code', внутренний _Safe__code не изменился
print(vars(s))
```
Результат:
```text
{'_Safe__code': '1234', '__code': '0000'}
```

## 4. Методы-геттеры и сеттеры

Для контролируемого доступа к закрытому атрибуту пишем специальные методы:
- **геттер** (getter, «получатель») — позволяет **прочитать** значение: `get_balance()`;
- **сеттер** (setter, «установщик») — **проверяет** значение и устанавливает его: `set_owner(name)`.

```python
class BankAccount:
    """Инкапсулированный банковский счёт."""
    MIN_OWNER_LENGTH = 2

    def __init__(self, owner, balance=0):
        self.__owner = ""
        self.__balance = 0
        self.__history = []
        self.set_owner(owner)          # проверка работает и в конструкторе
        if balance > 0:
            self.deposit(balance)

    # --- геттеры ---
    def get_owner(self):
        """Возвращает имя владельца счёта."""
        return self.__owner

    def get_balance(self):
        """Возвращает текущий баланс."""
        return self.__balance

    def get_history(self):
        """Возвращает КОПИЮ истории операций."""
        return list(self.__history)

    # --- сеттер ---
    def set_owner(self, name):
        """Проверяет и устанавливает имя владельца."""
        name = name.strip()
        if len(name) < self.MIN_OWNER_LENGTH:
            print("Ошибка: имя слишком короткое")
            return False
        self.__owner = name.title()
        return True

    # --- открытые действия ---
    def deposit(self, amount):
        """Пополняет счёт."""
        if amount <= 0:
            print("Ошибка: сумма должна быть положительной")
            return False
        self.__balance += amount
        self.__log(f"+{amount}")
        return True

    def withdraw(self, amount):
        """Снимает деньги."""
        if not 0 < amount <= self.__balance:
            print("Операция невозможна")
            return False
        self.__balance -= amount
        self.__log(f"-{amount}")
        return True

    # --- закрытый вспомогательный метод ---
    def __log(self, text):
        self.__history.append(text)


acc = BankAccount("дана серикказы", 1000)
acc.deposit(500)
acc.withdraw(5000)
acc.set_owner("Д")
print(acc.get_owner(), acc.get_balance(), acc.get_history())
```
Результат:
```text
Операция невозможна
Ошибка: имя слишком короткое
Дана Серикказы 1500 ['+1000', '+500']
```

Обрати внимание:
- **У баланса нет сеттера!** Баланс меняют только `deposit()` и `withdraw()` — это атрибут «только для чтения» (read-only). Мы не обязаны писать сеттер к каждому атрибуту — только там, где это имеет смысл.
- `get_history()` возвращает **копию** списка. Если вернуть сам `self.__history`, внешний код смог бы стереть историю через `acc.get_history().clear()`.
- `__log()` — закрытый метод: внешний код не может записать «фальшивую» операцию.

Теперь попробуем взломать снаружи:
```python
acc.balance = -1_000_000       # создан новый открытый атрибут — но на счёт он не влияет
print(acc.get_balance())       # 1500
```

## 5. Проектирование интерфейса класса

Когда пишешь класс, задай себе вопросы:

| Вопрос | Решение |
|---|---|
| Нужно ли читать эти данные снаружи? | да → геттер (или открытый атрибут) |
| Нужно ли изменять их снаружи? | да → сеттер с проверкой; нет → только геттер |
| Подчиняется ли значение правилам (пределы, формат)? | да → обязательно закрытый + сеттер |
| Это секрет (пароль, PIN)? | да → закрытый, без геттера; только метод проверки |
| Это вспомогательная вещь, нужная только внутри класса? | да → `_method` или `__method` |

**Правило:** по умолчанию скрывай внутренние данные, наружу открывай только необходимое. Но не скрывай лишнего: простые атрибуты без правил (например, название книги) могут оставаться открытыми.

### Пример секретных данных: пароль
```python
import hashlib


class User:
    """Учётная запись пользователя."""

    def __init__(self, login, password):
        self.login = login                         # открытый
        self.__password_hash = self.__hash(password)
        self.__failed_attempts = 0

    @staticmethod
    def __hash(text):
        return hashlib.sha256(text.encode("utf-8")).hexdigest()

    def check_password(self, password):
        """Проверяет пароль; после 3 неудачных попыток блокирует."""
        if self.__failed_attempts >= 3:
            print("Аккаунт заблокирован")
            return False
        if self.__hash(password) == self.__password_hash:
            self.__failed_attempts = 0
            return True
        self.__failed_attempts += 1
        return False


user = User("aigerim", "Py2026!")
print(user.check_password("12345"))
print(user.check_password("Py2026!"))
```
Результат:
```text
False
True
```
Сам пароль в объекте **вообще не хранится** — только его хеш (односторонний «отпечаток пальца»). Геттера нет — пароль прочитать невозможно, только проверить. (`@staticmethod` — метод, которому не нужен `self`; знак `@` обозначает декоратор.)

## 6. Преимущество инкапсуляции: внутреннее изменение — внешний код остаётся прежним

Представь: банк решил хранить баланс **в тиынах** (целым числом). Внутреннее устройство меняется, а интерфейс — нет:

```python
class Wallet:
    """Кошелёк: внутри хранит в тиынах, наружу показывает в тенге."""

    def __init__(self):
        self.__tiyn = 0

    def add(self, tenge):
        self.__tiyn += round(tenge * 100)

    def get_balance(self):
        return self.__tiyn / 100


w = Wallet()
w.add(0.1)
w.add(0.2)
print(w.get_balance())
print(0.1 + 0.2)
```
Результат:
```text
0.3
0.30000000000000004
```
Ни одна строка кода, использующего класс `Wallet`, не изменилась, а проблема точности решена.

## Частые ошибки

**1. Обращение к закрытому атрибуту снаружи класса.**
```text
print(acc.__balance)  →  AttributeError: 'BankAccount' object has no attribute '__balance'
```
Решение: используй геттер — `acc.get_balance()`.

**2. Написать снаружи `obj.__x = ...` и думать, что «изменил».** Так создаётся не внутренний, а новый атрибут (см. раздел 3).

**3. Разное написание имени внутри класса.**
```python
class Counter:
    def __init__(self):
        self.__value = 0

    def inc(self):
        self.__valeu += 1    # AttributeError: '_Counter__valeu' — опечатка в имени
```

**4. Возврат внутреннего списка/словаря из геттера напрямую.** Внешний код сможет его изменить. Возвращай копию: `list(...)`, `dict(...)`.

**5. Забыли проверку в сеттере** — тогда закрытый атрибут теряет смысл: `def set_age(self, age): self.__age = age` ничем не отличается от открытого атрибута.

**6. Сделать закрытым всё.** Писать `__` и «пустые» геттеры-сеттеры для каждого атрибута — утяжелять код. Скрывай только данные, у которых есть правила или секретность.

## Основные понятия

| Понятие | Пояснение |
|---|---|
| Инкапсуляция | Объединение данных и методов и сокрытие внутреннего устройства |
| Открытый интерфейс | Набор методов для внешнего кода |
| Открытый атрибут (public) | `name` — доступен отовсюду |
| Защищённый атрибут (protected) | `_name` — соглашение «внутреннее» |
| Закрытый атрибут (private) | `__name` — атрибут с искажённым именем, только для класса |
| Name mangling | Замена имени `__x` на `_Класс__x` |
| Геттер | Метод, возвращающий значение закрытого атрибута |
| Сеттер | Метод, проверяющий и устанавливающий значение |
| Read-only атрибут | Атрибут только для чтения, без сеттера |
| Целостность данных | Постоянная корректность состояния объекта |

## Примечание

- Рекомендация PEP 8: для внутренних атрибутов и методов достаточно одного подчёркивания (`_name`). Двойное подчёркивание (`__name`) применяют в основном для того, чтобы избежать конфликтов имён в классах-наследниках.
- Если имя заканчивается двумя подчёркиваниями (`__init__`, `__len__`), искажение имени не применяется — это специальные методы Python, свои атрибуты так не называй.
- `from module import *` не импортирует имена, начинающиеся с `_`, — и на уровне модуля `_` означает «внутреннее».
- Вместо методов-геттеров и сеттеров в Python обычно используют декоратор `@property`: снаружи это выглядит как обычный атрибут, а внутри работает проверка.
- Для хранения паролей в реальных системах используют не простой SHA-256, а медленные алгоритмы с «солью» (salt): `hashlib.scrypt`, `hashlib.pbkdf2_hmac` или библиотеку `bcrypt`. Документация: https://docs.python.org/3/library/hashlib.html.
