## 1. Инкапсуляция деген не?

**Инкапсуляция** (инкапсуляция, encapsulation; латынша *in capsula* — «капсула ішінде») — ОБП-нің негізгі қағидаларының бірі. Оның екі қыры бар:

1. **Біріктіру:** деректер (атрибуттар) мен оларды өңдейтін әдістер бір объектіде («капсулада») болады.
2. **Жасыру:** объектінің ішкі құрылымы сырттан жасырылады; сыртқы код объектімен тек **ашық интерфейс** — арнайы әдістер арқылы жұмыс істейді.

Аналогиялар:
- **Банкомат.** Сен ақша сақтайтын сейфке қол жеткізе алмайсың — тек экран мен батырмалар (интерфейс) арқылы: «балансты көру», «ақша шешу». Банкомат PIN-кодты тексереді, баланстан артық ақша бермейді.
- **Дәрі капсуласы.** Ішіндегі ұнтақ қорғалған, сен тек капсуланы жұтасың.
- **Теледидар.** Ішкі схемаларды ашпайсың — пультпен басқарасың. Пульт дыбысты 100-ден асырмайды.

```text
             СЫРТҚЫ КОД
                 │
                 ▼  тек әдістер арқылы
 ┌─────────────────────────────────────┐
 │  Ашық интерфейс (public):           │
 │   deposit(), withdraw(),            │
 │   get_balance()                     │
 ├─────────────────────────────────────┤
 │  Ішкі іске асыру (жасырын):         │
 │   __balance, __pin, _log(),         │
 │   _check_pin()                      │
 └─────────────────────────────────────┘
```

**Инкапсуляция не береді?**
- **Деректердің тұтастығы** — объект ешқашан «мағынасыз» күйге түспейді (теріс баланс, 150 жас, бос аты).
- **Қауіпсіздік** — құпия деректер (PIN, пароль) сыртқа шықпайды.
- **Өзгертуге еркіндік** — ішкі құрылымды (мысалы, балансты тиынмен сақтауды) өзгертсек, сыртқы код бұзылмайды, себебі ол тек интерфейсті қолданады.
- **Қарапайымдылық** — класты қолданушыға тек бірнеше түсінікті әдіс керек.

## 2. Python-дағы қатынау деңгейлері

Java, C++ сияқты тілдерде `public`, `protected`, `private` кілт сөздері бар. Python-да қатаң тыйым жоқ — оның орнына **атау беру келісімі** қолданылады: «Біз бәріміз ересек адамдармыз» (we are all consenting adults).

| Деңгейі | Жазылуы | Мағынасы | Сырттан қатынау |
|---|---|---|---|
| Ашық (public) | `self.name` | кез келген жерден қолдануға болады | `obj.name` — қалыпты |
| Қорғалған (protected) | `self._name` | «ішкі, тиіспе» — класс және оның ұрпақтары үшін | мүмкін, бірақ келісім бойынша **тиіспейміз** |
| Жабық (private) | `self.__name` | тек класс ішінде | `obj.__name` → `AttributeError` |

```python
class Demo:
    """Қатынау деңгейлерін көрсету."""

    def __init__(self):
        self.public = "ашық"
        self._protected = "қорғалған"
        self.__private = "жабық"

    def show(self):
        """Класс ішінен барлығына қатынауға болады."""
        print(self.public, self._protected, self.__private)


d = Demo()
d.show()
print(d.public)
print(d._protected)      # жұмыс істейді, бірақ — жаман стиль!
# print(d.__private)     # AttributeError: 'Demo' object has no attribute '__private'
```
Нәтижесі:
```text
ашық қорғалған жабық
ашық
қорғалған
```

- `_` (бір астын сызу) — бағдарламашыларға **сигнал**: «бұл — ішкі бөлік, оны тікелей өзгертпе, кейін өзгеруі мүмкін». VS Code да оны автотолтыруда төменге жасырады.
- `__` (екі астын сызу) — Python оны **атауын бұрмалау** арқылы жасырады.

Әдістер де қорғалған/жабық болуы мүмкін: `_log()`, `__check_pin()` — класстың ішкі көмекші әдістері.

## 3. Атауды бұрмалау (name mangling)

`__balance` атрибуты шын мәнінде «жоғалып кетпейді» — Python оны **`_КлассАты__balance`** деп қайта атайды:

```python
class Safe:
    """Сейф."""

    def __init__(self, code):
        self.__code = code


s = Safe("1234")
print(vars(s))
print(s._Safe__code)     # «бұзу» мүмкін — бірақ ЕШҚАШАН олай істеме
```
Нәтижесі:
```text
{'_Safe__code': '1234'}
1234
```

Яғни Python-дағы жабықтық — **құлып емес, «Кірмеңіз» деген жазу**: кездейсоқ қателерден қорғайды, бірақ әдейі бұзушыдан емес. Бұл жеткілікті, себебі инкапсуляцияның мақсаты — бағдарламашылардың **қателерінен** қорғау және кодты түсінікті ету.

Абай бол: класс сыртынан `obj.__x = 5` жазсаң, қате болмайды — жай ғана **жаңа**, басқа атрибут құрылады:
```python
s.__code = "0000"         # жаңа атрибут '__code' құрылды, ішкі _Safe__code өзгермеді
print(vars(s))
```
Нәтижесі:
```text
{'_Safe__code': '1234', '__code': '0000'}
```

## 4. Геттер және сеттер әдістері

Жабық атрибутқа бақыланатын қатынау үшін арнайы әдістер жазамыз:
- **геттер** (getter, «алушы») — мәнді **оқуға** береді: `get_balance()`;
- **сеттер** (setter, «орнатушы») — мәнді **тексеріп**, орнатады: `set_owner(name)`.

```python
class BankAccount:
    """Инкапсуляцияланған банк шоты."""
    MIN_OWNER_LENGTH = 2

    def __init__(self, owner, balance=0):
        self.__owner = ""
        self.__balance = 0
        self.__history = []
        self.set_owner(owner)          # тексеріс конструкторда да жұмыс істейді
        if balance > 0:
            self.deposit(balance)

    # --- геттерлер ---
    def get_owner(self):
        """Шот иесінің атын қайтарады."""
        return self.__owner

    def get_balance(self):
        """Ағымдағы балансты қайтарады."""
        return self.__balance

    def get_history(self):
        """Операциялар тарихының КӨШІРМЕСІН қайтарады."""
        return list(self.__history)

    # --- сеттер ---
    def set_owner(self, name):
        """Иесінің атын тексеріп орнатады."""
        name = name.strip()
        if len(name) < self.MIN_OWNER_LENGTH:
            print("Қате: аты тым қысқа")
            return False
        self.__owner = name.title()
        return True

    # --- ашық әрекеттер ---
    def deposit(self, amount):
        """Шотты толтырады."""
        if amount <= 0:
            print("Қате: сома оң болуы керек")
            return False
        self.__balance += amount
        self.__log(f"+{amount}")
        return True

    def withdraw(self, amount):
        """Ақша шешеді."""
        if not 0 < amount <= self.__balance:
            print("Операция мүмкін емес")
            return False
        self.__balance -= amount
        self.__log(f"-{amount}")
        return True

    # --- жабық көмекші әдіс ---
    def __log(self, text):
        self.__history.append(text)


acc = BankAccount("дана серікқызы", 1000)
acc.deposit(500)
acc.withdraw(5000)
acc.set_owner("Д")
print(acc.get_owner(), acc.get_balance(), acc.get_history())
```
Нәтижесі:
```text
Операция мүмкін емес
Қате: аты тым қысқа
Дана Серікқызы 1500 ['+1000', '+500']
```

Назар аудар:
- **Балансқа сеттер жоқ!** Балансты тек `deposit()` және `withdraw()` өзгертеді — бұл «тек оқуға арналған» (read-only) атрибут. Әр атрибутқа міндетті түрде сеттер жазбаймыз — тек мағынасы бар жерде.
- `get_history()` тізімнің **көшірмесін** қайтарады. Егер `self.__history`-дің өзін қайтарсақ, сыртқы код `acc.get_history().clear()` арқылы тарихты өшіріп тастар еді.
- `__log()` — жабық әдіс: сыртқы код «жалған» операция жаза алмайды.

Енді сырттан бұзып көрейік:
```python
acc.balance = -1_000_000       # жаңа ашық атрибут құрылды — бірақ ол шотқа әсер етпейді
print(acc.get_balance())       # 1500
```

## 5. Класстың интерфейсін жобалау

Класс жазғанда өзіңе сұрақ қой:

| Сұрақ | Шешім |
|---|---|
| Бұл деректі сырттан оқу керек пе? | иә → геттер (немесе ашық атрибут) |
| Сырттан өзгерту керек пе? | иә → тексерісі бар сеттер; жоқ → тек геттер |
| Мән ережеге бағына ма (шек, формат)? | иә → міндетті түрде жабық + сеттер |
| Құпия ма (пароль, PIN)? | иә → жабық, геттерсіз; тек тексеру әдісі |
| Тек класс ішінде керек көмекші ме? | иә → `_method` немесе `__method` |

**Ереже:** ішкі деректерді әдепкі бойынша жасыр, сыртқа тек қажеттісін аш. Бірақ артық жасырма: қарапайым, ережесіз атрибуттар (мысалы, кітаптың атауы) ашық бола береді.

### Құпия деректің мысалы: пароль
```python
import hashlib


class User:
    """Пайдаланушы аккаунты."""

    def __init__(self, login, password):
        self.login = login                         # ашық
        self.__password_hash = self.__hash(password)
        self.__failed_attempts = 0

    @staticmethod
    def __hash(text):
        return hashlib.sha256(text.encode("utf-8")).hexdigest()

    def check_password(self, password):
        """Парольді тексереді; 3 қате әрекеттен кейін бұғаттайды."""
        if self.__failed_attempts >= 3:
            print("Аккаунт бұғатталған")
            return False
        if self.__hash(password) == self.__password_hash:
            self.__failed_attempts = 0
            return True
        self.__failed_attempts += 1
        return False


user = User("aigerim", "Py2026!")
print(user.check_password("12345"))
print(user.check_password("Py2026!"))
```
Нәтижесі:
```text
False
True
```
Парольдің өзі объектіде **мүлдем сақталмайды** — тек оның хэші (бір бағытты «саусақ ізі»). Геттер жоқ — парольді оқу мүмкін емес, тек тексеру. (`@staticmethod` — `self` қажет емес әдіс; `@` белгісі декораторды білдіреді.)

## 6. Инкапсуляцияның артықшылығы: ішкі өзгеріс — сыртқы код сол қалпында

Елестет: банк балансты **тиынмен** (бүтін сан) сақтауды шешті. Ішкі құрылым өзгереді, ал интерфейс — жоқ:

```python
class Wallet:
    """Әмиян: ішінде тиынмен сақтайды, сыртқа теңгемен көрсетеді."""

    def __init__(self):
        self.__tiyn = 0

    def add(self, tenge):
        self.__tiyn += round(tenge * 100)

    def get_balance(self):
        return self.__tiyn / 100


w = Wallet()
w.add(0.1)
w.add(0.2)
print(w.get_balance())
print(0.1 + 0.2)
```
Нәтижесі:
```text
0.3
0.30000000000000004
```
`Wallet` класын қолданатын кодтың бірде-бір жолы өзгермеді, ал дәлдік мәселесі шешілді.

## Жиі кездесетін қателер

**1. Класс сыртынан жабық атрибутқа қатынау.**
```text
print(acc.__balance)  →  AttributeError: 'BankAccount' object has no attribute '__balance'
```
Шешімі: геттерді қолдан — `acc.get_balance()`.

**2. Класс сыртынан `obj.__x = ...` жазып, «өзгерттім» деп ойлау.** Бұл ішкі атрибутты емес, жаңа атрибутты құрады (3-бөлімді қара).

**3. Атауды ішінде әртүрлі жазу.**
```python
class Counter:
    def __init__(self):
        self.__value = 0

    def inc(self):
        self.__valeu += 1    # AttributeError: '_Counter__valeu' — қате жазылған атау
```

**4. Ішкі тізімді/сөздікті геттерден тікелей қайтару.** Сыртқы код оны өзгерте алады. Көшірме қайтар: `list(...)`, `dict(...)`.

**5. Сеттерде тексерісті ұмыту** — онда жабық атрибуттың мағынасы жоғалады: `def set_age(self, age): self.__age = age` — бұл ашық атрибуттан еш айырмасы жоқ.

**6. Барлығын жабық ету.** Әр атрибутқа `__` және «бос» геттер-сеттер жазу — кодты ауырлатады. Тек ережесі немесе құпиялығы бар деректерді жасыр.

## Негізгі ұғымдар

| Ұғым | Түсіндірме |
|---|---|
| Инкапсуляция | Деректер мен әдістерді біріктіру және ішкі құрылымды жасыру |
| Ашық интерфейс | Сыртқы кодқа арналған әдістер жиыны |
| Ашық атрибут (public) | `name` — кез келген жерден қатынауға болады |
| Қорғалған атрибут (protected) | `_name` — «ішкі» деген келісім |
| Жабық атрибут (private) | `__name` — атауы бұрмаланатын, тек класс ішіндегі атрибут |
| Name mangling | `__x` атауын `_Класс__x` түріне ауыстыру |
| Геттер | Жабық атрибуттың мәнін қайтаратын әдіс |
| Сеттер | Мәнді тексеріп орнататын әдіс |
| Read-only атрибут | Тек оқуға болатын, сеттері жоқ атрибут |
| Деректердің тұтастығы | Объект күйінің әрқашан дұрыс болуы |

## Ескерту

- PEP 8 ұсынысы: ішкі атрибуттар мен әдістер үшін бір астын сызу (`_name`) жеткілікті. Екі астын сызуды (`__name`) негізінен мұрагерлік кезінде ұрпақ кластардағы атаулар қақтығысының алдын алу үшін қолданады.
- Атаудың соңында да екі астын сызу болса (`__init__`, `__len__`), name mangling қолданылмайды — бұл Python-ның арнайы әдістері, өз атрибуттарыңды бұлай атама.
- `from module import *` модульдегі `_` таңбасымен басталатын атауларды импорттамайды — модуль деңгейінде де `_` «ішкі» дегенді білдіреді.
- Python-да геттер мен сеттер әдістерінің орнына әдетте `@property` декораторы қолданылады: сырттан қарағанда кәдімгі атрибут сияқты, ал ішінде тексеріс жұмыс істейді.
- Парольдерді нақты жүйелерде сақтау үшін жай SHA-256 емес, «тұзы» (salt) бар баяу алгоритмдер қолданылады: `hashlib.scrypt`, `hashlib.pbkdf2_hmac` немесе `bcrypt` кітапханасы. Құжаттама: https://docs.python.org/3/library/hashlib.html.
