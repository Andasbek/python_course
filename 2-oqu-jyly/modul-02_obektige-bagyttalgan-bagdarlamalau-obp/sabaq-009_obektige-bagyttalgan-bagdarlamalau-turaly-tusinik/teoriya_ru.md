## 1. Парадигмы программирования

**Парадигма** — способ написания программ, «стиль мышления».

| Парадигма | Основная идея | Средства Python |
|---|---|---|
| Императивная (последовательная) | команды выполняются одна за другой | присваивание, `input`, `print`, `if`, циклы |
| Процедурная | программа делится на функции (процедуры) | `def`, `return`, модули |
| **Объектно-ориентированная (ООП)** | программа состоит из взаимодействующих **объектов** | `class`, объекты, методы |
| Функциональная | программа — композиция функций | `map`, `filter`, `lambda` |

Python — **мультипарадигменный** язык: в одной программе можно сочетать все подходы.

**Объектно-ориентированное программирование** (ООП, object-oriented programming, OOP) — способ построения программы как совокупности **объектов**; каждый объект хранит свои данные (состояние) и может выполнять свои действия.

Языки, использующие ООП: Python, Java, C#, C++, JavaScript, Kotlin, Swift. Tkinter (окна и кнопки — объекты), Pygame (спрайты — объекты), Pandas (DataFrame — объект) — все построены на основе ООП.

## 2. Что такое объект?

**Объект** — отображение конкретной сущности в программе. Он состоит из двух вещей:

| | Вопрос | В программе | Пример (телефон) |
|---|---|---|---|
| **Состояние (state)** | «Какой он?» | **атрибуты** (переменные) | марка, цвет, уровень заряда, номер |
| **Поведение (behavior)** | «Что он умеет делать?» | **методы** (функции) | звонить, отправлять сообщение, заряжаться |

Ещё примеры:

| Объект | Атрибуты | Методы |
|---|---|---|
| Кот Мурзик | имя, окрас, возраст, сытость | мяукать, спать, есть |
| Автобус №92 | маршрут, число пассажиров, скорость | ехать, остановиться, взять пассажира |
| Банковская карта | владелец, номер, баланс | пополнить, оплатить, показать баланс |
| Игровой персонаж | имя, здоровье, координаты | ходить, прыгать, атаковать |
| Ученик | имя, класс, оценки | получить оценку, вычислить средний балл |

Атрибуты — обычно **существительные** (цвет, баланс), методы — **глаголы** (оплатить, ехать).

## 3. Что такое класс?

**Класс** (class) — **образец (шаблон, чертёж)** для создания однотипных объектов. Класс описывает, какие атрибуты и методы будут у объекта, а **объект** — конкретный **экземпляр** (instance) этого класса.

Аналогии:

| Класс | Объекты |
|---|---|
| Чертёж дома | конкретные дома, построенные по этому чертежу |
| Формочка для печенья | печенья, вырезанные формочкой |
| Пустой бланк анкеты «Ученик» | заполненные анкеты: Алия, Бекзат, ... |
| Модель автомобиля «Toyota Camry» | конкретные машины на улице (разных цветов, с разными номерами) |

```text
            ┌──────────────────────┐
            │   Класс: Cat         │   ← чертёж (пишем один раз)
            │   атрибуты: name,    │
            │   color, age         │
            │   методы: meow(),    │
            │   sleep()            │
            └──────────┬───────────┘
          ┌────────────┼────────────┐
          ▼            ▼            ▼
   ┌────────────┐ ┌────────────┐ ┌────────────┐
   │ Мурзик     │ │ Снежок     │ │ Барсик     │   ← объекты (экземпляры)
   │ серый, 3 г.│ │ белый, 1 г.│ │ чёрный, 5 л│
   └────────────┘ └────────────┘ └────────────┘
```

Важно:
- Из одного класса можно создать **сколько угодно** объектов.
- Атрибуты у всех объектов **одинаковые** (у всех есть `name`), но **значения разные** (Мурзик, Снежок).
- Методы **общие** для всех объектов, но каждый работает со своими данными.

## 4. Класс в Python: первый шаг

Класс объявляется ключевым словом `class`. Имя класса — в **PascalCase** (с заглавной буквы): `Cat`, `BankAccount`, `Student`.

```python
class Cat:
    """Класс, описывающий кошку."""
    pass


murzik = Cat()     # создание объекта (экземпляра) — «вызываем» класс как функцию
snezhok = Cat()

print(murzik)
print(type(murzik))
print(murzik is snezhok)
```
Результат (адреса на разных компьютерах различаются):
```text
<__main__.Cat object at 0x7f3a2c1b9d50>
<class '__main__.Cat'>
False
```
`pass` — пометка «пока пусто». `Cat()` создаёт новый объект; `murzik` и `snezhok` — **два разных** объекта.

### Атрибуты класса
Переменные, объявленные внутри класса, — **атрибуты класса**; они **общие** для всех объектов:

```python
class Cat:
    """Класс, описывающий кошку."""
    species = "домашняя кошка"
    legs = 4


murzik = Cat()
snezhok = Cat()
print(murzik.species, murzik.legs)
print(snezhok.species, snezhok.legs)
print(Cat.legs)
```
Результат:
```text
домашняя кошка 4
домашняя кошка 4
4
```
К атрибуту обращаемся через **точку**: `объект.атрибут`.

### Собственные атрибуты объекта (предварительный просмотр)
У каждой кошки своё имя. Атрибут можно добавить объекту напрямую через точку:

```python
class Cat:
    """Класс, описывающий кошку."""
    legs = 4


murzik = Cat()
murzik.name = "Мурзик"
murzik.color = "серый"

snezhok = Cat()
snezhok.name = "Снежок"
snezhok.color = "белый"

print(murzik.name, murzik.color, murzik.legs)
print(snezhok.name, snezhok.color, snezhok.legs)
```
Результат:
```text
Мурзик серый 4
Снежок белый 4
```

Это работает, но неудобно и опасно: если забыть добавить одному объекту `color`, возникнет `AttributeError`. Поэтому атрибуты задают в **конструкторе `__init__`**, который автоматически создаёт их **в момент создания** объекта.

### Метод (предварительный просмотр)
Метод — функция, объявленная внутри класса. Пример:

```python
class Cat:
    """Класс, описывающий кошку."""

    def meow(self):
        """Кошка мяукает."""
        print("Мяу!")


murzik = Cat()
murzik.meow()
```
Результат:
```text
Мяу!
```

## 5. В Python всё — объект

Даже простейшая программа на Python использует объекты, **сама того не показывая**:

```python
name = "алматы"
grades = [5, 3, 4]

print(type(name), type(grades), type(5), type(print))
print(name.upper())          # метод upper() класса str
grades.append(5)             # метод append() класса list
grades.sort()
print(grades)
print(isinstance(name, str), isinstance(grades, dict))
```
Результат:
```text
<class 'str'> <class 'list'> <class 'int'> <class 'builtin_function_or_method'>
АЛМАТЫ
[3, 4, 5, 5]
True False
```

- `str`, `list`, `dict`, `int` — **встроенные классы** Python.
- `"алматы"` — объект класса `str`; `upper()` — его метод.
- `grades.append(5)` — это **сообщение**: «объект `grades`, добавь к себе 5».
- `isinstance(объект, Класс)` — проверяет, является ли объект экземпляром этого класса.

С помощью `class` можно создавать **собственные классы** — то есть добавлять в Python новые типы.

## 6. Сравнение процедурного подхода и ООП

| | Процедурный | Объектно-ориентированный |
|---|---|---|
| Основная единица | функция | объект (класс) |
| Данные и действия | раздельно | объединены в одном объекте |
| Вызов | `move(player, 3, 0)` | `player.move(3, 0)` |
| Для небольшой программы | просто, быстро | может быть избыточным |
| Для большого проекта | становится беспорядочным | структурированно, легко расширять |
| Моделирование реального мира | сложнее | естественно («предметы» и «действия») |

Пример игрового персонажа в стиле ООП (`__init__` и `self` подробно рассматриваются в следующих темах):
```python
class Player:
    """Игровой персонаж."""

    def __init__(self, name, hp, x, y):
        self.name = name
        self.hp = hp
        self.x = x
        self.y = y

    def move(self, dx, dy):
        """Перемещает персонажа."""
        self.x += dx
        self.y += dy

    def take_damage(self, damage):
        """Уменьшает здоровье."""
        self.hp -= damage


batyr = Player("Батыр", 100, 0, 0)
naiza = Player("Найза", 80, 5, 2)
batyr.move(3, 0)
naiza.take_damage(15)
print(batyr.name, batyr.x, naiza.name, naiza.hp)
```
Результат:
```text
Батыр 3 Найза 65
```
Теперь данные и действия вместе: глядя на класс `Player`, сразу видно, что персонаж знает и что умеет делать.

## 7. Четыре принципа ООП (обзор)

| Принцип | Краткая суть | Пример из жизни |
|---|---|---|
| **Инкапсуляция** | скрывать данные внутри объекта и разрешать изменять их только через методы | банкомат: к счёту нет прямого доступа, только через кнопки |
| **Наследование** | новый класс наследует свойства существующего класса | «Электромобиль» умеет всё, что «Автомобиль», + заряжается |
| **Полиморфизм** | одноимённый метод в разных объектах работает по-разному | «издай звук» — кошка мяукает, собака лает |
| **Абстракция** | оставить только важное, скрыв лишние детали | водителю не нужно знать устройство двигателя — достаточно руля и педалей |

## 8. Проектирование класса: UML-диаграмма классов

Прежде чем писать код, класс **проектируют**. Программисты используют для этого диаграмму классов **UML** (Unified Modeling Language) — прямоугольник из трёх частей:

```text
┌─────────────────────────┐
│        Student          │  ← имя класса
├─────────────────────────┤
│ name: str               │  ← атрибуты
│ grade: int              │
│ marks: list             │
├─────────────────────────┤
│ add_mark(mark)          │  ← методы
│ average() -> float      │
│ print_info()            │
└─────────────────────────┘
```

Алгоритм проектирования класса:
1. Назови сущность (существительное) → имя класса.
2. «Какой он?» → атрибуты (существительные, характеристики).
3. «Что он умеет делать? Что с ним можно делать?» → методы (глаголы).
4. Оставь только то, что **нужно программе** (абстракция!). Школьному журналу цвет глаз ученика не нужен.

## Частые ошибки

**1. Путаница класса и объекта.** «Мурзик — класс» — неверно. `Cat` — класс (образец), Мурзик — объект (экземпляр).

**2. Забыли скобки при создании объекта.**
```python
class Cat:
    legs = 4


wrong = Cat      # это не объект, а ссылка на сам класс!
right = Cat()    # новый объект
print(wrong, right)
```

**3. Имя класса со строчной буквы.** `class cat:` — работает, но по PEP 8 правильно `class Cat:`.

**4. Обращение к несуществующему атрибуту.**
```python
class Cat:
    legs = 4


murzik = Cat()
# print(murzik.name)   # AttributeError: 'Cat' object has no attribute 'name'
murzik.name = "Мурзик"
print(murzik.name)
```

**5. Забыли отступ.** Тело класса (атрибуты, методы) сдвигается на 4 пробела после строки `class`.

**6. Класс для всего подряд.** Чтобы сложить два числа, класс не нужен. ООП — для сущностей, в которых данные и действия тесно связаны.

## Основные понятия

| Понятие | Пояснение |
|---|---|
| Парадигма | Способ написания программ |
| ООП (OOP) | Парадигма построения программы из объектов |
| Класс | Образец (чертёж) для создания объектов |
| Объект (экземпляр) | Конкретная сущность, созданная по классу |
| Атрибут | Свойство (переменная) объекта |
| Метод | Действие объекта (функция внутри класса) |
| Состояние (state) | Текущие значения атрибутов объекта |
| Атрибут класса | Атрибут, общий для всех объектов |
| `isinstance()` | Проверка принадлежности объекта заданному классу |
| UML-диаграмма | Способ проектирования класса в виде схемы |

## Примечание

- В Python 3 все классы неявно наследуются от `object`, поэтому `class Cat:` и `class Cat(object):` равнозначны. Запись с `(object)` встречается в старом коде для Python 2.
- Атрибут класса, хранящий изменяемый объект (например, список), общий для всех экземпляров: `class Cat: toys = []` — добавление игрушки одной кошке «добавит» её всем. Изменяемые данные создают в `__init__`.
- Встроенная функция `dir(obj)` показывает все атрибуты и методы объекта, а `vars(obj)` (или `obj.__dict__`) — только собственные атрибуты экземпляра.
- `type(obj) is Cat` проверяет точное совпадение класса, а `isinstance(obj, Cat)` учитывает и наследников — в большинстве случаев предпочтительнее `isinstance`.
- Официальное руководство по классам: https://docs.python.org/3/tutorial/classes.html.
