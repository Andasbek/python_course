## 1. Портфолио дегеніміз не және GitHub неге маңызды?

**Портфолио** — бағдарламашының өз жұмыстарының жинағы. Университетке түсуде, олимпиадада, жұмысқа орналасуда GitHub профилі — сіздің «электрондық түйіндемеңіз». Әр жоба:
- түсінікті аталған,
- README-мен сипатталған,
- таза құрылымды,
- тарихы (commit-тері) мағыналы болуы керек.

## 2. Жоба репозиторийінің құрылымы

```text
school-journal/
├── README.md            # жоба сипаттамасы
├── .gitignore           # Git қарамайтын файлдар
├── main.py              # бағдарламаның кіру нүктесі
├── models.py            # кластар (Student, ClassJournal ...)
├── data/
│   └── journal.json     # деректер (қажет болса)
└── screenshots/
    └── demo.png         # жұмыс скриншоты
```

Кластарды бөлек файлға шығарсақ, `main.py`-да оларды импорттаймыз:

```python
# main.py
# from models import Student, ClassJournal   # models.py файлы қасында тұрғанда


def main():
    print("Мектеп журналы іске қосылды")


if __name__ == "__main__":
    main()
```

`if __name__ == "__main__":` — файл тікелей іске қосылғанда ғана `main()` орындалады, ал басқа файлға импортталғанда — жоқ.

## 5. Жүктеу командалары

```bash
cd school-journal
git init
git add .
git commit -m "ОБП мини-жоба: Мектеп журналы"
git branch -M main
git remote add origin https://github.com/<логин>/school-journal.git
git push -u origin main
```

Репозиторий бұрыннан бар болса, тек:


## 6. Жобаны жарияламас бұрын тексеру

`git push` алдында репозиторийге дәл керекті нәрсе түсетініне көз жеткізген пайдалы:

```bash
git status            # қандай файлдар өзгерді және commit-ке не кіреді
git diff              # кодта нақты не өзгерді
git log --oneline     # commit-тердің қысқа тарихы
python main.py        # бағдарлама қатесіз іске қосылады
```

Тексеру тізімі:
- `README.md` жобаның мақсатын, мүмкіндіктерін және іске қосу командасын сипаттайды;
- `.gitignore` `__pycache__/`, `venv/`, редактор баптауларын шығарып тастайды;
- кодта құпиясөздер, токендер және жеке деректер жоқ;
- тест коды `if __name__ == "__main__":` ішінде;
- файл, класс және функция атаулары PEP 8-ге сай (`models.py`, `ClassJournal`, `add_grade`).

## 7. ОБП бойынша қысқаша анықтамалық

| Тақырып | Синтаксис | Мәні |
|---|---|---|
| Класс және объект | `class A:`, `a = A()` | Класс — үлгі, объект — оның данасы |
| Конструктор | `def __init__(self, ...)` | Жаңа объектінің атрибуттарын толтырады |
| Атрибуттар | `self.x` / `A.x` | Объект атрибуты / класс атрибуты |
| Инкапсуляция | `_x`, `__x`, `@property` | Деректерді жасыру, әдістер арқылы қол жеткізу |
| Мұрагерлік | `class B(A):` | B класы A-ның атрибуттары мен әдістерін алады |
| Override, `super()` | `def m(self): super().m()` | Ата-класс әдісін ауыстыру немесе кеңейту |
| Полиморфизм | бір шақыру `obj.m()` | Әр класс `m`-ді өзінше орындайды |
| Абстракция | `ABC`, `@abstractmethod` | «Келісім» класс, объектісі құрылмайды |
| Магиялық әдістер | `__str__`, `__repr__`, `__len__`, `__eq__` | `print`, `len`, `==` қолдауы |

Барлық тақырып бір мысалда:

```python
from abc import ABC, abstractmethod


class Person(ABC):                        # абстракті класс
    count = 0                             # класс атрибуты

    def __init__(self, name):             # конструктор
        self.name = name                  # объект атрибуты
        Person.count += 1

    @abstractmethod
    def role(self):                       # абстракті әдіс
        pass

    def __str__(self):                    # магиялық әдіс
        return f"{self.role()} {self.name}"


class Student(Person):                    # мұрагерлік
    def __init__(self, name, grade):
        super().__init__(name)            # ата-класты шақыру
        self._grade = grade               # «қорғалған» атрибут

    @property
    def grade(self):                      # инкапсуляция: тек оқу
        return self._grade

    def role(self):                       # қайта анықтау (override)
        return "Оқушы"


class Teacher(Person):
    def role(self):
        return "Мұғалім"


people = [Student("Ару", 8), Teacher("Сауле")]
for p in people:                          # полиморфизм
    print(p)
print("Құрылған объектілер:", Person.count)
```

Нәтижесі:
```text
Оқушы Ару
Мұғалім Сауле
Құрылған объектілер: 2
```

## Жиі кездесетін қателер

**1. `venv` папкасын немесе `__pycache__`-ті репозиторийге жүктеу** — `.gitignore` файлын push-қа **дейін** жасаңыз. Жүктеліп кетсе:

```bash
git rm -r --cached venv
git commit -m "venv репозиторийден алынды"
git push
```

**2. README жоқ немесе бос** — GitHub-тағы жоба түсініксіз болады.

**3. Бәрі бір commit-те** — «Initial commit» ішінде бүкіл жоба. Жұмыс барысында жиі commit жасаңыз.

**4. Импорт кезінде код орындалып кетеді**

```python
# models.py ішінде:
class Student:
    def __init__(self, name):
        self.name = name

print("Тест:", Student("Ару").name)   # импорттағанда да шығады!
```

Түзетуі: тест кодын `if __name__ == "__main__":` блогына салу.

## Негізгі ұғымдар

| Ұғым | Түсіндірмесі |
|---|---|
| Портфолио | Бағдарламашы жұмыстарының жинағы (GitHub профилі) |
| README.md | Жоба сипаттамасы бар Markdown файлы |
| .gitignore | Git қадағаламайтын файлдар тізімі |
| `if __name__ == "__main__":` | Файл тікелей іске қосылғанда ғана орындалатын блок |
| `git status` | Өзгерген және commit-ке дайындалған файлдарды көрсетеді |

## Ескерту

- `.gitignore` репозиторийге **бұрыннан** қосылған файлдарға әсер етпейді: оларды алдымен `git rm --cached` командасымен индекстен алып тастайды.
- GitHub HTTPS арқылы `git push` жасағанда кәдімгі құпиясөзді қабылдамайды — personal access token немесе SSH-кілт керек.
- Жобаның сыртқы кітапханалары `requirements.txt` файлында тізіледі (`pip freeze > requirements.txt`), орнату: `pip install -r requirements.txt`.
- Python жобаларына арналған дайын үлгі: https://github.com/github/gitignore репозиторийіндегі `Python.gitignore` файлы.
- README-де код блоктары тілі көрсетілген үш кері тырнақшамен (```` ```python ````) рәсімделеді — GitHub синтаксисті бояп көрсетеді.
- Іске қосу командасы жүйеге байланысты: Windows-та әдетте `python main.py` немесе `py main.py`, Linux/macOS-та — `python3 main.py`.
