## 1. Экосистема Python: технологии второго года

Python — язык общего назначения: на нём пишут консольные утилиты, программы с окнами, игры, веб-сервисы, скрипты для анализа данных. Сила Python — в огромном количестве **библиотек** (готовых модулей). Часть из них входит в **стандартную библиотеку** (устанавливается вместе с Python), остальные ставятся через менеджер пакетов `pip`.

| Направление | Инструменты и библиотеки | Что можно создать |
|---|---|---|
| Инструменты разработчика | VS Code, venv, pip, Git, GitHub, PEP 8 | Аккуратно оформленный проект с историей версий |
| Объектно-ориентированное программирование | `class`, объекты, методы, наследование | Модель «Библиотека», «Школьный журнал» |
| Графический интерфейс | `tkinter` (стандартная библиотека) | Калькулятор, список дел (To-Do List) |
| Компьютерные игры | `pygame` (через pip) | 2D-игра со спрайтами, звуком и меню |
| Работа с данными | `csv`, `json`, `sqlite3` (стандартная библиотека), SQL | База учащихся, хранение настроек |
| Интернет | `requests`, `BeautifulSoup`, HTTP, API | Приложение «Погода», сбор данных с сайтов |
| Анализ данных | `numpy`, `pandas`, `matplotlib` | Таблицы, статистика, графики |
| Качество кода | отладчик, `logging`, `unittest`, README | Протестированная и задокументированная программа |

Пример: модуль стандартной библиотеки подключается сразу, сторонний — только после установки.

```python
import json      # стандартная библиотека — работает сразу
import random    # тоже стандартная

data = {"name": "Айгерим", "score": random.randint(1, 10)}
print(json.dumps(data, ensure_ascii=False))
# import pygame  # сторонняя библиотека: сначала  pip install pygame
```

## 2. Как устроена программа на Python

Программа на Python — это текстовый файл с расширением `.py`. Его выполняет **интерпретатор**: читает строки сверху вниз и сразу их исполняет. Запуск из терминала:

```text
python main.py      (Windows)
python3 main.py     (Linux / macOS)
```

Почти любая программа следует схеме **ввод → обработка → вывод**:

```text
Ввод (input, файл, сеть) → Обработка (вычисления, условия, циклы) → Вывод (print, файл, окно)
```

По мере роста программа делится на части: **функции** (именованные блоки кода), **классы** (данные + поведение), **модули** (отдельные `.py`-файлы). Точку входа принято оформлять так:

```python
def main():
    """Главная функция программы."""
    print("Программа запущена")


if __name__ == "__main__":
    main()
```

Условие `if __name__ == "__main__":` истинно, только когда файл запущен напрямую, а не импортирован из другого модуля. Это позволяет использовать функции файла повторно, не запуская лишний код.

## 3. Жизненный цикл программного проекта

Любой проект (и маленький, и большой) проходит один и тот же цикл:

```text
Идея → Требования (ТЗ) → Проектирование → Разработка → Тестирование → Документирование → Защита
  ↑                                                                                         |
  └────────────────────────── получение отзывов и доработка ──────────────────────────────┘
```

- **Идея** — какую проблему решаем? Кому это нужно?
- **Техническое задание (ТЗ)** — что должна делать программа (список требований).
- **Проектирование** — из каких частей (функций, классов, файлов) она состоит.
- **Разработка** — написание кода, сохранение версий с помощью Git.
- **Тестирование** — поиск и исправление ошибок.
- **Документирование** — README, инструкция по запуску.
- **Защита** — презентация проекта.

В командных проектах распределяются роли: программист, дизайнер, звукорежиссёр, тестировщик, автор документации. Готовые проекты публикуются на **GitHub** и образуют **портфолио** программиста.

## 4. Пример: программа «Моя визитка»

Простейший вариант — только `input`, `int` и `print`:

```python
name = input("Как тебя зовут? ")
age = int(input("Сколько тебе лет? "))
hobby = input("Твоё хобби? ")

print("=" * 30)
print("Имя:", name)
print("Возраст:", age)
print("Хобби:", hobby)
print("В следующем году тебе будет", age + 1, "лет!")
print("=" * 30)
```

Результат:
```text
Как тебя зовут? Айгерим
Сколько тебе лет? 13
Твоё хобби? шахматы
==============================
Имя: Айгерим
Возраст: 13
Хобби: шахматы
В следующем году тебе будет 14 лет!
==============================
```

Тот же результат можно получить с помощью функции, словаря, генератора списка и f-строк — код становится универсальным: визитка подстраивается под любое количество полей и их длину.

```python
def make_card(person):
    """Возвращает визитку учащегося в виде строки."""
    lines = [f"{key}: {value}" for key, value in person.items()]
    width = max(len(line) for line in lines) + 4
    border = "*" * width
    body = "\n".join(f"* {line.ljust(width - 4)} *" for line in lines)
    return f"{border}\n{body}\n{border}"


student = {"Имя": "Ерлан", "Класс": "8 «Б»", "Мечта": "создавать игры"}
print(make_card(student))
```

Результат:
```text
*************************
* Имя: Ерлан            *
* Класс: 8 «Б»          *
* Мечта: создавать игры *
*************************
```

Здесь `str.ljust(n)` дополняет строку пробелами справа до длины `n`, а `"\n".join(...)` склеивает строки через перевод строки.

## 5. Безопасность кода и цифровая этика

- Не храни в коде и не загружай на GitHub пароли, токены, API-ключи и личные данные. Секреты выносят в отдельный файл (например, `.env`) и добавляют его в `.gitignore`.
- Не запускай незнакомые скрипты и не устанавливай пакеты с подозрительными именами: через `pip` можно установить вредоносный код (так называемый *typosquatting* — `reqeusts` вместо `requests`).
- Используя чужой код, указывай источник и соблюдай его **лицензию** (MIT, GPL и т.д.).
- Регулярно сохраняй работу и делай коммиты в Git — так ничего не потеряется.

## Частые ошибки

**1. Забыли `int()` при вводе числа.**
```python
age = input("Сколько тебе лет? ")
# print(age + 1)  # TypeError: can only concatenate str (not "int") to str
```
Пояснение: `input()` всегда возвращает строку (str). Правильный вариант:
```python
age = int(input("Сколько тебе лет? "))
print(age + 1)
```

**2. Забыли закрыть кавычки.**
```text
print("Привет)   →  SyntaxError: unterminated string literal
```
Правильно: `print("Привет")`.

**3. Файл назван как модуль стандартной библиотеки.** Если назвать свой файл `random.py` или `json.py`, то `import random` загрузит твой файл вместо стандартного модуля, и появится ошибка вида `AttributeError: module 'random' has no attribute 'randint'`. Давай файлам уникальные имена.

## Основные понятия

| Понятие | Пояснение |
|---|---|
| Интерпретатор | Программа, которая читает и выполняет код Python строка за строкой |
| Стандартная библиотека | Набор модулей, устанавливаемых вместе с Python (`json`, `random`, `tkinter`, `sqlite3`…) |
| Сторонний пакет | Библиотека, которую устанавливают через `pip` (`pygame`, `requests`, `pandas`…) |
| Модуль | Отдельный файл `.py`, который можно импортировать |
| Техническое задание (ТЗ) | Список требований к программе |
| Портфолио | Собрание проектов программиста (обычно на GitHub) |
| Лицензия | Условия, на которых разрешено использовать чужой код |

## Примечание

- Проверить версию Python можно командой `python --version`; в курсе используется Python 3.10 и новее (например, оператор `match` появился только в 3.10).
- Python 2 официально не поддерживается с 2020 года — примеры с `print "text"` без скобок из старых статей не заработают.
- Официальная документация и учебник: https://docs.python.org/3/ (раздел Tutorial) и список модулей стандартной библиотеки https://docs.python.org/3/library/.
- По PEP 8 имена файлов и модулей пишут строчными буквами через подчёркивание: `my_card.py`, а не `My Card.py` — пробелы в именах мешают импорту.
- `input()` всегда возвращает `str`; если пользователь введёт не число, `int()` вызовет `ValueError` — это стоит учитывать в реальных программах.
