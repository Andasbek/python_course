## 1. Что такое GitHub?

**GitHub** — платформа для хранения репозиториев Git в интернете, обмена ими и совместной разработки. На ней более 100 миллионов программистов; сам язык Python, а также такие проекты, как VS Code, pygame, pandas, разрабатываются на GitHub.

Похожие сервисы: GitLab, Bitbucket — принцип работы тот же.

| Понятие | Пояснение |
|---|---|
| Локальный репозиторий (local) | `.git` на твоём компьютере |
| Удалённый репозиторий (remote) | Копия на сервере GitHub |
| `origin` | Имя удалённого репозитория по умолчанию |
| Public | Видят все (для портфолио) |
| Private | Видишь только ты и приглашённые |

Аналогия: локальный репозиторий — фотоальбом в телефоне, GitHub — альбом в облаке. `push` — загрузить фото в облако, `pull` — получить новые фото из облака на телефон, `clone` — скопировать весь альбом на новый телефон.

```text
   Твой компьютер                            GitHub (origin)
 ┌───────────────────┐      git push       ┌───────────────────┐
 │ локальный         │ ──────────────────► │ удалённый         │
 │ репозиторий       │                     │ репозиторий       │
 │                   │ ◄────────────────── │                   │
 └───────────────────┘   git pull / clone  └───────────────────┘
```

## 2. Аккаунт и безопасность

1. github.com → **Sign up**: почта, пароль, имя пользователя (username).
2. Имя пользователя — адрес твоего портфолио: `https://github.com/aigerim-dev`. Выбери профессиональное, понятное имя (а не `super_killer_2013`).
3. Пароль — сложный, никому не сообщай его; включи **двухфакторную аутентификацию** (2FA).
4. Скрой личную почту: Settings → Emails → «Keep my email addresses private». Тогда GitHub выдаст почту вида `12345678+aigerim-dev@users.noreply.github.com` — её мы и укажем в Git:

```bash
git config --global user.email "12345678+aigerim-dev@users.noreply.github.com"
```

**Никогда не загружай в публичный репозиторий:** пароли, API-ключи, домашний адрес, телефон, фотографии личных документов.

## 3. Создание репозитория на GitHub

1. **+** в правом верхнем углу → **New repository**.
2. **Repository name**: `calculator` (строчные буквы, без пробелов, слова через дефис: `todo-app`).
3. **Description**: «Консольный калькулятор на Python».
4. **Public**.
5. Если локальный репозиторий уже существует — **не добавляй** README, .gitignore, license (создай пустой репозиторий), иначе истории будут конфликтовать.
6. **Create repository**.

GitHub покажет инструкцию по связыванию репозитория — её команды приведены ниже.

## 4. Связывание локального репозитория с GitHub

```bash
cd calculator
git remote add origin https://github.com/aigerim-dev/calculator.git
git remote -v
git branch -M main
git push -u origin main
```

| Команда | Значение |
|---|---|
| `git remote add origin URL` | Зарегистрировать удалённый репозиторий под именем `origin` |
| `git remote -v` | Посмотреть зарегистрированные remote |
| `git branch -M main` | Закрепить имя ветки `main` |
| `git push -u origin main` | Отправить коммиты; `-u` — запомнить связь |

Результат:
```text
Enumerating objects: 15, done.
Counting objects: 100% (15/15), done.
Writing objects: 100% (15/15), 1.85 KiB | 1.85 MiB/s, done.
To https://github.com/aigerim-dev/calculator.git
 * [new branch]      main -> main
branch 'main' set up to track 'origin/main'.
```

При первом `push` в браузере откроется окно входа в GitHub (Git Credential Manager). С 2021 года GitHub не принимает обычный пароль в терминале: используется вход через браузер или **персональный токен доступа** (Personal Access Token). Токен так же секретен, как пароль, не записывай его в код или репозиторий.

В следующие разы всё просто:
```bash
git add .
git commit -m "Добавлена операция возведения в степень"
git push
```

Если обновить страницу GitHub — будут видны файлы, количество коммитов, сообщение последнего коммита. В разделе **Commits** — вся история, diff каждого коммита.

## 5. git pull — получение изменений

Репозиторий может изменяться в двух местах: например, на двух разных компьютерах или когда два человека работают над одним проектом. Чтобы получить новые коммиты с GitHub в локальный репозиторий:

```bash
git pull
```
Результат:
```text
remote: Enumerating objects: 5, done.
Updating 9c41e02..b7d3a10
Fast-forward
 README.md | 4 ++++
 1 file changed, 4 insertions(+)
```

**Золотое правило:** перед началом работы — `git pull`, после окончания — `git push`.

Если `push` отклонён:
```text
! [rejected]        main -> main (fetch first)
error: failed to push some refs to 'https://github.com/aigerim-dev/calculator.git'
hint: Updates were rejected because the remote contains work that you do not have locally.
```
Причина — на GitHub есть коммиты, которых у тебя нет. Решение: сначала `git pull`, потом `git push`. (Если одна и та же строка изменена в двух местах, возникнет **конфликт** (conflict) — его разрешают вручную, выбирая правильный вариант между метками `<<<<<<<`, `=======`, `>>>>>>>` в файле, затем выполняют `git add` и `git commit`.)

## 6. git clone — копирование репозитория

Скачать проект на другой компьютер (или чужой проект):
```bash
git clone https://github.com/aigerim-dev/calculator.git
cd calculator
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```
`clone` копирует всю историю и автоматически настраивает `origin`.

| Команда | Когда |
|---|---|
| `git clone URL` | Первое скачивание проекта (один раз) |
| `git pull` | Обновление существующего проекта (часто) |
| `git push` | Отправка своих изменений (часто) |

## 7. Markdown и README.md

**README.md** — «обложка» репозитория: GitHub показывает его на главной странице проекта. Он пишется на **Markdown** — простом языке разметки.

| Markdown | Результат |
|---|---|
| `# Заголовок` | Большой заголовок |
| `## Подзаголовок` | Заголовок поменьше |
| `**жирный**` | **жирный** |
| `*курсив*` | *курсив* |
| `- пункт` | маркированный список |
| `1. пункт` | нумерованный список |
| `` `код` `` | `код` |
| `[текст](https://...)` | ссылка |
| `![картинка](screenshot.png)` | изображение |
| ` ```python ... ``` ` | блок кода |

Образец README:
````text
# Калькулятор

Консольный калькулятор на Python: операции +, -, *, /, **.

## Возможности
- 5 арифметических операций
- проверка деления на ноль
- работает в цикле, 0 — выход

## Запуск
```bash
python calc.py
```

## Скриншот
![Пример работы](screenshot.png)

## Автор
Айгерим Н., кружок «Python», 2026
````

## 8. Портфолио

**Портфолио** — витрина твоих работ. На GitHub оно состоит из двух частей:

1. **Профильный README** — специальный репозиторий, название которого **совпадает** с именем пользователя (`aigerim-dev/aigerim-dev`). Его файл README.md показывается вверху страницы профиля.
2. **Репозитории проектов** — каждый проект модуля в отдельном репозитории: `calculator`, `library-oop`, `todo-tkinter`, `space-game`, `students-db`, `weather-app`, `data-analysis`, `final-project`.

Образец профильного README:
```text
# Привет! Я — Айгерим 👋

Учусь на 2-м году в кружке «Python» в Алматы.

## Что я изучаю
- Python, ООП, Git
- Следующая цель: Tkinter и Pygame

## Мои проекты
| Проект | Описание | Технологии |
|---|---|---|
| [calculator](https://github.com/aigerim-dev/calculator) | Консольный калькулятор | Python |

## Связь
Пишите issue через GitHub.
```

Правила портфолио:
- в каждом проекте README и скриншот;
- осмысленные коммиты (история — это твой стиль работы);
- понятное название проекта, на английском строчными буквами;
- **никаких личных данных** (номер школы, телефон, адрес);
- в репозитории нет `.venv`, `__pycache__` (`.gitignore`).

## Частые ошибки

**1. Создали на GitHub репозиторий с README, а затем делают push локальной истории.**
```text
! [rejected] main -> main (fetch first)
```
Решение: создай пустой репозиторий или `git pull origin main --allow-unrelated-histories`; последний способ применяй осторожно.

**2. `remote origin already exists`.** origin уже зарегистрирован. Проверь: `git remote -v`; изменить: `git remote set-url origin ПРАВИЛЬНЫЙ_URL`.

**3. Ввод обычного пароля в терминале.** `Authentication failed` — войди через браузер или используй токен.

**4. Неправильно скопированный URL** (`github.com/aigerim-dev` — ссылка на профиль, а не на репозиторий). Правильно: `https://github.com/aigerim-dev/calculator.git`.

**5. Push без коммита.** `Everything up-to-date` — нет новых коммитов для отправки. Сначала `add` + `commit`.

**6. Загрузка секретной информации.** Даже если потом удалить файл, он **останется в истории**! Поэтому заранее `.gitignore` и внимательная проверка. Если пароль всё-таки попал в репозиторий — сразу смени его.

## Основные понятия

| Понятие | Пояснение |
|---|---|
| GitHub | Платформа для хранения репозиториев Git в облаке и совместной работы |
| Remote / origin | Удалённый репозиторий / его имя по умолчанию |
| push | Отправка локальных коммитов на GitHub |

## Примечание

- С 2020 года GitHub называет основную ветку новых репозиториев `main`, а не `master`. В старых инструкциях встречается `git push origin master`.
- `git pull` — это сочетание команд `git fetch` (скачать новые коммиты) и `git merge` (слить их). Чтобы только посмотреть изменения без слияния, используют `git fetch`, затем `git log origin/main`.
- Вместо HTTPS можно подключаться по SSH-ключам (`git@github.com:user/repo.git`); тогда вход при каждом `push` не нужен.
- GitHub отображает README по правилам GitHub Flavored Markdown: поддерживаются таблицы, списки задач (`- [ ]`) и подсветка кода по языку (```python).
- Официальная документация: https://docs.github.com/ и краткое руководство по Markdown: https://docs.github.com/en/get-started/writing-on-github.
