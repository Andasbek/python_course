## 1. Что такое среда разработки?

| Понятие | Пояснение | Пример |
|---|---|---|
| Интерпретатор | Программа, выполняющая код Python построчно | `python.exe`, `python3` |
| Редактор кода | Программа для написания текста (кода) | Notepad++, Sublime Text |
| IDE (integrated development environment, интегрированная среда разработки) | Редактор + запуск + отладчик + терминал + Git в одном месте | PyCharm, VS Code (с расширениями), Thonny |
| Терминал (консоль, командная строка) | Окно для управления компьютером текстовыми командами | PowerShell, cmd, bash |

Аналогия: интерпретатор — двигатель, редактор — руль, IDE — полностью оборудованная кабина автомобиля (руль, спидометр, навигатор, зеркала).

**Почему VS Code?** Бесплатный, лёгкий, работает в Windows/macOS/Linux, поддерживает Python, Git, Markdown, HTML, один из самых популярных редакторов в мире. PyCharm Community — мощная IDE специально для Python, её тоже можно использовать.

## 2. Знакомство с VS Code

### Установка и начальная настройка
1. Скачать и установить с сайта code.visualstudio.com (в Windows поставить галочку «Add to PATH»).
2. В разделе расширений (Extensions, `Ctrl+Shift+X`) установить расширение **Python** (Microsoft) — оно также добавит расширения Pylance (анализ кода) и Python Debugger.
3. При необходимости — язык интерфейса (Language Pack), тема (Theme).

### Части интерфейса
```text
┌───┬──────────────┬──────────────────────────────┐
│ А │  Explorer    │  Редактор (main.py)          │
│ к │  (файлы)     │                              │
│ т │              │                              │
│ и │              ├──────────────────────────────┤
│ в │              │  Терминал / Output / Problems│
└───┴──────────────┴──────────────────────────────┘
             Строка состояния (версия Python, venv)
```
- **Activity Bar** (значки на левом краю): Explorer, Search, Source Control (Git), Run and Debug, Extensions.
- **Explorer** — файлы папки проекта.
- **Редактор** — область написания кода, можно открыть несколько файлов рядом.
- **Панель** — терминал (`` Ctrl+` ``), ошибки (Problems), вывод (Output).
- **Строка состояния** — показывает выбранный интерпретатор Python.

### Важное правило: открывай не файл, а **папку**
Открываем папку проекта через File → Open Folder... Тогда VS Code видит весь проект, а терминал открывается в этой папке.

### Полезные сочетания клавиш

| Клавиши | Действие |
|---|---|
| `Ctrl+Shift+P` | Палитра команд (поиск любой команды) |
| `Ctrl+P` | Быстро открыть файл по имени |
| `` Ctrl+` `` | Открыть/закрыть терминал |
| `F5` | Запуск с отладкой |
| `Ctrl+/` | Превратить строку в комментарий |
| `Alt+↑ / Alt+↓` | Переместить строку вверх/вниз |
| `Shift+Alt+F` | Автоматическое форматирование кода |
| `F2` | Переименовать переменную везде |
| `Ctrl+D` | Выделить следующее такое же слово (мультикурсор) |

### Запуск программы
- Кнопка ▷ (Run Python File) в правом верхнем углу;
- или в терминале: `python main.py` (в macOS/Linux — `python3 main.py`).

### Отладчик (debugger) — профессиональный инструмент поиска ошибок
1. Щёлкни слева от номера строки, чтобы поставить **точку останова** (breakpoint, красная точка).
2. `F5` → Python File.
3. Программа остановится на этой строке; слева будут видны **текущие значения** переменных.
4. `F10` — следующая строка (Step Over), `F11` — войти внутрь функции (Step Into), `F5` — продолжить.

```python
def factorial(n):
    result = 1
    for i in range(1, n + 1):
        result *= i      # поставь breakpoint на эту строку и следи за изменением result
    return result


print(factorial(5))
```
Результат:
```text
120
```

## 4. Виртуальное окружение (venv)

### Проблема
Представь: твоему проекту 1 нужна версия `pygame` 2.5, а проект друга работает только на версии 2.1. Если все пакеты устанавливаются на компьютер **общими**, возникает конфликт версий. Кроме того, при переносе проекта на другой компьютер неизвестно, какие пакеты нужны.

### Решение
**Виртуальное окружение** (virtual environment) — отдельная изолированная «комната» Python внутри проекта: со своими пакетами и версиями. Аналогия: личный пенал каждого ученика — ручка одного не попадает в пенал другого.

```text
my_game/
├── .venv/            ← виртуальное окружение (в Git не загружается)
│   ├── Scripts/      (Windows) или bin/ (macOS/Linux)
│   └── Lib/site-packages/   ← пакеты этого проекта
├── main.py
└── requirements.txt  ← список необходимых пакетов
```

### Создание и активация
```bash
# 1. Перейти в папку проекта
cd my_game

# 2. Создать виртуальное окружение (.venv — имя папки)
python -m venv .venv          # Windows
python3 -m venv .venv         # macOS / Linux

# 3. Активировать
.venv\Scripts\activate        # Windows (cmd / PowerShell)
source .venv/bin/activate     # macOS / Linux

# 4. Деактивировать
deactivate
```

После активации в начале строки терминала появляется надпись `(.venv)`:
```text
(.venv) C:\Users\Aigerim\my_game>
```

Если в Windows PowerShell появляется ошибка «running scripts is disabled», достаточно один раз выполнить команду:
```bash
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

**Выбор интерпретатора в VS Code:** `Ctrl+Shift+P` → «Python: Select Interpreter» → Python внутри `.venv`. После этого терминал VS Code будет активировать окружение автоматически.

Проверка из Python, в каком окружении ты работаешь:
```python
import sys

print(sys.executable)      # какой интерпретатор работает
print(sys.prefix != sys.base_prefix)   # если True — мы в виртуальном окружении
```

## 5. pip — менеджер пакетов

**Пакет** (библиотека) — набор готовых модулей, написанных другими программистами. Они хранятся в **PyPI** (pypi.org, Python Package Index) — официальном «магазине» пакетов Python (более 500 тысяч пакетов). **pip** — инструмент, который скачивает и устанавливает пакеты из этого магазина. Аналогия: App Store / Play Market в смартфоне.

| Команда | Значение |
|---|---|
| `pip install requests` | Установить пакет |
| `pip install pygame==2.5.2` | Установить конкретную версию |
| `pip install --upgrade requests` | Обновить |
| `pip uninstall requests` | Удалить |
| `pip list` | Список установленных пакетов |
| `pip show requests` | Сведения о пакете |
| `pip freeze > requirements.txt` | Записать зависимости в файл |
| `pip install -r requirements.txt` | Установить все пакеты из файла |

Подсказка: надёжнее писать в форме `python -m pip install ...` — пакет установится именно в текущий Python.

### requirements.txt
«Список покупок» проекта: какие пакеты и каких версий нужны.

```text
colorama==0.4.6
requests==2.32.3
```

Когда друг скачает твой проект, ему достаточно нескольких команд:
```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

### Пример: первый сторонний пакет — colorama
```bash
pip install colorama
```
```python
from colorama import Fore, Style, init

init()  # включение цветов в терминале Windows
print(Fore.GREEN + "Успешно установлено!" + Style.RESET_ALL)
print(Fore.RED + "Пример ошибки" + Style.RESET_ALL)
print(Fore.YELLOW + "Предупреждение" + Style.RESET_ALL)
```
Результат (в терминале — разными цветами):
```text
Успешно установлено!
Пример ошибки
Предупреждение
```

Если пакет не установлен:
```text
ModuleNotFoundError: No module named 'colorama'
```
Это сигнал «пакета нет в этом окружении»: проверь, что venv активирован и в VS Code выбран правильный интерпретатор.

### Безопасность пакетов
- Устанавливай только известные пакеты с документацией (проверяй название на pypi.org).
- Бывают поддельные пакеты с похожими названиями (с опечатками вроде `reqeusts`) — будь внимателен.
- Перед установкой проверь на pypi.org автора пакета, число загрузок и дату последнего обновления.

## 6. Образец структуры проекта

```text
project_name/
├── .venv/              # виртуальное окружение
├── .gitignore          # файлы, которые Git игнорирует (.venv/, __pycache__/)
├── README.md           # описание проекта
├── requirements.txt    # зависимости
├── main.py             # точка входа
└── utils.py            # вспомогательные функции
```

Алгоритм работы (для каждого нового проекта):
1. Создай папку → в VS Code **Open Folder**.
2. `python -m venv .venv` → выбери интерпретатор.
3. Нужные пакеты `pip install` → `pip freeze > requirements.txt`.
4. Напиши `main.py` → запусти.
5. `git init` — начни сохранять версии с помощью Git.

## Частые ошибки

**1. Команда `python` не найдена.**
```text
'python' is not recognized as an internal or external command
```
Причина: при установке Python не была отмечена галочка «Add Python to PATH». Решение: переустановить Python (с галочкой) или использовать в Windows команду `py`.

**2. Пакет установил, но `ModuleNotFoundError`.**
Причина: пакет установлен в один интерпретатор, а VS Code использует другой. Решение: «Python: Select Interpreter» → `.venv`; `python -m pip install ...`.

**3. Имя стандартного модуля в качестве имени файла.**
```text
random.py  ← если назвать так свой файл, import random импортирует твой файл
```
Решение: не называй файлы `random.py`, `turtle.py`, `pygame.py`.

**4. Ручное изменение папки `.venv` или копирование её на другой компьютер.**
Виртуальное окружение не предназначено для копирования. Вместо этого создай новое окружение по `requirements.txt`.

**5. `pip install` без активации venv** — пакет установится в общую систему.

## Основные понятия

| Понятие | Пояснение |
|---|---|
| IDE | Среда, объединяющая инструменты написания кода, запуска, отладки, Git |
| VS Code | Бесплатный редактор кода от Microsoft с расширениями |
| Расширение (extension) | Модуль, добавляющий в VS Code новую возможность |
| Терминал | Окно управления с помощью команд |
| Отладчик (debugger) | Инструмент пошагового выполнения программы и наблюдения за переменными |
| Breakpoint | Точка, в которой программа останавливается |
| Виртуальное окружение (venv) | Изолированная среда Python для проекта |
| Пакет (библиотека) | Набор готовых модулей |
| PyPI | Официальный репозиторий пакетов Python |
| pip | Менеджер для установки пакетов |
| requirements.txt | Список зависимостей проекта |

## Примечание

- Модуль `venv` входит в стандартную библиотеку начиная с Python 3.3, отдельно устанавливать его не нужно. В некоторых дистрибутивах Linux может понадобиться дополнительно установить пакет `python3-venv`.
- Чтобы папка `.venv` не попала в Git, добавь строку `.venv/` в файл `.gitignore`; окружение всегда можно пересоздать по `requirements.txt`.
- `pip freeze` записывает все пакеты окружения, включая косвенные зависимости. Поэтому перед созданием `requirements.txt` убедись, что в окружении нет лишних пакетов.
- В новых версиях Linux и macOS установка через `pip install` в системный Python может блокироваться ошибкой `externally-managed-environment` (PEP 668) — ещё одна причина работать в виртуальном окружении.
- Официальная документация: https://docs.python.org/3/library/venv.html и https://pip.pypa.io/.
