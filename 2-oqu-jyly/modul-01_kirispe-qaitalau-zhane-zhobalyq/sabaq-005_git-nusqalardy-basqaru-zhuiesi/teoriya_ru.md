## 1. Система контроля версий (VCS)

**Система контроля версий** (version control system, VCS) — система, которая хранит историю всех изменений в файлах и позволяет вернуться к любой прежней версии.

Аналогия: **точки сохранения** (save points) в компьютерной игре. Перед трудным уровнем ты сохраняешь игру — если проиграешь, начнёшь с этого места. В Git такая точка сохранения называется **коммитом** (commit).

Что даёт VCS:
- историю каждого изменения: **кто**, **когда**, **что** изменил и **почему**;
- возврат к любой версии;
- параллельную работу команды над одним проектом;
- резервную копию кода (например, на GitHub).

**Git** — самая популярная VCS в мире. Её создал в 2005 году Линус Торвальдс, автор ядра Linux. Git — **распределённая** система: на каждом компьютере хранится полная история проекта.

Git и GitHub — разные вещи:
| Git | GitHub |
|---|---|
| Программа на компьютере | Сайт (сервис) в интернете |
| Хранит версии локально | Хранит репозитории в облаке, позволяет делиться ими |
| Работает без интернета | Нужен интернет |

## 2. Однократная настройка Git

Проверь, что Git установлен:
```bash
git --version
```
Результат:
```text
git version 2.46.0.windows.1
```

К каждому коммиту записывается автор, поэтому один раз укажи своё имя и почту:
```bash
git config --global user.name "Aigerim Nurlanqyzy"
git config --global user.email "aigerim@example.com"
git config --global init.defaultBranch main
git config --global core.editor "code --wait"
git config --list
```
Внимание: в будущем эта почта будет публично видна на GitHub. Чтобы скрыть её, можно использовать служебную почту, которую предоставляет GitHub (`...@users.noreply.github.com`).

## 3. Три зоны Git

```text
 Рабочий каталог          Индекс                  Репозиторий
 (working directory)      (staging area)          (папка .git)
 ┌──────────────┐  git add  ┌──────────────┐ git commit ┌──────────────┐
 │ ты изменяешь │ ────────► │ подготовлено │ ─────────► │ история      │
 │ файлы        │           │ к следующему │            │ сохранённых  │
 │              │           │ коммиту      │            │ версий       │
 └──────────────┘           └──────────────┘            └──────────────┘
```

Аналогия — **фотосъёмка**:
- рабочий каталог — люди в комнате (могут двигаться в любой момент);
- `git add` — собрать в кадр тех, кто будет фотографироваться;
- `git commit` — нажать кнопку фотоаппарата, фото попадает в альбом;
- `git log` — листать фотоальбом.

Состояния файла:

| Состояние | Значение | Что показывает `git status` |
|---|---|---|
| Untracked | Новый файл, который Git не отслеживает | красным, «Untracked files» |
| Modified | Изменён, но не добавлен в индекс | красным, «modified» |
| Staged | Добавлен в индекс, готов к коммиту | зелёным, «Changes to be committed» |
| Committed | Сохранён в репозитории | «nothing to commit, working tree clean» |

## 4. Основные команды

### git init — создание репозитория
```bash
mkdir calculator
cd calculator
git init
```
Результат:
```text
Initialized empty Git repository in C:/Users/Aigerim/calculator/.git/
```
В папке появляется скрытая папка `.git` — в ней хранится вся история. Не изменяй и не удаляй её вручную!

### git status — текущее состояние
Самая часто используемая команда — «что сейчас происходит?». Если сомневаешься — `git status`.

Создадим файл `calc.py`:
```python
def add(a, b):
    """Возвращает сумму двух чисел."""
    return a + b


print(add(2, 3))
```

```bash
git status
```
Результат:
```text
On branch main

No commits yet

Untracked files:
  (use "git add <file>..." to include in what will be committed)
        calc.py

nothing added to commit but untracked files present (use "git add" to track)
```

### git add — добавление в индекс
```bash
git add calc.py      # один файл
git add .            # все изменения в текущей папке
git status
```
Результат:
```text
On branch main

No commits yet

Changes to be committed:
  (use "git rm --cached <file>..." to unstage)
        new file:   calc.py
```

### git commit — сохранение версии
```bash
git commit -m "Создан калькулятор с функцией сложения"
```
Результат:
```text
[main (root-commit) 3f2a1b7] Создан калькулятор с функцией сложения
 1 file changed, 6 insertions(+)
 create mode 100644 calc.py
```
`3f2a1b7` — уникальный идентификатор коммита (хеш, краткая форма).

Теперь изменим файл — добавим функцию вычитания:
```python
def add(a, b):
    """Возвращает сумму двух чисел."""
    return a + b


def sub(a, b):
    """Возвращает разность двух чисел."""
    return a - b


print(add(2, 3), sub(10, 4))
```

### git diff — что изменилось?
```bash
git diff
```
Результат (сокращённо):
```text
@@ -3,4 +3,9 @@ def add(a, b):
     return a + b
 
 
-print(add(2, 3))
+def sub(a, b):
+    """Возвращает разность двух чисел."""
+    return a - b
+
+
+print(add(2, 3), sub(10, 4))
```
`-` — удалённая строка, `+` — добавленная строка. `git diff --staged` показывает изменения в индексе.

```bash
git add calc.py
git commit -m "Добавлена функция вычитания"
```

### git log — история
```bash
git log
```
Результат:
```text
commit 9c41e02d7a... (HEAD -> main)
Author: Aigerim Nurlanqyzy <aigerim@example.com>
Date:   Thu Sep 10 15:42:10 2026 +0500

    Добавлена функция вычитания

commit 3f2a1b7c55...
Author: Aigerim Nurlanqyzy <aigerim@example.com>
Date:   Thu Sep 10 15:30:02 2026 +0500

    Создан калькулятор с функцией сложения
```

Компактные варианты:
```bash
git log --oneline
git log --oneline --graph --all
git log -3          # последние 3 коммита
```
Результат:
```text
9c41e02 (HEAD -> main) Добавлена функция вычитания
3f2a1b7 Создан калькулятор с функцией сложения
```
`HEAD` — указатель «ты сейчас здесь». Чтобы выйти из просмотра истории (если экран остановился со знаком `:`), нажми клавишу `q`.

## 5. Отмена изменений (первые шаги)

| Ситуация | Команда |
|---|---|
| Вернуть файл в состояние последнего коммита (несохранённые изменения пропадут!) | `git restore calc.py` |
| Убрать файл из индекса (изменения сохранятся) | `git restore --staged calc.py` |
| Посмотреть файл из прежнего коммита | `git show 3f2a1b7:calc.py` |
| Исправить сообщение последнего коммита | `git commit --amend -m "Новый текст"` |
| «Отменить» коммит с помощью нового коммита | `git revert 9c41e02` |

Чаще всего используется `git restore`: если эксперимент не удался, вернуться к последней сохранённой версии.

## 6. Хорошее сообщение коммита

Сообщение коммита — это письмо себе в будущем и команде.

| Плохо | Хорошо |
|---|---|
| `asdf` | `В калькулятор добавлена операция деления` |
| `исправил` | `Исправлена ошибка при делении на ноль` |
| `изменения` | `Меню разделено на функции` |
| `всё` (20 файлов сразу) | несколько небольших осмысленных коммитов |

Правила:
1. Сообщение кратко (примерно до 50 символов) говорит, **что** сделано.
2. Один коммит — одно логическое изменение.
3. Не коммить неработающий код (по крайней мере в основную ветку).
4. Коммить часто: после каждого завершённого небольшого шага.

## 7. .gitignore — файлы, которые Git игнорирует

Некоторые файлы не нужно хранить в истории: виртуальное окружение (его можно пересоздать по `requirements.txt`), кэш Python, личные настройки, секретные ключи.

Файл `.gitignore` (в корне проекта):
```text
# Виртуальное окружение
.venv/
venv/

# Кэш Python
__pycache__/
*.pyc

# Настройки редактора
.vscode/

# Секретные данные
.env
```
`*` — любая последовательность символов. Сам файл `.gitignore` коммитится.

## 8. Git в VS Code

Раздел **Source Control** слева (`Ctrl+Shift+G`):
- список изменённых файлов (`U` — untracked, `M` — modified, `A` — added);
- `+` рядом с файлом — `git add`;
- поле сообщения вверху + кнопка ✓ Commit — `git commit`;
- при щелчке по файлу — сравнение старой и новой версий слева/справа (diff).

Однако сначала лучше освоить команды в терминале: они работают в любой среде и помогают ясно понимать, что происходит.

## 9. Рабочий цикл (ежедневный алгоритм)

```text
изменить файл → git status → git diff → git add . → git commit -m "..." → git log --oneline
        ↑                                                                         │
        └─────────────────────────────── следующий шаг ──────────────────────────┘
```

## Частые ошибки

**1. Выполнение `git init` не в той папке** (например, во всей папке `Documents`). В результате Git начинает отслеживать тысячи файлов. Решение: проверь через `git status`, аккуратно удали ошибочно созданную папку `.git` и заново выполни `git init` в правильной папке.

**2. Не настроено имя пользователя.**
```text
Author identity unknown
*** Please tell me who you are.
```
Решение: `git config --global user.name` и `user.email`.

**3. `git commit` без `-m`.** В терминале открывается текстовый редактор (Vim). Выход: `Esc`, затем `:q!` и Enter. Поэтому пиши `-m "сообщение"` или задай настройку `core.editor`.

**4. Забыли `git add`.**
```text
no changes added to commit (use "git add" and/or "git commit -a")
```
Перед коммитом добавь изменения в индекс.

**5. Коммит папки `.venv`.** В историю попадают тысячи файлов. Сначала создай `.gitignore`, потом `git add .`. Если уже допустил ошибку: `git rm -r --cached .venv` и снова коммит.

**6. «Всё в одном коммите».** Работа за весь день — один коммит «изменения». Найти ошибку в истории будет невозможно.

## Основные понятия

| Понятие | Пояснение |
|---|---|
| VCS | Система контроля версий |
| Git | Распределённая система контроля версий |
| Репозиторий (repository) | Файлы проекта и их полная история |
| Рабочий каталог | Папка проекта, в которой изменяются файлы |
| Индекс (staging area) | Изменения, подготовленные к следующему коммиту |
| Коммит (commit) | Сохранённое состояние проекта (точка сохранения) |
| Хеш | Уникальный идентификатор коммита |
| HEAD | Указатель на текущий коммит |
| `.gitignore` | Список файлов, которые Git не отслеживает |
| diff | Различие между двумя версиями |

## Примечание

- `git add .` добавляет изменения только в текущей папке, а `git add -A` — во всём репозитории (включая удалённые файлы). В Git 2.x при запуске из корня проекта результат обеих команд одинаков.
- Git не отслеживает пустые папки. Если пустую папку нужно сохранить, в неё кладут пустой файл, например `.gitkeep`.
- `.gitignore` действует только на ещё не отслеживаемые файлы. Если файл уже был закоммичен, его сначала убирают из индекса командой `git rm --cached <файл>`.
- Команда `git restore` появилась в Git 2.23; в старых инструкциях вместо неё пишут `git checkout -- <файл>`.
- Официальная документация и бесплатная книга «Pro Git»: https://git-scm.com/doc. Готовый шаблон `.gitignore` для Python-проектов: https://github.com/github/gitignore/blob/main/Python.gitignore.
