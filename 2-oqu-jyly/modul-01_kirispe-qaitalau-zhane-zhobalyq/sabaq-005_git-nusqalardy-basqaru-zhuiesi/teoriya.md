## 1. Нұсқаларды басқару жүйесі (VCS)

**Нұсқаларды басқару жүйесі** (система контроля версий, version control system, VCS) — файлдардағы барлық өзгерістің тарихын сақтайтын, кез келген бұрынғы нұсқаға қайтуға мүмкіндік беретін жүйе.

Аналогия: компьютерлік ойындағы **сақтау нүктелері** (save points). Қиын деңгейдің алдында ойынды сақтайсың — жеңілсең, сол жерден қайта бастайсың. Git-те мұндай сақтау нүктесі **коммит** (commit) деп аталады.

VCS не береді:
- әр өзгерістің тарихы: **кім**, **қашан**, **не** өзгертті, **неге**;
- кез келген нұсқаға қайту;
- командамен бір жобада қатар жұмыс істеу;
- кодтың сақтық көшірмесі (мысалы, GitHub-та).

**Git** — әлемдегі ең танымал VCS. Оны 2005 жылы Linux ядросының авторы Линус Торвальдс жасаған. Git — **таратылған** жүйе: әр компьютерде жобаның толық тарихы сақталады.

Git және GitHub — әртүрлі нәрселер:
| Git | GitHub |
|---|---|
| Компьютердегі бағдарлама | Интернеттегі сайт (сервис) |
| Нұсқаларды жергілікті сақтайды | Репозиторийлерді бұлтта сақтайды, бөліседі |
| Интернетсіз жұмыс істейді | Интернет қажет |

## 2. Git-ті бір рет баптау

Git орнатылғанын тексер:
```bash
git --version
```
Нәтижесі:
```text
git version 2.46.0.windows.1
```

Әр коммитке авторы жазылады, сондықтан атыңды және поштаңды бір рет көрсет:
```bash
git config --global user.name "Aigerim Nurlanqyzy"
git config --global user.email "aigerim@example.com"
git config --global init.defaultBranch main
git config --global core.editor "code --wait"
git config --list
```
Ескерту: бұл пошта болашақта GitHub-та жария көрінеді. Оны жасыру үшін GitHub ұсынатын жасырын поштаны (`...@users.noreply.github.com`) қолдануға болады.

## 3. Git-тің үш аймағы

```text
 Жұмыс каталогы          Индекс                  Репозиторий
 (working directory)     (staging area)          (.git папкасы)
 ┌──────────────┐  git add  ┌──────────────┐ git commit ┌──────────────┐
 │ файлдарды    │ ────────► │ келесі       │ ─────────► │ сақталған    │
 │ өзгертесің   │           │ коммитке     │            │ нұсқалар     │
 │              │           │ дайындалған  │            │ тарихы       │
 └──────────────┘           └──────────────┘            └──────────────┘
```

Аналогия — **фотосурет түсіру**:
- жұмыс каталогы — бөлмедегі адамдар (кез келген уақытта қозғалады);
- `git add` — суретке түсетіндерді кадрға жинау;
- `git commit` — фотоаппараттың батырмасын басу, суреттің альбомға түсуі;
- `git log` — фотоальбомды парақтау.

Файлдың күйлері:

| Күй | Мағынасы | `git status` көрсетуі |
|---|---|---|
| Untracked | Git бақыламайтын жаңа файл | қызыл, «Untracked files» |
| Modified | Өзгертілген, бірақ индекске қосылмаған | қызыл, «modified» |
| Staged | Индекске қосылған, коммитке дайын | жасыл, «Changes to be committed» |
| Committed | Репозиторийде сақталған | «nothing to commit, working tree clean» |

## 4. Негізгі командалар

### git init — репозиторий құру
```bash
mkdir calculator
cd calculator
git init
```
Нәтижесі:
```text
Initialized empty Git repository in C:/Users/Aigerim/calculator/.git/
```
Папкада жасырын `.git` папкасы пайда болады — бүкіл тарих сонда сақталады. Оны қолмен өзгертпе және жойма!

### git status — ағымдағы күй
Ең жиі қолданылатын команда — «қазір не болып жатыр?». Күмәнің болса — `git status`.

`calc.py` файлын құрайық:
```python
def add(a, b):
    """Екі санның қосындысын қайтарады."""
    return a + b


print(add(2, 3))
```

```bash
git status
```
Нәтижесі:
```text
On branch main

No commits yet

Untracked files:
  (use "git add <file>..." to include in what will be committed)
        calc.py

nothing added to commit but untracked files present (use "git add" to track)
```

### git add — индекске қосу
```bash
git add calc.py      # бір файл
git add .            # ағымдағы папкадағы барлық өзгеріс
git status
```
Нәтижесі:
```text
On branch main

No commits yet

Changes to be committed:
  (use "git rm --cached <file>..." to unstage)
        new file:   calc.py
```

### git commit — нұсқаны сақтау
```bash
git commit -m "Қосу функциясы бар калькулятор құрылды"
```
Нәтижесі:
```text
[main (root-commit) 3f2a1b7] Қосу функциясы бар калькулятор құрылды
 1 file changed, 6 insertions(+)
 create mode 100644 calc.py
```
`3f2a1b7` — коммиттің бірегей идентификаторы (хэші, қысқаша түрі).

Енді файлды өзгертейік — азайту функциясын қосамыз:
```python
def add(a, b):
    """Екі санның қосындысын қайтарады."""
    return a + b


def sub(a, b):
    """Екі санның айырмасын қайтарады."""
    return a - b


print(add(2, 3), sub(10, 4))
```

### git diff — не өзгерді?
```bash
git diff
```
Нәтижесі (қысқартылған):
```text
@@ -3,4 +3,9 @@ def add(a, b):
     return a + b
 
 
-print(add(2, 3))
+def sub(a, b):
+    """Екі санның айырмасын қайтарады."""
+    return a - b
+
+
+print(add(2, 3), sub(10, 4))
```
`-` — алынған жол, `+` — қосылған жол. `git diff --staged` индекстегі өзгерістерді көрсетеді.

```bash
git add calc.py
git commit -m "Азайту функциясы қосылды"
```

### git log — тарих
```bash
git log
```
Нәтижесі:
```text
commit 9c41e02d7a... (HEAD -> main)
Author: Aigerim Nurlanqyzy <aigerim@example.com>
Date:   Thu Sep 10 15:42:10 2026 +0500

    Азайту функциясы қосылды

commit 3f2a1b7c55...
Author: Aigerim Nurlanqyzy <aigerim@example.com>
Date:   Thu Sep 10 15:30:02 2026 +0500

    Қосу функциясы бар калькулятор құрылды
```

Ықшам түрлері:
```bash
git log --oneline
git log --oneline --graph --all
git log -3          # соңғы 3 коммит
```
Нәтижесі:
```text
9c41e02 (HEAD -> main) Азайту функциясы қосылды
3f2a1b7 Қосу функциясы бар калькулятор құрылды
```
`HEAD` — «сен қазір осы жердесің» деген көрсеткіш. Тарихтан шығу үшін (егер экран `:` белгісімен тоқтаса) `q` пернесін бас.

## 5. Өзгерістерді қайтару (алғашқы қадамдар)

| Жағдай | Команда |
|---|---|
| Файлды соңғы коммиттегі күйге қайтару (сақталмаған өзгерістер жойылады!) | `git restore calc.py` |
| Файлды индекстен шығару (өзгеріс сақталады) | `git restore --staged calc.py` |
| Бұрынғы коммиттегі файлды көру | `git show 3f2a1b7:calc.py` |
| Соңғы коммиттің хабарламасын түзету | `git commit --amend -m "Жаңа мәтін"` |
| Коммитті «болдырмау» жаңа коммит арқылы | `git revert 9c41e02` |

Ең жиі қолданылатыны — `git restore`: эксперимент сәтсіз болса, соңғы сақталған нұсқаға оралу.

## 6. Жақсы коммит хабарламасы

Коммит хабарламасы — болашақтағы өзіңе және командаға жазылған хат.

| Жаман | Жақсы |
|---|---|
| `asdf` | `Калькуляторға бөлу амалы қосылды` |
| `түзеттім` | `Нөлге бөлу кезіндегі қате түзетілді` |
| `өзгерістер` | `Мәзір функцияларға бөлінді` |
| `бәрі` (20 файл бірден) | бірнеше шағын, мағыналы коммит |

Ережелер:
1. Хабарлама **не** істелгенін қысқа (≈50 таңбаға дейін) айтады.
2. Бір коммит — бір логикалық өзгеріс.
3. Жұмыс істемейтін кодты коммиттеме (тым болмаса негізгі тармақта).
4. Жиі коммитте: әр аяқталған шағын қадамнан кейін.

## 7. .gitignore — Git елемейтін файлдар

Кейбір файлдарды тарихта сақтау керек емес: виртуалды орта (оны `requirements.txt`-тен қайта құруға болады), Python-ның кэші, жеке баптаулар, құпия кілттер.

`.gitignore` файлы (жоба түбірінде):
```text
# Виртуалды орта
.venv/
venv/

# Python кэші
__pycache__/
*.pyc

# Редактор баптаулары
.vscode/

# Құпия деректер
.env
```
`*` — кез келген таңбалар тізбегі. `.gitignore` файлының өзі коммиттеледі.

## 8. VS Code-тағы Git

Сол жақтағы **Source Control** (`Ctrl+Shift+G`) бөлімі:
- өзгерген файлдар тізімі (`U` — untracked, `M` — modified, `A` — added);
- файлдың жанындағы `+` — `git add`;
- жоғарыдағы хабарлама өрісі + ✓ Commit батырмасы — `git commit`;
- файлды басқанда — сол/оң жақта ескі мен жаңа нұсқаны салыстыру (diff).

Алайда алдымен командаларды терминалда меңгерген дұрыс: олар кез келген ортада жұмыс істейді және не болып жатқанын анық түсінуге көмектеседі.

## 9. Жұмыс циклі (күнделікті алгоритм)

```text
файлды өзгерту → git status → git diff → git add . → git commit -m "..." → git log --oneline
        ↑                                                                         │
        └─────────────────────────────── келесі қадам ───────────────────────────┘
```

## Жиі кездесетін қателер

**1. `git init`-ті қате папкада орындау** (мысалы, бүкіл `Documents` ішінде). Нәтижесінде Git мыңдаған файлды бақылай бастайды. Шешімі: `git status` арқылы тексер, қате жасалған `.git` папкасын абайлап жой, дұрыс папкада қайта `git init`.

**2. Пайдаланушы аты бапталмаған.**
```text
Author identity unknown
*** Please tell me who you are.
```
Шешімі: `git config --global user.name` және `user.email`.

**3. `-m`-сіз `git commit`.** Терминалда мәтіндік редактор (Vim) ашылады. Шығу: `Esc`, кейін `:q!` және Enter. Сондықтан `-m "хабарлама"` жаз немесе `core.editor` баптауын орнат.

**4. `git add`-ті ұмыту.**
```text
no changes added to commit (use "git add" and/or "git commit -a")
```
Коммиттің алдында өзгерістерді индекске қос.

**5. `.venv` папкасын коммиттеу.** Мыңдаған файл тарихқа түседі. Алдымен `.gitignore` құр, сонан соң `git add .`. Егер жіберіп қойсаң: `git rm -r --cached .venv` және қайта коммит.

**6. «Бәрі бір коммитте».** Бір күндік жұмыс — бір «өзгерістер» коммиті. Тарихтан қатені іздеу мүмкін болмайды.

## Негізгі ұғымдар

| Ұғым | Түсіндірме |
|---|---|
| VCS | Нұсқаларды басқару жүйесі |
| Git | Таратылған нұсқаларды басқару жүйесі |
| Репозиторий (repository) | Жоба файлдары мен олардың толық тарихы |
| Жұмыс каталогы | Файлдарды өзгертетін жоба папкасы |
| Индекс (staging area) | Келесі коммитке дайындалған өзгерістер |
| Коммит (commit) | Жобаның сақталған күйі (сақтау нүктесі) |
| Хэш | Коммиттің бірегей идентификаторы |
| HEAD | Ағымдағы коммитке көрсеткіш |
| `.gitignore` | Git бақыламайтын файлдар тізімі |
| diff | Екі нұсқаның айырмашылығы |

## Ескерту

- `git add .` ағымдағы папкадағы өзгерістерді ғана қосады, ал `git add -A` бүкіл репозиторийдегі өзгерістерді (жойылған файлдарды да) қосады. Git 2.x нұсқасында `.` түбірлік папкадан орындалса, екеуінің нәтижесі бірдей.
- Git бос папкаларды бақыламайды. Бос папканы сақтау керек болса, ішіне `.gitkeep` сияқты бос файл салады.
- `.gitignore` тек әлі бақыланбаған файлдарға әсер етеді. Файл бұрын коммиттелген болса, алдымен оны `git rm --cached <файл>` арқылы индекстен алып тастау керек.
- `git restore` командасы Git 2.23 нұсқасында пайда болды; ескі нұсқаулықтарда оның орнына `git checkout -- <файл>` жазылады.
- Ресми құжаттама және тегін «Pro Git» кітабы: https://git-scm.com/doc. Python жобаларына арналған дайын `.gitignore` үлгісі: https://github.com/github/gitignore/blob/main/Python.gitignore.
