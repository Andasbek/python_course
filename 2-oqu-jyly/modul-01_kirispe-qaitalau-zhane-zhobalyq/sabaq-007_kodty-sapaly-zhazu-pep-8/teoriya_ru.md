## 1. Что такое PEP 8?

**PEP** (Python Enhancement Proposal) — документы с предложениями по развитию языка Python. **PEP 8** — официальное руководство по стилю написания кода на Python (с 2001 года, Гвидо ван Россум и др.). Этого стиля придерживается всё сообщество Python — программисты Google, NASA, Instagram.

Главная идея PEP 8: **«Код читается гораздо чаще, чем пишется»**.

Философия Python описана в PEP 20 («The Zen of Python»), её можно вывести прямо из интерпретатора:
```python
import this
```
Результат (фрагмент):
```text
Beautiful is better than ugly.
Explicit is better than implicit.
Simple is better than complex.
Readability counts.
```
«Красивое лучше, чем уродливое. Явное лучше, чем неявное. Простое лучше, чем сложное. Читаемость имеет значение».

## 2. Правила форматирования

### 2.1. Отступы
- На каждый уровень — **4 пробела**. Не смешивай Tab и пробелы (VS Code автоматически превращает Tab в 4 пробела).

### 2.2. Длина строки
- Строка — не длиннее **79 символов** (многие команды допускают до 88–100). Длинную строку переноси внутри скобок:

```python
total_price = (
    notebook_price * notebook_count
    + pen_price * pen_count
    + bag_price
)
```

### 2.3. Пустые строки
- Между функциями и классами верхнего уровня — **2 пустые строки**.
- Между методами внутри класса — 1 пустая строка.
- Внутри функции логические части можно разделять 1 пустой строкой.

### 2.4. Пробелы

| Правильно | Неправильно | Правило |
|---|---|---|
| `x = 5` | `x=5` | пробелы вокруг `=` |
| `a + b * c` | `a+b*c` | вокруг операций |
| `print(x, y)` | `print( x , y )` | внутри скобок у краёв — нет, после запятой — есть |
| `grades[0]` | `grades [0]` | перед индексом — нет |
| `def f(x, y=0):` | `def f(x, y = 0):` | вокруг `=` в значении по умолчанию — нет |
| `area(width=3)` | `area(width = 3)` | и в именованном аргументе — нет |

### 2.5. Импорты
- В самом начале файла, каждый на отдельной строке.
- Порядок: стандартная библиотека → сторонние пакеты → твои модули, между группами — пустая строка.

```python
import os
import random

import requests

from grades_utils import calc_average
```
Не пиши `from module import *` — становится непонятно, откуда взялось какое имя.

### 2.6. В одной строке — одно действие
```python
# Плохо
if x > 0: print("положительное"); count += 1

# Хорошо
if x > 0:
    print("положительное")
    count += 1
```

### 2.7. Сравнения
```python
items = []
is_ready = True
result = None

if not items:            # вместо if len(items) == 0:
    print("Список пуст")
if is_ready:             # вместо if is_ready == True:
    print("Готово")
if result is None:       # вместо if result == None:
    print("Результата нет")
```
Результат:
```text
Список пуст
Готово
Результата нет
```

## 3. Правила именования

| Объект | Стиль | Пример |
|---|---|---|
| Переменная, функция, метод | `snake_case` (строчные буквы + подчёркивание) | `student_name`, `calc_average()` |
| Константа | `UPPER_SNAKE_CASE` | `MAX_SPEED`, `TAX_RATE` |
| Класс | `PascalCase` (CapWords) | `Student`, `BankAccount` |
| Модуль (файл) | короткий `snake_case` | `grades_utils.py` |
| «Внутреннее» имя | с `_` в начале | `_helper()` |

Значение префикса `_` в классах подробнее рассматривается в теме ООП (инкапсуляция).

### Признаки хорошего имени
1. **Осмысленное**: не `d`, а `days_left`; не `lst`, а `student_names`.
2. **На английском или понятным транслитом** — в одном проекте на одном языке: `price`, а не смесь с `tsena`.
3. **Функция — глагол**: `get_weather()`, `print_report()`, `is_valid()`.
4. **Логическая переменная — вопрос**: `is_open`, `has_ticket`, `can_jump`.
5. **Список — множественное число**: `grades`, `students`; один элемент — единственное: `for student in students`.
6. **Однобуквенные имена** — только в коротких циклах (`i`, `j`) и в математике (`x`, `y`).
7. Не «перекрывай» встроенные имена: не называй переменные `list`, `str`, `sum`, `max`, `input`.
8. Не используй `l` (строчная L), `O` (заглавная О), `I` (заглавная i) как одиночные буквы: их путают с `1` и `0`.

```python
# Плохо
sum = 0
list = [3, 5]
for l in list:
    sum += l
# print(sum([1, 2]))  →  TypeError: 'int' object is not callable

# Хорошо
total = 0
prices = [3, 5]
for price in prices:
    total += price
print(total, sum([1, 2]))
```

## 4. Комментарии

Комментарий должен объяснять не **что** делает код, а **почему** сделано именно так. «Что» говорят сами хорошие имена.

```python
# Плохо — повторяет код
i = i + 1  # прибавляем к i единицу

# Хорошо — объясняет причину
attempts += 1  # пользователю даётся 3 попытки, затем блокировка
```

Правила PEP 8:
- После `#` один пробел: `# комментарий`.
- Комментарий в конце строки отделяется от кода минимум 2 пробелами.
- Комментарий пишется полным предложением и должен соответствовать коду — изменил код, обнови и комментарий. **Устаревший комментарий хуже, чем отсутствие комментария.**
- Не храни ненужный код, превращая его в комментарий, — есть Git, старая версия сохранена в истории.

## 5. Docstring — строка документации

**Docstring** — строка в тройных кавычках (`"""..."""`), стоящая первой строкой функции, модуля или класса. В отличие от комментария, она **сохраняется внутри программы** и читается с помощью `help()` (PEP 257).

### Однострочный docstring
```python
def square(n):
    """Возвращает квадрат числа."""
    return n * n
```

### Многострочный docstring
```python
def convert_currency(amount, rate, commission=0.01):
    """Переводит тенге в иностранную валюту.

    Args:
        amount: сумма в тенге.
        rate: курс 1 единицы валюты в тенге.
        commission: комиссия банка (в долях, по умолчанию 1%).

    Returns:
        Сумма в валюте после удержания комиссии (до 2 знаков).
    """
    result = amount / rate * (1 - commission)
    return round(result, 2)


print(convert_currency(50_000, 500))
help(convert_currency)
```
Результат:
```text
99.0
Help on function convert_currency in module __main__:

convert_currency(amount, rate, commission=0.01)
    Переводит тенге в иностранную валюту.

    Args:
        amount: сумма в тенге.
        rate: курс 1 единицы валюты в тенге.
        commission: комиссия банка (в долях, по умолчанию 1%).

    Returns:
        Сумма в валюте после удержания комиссии (до 2 знаков).
```

Правила docstring:
- первая строка — короткое предложение с точкой в конце: **что делает / что возвращает** функция;
- в сложной функции — пустая строка, затем параметры (`Args`) и результат (`Returns`);
- можно прочитать и через атрибут `__doc__`: `print(square.__doc__)`;
- VS Code показывает docstring при наведении мыши на функцию.

### Docstring модуля
Самая первая строка файла:
```python
"""Вспомогательные функции для работы со школьным журналом.

Автор: Айгерим Н., 2026.
"""
```

## 6. Аннотации типов (кратко)

Python 3.5+ позволяет указывать ожидаемый тип параметров и результата. На работу программы это не влияет, но улучшает чтение и подсказки VS Code:

```python
def greet(name: str, times: int = 1) -> str:
    """Возвращает строку приветствия, повторённую times раз."""
    return ("Привет, " + name + "! ") * times


print(greet("Ерлан", 2))
```
Результат:
```text
Привет, Ерлан! Привет, Ерлан! 
```

## 7. Автоматические инструменты

Проверять стиль вручную долго — программисты используют инструменты:

| Инструмент | Тип | Что делает |
|---|---|---|
| **Black** | форматировщик | автоматически приводит код к единому стилю |
| **Ruff** | линтер + форматировщик | находит ошибки и нарушения стиля (очень быстро) |
| **Flake8** / **pycodestyle** | линтер | перечисляет нарушения PEP 8 |
| **Pylance** (VS Code) | анализатор | неиспользуемые переменные, неверные имена |

```bash
pip install ruff
ruff check main.py
ruff format main.py
```
Результат (пример):
```text
main.py:1:1: F401 [*] `os` imported but unused
main.py:7:5: E741 Ambiguous variable name: `l`
Found 2 errors.
```

В VS Code: Extensions → «Ruff» или «Black Formatter» → в настройках включи `Format On Save`. Теперь при каждом сохранении (`Ctrl+S`) код будет форматироваться автоматически.

## 8. Пример рефакторинга

**Рефакторинг** — улучшение структуры и читаемости кода без изменения поведения программы.

Исходный код:
```python
import random,os
def Game(n):
    x=random.randint(1,n)
    T=0
    while True:
        a=int(input("?"))
        T+=1
        if a==x: print("ok",T);break
        elif a<x:print("up")
        else:print("down")
Game(100)
```

После рефакторинга:
```python
"""Игра «Угадай число»."""

import random

MAX_NUMBER = 100


def play_guess_game(max_number):
    """Проводит игру по угадыванию числа, загаданного компьютером.

    Returns:
        Количество попыток, сделанных игроком.
    """
    secret = random.randint(1, max_number)
    attempts = 0
    while True:
        guess = int(input(f"Число от 1 до {max_number}: "))
        attempts += 1
        if guess == secret:
            print(f"Угадал! Количество попыток: {attempts}")
            return attempts
        if guess < secret:
            print("Больше")
        else:
            print("Меньше")


if __name__ == "__main__":
    play_guess_game(MAX_NUMBER)
```
Что изменилось: удалён неиспользуемый `os`, импорт на отдельной строке, константа `MAX_NUMBER`, имя функции в `snake_case` и в форме глагола, осмысленные переменные, одно действие в строке, пробелы, docstring, понятные сообщения, `if __name__ == "__main__":`.

## Частые ошибки

**1. Имя встроенной функции для переменной** (`sum`, `list`, `max`, `input`). Результат — `TypeError: 'int' object is not callable`. Решение — другое имя: `total`, `items`.

**2. Путаница docstring и комментария.**
```python
def area(a, b):
    # Площадь прямоугольника   ← это не docstring, help() его не покажет
    return a * b


def area_ok(a, b):
    """Возвращает площадь прямоугольника."""
    return a * b
```

**3. Docstring не в первой строке функции.** Docstring должен быть **самой первой** строкой после `def`, иначе он останется просто строкой.

**4. Смешанный стиль:** `studentName`, `Student_name`, `STUDENTname` — в одном проекте. В Python для переменных — только `snake_case`.

**5. Избыточные комментарии** — к каждой строке пишут, «что она делает». Вместо этого улучши имена.

**6. Смешение Tab и пробелов.**
```text
TabError: inconsistent use of tabs and spaces in indentation
```

## Основные понятия

| Понятие | Пояснение |
|---|---|
| PEP 8 | Официальное руководство по стилю кода Python |
| Читаемость (readability) | Лёгкость понимания кода человеком |
| snake_case | `слово_слово` — имена переменных, функций |
| PascalCase | `СловоСлово` — имена классов |
| UPPER_CASE | Имена констант |
| Комментарий | Запись, начинающаяся с `#`, объясняющая «почему» |
| Docstring | Документация функции/модуля/класса `"""..."""` |
| Линтер | Инструмент проверки стиля и ошибок |
| Форматировщик | Инструмент автоматического форматирования кода |
| Рефакторинг | Улучшение кода без изменения его поведения |

## Примечание

- PEP 8 сам предупреждает: «глупая последовательность — пугало маленьких умов». Если в проекте уже принят свой стиль, важнее писать новый код в этом же стиле.
- Black по умолчанию использует длину строки 88 символов, а PEP 8 — 79. Согласуй настройки Ruff и Black в файле `pyproject.toml` (параметр `line-length`).
- Существует несколько популярных стилей docstring: Google (`Args:`/`Returns:`), NumPy и reStructuredText (`:param x:`). В одном проекте используй какой-то один.
- Аннотации типов не проверяются при выполнении: `greet(5)` может запуститься без ошибки. Для проверки типов применяют статические анализаторы `mypy` или Pylance. С Python 3.9 можно писать `list[int]`, с 3.10 — `int | None`.
- Официальные тексты: PEP 8 — https://peps.python.org/pep-0008/, PEP 257 (docstring) — https://peps.python.org/pep-0257/.
