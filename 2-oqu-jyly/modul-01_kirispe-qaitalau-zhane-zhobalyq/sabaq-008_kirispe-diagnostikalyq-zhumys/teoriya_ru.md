## 1. Базовые умения Python: контрольный список

Прежде чем переходить к объектно-ориентированному программированию и проектам, нужно уверенно владеть базой первого года и инструментами разработчика.

| Тема | Что нужно уметь | Мини-пример |
|---|---|---|
| Типы и ввод | преобразовывать ввод, работать с `int`, `float`, `str`, `bool` | `age = int(input())` |
| Условия | строить цепочки `if/elif/else`, сложные условия | `if 12 <= age <= 17 and has_ticket:` |
| Циклы | `for` с `range`, `while`, `break`, `continue` | `for i in range(1, 11, 2):` |
| Коллекции | список, кортеж, словарь, множество и их методы | `freq[w] = freq.get(w, 0) + 1` |
| Функции | параметры, значения по умолчанию, `return`, docstring | `def avg(nums, digits=2):` |
| Структура кода | модули, `import`, `main()`, `if __name__ == "__main__":` | `from utils import avg` |
| Инструменты | venv, pip, Git, GitHub, PEP 8 | `git commit -m "..."` |

Пример программы, которая объединяет большую часть базовых умений:

```python
def describe(grades):
    """Возвращает словарь со статистикой по списку оценок."""
    if not grades:
        return {}
    return {
        "среднее": round(sum(grades) / len(grades), 2),
        "лучшая": max(grades),
        "пятёрок": grades.count(5),
    }


journal = {"Алия": [5, 4, 5], "Бекзат": [3, 4], "Дана": []}
for name, grades in journal.items():
    stats = describe(grades)
    status = stats if stats else "нет оценок"
    print(f"{name}: {status}")
```

Результат:
```text
Алия: {'среднее': 4.67, 'лучшая': 5, 'пятёрок': 2}
Бекзат: {'среднее': 3.5, 'лучшая': 4, 'пятёрок': 0}
Дана: нет оценок
```

Здесь используются функция с docstring, проверка пустого списка, словарь, встроенные функции `sum`, `len`, `max`, `round`, метод `count`, цикл по `items()`, тернарное выражение и f-строка.

## 2. Проектное мышление

**Проект** — работа, которая решает определённую **проблему**, имеет конкретный **результат** (продукт) и **срок**.

Составные части проекта:

```text
Проблема ──► Пользователь ──► Решение (идея) ──► Возможности ──► Технологии ──► Результат
"Почему?"     "Для кого?"      "Что делаем?"      "Что умеет?"     "Чем?"         "Как измерим?"
```

Пример:
- **Проблема:** ученики забывают сроки сдачи домашних заданий.
- **Пользователь:** учащиеся 5–11 классов.
- **Решение:** «Дневник домашних заданий» — оконное приложение.
- **Возможности:** добавление задания, фильтр по предмету, напоминание при приближении срока, график статистики.
- **Технологии:** ООП (классы), Tkinter, SQLite, Matplotlib.
- **Результат:** 5 одноклассников пользовались неделю и оставили отзывы.

### Признаки хорошей идеи проекта
1. **Решает реальную проблему** — не только «потому что интересно», а полезна кому-то.
2. **Интересна автору** — над крупным проектом работают долго, мотивация важна.
3. **Выполнима** — соответствует уровню знаний и времени (не слишком лёгкая и не слишком сложная).
4. **Расширяема** — сначала простая версия (MVP), затем добавляются возможности.
5. **Объединяет несколько технологий** — например: ООП + Tkinter + SQLite + API.

**MVP** (minimum viable product, минимально жизнеспособный продукт) — первая версия только с основной функцией. Аналогия: если хочешь сделать велосипед, сначала сделай самокат — он тоже едет, потом его доработаешь. А одно колесо — это не MVP.

### Проверка идеи: SMART
| Буква | Значение | Вопрос |
|---|---|---|
| S — Specific | Конкретная | Что именно делает программа? |
| M — Measurable | Измеримая | Как узнать, что она готова? |
| A — Achievable | Достижимая | Хватит ли знаний и времени? |
| R — Relevant | Актуальная | Кому и зачем это нужно? |
| T — Time-bound | Ограниченная по времени | Когда она будет завершена? |

## 3. Методы поиска идей

### 3.1. Мозговой штурм (brainstorming)
- За короткое время записать **как можно больше** идей, не критикуя их.
- Затем сгруппировать похожие идеи и выбрать лучшие по критериям из раздела 2.

### 3.2. «Проблема → Решение»
Оглянись вокруг: какие неудобства есть в школе, дома, в городе?
- «В столовой длинная очередь» → приложение для предварительного заказа.
- «Забываю домашнее задание» → приложение-дневник.
- «Трудно запоминать английские слова» → игра с флеш-карточками.
- «В городе нет понятной информации о загрязнении воздуха» → программа, получающая данные через API и строящая графики.

### 3.3. «От технологии к идее»
Возьми технологию Python и спроси: «Что можно сделать этим инструментом?»

| Технология | Что можно сделать |
|---|---|
| ООП | персонажи игр, библиотечная система, банковский счёт |
| Tkinter | калькулятор, дневник, программа-тест, переводчик |
| Pygame | платформер, «змейка», космическая стрелялка, обучающая игра |
| SQLite | база учащихся, каталог библиотеки, склад магазина |
| API | погода, курс валют, космические снимки, карта землетрясений |
| BeautifulSoup | агрегатор новостей, сравнение цен |
| Pandas + Matplotlib | статистика оценок, спортивные результаты, анализ качества воздуха |

### 3.4. SCAMPER (улучшение существующего)
Возьми существующую программу (например, игру «змейка») и измени её: **S**ubstitute — замени (вместо змеи — космический корабль), **C**ombine — объедини (игра + английские слова), **A**dapt — адаптируй, **M**odify — измени, **P**ut to other use — используй для другой цели, **E**liminate — убери, **R**everse — сделай наоборот.

## 5. От идеи к коду: декомпозиция и MVP

**Декомпозиция** — разбиение большой задачи на маленькие, каждую из которых можно запрограммировать отдельно. Каждая функция MVP превращается в функцию (позже — в метод класса), а данные — в структуру (список словарей, позже — объекты и таблица базы данных).

```text
«Дневник домашних заданий»
├── хранить задания        → список словарей homeworks
├── добавить задание       → add_homework()
└── показать ближайшие     → upcoming()
```

Консольный MVP на Python:

```python
"""MVP «Дневник домашних заданий»: консольная версия."""

from datetime import date

homeworks = []


def add_homework(subject, text, deadline):
    """Добавляет задание в список."""
    homeworks.append({"subject": subject, "text": text, "deadline": deadline})


def upcoming(days=2, today=None):
    """Возвращает задания со сроком не позже чем через days дней."""
    today = today or date.today()
    return [hw for hw in homeworks if 0 <= (hw["deadline"] - today).days <= days]


def main():
    add_homework("Математика", "№ 145–150", date(2026, 9, 18))
    add_homework("История", "§ 3, конспект", date(2026, 9, 25))
    for hw in upcoming(today=date(2026, 9, 17)):
        print(f"{hw['deadline']}: {hw['subject']} — {hw['text']}")


if __name__ == "__main__":
    main()
```

Результат:
```text
2026-09-18: Математика — № 145–150
```

Вычитание двух объектов `date` даёт объект `timedelta`, у которого атрибут `.days` — разница в днях. Дальше MVP развивается по версиям: классы (ООП) → окно (Tkinter) → сохранение (SQLite) → графики (Matplotlib); каждая версия фиксируется коммитом в Git.

## 6. Питч — представление идеи за 1 минуту

**Питч** (elevator pitch, «презентация в лифте») — очень краткое и убедительное изложение идеи.

Структура (60 секунд):
1. **Крючок** (10 с): «Вы когда-нибудь забывали домашнее задание?»
2. **Проблема** (10 с): кому и почему трудно.
3. **Решение** (20 с): что делает программа, 2–3 основные возможности.
4. **Технологии** (10 с): с помощью чего она будет сделана.
5. **Призыв** (10 с): «Ищу в команду дизайнера» или «Жду ваших отзывов».

## Частые ошибки

**В коде:**
1. Не преобразовать `input()` в число → `TypeError` при вычислениях.
2. Деление на `len()` пустого списка → `ZeroDivisionError`; сначала проверь `if not items:`.
3. Не проверить программу на разных данных — запусти её минимум с 2–3 разными вводами, включая граничные (0, пустая строка, пустой список).

**При выборе идеи проекта:**
1. **Слишком большая идея:** «3D-игра как Minecraft» или «приложение как Kaspi» — в одиночку за год сделать невозможно. Решение: уменьшить до MVP.
2. **Слишком маленькая идея:** «программа, складывающая два числа» — для крупного проекта мало, технологии не объединяются.
3. **Идея без проблемы:** «Просто сделаю окно» — подумай, кому и зачем это нужно.
4. **Копия:** повторение готового проекта из интернета без собственного вклада. Вдохновляться можно, но добавь свою идею и укажи источник.

## Основные понятия

| Понятие | Пояснение |
|---|---|
| Проект | Работа, решающая проблему, с результатом и сроком |
| Целевой пользователь | Для кого предназначен проект |
| MVP | Первая работающая версия только с основной функцией |
| Декомпозиция | Разбиение большой задачи на маленькие части |
| SMART | Критерии проверки цели |
| Мозговой штурм | Метод генерации множества идей без критики |
| Питч | Краткое (≈1 мин) представление идеи |
| Риск | То, что может помешать выполнению проекта |

## Примечание

- Модуль `datetime` входит в стандартную библиотеку: `date.today()` возвращает текущую дату, `date.fromisoformat("2026-09-18")` превращает строку в дату. Документация: https://docs.python.org/3/library/datetime.html.
- Глобальный список `homeworks` удобен для MVP, но в больших программах данные лучше передавать через параметры или хранить в объекте класса — так код проще тестировать.
- В шаблоне `today = today or date.today()` значение по умолчанию вычисляется при каждом вызове. Писать `def upcoming(today=date.today())` нельзя: значение по умолчанию вычисляется один раз при определении функции.
- Идеи и планы удобно вести в Markdown прямо в репозитории (`ideas.md`, `README.md`) и отслеживать задачи через GitHub Issues.
- Прежде чем писать своё, поищи готовые библиотеки на https://pypi.org/ — часто нужная функциональность уже реализована.
