## 1. Командалық репозиторий: Collaborator және clone

Тимлид GitHub-та репозиторий ашып, қалғандарды шақырады:
**Settings → Collaborators → Add people** → командаластың логині. Командалас поштадағы шақыруды қабылдайды.

Әр мүше репозиторийді өз компьютеріне көшіреді:

```bash
git clone https://github.com/aliya-team/qyran-game.git
cd qyran-game
git config user.name "Nurlan Seitov"
git config user.email "nurlan@example.com"
```

`git clone` — репозиторийдің бүкіл тарихымен бірге толық көшірмесін жасайды және `origin` деген қашықтағы (remote) байланысты автоматты түрде орнатады.

## 2. Командалық жұмыстың басты мәселесі

Елестетіп көріңіз: Нұрлан мен Дана бір уақытта `main.py`-ді өзгертті. Нұрлан бірінші `push` жасады. Дана `push` жасағанда Git қабылдамайды:

```text
! [rejected]        main -> main (fetch first)
error: failed to push some refs to 'https://github.com/aliya-team/qyran-game.git'
hint: Updates were rejected because the remote contains work that you do not have locally.
```

Git айтып тұр: «Серверде сенде жоқ жаңа өзгерістер бар. Алдымен оларды ал (`pull`)». Бұл — қате емес, **қорғаныс**: Git біреудің жұмысын үнсіз өшіріп жібермейді.

**Алтын ереже:** жұмысты бастамас бұрын — `git pull`; жұмысты аяқтағанда — `commit`, `pull`, сосын `push`.

## 3. Тармақтар (branch)

**Тармақ** — жобаның параллель нұсқасы. Негізгі тармақ `main` әрқашан **жұмыс істейтін** ойынды сақтайды. Әр мүше жаңа мүмкіндікті өз тармағында жасайды, дайын болғанда `main`-ге қосады.

**Аналогия:** `main` — таза көшірме. Әр мүше алдымен өз жобасына (тармаққа) жазады, тексерілген соң ғана өзгерістер таза көшірмеге көшіріледі.

```text
main:      A───B───────────F───G
                \         /   /
feature/player   C───D───┘   /
                  \         /
feature/sound      E───────┘
```

### Тармақ командалары

| Команда | Не істейді |
|---|---|
| `git branch` | Барлық жергілікті тармақтарды көрсетеді (`*` — ағымдағысы) |
| `git branch feature/player` | Жаңа тармақ құрады |
| `git switch feature/player` | Тармаққа ауысады (ескі жолы: `git checkout`) |
| `git switch -c feature/player` | Құрады және бірден ауысады |
| `git merge feature/player` | Көрсетілген тармақты ағымдағы тармаққа біріктіреді |
| `git branch -d feature/player` | Біріктірілген тармақты өшіреді |
| `git push -u origin feature/player` | Тармақты GitHub-қа бірінші рет жібереді |

Тармақ атауларының келісімі: `feature/...` — жаңа мүмкіндік, `fix/...` — қатені түзету, `assets/...` — ресурстар.

### Мүмкіндік-тармақ (feature branch) жұмыс тәртібі

```bash
# 1. main-ді жаңарту
git switch main
git pull

# 2. Өз тапсырмаңа тармақ ашу
git switch -c feature/enemies

# 3. Жұмыс істеу, жиі коммит жасау
git add enemies.py
git commit -m "Enemy класы: оңнан солға қозғалыс"

# 4. Тармақты GitHub-қа жіберу
git push -u origin feature/enemies

# 5. GitHub-та Pull Request ашу, командалас тексереді, Merge басылады

# 6. main-ге оралып, жаңарту
git switch main
git pull
git branch -d feature/enemies
```

## 4. Pull Request және код тексеру (code review)

**Pull Request (PR)** — «Менің тармағымды `main`-ге қосуды сұраймын» деген өтініш. GitHub-та тармақты жібергеннен кейін **Compare & pull request** батырмасы шығады.

PR-да жазылатындар:
- **атауы:** «Жаулар класы қосылды»;
- **сипаттамасы:** не өзгерді, қалай тексеруге болады, қандай Kanban тапсырмасы (мысалы, `Closes #4` — 4-Issue автоматты жабылады).

Командалас (мысалы, тимлид) **Files changed** бөлімінде кодты оқып, жолға пікір қалдырады, соңында **Approve** (мақұлдау) немесе **Request changes** (түзетуді сұрау) береді.

### Code review чек-парағы

- [ ] Ойын іске қосылады, қате шықпайды
- [ ] Код PEP 8 бойынша жазылған, атаулар түсінікті
- [ ] Класс пен функцияларда docstring бар
- [ ] Тұрақтылар `settings.py`-ден алынған
- [ ] Басқа адамның файлдары қажетсіз өзгертілмеген
- [ ] Артық файлдар (`__pycache__`, `.venv`) жоқ

Пікірді сыпайы жазамыз: «Мұнда `speed`-ті `settings.py`-ге шығарсақ қалай?» — «Бұл қате, қайта жаз» дегеннен әлдеқайда жақсы.

## 5. Біріктіру қақтығысы (merge conflict)

Екі адам **бір файлдың бір жолын** әртүрлі өзгертсе, Git қайсысын таңдауды білмейді — **қақтығыс** туындайды.

Мысал: `settings.py`-де Нұрлан `FPS = 60` дегенді `FPS = 30` етті, Дана `FPS = 120` етті. Дана `git pull` немесе `git merge` жасағанда:

```text
Auto-merging settings.py
CONFLICT (content): Merge conflict in settings.py
Automatic merge failed; fix conflicts and then commit the result.
```

Файлдың ішінде Git белгілер қояды:

```text
WIDTH = 800
HEIGHT = 600
<<<<<<< HEAD
FPS = 120
=======
FPS = 30
>>>>>>> main
TITLE = "Қыран"
```

- `<<<<<<< HEAD` пен `=======` арасы — **сенің** нұсқаң;
- `=======` пен `>>>>>>>` арасы — **келген** нұсқа.

### Қақтығысты шешу қадамдары

1. Файлды ашу (VS Code қақтығысты түспен белгілейді және «Accept Current / Accept Incoming / Accept Both» батырмаларын ұсынады).
2. Командаласпен **келісу**: қай мән дұрыс?
3. Белгілерді (`<<<<<<<`, `=======`, `>>>>>>>`) **толық өшіріп**, дұрыс кодты қалдыру:

```python
WIDTH = 800
HEIGHT = 600
FPS = 60  # командамен келісілді
TITLE = "Қыран"
```

4. Ойынды іске қосып тексеру.
5. Коммит жасау:

```bash
git add settings.py
git commit -m "settings.py-дегі FPS қақтығысы шешілді"
git push
```

### Қақтығысты қалай азайтамыз?

- әр файлдың бір иесі бар (жоба модульдерге бөлінген);
- жиі `pull` жасаймыз — өзгерістер аз болғанда біріктіру оңай;
- кішкене PR-лар: бір PR — бір тапсырма;
- ортақ файлдарды (`settings.py`, `main.py`) тек келісіп өзгертеміз.

## 6. Жақсы коммит хабарламасы

Коммит хабарламасы — командаластарға жазылған хат. Оны оқып, не өзгергенін түсіну керек.

| Жаман | Жақсы |
|---|---|
| `update` | `Player: экраннан шығып кетпеу шекарасы қосылды` |
| `asdf` | `Соққы дыбысы (hit.wav) және оны ойнату қосылды` |
| `түзеттім` | `Fix: Game Over кейін ұпай нөлге түспейтін қате түзетілді` |
| `көп өзгеріс` | (бір коммитте бір ғана мағыналы өзгеріс) |

Ереже: хабарлама **не істелгенін** айтады, 50–70 таңбадан аспайды, бір коммит — бір ой.

## 7. `.gitignore` — репозиторийге не жібермейміз

Кейбір файлдар компьютерде автоматты пайда болады, оларды бөлісудің қажеті жоқ (керісінше, қақтығыс тудырады):

```text
# .gitignore
__pycache__/
*.pyc
.venv/
venv/
.vscode/
.idea/
.DS_Store
Thumbs.db
highscore.txt
```

`highscore.txt` — әр ойыншының жеке рекорды, оны да репозиторийге жібермейміз.

## 8. Пайдалы қарау командалары

```bash
git status                     # не өзгерді, қай тармақтамын
git log --oneline --graph --all # тармақтар тарихы сызба түрінде
git diff                       # әлі add жасалмаған өзгерістер
git fetch                      # серверден жаңалықтарды алу (біріктірмей)
git restore player.py          # файлдағы сақталмаған өзгерістерді болдырмау
```

## 9. Модульдерді бір ойынға жинау

Әр мүше өз модулін жазғаннан кейін `main.py` оларды біріктіреді. Мысал:

```python
# enemies.py — бағдарламашының модулі
import random
import pygame

WIDTH, HEIGHT = 800, 600  # жобада: from settings import WIDTH, HEIGHT


class Enemy(pygame.sprite.Sprite):
    """Оңнан солға ұшатын кедергі (тау шыңы немесе бұлт)."""

    def __init__(self, speed=4):
        super().__init__()
        self.image = pygame.Surface((40, 40))
        self.image.fill((90, 90, 90))
        y = random.randint(20, HEIGHT - 60)
        self.rect = self.image.get_rect(topleft=(WIDTH, y))
        self.speed = speed

    def update(self):
        self.rect.x -= self.speed
        if self.rect.right < 0:
            self.kill()  # экраннан шықса — топтан өшіріледі
```

## Жиі кездесетін қателер

**1. `main`-ге тікелей push жасау.** Аяқталмаған код `main`-ге түсіп, бүкіл команданың ойыны бұзылады.
→ Дұрыс: әрқашан `feature/...` тармағында жұмыс істеп, PR арқылы біріктіру.

**2. Қақтығыс белгілерін өшірмей коммит жасау.**

```text
<<<<<<< HEAD
FPS = 120
=======
FPS = 30
>>>>>>> main
```

Python бұл жолдарды оқи алмайды → `SyntaxError`. Дұрыс: белгілерді толық өшіріп, бір мәнді қалдыру, ойынды іске қосып тексеру.

**3. Жұмысты `pull`-сыз бастау.** Ескі нұсқада ұзақ жұмыс істеп, соңында үлкен қақтығыс шығады. Дұрыс: жұмыс басында — `git switch main` және `git pull`.

**4. `__pycache__` пен `.venv`-ті репозиторийге жіберу.** Дұрыс: жобаның басында `.gitignore` жасау. Егер жіберіп қойсаң:

```bash
git rm -r --cached __pycache__
git commit -m "__pycache__ репозиторийден алынды"
```

**5. Басқа тармақта екеніңді байқамау.** `git status` бірінші жолында әрқашан ағымдағы тармақ жазылады: `On branch feature/player`. Коммит алдында тексер!

**6. Импорттағы цикл.** `player.py` → `import main`, `main.py` → `import player` — бір-бірін импорттаса, `ImportError` шығады. Дұрыс: модульдер тек `settings.py`-ді импорттайды, ал оларды тек `main.py` біріктіреді.

## Негізгі ұғымдар

| Ұғым | Түсіндірмесі |
|---|---|
| Collaborator | Репозиторийге жазу құқығы берілген қатысушы |
| `git clone` | Қашықтағы репозиторийдің толық көшірмесін жасау |
| Тармақ (branch) | Жобаның параллель даму жолы |
| `main` | Әрқашан жұмыс істейтін негізгі тармақ |
| Merge | Бір тармақтың өзгерістерін екіншісіне біріктіру |
| Pull Request (PR) | Тармақты біріктіруге GitHub-тағы өтініш |
| Code review | Командаластың кодын оқып тексеру |
| Merge conflict | Екі өзгеріс бір жолда кездескенде туатын қақтығыс |
| `origin` | Қашықтағы (GitHub-тағы) репозиторийдің әдепкі атауы |
| `.gitignore` | Git бақыламайтын файлдар тізімі |

## Ескерту

- `git switch` және `git restore` Git 2.23 нұсқасында шамадан тыс жүктелген `git checkout` командасының орнына пайда болды; ескі нұсқаулықтарда кездесетін `git checkout -b feature/x` — `git switch -c feature/x`-пен бірдей.
- `git pull` = `git fetch` + `git merge`. `git pull --rebase` нұсқасы сіздің коммиттеріңізді жаңаларының үстіне көшіріп, тарихты сызықтық етеді, бірақ оны жарияланған ортақ тармақтарға қолдануға болмайды.
- Шешілмеген қақтығысы бар Python файлдары іске қосылмайды (`SyntaxError`), ал `.json`, `.txt` және `.md` файлдарында `<<<<<<<` белгілері байқалмай қалуы мүмкін — коммит алдында оларды `git diff --check` немесе `git grep "<<<<<<<"` арқылы іздеңіз.
- `.gitignore` бұрыннан бақыланып жүрген файлдарға әсер етпейді; оларды индекстен `git rm --cached` командасымен алып тастау керек.
- Барлық мүшеде орта бірдей болуы үшін репозиторийге `requirements.txt` салынады (`pip freeze > requirements.txt` арқылы жасалады), ал `.venv` папкасының өзі — ешқашан.
- Ресми құжаттама: https://git-scm.com/doc және Python модульдері туралы бөлім https://docs.python.org/3/tutorial/modules.html
