## 2. Markdown — құжаттаманың тілі

**Markdown** — қарапайым мәтінге белгілер қосу арқылы пішімдеу тілі. GitHub `.md` файлдарын әдемі бет ретінде көрсетеді.

```markdown
# 1-деңгейлі тақырып
## 2-деңгейлі тақырып
### 3-деңгейлі тақырып

Қарапайым абзац. **Қалың мәтін**, *курсив*, `код_сөзі`.

- нүктелі тізім
- екінші элемент
  - ішкі элемент

1. нөмірленген тізім
2. екінші қадам

[Сілтеме мәтіні](https://github.com)
![Суреттің сипаттамасы](images/screenshot.png)

> Ескерту немесе дәйексөз

| Баған 1 | Баған 2 |
|---|---|
| мән | мән |

- [x] орындалған тапсырма
- [ ] орындалмаған тапсырма
```

Код блогы үш кері тырнақшамен (```` ``` ````) жазылып, тілі көрсетіледі (` ```python `, ` ```bash `) — сонда GitHub синтаксисті түспен бөледі.

VS Code-та `.md` файлды ашып, `Ctrl+Shift+V` бассаңыз — дайын көрінісін көресіз.

## 3. README.md құрылымы

### README жазу ережелері

1. **Бірінші абзац** — жобаның не істейтінін 1–2 сөйлеммен айтады.
2. **Скриншот немесе GIF** — мың сөзден артық (GUI, ойын, графиктер).
3. **Орнату командалары** — көшіріп қоюға дайын, тексерілген. Таза компьютерде (немесе жаңа venv-те) өзіңіз бір рет орындап көріңіз!
4. **Қысқа әрі құрылымды** — ұзақ мәтін емес, тақырыптар мен тізімдер.
5. **Жаңартып отыру** — код өзгерсе, README де өзгереді.
6. Құпия деректер (пароль, API кілті) README-де болмауы керек; оның орнына `.env.example` үлгісін көрсету.

## 4. Пайдаланушы нұсқаулығы

Пайдаланушы нұсқаулығы — бағдарламашы емес адамға арналған. Ол «код», «функция», «терминал» сөздерін білмеуі мүмкін.

**Құрылымы:**
1. **Кіріспе** — бағдарлама кімге және не үшін.
2. **Іске қосу** — қарапайым қадамдар (мүмкін болса, «белгішені екі рет басыңыз»).
3. **Негізгі сценарийлер** — «Қалай ... жасауға болады?» түрінде; әр сценарий — нөмірленген қадамдар + скриншот.
4. **Жиі қойылатын сұрақтар (FAQ) / Ақаулар** — «Бағдарлама ашылмаса не істеу керек?»
5. **Байланыс** — қатені кімге хабарлау керек.

### Үлгі фрагмент

```markdown
## Жаңа кітапты қалай қосуға болады?

1. Басты терезеде **«Кітап қосу»** батырмасын басыңыз.
2. Ашылған терезеде кітаптың **атауын**, **авторын** және **жылын** енгізіңіз.
   Жыл — 4 цифр (мысалы, 2019).
3. **«Сақтау»** батырмасын басыңыз.
4. Кітап кестенің соңында пайда болады.

![Кітап қосу терезесі](images/add_book.png)

> **Назар аударыңыз:** атау өрісі бос болса, бағдарлама «Атауын енгізіңіз» деген ескерту береді.

## Жиі қойылатын сұрақтар

**Деректерім қайда сақталады?**
Барлық дерек `library.db` файлында. Оның көшірмесін жасау үшін **Файл → Сақтық көшірме** мәзірін таңдаңыз.
```

**Жақсы нұсқаулық белгілері:** етістіктің бұйрық райы («басыңыз», «енгізіңіз»); бір қадам — бір әрекет; батырма атаулары бағдарламадағыдай, қалың әріппен; әр күрделі қадамға скриншот.

## 5. Талаптар тізімі: `requirements.txt`

Жобаңыз `pandas`, `matplotlib`, `requests` кітапханаларын қолданса, басқа адам оларды орнатуы керек. Оларды қолмен тізбелемей, **талаптар файлы** жасаймыз.

### Жасау

venv белсенді болғанда:

```bash
pip freeze > requirements.txt
```

`requirements.txt` мазмұны (мысал):
```text
contourpy==1.3.1
matplotlib==3.9.2
numpy==2.1.3
pandas==2.2.3
requests==2.32.3
```

`==` — нақты нұсқа («бекітілген», pinned). Бұл жоба бір жылдан кейін де дәл сол нұсқалармен орнатылатынына кепілдік береді.

### Орнату

```bash
pip install -r requirements.txt
```

### Ескертулер

- `pip freeze` venv-ке **орнатылған барлық** пакетті жазады, оның ішінде тәуелділіктердің тәуелділіктерін де. Қажет болса, тек тікелей импорттайтын кітапханаларды қолмен жазуға болады: `pandas>=2.0`.
- Python-ның стандартты кітапханалары (`tkinter`, `sqlite3`, `csv`, `json`, `unittest`, `logging`) `requirements.txt`-ке **жазылмайды** — олар Python-мен бірге келеді.
- venv-ті жаһандық Python-да емес, venv **ішінде** `pip freeze` жасаңыз — әйтпесе компьютердегі бар-жоқ пакет түгел тізімге түседі.
- `venv/` папкасы GitHub-қа **жүктелмейді** (`.gitignore`), оның орнына `requirements.txt` жүктеледі.

**Жүйелік талаптар** (README-дегі «Талаптар» бөлімі) — Python нұсқасы, операциялық жүйе, экран ажыратымдылығы, интернет қажеттілігі т.б. Python нұсқасын білу: `python --version`.

## 6. Код ішіндегі құжаттама: docstring

Docstring — функция, класс немесе модуль басындағы `"""..."""` мәтіні. Ол кодпен бірге сақталады және `help()` арқылы оқылады.

```python
def tusim_esepte(baga, sany, zhenildik=0):
    """Тауар түсімін есептейді.

    Args:
        baga (float): бір дананың бағасы, теңге.
        sany (int): сатылған дана саны.
        zhenildik (float): жеңілдік пайызы, 0..100. Әдепкі мәні 0.

    Returns:
        float: жеңілдікті ескергендегі түсім.

    Raises:
        ValueError: жеңілдік 0..100 аралығынан тыс болса.
    """
    if not 0 <= zhenildik <= 100:
        raise ValueError("Жеңілдік 0..100 аралығында болуы керек")
    return baga * sany * (1 - zhenildik / 100)


help(tusim_esepte)
print(tusim_esepte.__doc__.splitlines()[0])
```

Нәтижесі (соңғы жол):
```text
Тауар түсімін есептейді.
```

Терминалда модульдің барлық docstring-ін көру: `python -m pydoc <модуль_аты>`; HTML бет жасау: `python -m pydoc -w <модуль_аты>`.

**Түсініктеме (`#`) мен docstring айырмашылығы:** docstring — функция **не істейді** және **қалай қолдану керек** (сырттан қарағанда); түсініктеме — кодтың ішінде **неге** осылай жазылғаны.

## Жиі кездесетін қателер

**1. README-де тек жоба атауы.** GitHub автоматты жасаған `# my-project` деген бір жол — бұл README емес.

**2. Тексерілмеген командалар.** README-де `python app.py` жазылған, бірақ файл аты `main.py`. Әр команданы көшіріп, өзіңіз орындап көріңіз.

**3. Суреттің абсолютті жолы.** `![](C:/Users/Aliya/Desktop/1.png)` — GitHub-та көрінбейді. Дұрысы — репозиторий ішіндегі салыстырмалы жол: `![](images/1.png)`, ал сурет файлы да репозиторийге жүктелуі керек.

**4. `pip freeze` жаһандық ортада.** 150 жолдық `requirements.txt` пайда болады. venv-ті белсендіріп барып жасаңыз.

**5. Кодты түсініктемемен «қайталау».**
```python
i = i + 1    # i-ге 1 қосамыз
```
Бұл ештеңе түсіндірмейді. Жақсы түсініктеме — **неге**:
```python
i = i + 1    # тақырып жолын өткізіп жібереміз
```

## Ескерту

- Файл репозиторий түбірінде (немесе `.github/`, `docs/` қалтасында) жатса, GitHub README-ді автоматты түрде көрсетеді; атау регистрге тәуелсіз, бірақ `README.md` деп жазу қабылданған.
- Markdown-да тізім, кесте және код блогы алдында бос жол қажет — әйтпесе GitHub-та олар алдыңғы абзацпен қосылып кетуі мүмкін.
- Қолданба кітапханалары үшін қатаң `==` орнына кейде ауқым жазылады: `pandas>=2.0,<3.0` — жоба түзетулерді алады, бірақ үйлесімсіз негізгі нұсқада бұзылмайды.
- Docstring [PEP 257](https://peps.python.org/pep-0257/) бойынша рәсімделеді: бірінші жол — бір сөйлеммен қысқа сипаттама, содан кейін бос жол және толығырақ; үш қос тырнақша `"""` қолданыңыз.
- `Args:`/`Returns:`/`Raises:` бөлімдерінің пішімі — Google стилі; NumPy және reStructuredText (Sphinx) стильдері де кең таралған. Бір жобада бір стильді қолданыңыз.
- Құжаттама: [pydoc](https://docs.python.org/3/library/pydoc.html), [GitHub Flavored Markdown](https://github.github.com/gfm/), [Requirements File Format](https://pip.pypa.io/en/stable/reference/requirements-file-format/).
