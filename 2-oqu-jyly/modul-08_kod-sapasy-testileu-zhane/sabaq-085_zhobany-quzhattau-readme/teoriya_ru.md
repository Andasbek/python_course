## 1. Виды документации

| Вид | Читатель | Содержание | Где |
|---|---|---|---|
| README.md | Любой человек, впервые пришедший в проект | Что, зачем, как установить, как запустить | В корне репозитория |
| Руководство пользователя | Человек, пользующийся программой (не программист!) | Пошаговые действия, скриншоты, частые вопросы | `docs/user_guide.md` или раздел README |
| Список требований | Тот, кто устанавливает / компьютер | Версия Python, библиотеки | `requirements.txt` |
| Документация разработчика | Программист, продолжающий код | Архитектура, модули, функции | docstring, `docs/` |
| Комментарии (`#`) | Тот, кто читает код | «Почему сделано именно так» | Внутри кода |
| Журнал изменений | Пользователь и разработчик | Что изменилось по версиям | `CHANGELOG.md` |

## 2. Markdown — язык документации

**Markdown** — язык форматирования с помощью меток в обычном тексте. GitHub показывает файлы `.md` как красиво оформленные страницы.

```markdown
# Заголовок 1-го уровня
## Заголовок 2-го уровня
### Заголовок 3-го уровня

Обычный абзац. **Жирный текст**, *курсив*, `слово_кода`.

- маркированный список
- второй элемент
  - вложенный элемент

1. нумерованный список
2. второй шаг

[Текст ссылки](https://github.com)
![Описание изображения](images/screenshot.png)

> Примечание или цитата

| Столбец 1 | Столбец 2 |
|---|---|
| значение | значение |

- [x] выполненная задача
- [ ] невыполненная задача
```

Блок кода пишется в тройных обратных кавычках (```` ``` ````) с указанием языка (` ```python `, ` ```bash `) — тогда GitHub подсвечивает синтаксис цветом.

Если открыть файл `.md` в VS Code и нажать `Ctrl+Shift+V` — увидите готовый вид.

## 3. Структура README.md

README — «лицо» и «визитная карточка» проекта. Хороший README отвечает на 5 вопросов: **Что это? Зачем? Как установить? Как пользоваться? Кто сделал?**

### Образец README

````markdown
# Школьная библиотека

Оконное приложение для учёта книг и читателей школьной библиотеки
(Tkinter + SQLite).

![Главное окно](images/main_window.png)

- экспорт данных в CSV.

## Требования
- Python 3.10 или новее
- Windows 10/11, macOS или Linux

## Установка

## Запуск

```
````

### Правила написания README

1. **Первый абзац** — 1–2 предложения о том, что делает проект.
2. **Скриншот или GIF** — лучше тысячи слов (GUI, игра, графики).
3. **Команды установки** — готовые к копированию, проверенные. Выполните их сами один раз на чистом компьютере (или в новом venv)!
4. **Кратко и структурировано** — не длинный текст, а заголовки и списки.
5. **Обновляйте** — меняется код, меняется и README.
6. Секретных данных (пароль, API-ключ) в README быть не должно; вместо этого показывайте образец `.env.example`.

## 4. Руководство пользователя

Руководство пользователя предназначено для человека, который не является программистом. Он может не знать слов «код», «функция», «терминал».

**Структура:**
1. **Введение** — для кого и для чего программа.
2. **Запуск** — простые шаги (по возможности «дважды щёлкните по значку»).
3. **Основные сценарии** — в виде «Как сделать ...?»; каждый сценарий — нумерованные шаги + скриншот.
4. **Часто задаваемые вопросы (FAQ) / Неполадки** — «Что делать, если программа не открывается?»
5. **Контакты** — кому сообщать об ошибке.

### Образец фрагмента

```markdown
## Как добавить новую книгу?

1. В главном окне нажмите кнопку **«Добавить книгу»**.
2. В открывшемся окне введите **название**, **автора** и **год** книги.
   Год — 4 цифры (например, 2019).
3. Нажмите кнопку **«Сохранить»**.
4. Книга появится в конце таблицы.

![Окно добавления книги](images/add_book.png)

> **Обратите внимание:** если поле названия пустое, программа выдаст предупреждение «Введите название».

## Часто задаваемые вопросы

**Где хранятся мои данные?**
Все данные — в файле `library.db`. Чтобы сделать его копию, выберите меню **Файл → Резервная копия**.
```

**Признаки хорошего руководства:** повелительное наклонение глаголов («нажмите», «введите»); один шаг — одно действие; названия кнопок — как в программе, жирным шрифтом; к каждому сложному шагу — скриншот.

## 5. Список требований: `requirements.txt`

Если ваш проект использует библиотеки `pandas`, `matplotlib`, `requests`, другой человек должен их установить. Вместо того чтобы перечислять их вручную, создаём **файл требований**.

### Создание

При активированном venv:

```bash
pip freeze > requirements.txt
```

Содержимое `requirements.txt` (пример):
```text
contourpy==1.3.1
matplotlib==3.9.2
numpy==2.1.3
pandas==2.2.3
requests==2.32.3
```

`==` — точная версия («закреплённая», pinned). Это гарантирует, что проект и через год установится именно с этими версиями.

### Установка

```bash
pip install -r requirements.txt
```

### Примечания

- `pip freeze` записывает **все установленные** в venv пакеты, включая зависимости зависимостей. При необходимости можно вручную записать только непосредственно импортируемые библиотеки: `pandas>=2.0`.
- Стандартные библиотеки Python (`tkinter`, `sqlite3`, `csv`, `json`, `unittest`, `logging`) в `requirements.txt` **не записываются** — они поставляются вместе с Python.
- Делайте `pip freeze` **внутри** venv, а не в глобальном Python — иначе в список попадут все пакеты, какие есть на компьютере.
- Папка `venv/` на GitHub **не загружается** (`.gitignore`), вместо неё загружается `requirements.txt`.

**Системные требования** (раздел «Требования» в README) — версия Python, операционная система, разрешение экрана, необходимость интернета и т.д. Узнать версию Python: `python --version`.

## 6. Документация внутри кода: docstring

Docstring — текст `"""..."""` в начале функции, класса или модуля. Он хранится вместе с кодом и читается через `help()`.

```python
def tusim_esepte(baga, sany, zhenildik=0):
    """Вычисляет выручку от товара.

    Args:
        baga (float): цена одной штуки, тенге.
        sany (int): количество проданных штук.
        zhenildik (float): процент скидки, 0..100. По умолчанию 0.

    Returns:
        float: выручка с учётом скидки.

    Raises:
        ValueError: если скидка вне диапазона 0..100.
    """
    if not 0 <= zhenildik <= 100:
        raise ValueError("Скидка должна быть в диапазоне 0..100")
    return baga * sany * (1 - zhenildik / 100)


help(tusim_esepte)
print(tusim_esepte.__doc__.splitlines()[0])
```

Результат (последняя строка):
```text
Вычисляет выручку от товара.
```

Посмотреть все docstring модуля в терминале: `python -m pydoc <имя_модуля>`; создать HTML-страницу: `python -m pydoc -w <имя_модуля>`.

**Разница между комментарием (`#`) и docstring:** docstring — **что делает** функция и **как её использовать** (взгляд снаружи); комментарий — внутри кода, **почему** написано именно так.

## 7. Чек-лист документации

| № | Проверка |
|---|---|
| 1 | Первый абзац README говорит, что делает проект |
| 2 | Есть скриншот/GIF (для GUI, игр, графиков) |
| 3 | Есть разделы «Требования», «Установка», «Запуск», команды проверены |
| 4 | Есть `requirements.txt`, и он создан внутри venv |
| 5 | Руководство пользователя понятно человеку, не являющемуся программистом |
| 6 | У всех функций и классов есть docstring |
| 7 | Описана структура проекта |
| 8 | Указано, как запускать тесты |
| 9 | Указаны автор и год |
| 10 | Нет секретных данных |

## Частые ошибки

**1. В README только название проекта.** Одна строка `# my-project`, автоматически созданная GitHub, — это не README.

**2. Непроверенные команды.** В README написано `python app.py`, а файл называется `main.py`. Скопируйте и выполните каждую команду сами.

**3. Абсолютный путь к изображению.** `![](C:/Users/Aliya/Desktop/1.png)` — на GitHub не отображается. Правильно — относительный путь внутри репозитория: `![](images/1.png)`, причём файл изображения тоже должен быть загружен в репозиторий.

**4. `pip freeze` в глобальной среде.** Получается `requirements.txt` из 150 строк. Создавайте его, только активировав venv.

**5. «Повторение» кода комментарием.**
```python
i = i + 1    # прибавляем к i единицу
```
Это ничего не объясняет. Хороший комментарий — **почему**:
```python
i = i + 1    # пропускаем строку заголовка
```

## Основные понятия

| Понятие | Объяснение |
|---|---|
| Документация | Тексты, помогающие понять, установить и использовать программу |
| README.md | Основное описание проекта, главная страница репозитория |
| Markdown | Язык форматирования обычного текста (`#`, `**`, `-`, `![]()`) |
| Руководство пользователя | Пошаговая инструкция по использованию программы |
| `requirements.txt` | Список библиотек и версий, необходимых проекту |
| `pip freeze` | Вывод установленных пакетов с их версиями |
| Docstring | Встроенное описание функции/класса |
| FAQ | Часто задаваемые вопросы и ответы |

## Примечание

- GitHub отображает README автоматически, если файл лежит в корне репозитория (или в папке `.github/`, `docs/`); имя регистронезависимо, но принято `README.md`.
- В Markdown пустая строка нужна перед списком, таблицей и блоком кода — иначе на GitHub они могут слиться с предыдущим абзацем.
- Вместо жёсткого `==` для библиотек приложения иногда пишут диапазон: `pandas>=2.0,<3.0` — так проект получает исправления, но не ломается на несовместимой мажорной версии.
- Docstring оформляют по [PEP 257](https://peps.python.org/pep-0257/): первая строка — краткое описание в одну фразу, затем пустая строка и подробности; используйте тройные двойные кавычки `"""`.
- Формат разделов `Args:`/`Returns:`/`Raises:` — это стиль Google; также распространены стили NumPy и reStructuredText (Sphinx). Внутри одного проекта используйте один стиль.
- Документация: [pydoc](https://docs.python.org/3/library/pydoc.html), [GitHub Flavored Markdown](https://github.github.com/gfm/), [Requirements File Format](https://pip.pypa.io/en/stable/reference/requirements-file-format/).
