## 1. Три принципа информационной безопасности (CIA)

| Принцип | Значение | Пример нарушения | Защита |
|---|---|---|---|
| **Конфиденциальность** (Confidentiality) | Информацию видит только тот, у кого есть разрешение | Утечка базы паролей | Хэширование, шифрование, ограничение доступа |
| **Целостность** (Integrity) | Информация не изменяется без разрешения | Кто-то изменил оценку в журнале | Проверка, логирование, резервное копирование, хэш |
| **Доступность** (Availability) | Информация доступна, когда нужна | Сервер упал, сайт не открывается | Резервная копия, резервный сервер |

## 2. Хранение секретных данных отдельно от кода

**Секретные данные** (секреты): API-ключи, пароль базы данных, токены, токен бота (Telegram), пароль электронной почты.

**Главное правило:** секрет **никогда** не должен находиться в коде, README, на скриншоте, в логе и в истории Git.

### Через переменные окружения

```python
import os

api_key = os.environ.get("WEATHER_API_KEY")
if api_key is None:
    print("Ошибка: переменная окружения WEATHER_API_KEY не задана")
else:
    print("Ключ загружен, длина:", len(api_key))   # сам ключ никогда не выводим!
```

Файл `.env` + библиотека `python-dotenv` (`pip install python-dotenv`):

```text
# .env  (этот файл в .gitignore!)
WEATHER_API_KEY=sk-...
DB_PASSWORD=...
```

```python
import os

from dotenv import load_dotenv

load_dotenv()                          # загружает значения из файла .env в переменные окружения
api_key = os.getenv("WEATHER_API_KEY")
```

В репозиторий загружаем образец **`.env.example`** (без значений), другие копируют его и вписывают свой ключ:

```text
WEATHER_API_KEY=впишите_сюда_свой_ключ
```

### Если секрет случайно опубликован

1. **Немедленно** сделайте ключ недействительным («Revoke / Regenerate» на сайте сервиса). Это самый важный шаг!
2. Получите новый ключ и запишите его в `.env`.
3. Уберите файл из кода и добавьте его в `.gitignore`.

Просто удалить файл и сделать новый коммит **недостаточно**: в старых коммитах ключ сохраняется и виден через `git log -p`.

## 3. Пароли

### Ввод пароля: `getpass`

```python
from getpass import getpass

parol = getpass("Пароль: ")      # вводимые символы в терминале не отображаются
```

(В некоторых окнах вывода VS Code `getpass` может выдавать предупреждение — запускайте в обычном терминале.)

### Пароль никогда не храним в открытом виде

Если база данных утечёт, открытые пароли будут сразу украдены. Поэтому храним **хэш**.

**Хэш-функция** превращает любой текст в «отпечаток пальца» фиксированной длины:
- из одного и того же текста всегда получается один и тот же хэш;
- восстановить исходный текст по хэшу невозможно (одностороннее преобразование);
- изменение одного символа полностью меняет хэш.

```python
import hashlib

print(hashlib.sha256("qwerty123".encode()).hexdigest())
print(hashlib.sha256("qwerty124".encode()).hexdigest())
```

Результат:
```text
daaad6e5604e8e17bd9f108d91e26afe6281dac8fda0091040a7a6d7bd9b43b5
45163e5dd5f90a71b49d4f9d3dd0b3ec40e576f7795bc26e0decf337cafba5d1
```

**Хэширование ≠ шифрование.** Зашифрованный текст можно расшифровать ключом; «расшифровать» хэш невозможно. При входе введённый пароль снова хэшируем и сравниваем с сохранённым хэшем.

### Соль (salt) и медленный хэш

Простого SHA-256 недостаточно: (1) если у двух людей одинаковые пароли, одинаковы и хэши; (2) злоумышленники используют готовые таблицы хэшей популярных паролей; (3) SHA-256 слишком **быстрый** — можно проверять миллиарды вариантов в секунду.

Решение:
- **соль** — случайная строка для каждого пользователя, она добавляется к паролю при хэшировании и хранится вместе с хэшем;
- **медленный хэш** — `hashlib.pbkdf2_hmac` повторяет хэширование сотни тысяч раз; законный пользователь этого не замечает, а для злоумышленника, перебирающего миллионы вариантов, это обходится очень дорого.

```python
import hashlib
import hmac
import secrets

QAITALAU = 200_000


def parol_hashtau(parol):
    """Возвращает соль и хэш пароля (оба — hex-строки)."""
    tuz = secrets.token_bytes(16)
    hash_bytes = hashlib.pbkdf2_hmac("sha256", parol.encode(), tuz, QAITALAU)
    return tuz.hex(), hash_bytes.hex()


def parol_tekseru(parol, tuz_hex, hash_hex):
    """Проверяет, соответствует ли введённый пароль сохранённому хэшу."""
    zhana = hashlib.pbkdf2_hmac("sha256", parol.encode(), bytes.fromhex(tuz_hex), QAITALAU)
    return hmac.compare_digest(zhana.hex(), hash_hex)


tuz, h = parol_hashtau("Almaty#2027")
print("Соль:", tuz)
print("Хэш:", h[:20] + "...")
print(parol_tekseru("Almaty#2027", tuz, h))
print(parol_tekseru("almaty#2027", tuz, h))
```

Результат (соль и хэш при каждом запуске разные):
```text
Соль: 3f9a1c0b7e5d42a8916c0de4b2f57a13
Хэш: 8c41e0a9b3f2d7615e0c...
True
False
```

`hmac.compare_digest` выполняет сравнение за постоянное время, поэтому злоумышленник не сможет подобрать хэш по времени ответа. В профессиональных проектах используются также библиотеки `bcrypt` или `argon2`.

### Не `random`, а `secrets`

Модуль `random` предназначен для игр и моделирования — его результат можно предсказать. Для паролей, токенов, кодов подтверждения — **`secrets`**:

```python
import secrets
import string

alfavit = string.ascii_letters + string.digits + "!@#$%&*"
parol = "".join(secrets.choice(alfavit) for _ in range(14))
print("Новый пароль:", parol)
print("Токен:", secrets.token_urlsafe(16))
print("SMS-код:", f"{secrets.randbelow(1_000_000):06d}")
```

### Правила надёжного пароля

- не менее 12 символов; длина важнее сложности;
- строчные и заглавные буквы, цифры, специальные символы;
- не словарное слово, не дата рождения, не имя, не `123456`, не `qwerty`;
- для каждого сайта — **отдельный** пароль (если один сайт утечёт, остальные в безопасности);
- менеджер паролей и **двухфакторная аутентификация** (2FA) — код в SMS или в приложении.

**Секретная фраза** (passphrase): `Утром-пью-3-чашки-чая!` — легко запомнить, трудно взломать.

## 4. SQL-инъекция

При работе с базой данных (например, SQLite) составлять запрос через f-строку — **опасно**:

```python
import sqlite3

conn = sqlite3.connect(":memory:")
conn.execute("CREATE TABLE users (login TEXT, parol_hash TEXT)")
conn.execute("INSERT INTO users VALUES ('aliya', 'x'), ('erlan', 'y')")

login = "' OR '1'='1"                                     # «логин» злоумышленника
qauipti = f"SELECT * FROM users WHERE login = '{login}'"
print(conn.execute(qauipti).fetchall())                   # ВСЕ пользователи!

qauipsiz = "SELECT * FROM users WHERE login = ?"
print(conn.execute(qauipsiz, (login,)).fetchall())        # никто не найден
```

Результат:
```text
[('aliya', 'x'), ('erlan', 'y')]
[]
```

В f-строке ввод становится **частью кода** SQL: `WHERE login = '' OR '1'='1'` — всегда истинно. В параметризованном запросе (`?`) ввод всегда воспринимается как **значение**. Правило: значение, пришедшее от пользователя, передаём в SQL только через `?`.

Общее правило — **никогда не доверяй пользовательскому вводу**: проверяй длину, тип, формат (валидация).

## 5. Персональные данные и этика

### Что такое персональные данные

**Персональные (личные) данные** — любая информация, позволяющая прямо или косвенно установить личность человека: ФИО, ИИН, телефон, адрес, фото, дата рождения, геолокация, оценки, сведения о здоровье.

В Казахстане эта сфера регулируется **Законом РК «О персональных данных и их защите»** (2013 г.). В Европе — GDPR. Основные требования схожи.

### Принципы обработки данных

| Принцип | Значение | Что делает программист |
|---|---|---|
| **Согласие** | Человек даёт согласие на сбор своих данных | Отметка «Согласен» в форме регистрации, понятная цель |
| **Соответствие цели** | Данные используются только для заявленной цели | Не продавать данные опроса рекламщикам |
| **Минимизация** | Собираются только необходимые данные | Для игры не нужны ИИН и адрес |
| **Срок хранения** | Когда необходимость отпала, данные удаляются | Удаление старых отчётов |
| **Безопасность** | Данные защищены | Хэширование, ограничение доступа, резервное копирование |
| **Права субъекта** | Человек может увидеть, исправить свои данные и потребовать их удаления | Функция «Удалить аккаунт» |

### Сокрытие данных (анонимизация, маскирование)

Для анализа или отображения полные данные человека не нужны:

```python
def telefon_maska(tel):
    """Скрывает середину номера телефона: +7 701 *** ** 67"""
    cifr = "".join(c for c in tel if c.isdigit())
    return f"+7 {cifr[1:4]} *** ** {cifr[-2:]}"


def zhsn_maska(zhsn):
    """Оставляет только первые 6 цифр ИИН (дату рождения)."""
    return zhsn[:6] + "******"


print(telefon_maska("+7 (701) 555-12-67"))
print(zhsn_maska("050315501230"))
```

Результат:
```text
+7 701 *** ** 67
050315******
```

**Анонимизация** — сделать так, чтобы установить личность было вообще невозможно (удалить ФИО, превратить возраст в группу «15–17 лет»). **Псевдонимизация** — заменить имя кодом (`Ученик_017`), таблица кодов хранится отдельно, в защищённом месте.

### Этические вопросы

Закон охватывает не всё. Каждый программист должен задавать себе вопросы:
- Знает ли человек, что я собираю эти данные? Не был бы он против?
- Кому будет нанесён вред, если эта информация утечёт?
- Не дискриминирует ли моя программа кого-либо (например, по полу, национальности)?
- Не использую ли я этот код для несанкционированного доступа к чужой учётной записи?

**Помните:** несанкционированный доступ к чужому аккаунту, компьютеру, сети — даже «ради игры», «ради проверки» — влечёт ответственность по Уголовному кодексу РК. Проверять безопасность можно только в **своей** системе или с письменного разрешения владельца.

## 6. Чек-лист безопасного кода

| № | Проверка |
|---|---|
| 1 | В коде, README, логе нет секретов (ключей, паролей, токенов) |
| 2 | `.env`, `*.db`, `*.log`, `venv/` — в `.gitignore` |
| 3 | Пароли хранятся в виде медленного хэша с солью |
| 4 | Случайные секретные значения создаются через `secrets` |
| 5 | SQL-запросы только параметризованные (`?`) |
| 6 | Пользовательский ввод проверяется (тип, длина, формат) |
| 7 | Собираются только необходимые персональные данные, получено согласие |
| 8 | Персональные данные, выводимые на экран или в отчёт, замаскированы |
| 9 | Есть резервная копия базы данных |
| 10 | Сообщения об ошибках не раскрывают внутреннюю информацию (пути, структуру) |

## Частые ошибки

**1. Записать ключ в код и сказать «потом уберу».**
```python
API_KEY = "sk-live-12345abcdef"      # один раз сделали push — ключ опубликован
```
Правильно:
```python
import os

API_KEY = os.getenv("API_KEY")
```

**2. Хранение пароля в открытом виде или запись его в лог.**
```python
import logging

parol = "Almaty#2027"
logging.info("Попытка входа: login=aliya, parol=%s", parol)    # НЕЛЬЗЯ!
```
В лог пишем только логин и результат: `logging.info("Попытка входа: login=%s, успешно=%s", "aliya", False)`.

**3. Использование `random` для пароля** — его результат можно предсказать. Используйте `secrets`.

**4. MD5/SHA-256 без соли** — подбирается за несколько секунд по готовым таблицам.

**5. Раздельные сообщения «Неверный пароль» и «Такого пользователя нет».** Так злоумышленник узнаёт, какие логины существуют. Одно сообщение: «Неверный логин или пароль».

## Основные понятия

| Понятие | Объяснение |
|---|---|
| Триада CIA | Конфиденциальность, целостность, доступность |
| Секрет (secret) | Ключ, пароль, токен — значение, которое нельзя публиковать |
| Переменная окружения | Значение настройки, хранящееся в системе вне кода |
| Хэш | Односторонний «отпечаток» текста |
| Соль (salt) | Случайная строка, добавляемая к паролю перед хэшированием |
| `secrets` | Модуль криптографически безопасных случайных значений |
| SQL-инъекция | Атака с изменением SQL-запроса через ввод |
| Персональные данные | Информация, позволяющая установить личность человека |
| Анонимизация / маскирование | Устранение возможности установить личность по данным / частичное сокрытие |
| 2FA | Двухфакторная аутентификация |

## Примечание

- `load_dotenv()` по умолчанию **не перезаписывает** переменные окружения, которые уже заданы в системе; чтобы значения из `.env` имели приоритет, используйте `load_dotenv(override=True)`.
- Если файл с секретом уже попал в Git, `.gitignore` его не скроет: файл нужно убрать из индекса командой `git rm --cached .env`, а ключ — отозвать.
- Для `pbkdf2_hmac` с SHA-256 OWASP рекомендует сотни тысяч итераций (ориентир — 600 000); число итераций храните вместе с солью и хэшем, чтобы позже его можно было увеличить.
- В Python 3.6+ модуль `secrets` — стандартный способ получать криптостойкие случайные значения; `random.seed()` делает последовательность `random` полностью воспроизводимой, поэтому она непригодна для паролей.
- Параметризованные запросы защищают только **значения**; имена таблиц и столбцов через `?` передать нельзя — их выбирают из заранее заданного списка допустимых имён.
- Документация: [secrets](https://docs.python.org/3/library/secrets.html), [hashlib](https://docs.python.org/3/library/hashlib.html), [sqlite3 — placeholders](https://docs.python.org/3/library/sqlite3.html#sqlite3-placeholders).
