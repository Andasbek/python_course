## 1. Қателердің үш түрі

| Түрі | Қашан табылады | Мысал | Табу қиындығы |
|---|---|---|---|
| Синтаксистік (SyntaxError) | Іске қоспас бұрын | Қос нүкте ұмытылған, жақша жабылмаған | Оңай — Python өзі көрсетеді |
| Орындалу кезіндегі (runtime, exception) | Орындау барысында | 0-ге бөлу, жоқ кілт, жоқ файл | Орташа — Traceback көмектеседі |
| Логикалық | Ешқашан өзі табылмайды! | Орташаны есептегенде бір элементке аз бөлу | Қиын — бағдарлама «жұмыс істейді», бірақ жауабы қате |

Логикалық қате мысалы:

```python
bagalar = [5, 4, 3, 5]
ortasha = sum(bagalar) / (len(bagalar) - 1)    # қате: -1 артық
print("Орташа:", ortasha)
```

Нәтижесі:
```text
Орташа: 5.666666666666667
```

Бағдарлама қатесіз аяқталды, бірақ орташа баға 5-тен үлкен болуы мүмкін емес! Логикалық қатені табу үшін **күтілетін нәтижені алдын ала білу** керек.

## 2. Traceback-ті оқу

```python
def ortasha_ball(ballar):
    return sum(ballar) / len(ballar)


def synyp_esebi(synyptar):
    for atau, ballar in synyptar.items():
        print(atau, ortasha_ball(ballar))


synyp_esebi({"9А": [80, 90], "9Ә": []})
```

Нәтижесі:
```text
9А 85.0
Traceback (most recent call last):
  File "esep.py", line 10, in <module>
    synyp_esebi({"9А": [80, 90], "9Ә": []})
  File "esep.py", line 7, in synyp_esebi
    print(atau, ortasha_ball(ballar))
  File "esep.py", line 2, in ortasha_ball
    return sum(ballar) / len(ballar)
ZeroDivisionError: division by zero
```

**Төменнен жоғары қарай оқимыз:**
1. **Соңғы жол** — қатенің түрі мен сипаттамасы: `ZeroDivisionError: division by zero`.
2. **Оның үстіндегі жол** — қате нақты болған жер: `line 2, in ortasha_ball`.
3. **Жоғарырақ** — шақырулар тізбегі (стек): `<module>` → `synyp_esebi` → `ortasha_ball`. Бұл «қате қалай сол жерге жетті» дегенді көрсетеді.

Қорытынды: `9Ә` сыныбының ballar тізімі бос. Түзету — бос тізімді тексеру:

```python
def ortasha_ball(ballar):
    if not ballar:
        return 0
    return sum(ballar) / len(ballar)
```

## 3. Қате іздеудің жүйелі алгоритмі

```text
1. ҚАЙТАЛА      →  Қатені тұрақты түрде қайта шығар (қандай енгізуде?)
2. ОҚШАУЛА      →  Қатені тудыратын ең кішкентай кодты тап (minimal example)
3. БОЛЖАМ ЖАСА  →  «Менің ойымша, x айнымалысы осы жерде None болып тұр»
4. ТЕКСЕР       →  print / logging / debugger арқылы болжамды тексер
5. ТҮЗЕТ        →  Себепті түзет (симптомды емес!)
6. ҚАЙТА ТЕКСЕР →  Қате жойылды ма? Басқа жер бұзылмады ма? (автоматты тесттер)
```

**Пайдалы әдістер:**

- **Екіге бөлу (бисекция).** 200 жолдық кодтың ортасына `print` қойып, қате оған дейін бе, кейін бе — тексеру. Әр қадамда іздеу аймағы екі есе кішірейеді.
- **«Үйрек әдісі» (rubber duck debugging).** Кодты жол-жолымен ойыншыққа (немесе досыңызға) дауыстап түсіндіріңіз. Түсіндіру барысында қате өзі көрініп қалады — бұл шынымен жұмыс істейді!
- **Соңғы өзгерісті тексеру.** «Кеше жұмыс істеп тұрды» — `git diff` және `git log` арқылы не өзгергенін қараңыз.
- **Қате хабарламасын іздеу.** Соңғы жолды толығымен іздеу жүйесіне (немесе құжаттамаға) көшіру.
- **Деректерді тексеру.** Көп қате кодта емес, деректе: бос жол, артық бос орын, `"5"` (мәтін) мен `5` (сан).

### `print`-пен түзету (ең қарапайым)

```python
def zhenildik_baga(baga, paiyz):
    print(f"DEBUG: baga={baga!r}, paiyz={paiyz!r}")      # !r — типін де көрсетеді
    return baga - baga * paiyz / 100
```

`!r` пішімі `'500'` (мәтін) мен `500`-ді (сан) ажыратады — тип қателерін табуда өте пайдалы.

## 4. VS Code түзеткіші (debugger)

`print`-ті көп жерге қойып, кейін өшіру — ыңғайсыз. Түзеткіш бағдарламаны **кез келген жолда тоқтатып**, барлық айнымалыларды көрсетеді.

**Жұмыс реті:**
1. Жол нөмірінің сол жағын басып, **тоқтау нүктесін** (breakpoint, қызыл нүкте) қойыңыз.
2. `F5` (немесе «Run → Start Debugging» → «Python File»).
3. Бағдарлама тоқтау нүктесінде кідіреді. Сол жақтағы **VARIABLES** панелінде барлық айнымалылардың ағымдағы мәні көрінеді.
4. Басқару батырмалары:

| Батырма | Перне | Әрекеті |
|---|---|---|
| Continue | `F5` | Келесі тоқтау нүктесіне дейін жалғастыру |
| Step Over | `F10` | Келесі жолға өту (функцияның ішіне кірмей) |
| Step Into | `F11` | Шақырылған функцияның ішіне кіру |
| Step Out | `Shift+F11` | Ағымдағы функциядан шығу |
| Restart | `Ctrl+Shift+F5` | Қайта бастау |
| Stop | `Shift+F5` | Тоқтату |

5. **WATCH** панеліне өрнек жазып (мысалы, `len(ballar)`), оның мәнін бақылауға болады.
6. **CALL STACK** — Traceback сияқты, шақырулар тізбегі.
7. **Шартты тоқтау нүктесі:** қызыл нүктені тінтуірдің оң жағымен басып → «Edit Breakpoint» → `i == 57`. Цикл 57-айналымға жеткенде ғана тоқтайды.

Терминалда жұмыс істегенде — кіріктірілген `breakpoint()` функциясы (Python 3.7+) `pdb` түзеткішін іске қосады: `n` — келесі жол, `s` — ішіне кіру, `p x` — айнымалыны шығару, `c` — жалғастыру, `q` — шығу.

## 5. `assert` — өзіңді тексеру

`assert шарт, "хабарлама"` — шарт жалған болса, `AssertionError` шығарады. Бұл «бұл жерде міндетті түрде осылай болуы керек» деген болжамды кодқа жазу:

```python
def paiyz(bolik, butin):
    assert butin > 0, "Бүтіннің мәні оң болуы керек"
    return bolik / butin * 100


print(paiyz(25, 200))
```

Нәтижесі:
```text
12.5
```

`assert` пайдаланушының енгізуін тексеру үшін **емес** (оны `if` + хабарлама арқылы жасаймыз), бағдарламашының өз қателерін ерте табу үшін.

## 6. `logging` модулі

### Неге `print` жеткіліксіз?

| | `print` | `logging` |
|---|---|---|
| Маңыздылық деңгейі | Жоқ | 5 деңгей |
| Уақыт, файл, жол нөмірі | Қолмен | Автоматты |
| Өшіру/қосу | Әр жолды жою керек | Бір жолмен (`level=`) |
| Файлға жазу | Қолмен | `filename=` |
| Нақты жобаларда | Тек уақытша | Стандарт |

**Лог (журнал)** — бағдарламаның «күнделігі»: не болды, қашан, қай жерде. Сервер түнде құласа, бағдарламашы таңертең лог файлды оқып, себебін табады.

### Деңгейлер

| Деңгей | Сан | Қашан |
|---|---|---|
| `DEBUG` | 10 | Түзетуге арналған егжей-тегжей (айнымалылар мәні) |
| `INFO` | 20 | Қалыпты оқиғалар («Файл оқылды: 150 жол») |
| `WARNING` | 30 | Күтпеген, бірақ жұмыс жалғасады («3 бос мән толтырылды») |
| `ERROR` | 40 | Қате: бір әрекет орындалмады («Файл табылмады») |
| `CRITICAL` | 50 | Бағдарлама жұмысын жалғастыра алмайды |

Әдепкі деңгей — `WARNING`: одан төмендері (`DEBUG`, `INFO`) көрсетілмейді.

### Қарапайым мысал

```python
import logging

logging.basicConfig(
    level=logging.DEBUG,
    format="%(asctime)s | %(levelname)-8s | %(message)s",
    datefmt="%H:%M:%S",
)

logging.debug("Бағдарлама басталды")
logging.info("Пайдаланушы кірді: %s", "Әлия")
logging.warning("Пароль әлсіз")
logging.error("Деректер қорына қосылу мүмкін болмады")
```

Нәтижесі (уақыты өзгеше болады):
```text
10:15:02 | DEBUG    | Бағдарлама басталды
10:15:02 | INFO     | Пайдаланушы кірді: Әлия
10:15:02 | WARNING  | Пароль әлсіз
10:15:02 | ERROR    | Деректер қорына қосылу мүмкін болмады
```

Ескерту: `basicConfig` бағдарламада **бір рет** және ең басында шақырылады. `%s` арқылы мән беру f-жолдан тиімдірек (хабарлама көрсетілмесе, жол құрастырылмайды).

### Формат өрістері

| Өріс | Мағынасы |
|---|---|
| `%(asctime)s` | Уақыт |
| `%(levelname)s` | Деңгей атауы |
| `%(message)s` | Хабарлама |
| `%(name)s` | Логгер аты |
| `%(filename)s`, `%(lineno)d` | Файл аты, жол нөмірі |
| `%(funcName)s` | Функция аты |

### Файлға жазу және өз логгерің

```python
import logging

logging.basicConfig(
    filename="app.log",
    encoding="utf-8",
    level=logging.INFO,
    format="%(asctime)s [%(levelname)s] %(name)s:%(lineno)d — %(message)s",
)
logger = logging.getLogger(__name__)     # модульдің өз логгері


def bolu(a, b):
    logger.debug("bolu(%s, %s) шақырылды", a, b)
    try:
        natije = a / b
    except ZeroDivisionError:
        logger.exception("Нөлге бөлу әрекеті: a=%s", a)    # Traceback-пен бірге жазады
        return None
    logger.info("Нәтиже: %s", natije)
    return natije


bolu(10, 2)
bolu(5, 0)
```

`app.log` файлының мазмұны (шамамен):
```text
2027-03-29 10:20:11,532 [INFO] __main__:15 — Нәтиже: 5.0
2027-03-29 10:20:11,533 [ERROR] __main__:13 — Нөлге бөлу әрекеті: a=5
Traceback (most recent call last):
  File "app.py", line 11, in bolu
    natije = a / b
ZeroDivisionError: division by zero
```

`DEBUG` хабарламасы файлға түспеді, себебі `level=logging.INFO`. Түзету кезінде `level=logging.DEBUG` деп өзгертсеңіз — бәрі көрінеді. **Бір жолды** өзгерту арқылы!

`logger.exception(...)` тек `except` блогының ішінде қолданылады — ол `ERROR` деңгейімен жазып, Traceback-ті қосады.

### Логтау ережелері

- Құпия деректерді (пароль, API кілті, карта нөмірі) **ешқашан** логқа жазбаңыз.
- Хабарлама нақты болсын: «Қате» емес, «Файл табылмады: data/raw.csv».
- `app.log` файлын `.gitignore`-ға қосыңыз.

## Жиі кездесетін қателер

**1. Traceback-ті жоғарыдан оқу.** Ең маңызды ақпарат — соңғы екі жолда.

**2. Симптомды түзету.**
```python
try:
    ortasha = sum(ballar) / len(ballar)
except Exception:
    pass                     # қате «жоғалды», бірақ себебі қалды — одан да қауіпті
```
Дұрысы — себепті түзету (бос тізімді тексеру) немесе нақты қатені ұстап, логқа жазу:
```python
import logging

ballar = []
if ballar:
    ortasha = sum(ballar) / len(ballar)
else:
    logging.warning("Баллдар тізімі бос — орташа 0 деп алынды")
    ortasha = 0
```

**3. `basicConfig`-ті кеш шақыру.** Алдымен `logging.info(...)`, сосын `basicConfig(...)` — баптаулар қолданылмайды. `basicConfig` — ең басында.

**4. `logging.debug` көрінбейді.** Әдепкі деңгей `WARNING`. `level=logging.DEBUG` қосыңыз.

**5. Бірнеше нәрсені бір уақытта өзгерту.** Үш түзету енгіздіңіз, қате жойылды — қайсысы көмектесті? Бір уақытта — бір өзгеріс.

## Негізгі ұғымдар

| Ұғым | Түсіндірме |
|---|---|
| Баг (bug) | Бағдарламадағы қате |
| Debugging (түзету) | Қатені табу және жою үдерісі |
| Traceback | Қате болған жер мен шақырулар тізбегін көрсететін хабар |
| Логикалық қате | Бағдарлама қатесіз жұмыс істейді, бірақ нәтижесі қате |
| Тоқтау нүктесі (breakpoint) | Түзеткіш бағдарламаны тоқтататын жол |
| Step Over / Step Into | Келесі жолға өту / функция ішіне кіру |
| `assert` | Шарт жалған болса, қате шығаратын тексеру |
| Лог (журнал) | Бағдарлама оқиғаларының жазбасы |
| Логтау деңгейі | Хабарламаның маңыздылығы: DEBUG → CRITICAL |

## Ескерту

- Python 3.11-ден бастап Traceback қате болған жолдағы нақты өрнектің астын `^^^^` таңбаларымен сызады, ал 3.12–3.13 атаулардағы мүмкін қателерді ұсынады (`Did you mean: 'ballar'?`).
- `-O` жалаушасымен (`python -O app.py`) іске қосылған Python барлық `assert` нұсқаулықтарын **өткізіп жібереді**, сондықтан деректерді тексеру үшін оларға сенуге болмайды.
- Түбірлік логгерде өңдеушілер бұрыннан бар болса, `logging.basicConfig()` ештеңе істемейді; Python 3.8+ нұсқасында оны `force=True` параметрімен қайта баптауға болады.
- Кітапхана модульдерінде `logger = logging.getLogger(__name__)` қолданыңыз және `basicConfig` шақырмаңыз — логтауды басты бағдарлама баптайды.
- Үлкен лог-файлдар үшін `logging.handlers.RotatingFileHandler` бар: ол файл өлшемін шектейді және бірнеше ескі көшірмені сақтайды.
- Құжаттама: [Logging HOWTO](https://docs.python.org/3/howto/logging.html), [pdb — Python отладчигі](https://docs.python.org/3/library/pdb.html).
