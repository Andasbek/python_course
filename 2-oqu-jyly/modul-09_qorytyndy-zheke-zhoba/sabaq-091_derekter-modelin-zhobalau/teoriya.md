## 1. Деректер моделі дегеніміз не?

**Деректер моделі (модель данных, data model)** — бағдарлама қандай ақпаратты сақтайтынын, ол ақпарат қандай бөліктерге бөлінетінін және бөліктер бір-бірімен қалай байланысатынын сипаттайтын сызба.

Модель үш сұраққа жауап береді:

| Сұрақ | Ұғым | Мысал («Қалта ақшасы» жобасы) |
|---|---|---|
| Нені сақтаймыз? | **Мән** (entity) | Пайдаланушы, Санат, Операция |
| Оның қандай қасиеттері бар? | **Атрибут** (attribute) | Операцияның сомасы, күні, түсініктемесі |
| Олар қалай байланысқан? | **Байланыс** (relationship) | Бір санатта көп операция болады |

Осы тақырыптағы өтпелі мысал — «Қалта ақшасы» жобасы (кіріс пен шығысты есептейтін Tkinter + SQLite + Matplotlib + API қосымшасы). Дәл осы қадамдар кез келген жобаға қолданылады.

## 2. ТТ мәтінінен мәндерді табу

Қарапайым тәсіл — **зат есім мен етістік әдісі**:
- ТТ-дағы **зат есімдер** → мән немесе атрибут үміткерлері;
- **етістіктер** → байланыс немесе әрекет (функция) үміткерлері.

ТТ үзіндісі:
> «Пайдаланушы өзінің **кірісі** мен **шығысын** енгізеді. Әр **операцияның** **сомасы**, **күні**, **санаты** (тамақ, көлік, ойын-сауық) және **түсініктемесі** болады. Пайдаланушы айлық **лимит** қоя алады. Бағдарлама сомаларды **валюта бағамы** бойынша долларға аударып көрсетеді.»

Зат есімдерді сұрыптаймыз:

| Зат есім | Шешім | Себебі |
|---|---|---|
| Пайдаланушы | **Мән** | өз атрибуттары бар (аты, логин) |
| Операция | **Мән** | негізгі сақталатын ақпарат |
| Санат | **Мән** | бірнеше операцияға ортақ, өз аты мен түсі бар |
| Сома, күн, түсініктеме | Атрибут | бір мәннің қасиеттері |
| Кіріс/шығыс | Атрибут (`kind`) | операцияның түрі ғана |
| Лимит | Атрибут немесе мән | бір санатқа бір айға қойылса — жеке кесте `budget` |
| Валюта бағамы | **Сақталмайды** | API-дан алынады, кэш ретінде ғана сақтауға болады |

> **Ереже:** егер бір ақпарат бірнеше жазбада **қайталанатын** болса және оның өзінің қасиеттері болса — ол жеке мән (кесте) болуға лайық.

## 3. Атрибуттар және деректер түрлері

SQLite-та негізгі түрлер аз, бірақ дұрыс таңдау маңызды:

| SQLite түрі | Python түрі | Не сақталады | Мысал |
|---|---|---|---|
| `INTEGER` | `int` | бүтін сан, id, логикалық 0/1 | `id`, `amount` (теңгемен) |
| `REAL` | `float` | бөлшек сан | орташа баға, координата |
| `TEXT` | `str` | мәтін, күн (ISO форматта) | `'2027-04-15'`, `'Тамақ'` |
| `BLOB` | `bytes` | екілік дерек | сурет (сирек қолданылады) |

Кеңестер:
- **Ақшаны** тиынмен немесе теңгемен `INTEGER` ретінде сақтаған дұрыс: `0.1 + 0.2` сияқты бөлшек қателер болмайды.
- **Күнді** `TEXT` ретінде `ЖЖЖЖ-АА-КК` форматында сақтаңыз: сонда `ORDER BY date` дұрыс сұрыптайды.
- Атрибут **атомар** болсын: «Аты-жөні» емес, `first_name` және `last_name`; «Мекенжай» бір жолда болса да, қала бойынша сүзгі керек болса — `city` жеке өріс.

## 4. Кілттер және шектеулер (constraints)

| Шектеу | Мағынасы | Мысал |
|---|---|---|
| `PRIMARY KEY` | жазбаның бірегей нөмірі | `id INTEGER PRIMARY KEY AUTOINCREMENT` |
| `FOREIGN KEY` | басқа кестенің жазбасына сілтеме | `category_id REFERENCES category(id)` |
| `NOT NULL` | бос болмауы керек | `amount INTEGER NOT NULL` |
| `UNIQUE` | қайталанбауы керек | `login TEXT UNIQUE` |
| `CHECK` | мәнге шарт | `CHECK (amount > 0)` |
| `DEFAULT` | әдепкі мән | `created TEXT DEFAULT CURRENT_TIMESTAMP` |

**Табиғи кілт** (ЖСН, логин) мен **жасанды кілт** (`id`) бар. Жобада әрдайым жасанды `id` қолданыңыз: табиғи мән өзгеруі мүмкін (пайдаланушы логинін ауыстырады), ал `id` ешқашан өзгермейді.

> **Маңызды:** SQLite-та сыртқы кілттер әдепкі бойынша **тексерілмейді**. Әр қосылған сайын `PRAGMA foreign_keys = ON;` орындау керек.

## 5. Байланыс түрлері

| Түрі | Мағынасы | Өмірлік мысал | Қалай жүзеге асады |
|---|---|---|---|
| **1:1** (бірге-бір) | А-ның бір жазбасына B-ның тек бір жазбасы | Оқушы ↔ Оқушы билеті | B кестесінде `UNIQUE` сыртқы кілт (немесе бір кестеге біріктіру) |
| **1:N** (бірге-көп) | А-ның бір жазбасына B-ның көп жазбасы | Сынып → Оқушылар; Санат → Операциялар | «Көп» жақтағы кестеге сыртқы кілт қосамыз |
| **N:M** (көпке-көп) | екі жақта да көп | Оқушылар ↔ Үйірмелер | **Аралық кесте** (junction table) екі сыртқы кілтпен |

### N:M байланысты аралық кесте арқылы шешу
Бір оқушы бірнеше үйірмеге барады, бір үйірмеде көп оқушы бар. Оқушы кестесіне `club1, club2, club3` бағандарын қосу — **қате** (неше үйірме болатынын білмейміз). Дұрысы:

```text
student            enrollment                 club
--------           -------------------        --------
id  (PK)  <───┐    student_id (FK) ──┘        id (PK)
name          └──  club_id    (FK) ────────>  title
                   joined_date
                   PRIMARY KEY (student_id, club_id)
```

Аралық кестеде байланыстың өз атрибуттары да болуы мүмкін (`joined_date` — қашан жазылды).

## 6. ER-сызба (Entity–Relationship)

ER-сызба — мәндерді тіктөртбұрыш, байланыстарды сызық арқылы көрсететін сурет. Қағазға немесе draw.io-да салуға болады. Мәтіндік түрде («қарға аяғы» белгісінің орнына 1 және N):

```text
┌──────────────┐ 1        N ┌───────────────────┐ N        1 ┌──────────────┐
│    user      │────────────│    operation      │────────────│   category   │
├──────────────┤            ├───────────────────┤            ├──────────────┤
│ id   PK      │            │ id          PK    │            │ id    PK     │
│ name         │            │ user_id     FK    │            │ title UNIQUE │
│ login UNIQUE │            │ category_id FK    │            │ kind         │
└──────────────┘            │ amount            │            │ color        │
        │ 1                 │ op_date           │            └──────────────┘
        │                   │ note              │                   │ 1
        │ N                 └───────────────────┘                   │
┌──────────────────────┐                                            │
│       budget         │ N ─────────────────────────────────────────┘
├──────────────────────┤
│ id PK, user_id FK,   │
│ category_id FK,      │
│ month, limit_amount  │
└──────────────────────┘
```

Оқылуы: «Бір пайдаланушының көп операциясы бар», «Бір санатқа көп операция жатады», «Әр пайдаланушы әр санатқа әр айға бір лимит қояды».

## 7. Қалыпқа келтіру (нормализация) — қарапайым тілмен

Төмендегі «бір кестеге бәрін жаздық» мысалын қараңыз:

| op_id | user_name | user_login | category | category_color | amount | date |
|---|---|---|---|---|---|---|
| 1 | Айгерім | aigerim | Тамақ, Көлік | жасыл | 1500 | 2027-04-01 |
| 2 | Айгерім | aigerim | Тамақ | жасыл | 800 | 2027-04-02 |
| 3 | Айгерім | aigerim | Ойын | қызыл | 2000 | 2027-04-03 |

Мәселелер (аномалиялар):
- **Қайталану:** «Айгерім, aigerim» әр жолда жазылған — жад босқа жұмсалады.
- **Жаңарту аномалиясы:** «Тамақ» санатының түсін өзгертсек, барлық жолды өзгерту керек; біреуін ұмытсақ — дерек қарама-қайшы.
- **Жою аномалиясы:** 3-жолды өшірсек, «Ойын» санаты туралы ақпарат мүлде жоғалады.
- **Атомар емес мән:** «Тамақ, Көлік» — бір ұяшықта екі мән.

Үш негізгі ереже:

| Қалыпты форма | Қысқаша ереже | Түзету |
|---|---|---|
| **1НФ** | Әр ұяшықта бір ғана мән, қайталанатын топ (`club1, club2`) жоқ | «Тамақ, Көлік» → екі жеке жол немесе аралық кесте |
| **2НФ** | Кілт емес өріс **бүкіл** кілтке тәуелді (құрама кілт болса) | аралық кестеде оқушы атын сақтамаймыз |
| **3НФ** | Кілт емес өріс тек кілтке тәуелді, басқа кілт емес өріске емес | `category_color` санатқа тәуелді → `category` кестесіне көшіреміз |

> **Есте сақтау үшін:** «Әр дерек бір-ақ рет, өз орнында сақталады».

**Ерекшелік (денормализация):** кейде есептеу жылдамдығы үшін әдейі қайталайды (мысалы, жиын соманы сақтау). Шағын жобада бұл әдетте қажет емес — алдымен 3НФ-қа дейін жеткізіңіз.

## 8. Деректер сөздігі (data dictionary)

Деректер сөздігі — әр кестенің әр өрісі туралы кесте-құжат. Ол README-ге немесе `docs/data_model.md` файлына жазылады және жоба құжаттамасының бөлігі болып табылады.

**`operation` кестесі:**

| Өріс | Түрі | Шектеу | Сипаттама |
|---|---|---|---|
| `id` | INTEGER | PK, AUTOINCREMENT | операция нөмірі |
| `user_id` | INTEGER | FK → user.id, NOT NULL | кімнің операциясы |
| `category_id` | INTEGER | FK → category.id, NOT NULL | санаты |
| `amount` | INTEGER | NOT NULL, CHECK > 0 | сомасы, теңге |
| `op_date` | TEXT | NOT NULL | күні, `ЖЖЖЖ-АА-КК` |
| `note` | TEXT | — | түсініктеме (міндетті емес) |

## 9. Модельді SQLite схемасына айналдыру

Схеманы бөлек `schema.sql` файлында немесе Python ішінде сақтаймыз. `executescript()` бірнеше SQL нұсқауын бірден орындайды.

```python
import sqlite3

SCHEMA = """
CREATE TABLE IF NOT EXISTS user (
    id    INTEGER PRIMARY KEY AUTOINCREMENT,
    name  TEXT NOT NULL,
    login TEXT NOT NULL UNIQUE
);

CREATE TABLE IF NOT EXISTS category (
    id    INTEGER PRIMARY KEY AUTOINCREMENT,
    title TEXT NOT NULL UNIQUE,
    kind  TEXT NOT NULL CHECK (kind IN ('кіріс', 'шығыс')),
    color TEXT DEFAULT '#888888'
);

CREATE TABLE IF NOT EXISTS operation (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id     INTEGER NOT NULL REFERENCES user(id) ON DELETE CASCADE,
    category_id INTEGER NOT NULL REFERENCES category(id),
    amount      INTEGER NOT NULL CHECK (amount > 0),
    op_date     TEXT NOT NULL,
    note        TEXT
);

CREATE TABLE IF NOT EXISTS budget (
    id           INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id      INTEGER NOT NULL REFERENCES user(id) ON DELETE CASCADE,
    category_id  INTEGER NOT NULL REFERENCES category(id),
    month        TEXT NOT NULL,
    limit_amount INTEGER NOT NULL CHECK (limit_amount > 0),
    UNIQUE (user_id, category_id, month)
);
"""


def create_db(path="qalta.db"):
    """Деректер қорын және кестелерді құрады."""
    conn = sqlite3.connect(path)
    conn.execute("PRAGMA foreign_keys = ON;")
    conn.executescript(SCHEMA)
    conn.commit()
    return conn


if __name__ == "__main__":
    conn = create_db(":memory:")
    tables = conn.execute(
        "SELECT name FROM sqlite_master WHERE type='table' AND name NOT LIKE 'sqlite_%'"
    ).fetchall()
    print("Құрылған кестелер:", [t[0] for t in tables])
    conn.close()
```

Нәтижесі:
```text
Құрылған кестелер: ['user', 'category', 'operation', 'budget']
```

`ON DELETE CASCADE` — пайдаланушы өшірілсе, оның барлық операциялары да автоматты түрде өшеді. `UNIQUE (user_id, category_id, month)` — бір айда бір санатқа екі лимит қоюға болмайды.

### Модельді тексеру: сұраныс жазып көрейік
Модель дұрыс па — оны ТТ-дағы негізгі сұрақтарға SQL арқылы жауап беріп тексереміз. Мысалы: «Сәуір айында қай санатқа қанша жұмсалды?»

```python
import sqlite3

conn = sqlite3.connect(":memory:")
conn.executescript("""
CREATE TABLE category (id INTEGER PRIMARY KEY, title TEXT, kind TEXT);
CREATE TABLE operation (id INTEGER PRIMARY KEY, category_id INTEGER,
                        amount INTEGER, op_date TEXT);
INSERT INTO category VALUES (1, 'Тамақ', 'шығыс'), (2, 'Көлік', 'шығыс');
INSERT INTO operation (category_id, amount, op_date) VALUES
    (1, 1500, '2027-04-01'), (1, 800, '2027-04-02'), (2, 200, '2027-04-02');
""")
rows = conn.execute("""
    SELECT c.title, SUM(o.amount)
    FROM operation AS o
    JOIN category AS c ON c.id = o.category_id
    WHERE o.op_date LIKE '2027-04-%'
    GROUP BY c.title
    ORDER BY SUM(o.amount) DESC
""").fetchall()
for title, total in rows:
    print(f"{title}: {total} тг")
```

Нәтижесі:
```text
Тамақ: 2300 тг
Көлік: 200 тг
```

Егер ТТ-дағы бір сұраққа модель арқылы жауап беру мүмкін болмаса — модельде бір нәрсе жетіспейді.

## 10. Python кластарымен байланыс

Көпқабатты архитектурада әр мәнге бір класс сәйкес келеді. Кестенің бір жолы — бір объект:

```python
class Category:
    """Санат: кестенің бір жолына сәйкес келетін объект."""

    def __init__(self, id_, title, kind, color="#888888"):
        self.id = id_
        self.title = title
        self.kind = kind
        self.color = color

    @classmethod
    def from_row(cls, row):
        """SQL жолынан (кортеж) объект жасайды."""
        return cls(*row)

    def __repr__(self):
        return f"Category({self.id}, {self.title!r}, {self.kind!r})"


row = (1, "Тамақ", "шығыс", "#2e7d32")
cat = Category.from_row(row)
print(cat)
```

Нәтижесі:
```text
Category(1, 'Тамақ', 'шығыс')
```

## 11. SQLite па, JSON ба, CSV ме?

| Жағдай | Таңдау |
|---|---|
| Бірнеше байланысқан мән, іздеу/сүзу/есеп көп | **SQLite** |
| Баптаулар, шағын тізім (рекордтар кестесі, 10–100 жазба) | **JSON** |
| Деректерді Excel-ге немесе Pandas-қа беру | **CSV** экспорт |
| Деректер API-дан келеді, сақтау қажет емес | сақтамаймыз, қажет болса кэш |

Ойын жобасында (Pygame) да модель керек: `player`, `level`, `score` — бірақ олар JSON-да сақталуы мүмкін. Сонда да **құрылымын** алдын ала жобалаймыз.

```python
import json

# Ойынның деректер моделі JSON түрінде
save_data = {
    "player": {"name": "Нұрлан", "coins": 120},
    "levels": [
        {"number": 1, "best_score": 340, "stars": 3},
        {"number": 2, "best_score": 150, "stars": 1},
    ],
}
text = json.dumps(save_data, ensure_ascii=False, indent=2)
print(text[:60])
```

Нәтижесі:
```text
{
  "player": {
    "name": "Нұрлан",
    "coins": 120
  },
```

## Жиі кездесетін қателер

**1. Бір кестеге бәрін жазу.**
```text
students(id, name, club1, club2, club3)    -- қате: үйірме саны шектеулі, бос бағандар көп
```
Дұрысы: `student`, `club` және аралық `enrollment(student_id, club_id)` кестесі.

**2. Сыртқы кілтті «бір» жаққа қою.**
```text
category(id, title, operation_id)          -- қате: санатта тек бір операция болып қалады
```
Дұрысы: сыртқы кілт «көп» жақта — `operation(..., category_id)`.

**3. Сыртқы кілтті қосуды ұмыту.**
```python
import sqlite3
conn = sqlite3.connect(":memory:")
# PRAGMA жоқ — бар емес санатқа сілтеме қате бермейді!
conn.executescript("""
CREATE TABLE category (id INTEGER PRIMARY KEY, title TEXT);
CREATE TABLE operation (id INTEGER PRIMARY KEY,
                        category_id INTEGER REFERENCES category(id));
INSERT INTO operation (category_id) VALUES (999);
""")
print("Қате жазба қабылданды:", conn.execute("SELECT * FROM operation").fetchall())
```
Нәтижесі:
```text
Қате жазба қабылданды: [(1, 999)]
```
Дұрысы: қосылғаннан кейін бірден `conn.execute("PRAGMA foreign_keys = ON")` — сонда `sqlite3.IntegrityError: FOREIGN KEY constraint failed` шығады.

**4. Есептелетін мәнді сақтау.** Оқушының жасын (`age`) сақтау — бір жылдан кейін қате болады. Туған күнін (`birth_date`) сақтап, жасын есептеңіз. Сол сияқты балансты сақтамай, операциялардан `SUM` арқылы есептеңіз.

**5. Ақшаны `REAL` түрінде сақтау.** `0.1 + 0.2 == 0.30000000000000004`. Ақшаны теңгемен/тиынмен `INTEGER` ретінде сақтаңыз.

## Ескерту

- `PRAGMA foreign_keys = ON` тек ағымдағы қосылымға әсер етеді: оны «қорды құрғанда» бір рет емес, қосылым ашатын функцияның ішінде қосыңыз.
- SQLite-та `AUTOINCREMENT` міндетті емес: `INTEGER PRIMARY KEY` бағаны нөмірді өзі автоматты алады; `AUTOINCREMENT` тек өшірілген жазбалардың нөмірлері қайта қолданылмайтынына кепілдік береді.
- SQLite «икемді типтеуді» қолданады: `INTEGER` бағанына жол жазуға болады. SQLite 3.37 нұсқасынан бастап кестені `STRICT` деп жариялауға болады, сонда түрлер қатаң тексеріледі.
- Сұранысқа мәндерді тек `?` параметрлері арқылы қойыңыз (`conn.execute("... WHERE id = ?", (op_id,))`), f-жол арқылы емес — бұл SQL-инъекциядан қорғайды.
- Кесте мен баған атауларын `snake_case` түрінде және жекеше түрде жазыңыз (`operation`, `category_id`) — PEP 8 бойынша айнымалы атаулары сияқты.
