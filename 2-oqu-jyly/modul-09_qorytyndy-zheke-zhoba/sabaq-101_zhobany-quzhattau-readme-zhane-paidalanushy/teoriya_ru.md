## 1. Виды документации

| Документ | Читатель | На какой вопрос отвечает | Где находится |
|---|---|---|---|
| **README.md** | любой посетитель репозитория | Что это? Зачем нужно? Как запустить? | корень репозитория |
| **Руководство пользователя** | человек, пользующийся программой | Как сделать ...? Что делать, если ...? | `docs/user_guide.md` |
| **Документация разработчика** | тот, кто развивает код (в том числе вы через год!) | Как устроен код? Что принимает функция? | docstring, `docs/architecture.md` |
| **CHANGELOG.md** | пользователи, разработчики | Что изменилось между версиями? | корень репозитория |
| **LICENSE** | другие разработчики | Можно ли использовать этот код? | корень репозитория |

## 2. Markdown: краткая шпаргалка

| Что нужно | Markdown | Результат |
|---|---|---|
| Заголовки | `# Большой`, `## Средний`, `### Малый` | заголовки 1–3 уровня |
| Жирный / курсив | `**жирный**`, `*курсив*` | **жирный**, *курсив* |
| Список | `- пункт` или `1. пункт` | маркированный / нумерованный список |
| Список задач | `- [x] готово`, `- [ ] нет` | список с отметками |
| Код (в строке) | `` `python main.py` `` | `python main.py` |
| Блок кода | три обратные кавычки + название языка | блок кода с подсветкой |
| Ссылка | `[текст](https://...)` | кликабельная ссылка |
| Изображение | `![описание](docs/screenshots/main.png)` | изображение |
| Таблица | `\| А \| Б \|` + `\|---\|---\|` | таблица |
| Примечание | `> текст` | блок цитаты |

**Важно:** для изображений используйте **относительный путь** (`docs/screenshots/main.png`) — тогда они будут видны и на GitHub, и на локальном компьютере. Пути `C:\Users\...` на GitHub не работают.

## 3. Структура README

1. **Название и описание в одно предложение** — должно пройти «30-секундный тест»: незнакомый человек за полминуты чтения понимает, что это за программа и как её запустить.
2. **Скриншот** — на видном месте (картинка объясняет быстрее слов).
3. **Проблема и решение** — для кого и зачем.
4. **Возможности** — маркированный список.
5. **Технологии** — перечислить основные и кратко объяснить, почему выбраны.
6. **Установка и запуск** — конкретные команды, которые можно скопировать.
7. **Использование** — 3–5 шагов или ссылка на руководство.
8. **Структура проекта** — дерево папок.
9. **Тестирование** — как запускать тесты, результат.
10. **Планы на будущее** — идеи, не вошедшие до feature freeze.
11. **Автор и лицензия**; использованные источники (библиотеки, API, если применялся ИИ-помощник — где именно).

### Образец: README.md «Карманных денег»

~~~markdown
# Карманные деньги

Оконное приложение, которое помогает видеть, на что уходят
карманные деньги, и копить на цель.

![Главное окно](docs/screenshots/main.png)

## Проблема и решение
По результатам опроса 14 из 20 школьников не знают, почему к концу месяца
у них заканчиваются деньги. «Карманные деньги» позволяют записать каждый расход
за 5 секунд, увидеть диаграмму по категориям и спрогнозировать, когда
вы накопите на цель (например, на велосипед).

## Возможности
- ввод, редактирование и удаление доходов и расходов по категориям;
- баланс и месячный отчёт, круговая диаграмма по категориям;
- месячный лимит на категории и предупреждение при превышении;
- перевод сумм в доллары (текущий курс, без интернета — последний сохранённый курс);
- экспорт в CSV (для Excel), сохранение диаграммы в PNG.
~~~

## 4. Руководство пользователя

README — «о проекте», руководство — «как пользоваться». Его читателем может быть человек, не знающий программирования (например, ваша бабушка или ученик 5-го класса).

### Структура
1. **Что делает программа** — 2–3 предложения.
2. **Системные требования и установка** (или запуск `.exe`).
3. **Знакомство с окном** — скриншот с пронумерованными частями: «1 — баланс, 2 — форма ввода, 3 — таблица, 4 — диаграмма».
4. **Основные задачи** — каждый сценарий отдельным разделом: «Как добавить расход?», «Как удалить операцию?», «Как сохранить отчёт?».
5. **Частые вопросы и устранение неполадок** — «Что делать, если...».
6. **Контакты** — кому писать, если нашли ошибку (GitHub Issues).

### Правила изложения
| Правило | Плохо | Хорошо |
|---|---|---|
| Один шаг — одно действие | «Введите сумму, выберите категорию и сохраните» | 1. Введите сумму. 2. Выберите категорию. 3. Нажмите «Сохранить». |
| Повелительное наклонение, на «вы» | «Необходим ввод суммы» | «Введите сумму» |
| Точно называть элементы интерфейса | «нажмите кнопочку сохранения» | Нажмите кнопку **«Сохранить»** |
| Сообщать результат | — | «Операция появится в таблице, баланс обновится.» |
| Без технических терминов | «если возникнет ValueError» | «если появится сообщение “Введите сумму числом”» |
| Скриншот | длинное описание | изображение с отмеченным местом действия |

### Фрагмент руководства (образец)
~~~markdown
## Как добавить расход?

1. В левой части окна выберите переключатель **«Расход»**.
2. В поле **«Сумма (тг)»** введите сумму цифрами, например: `800`.
3. В списке **«Категория»** выберите категорию, например: «Еда».
4. По желанию кратко напишите в поле **«Комментарий»**: «Обед».
5. Нажмите кнопку **«Сохранить»** (или Enter).

Результат: операция появится в начале таблицы, баланс уменьшится на 800 тенге,
диаграмма обновится.

![Добавление расхода](screenshots/add_expense.png)

## Частые вопросы

**Появилось сообщение «Введите сумму числом».**
В поле суммы есть буква, точка или знак минус. Введите только цифры: `1500`.

**Сумма в долларах не отображается.**
Проверьте подключение к интернету. Без интернета программа использует последний
сохранённый курс; если программа впервые открыта без интернета, показываются только тенге.

**Где хранятся мои данные? Как перенести их на другой компьютер?**
Все данные находятся в файле `qalta.db` в папке программы. Скопируйте этот файл
в папку программы на другом компьютере.
~~~

## 5. Документация разработчика: docstring

Для того, кто читает код (и для вас), пишем docstring для каждого модуля, класса и открытой функции. Хороший docstring описывает: **что делает**, **параметры**, **что возвращает**, **какую ошибку выбрасывает**.

```python
def forecast_goal_date(goal, balance, net_per_month, today):
    """Прогнозирует дату достижения цели.

    Параметры:
        goal (int): сумма цели, тенге.
        balance (int): текущий баланс, тенге.
        net_per_month (int): чистые накопления в месяц (доход - расход).
        today (datetime.date): дата начала расчёта.

    Возвращает:
        datetime.date | None: прогнозируемая дата; если накоплений нет — None.

    Пример:
        >>> import datetime
        >>> forecast_goal_date(1000, 400, 300, datetime.date(2027, 5, 1))
        datetime.date(2027, 6, 30)
    """
    import datetime
    import math
    if balance >= goal:
        return today
    if net_per_month <= 0:
        return None
    days = math.ceil((goal - balance) / (net_per_month / 30))
    return today + datetime.timedelta(days=days)


help(forecast_goal_date)
```

`help()` или в терминале `python -m pydoc qalta.logic` — показывает документацию, автоматически собранную из docstring. А примеры с `>>>` может проверить `python -m doctest qalta/logic.py -v` — это гарантия того, что документация и код соответствуют друг другу.

## Частые ошибки

**1. README состоит только из названия** или в нём написано «Это мой проект». Не проходит 30-секундный тест.

**2. Команды установки не проверены.** В README `python app.py`, а файл называется `main.py`. Правильно: выполнить команды в чистой папке **дословно** по README (тест чистого окружения: `git clone` → новый `venv` → `pip install -r requirements.txt`).

**3. Изображение не отображается.** Причины: абсолютный путь; заглавные буквы в имени файла (`Main.PNG` ≠ `main.png` — GitHub различает регистр); изображение не загружено в репозиторий.

**4. Незакрытый блок кода.** После незакрытых трёх обратных кавычек весь README отображается как код. Предварительно просмотрите в VS Code через `Ctrl+Shift+V`.

**5. Руководство на языке разработчика.** «Сделайте select item-а из Combobox». Правильно: «Выберите категорию из списка».

**6. Docstring не соответствует коду.** Функция изменилась, а docstring — старый. `doctest` это обнаружит.

## Основные понятия
| Понятие | Объяснение |
|---|---|
| README | главная страница репозитория: о проекте и как его запустить |
| Руководство пользователя | документ, пошагово объясняющий, как пользоваться программой |
| Документация разработчика | описание структуры кода и функций |
| Markdown | язык форматирования текста с помощью простых обозначений |
| CHANGELOG | история изменений по версиям |
| Лицензия | условия использования кода (например, MIT) |
| `pydoc` | инструмент, показывающий документацию из docstring |
| `doctest` | инструмент, проверяющий примеры из docstring как тесты |

## Примечание

- Стиль docstring описан в PEP 257: первая строка — краткое описание в повелительном/изъявительном наклонении, затем пустая строка и подробности; закрывающие `"""` — на отдельной строке.
- Широко распространены два формата разделов docstring: Google style (`Args:`, `Returns:`, `Raises:`) и NumPy style; инструменты вроде Sphinx умеют превращать их в HTML-документацию.
- `doctest` сравнивает вывод **посимвольно**: лишний пробел или другой порядок ключей словаря делает пример «упавшим» — в примерах выводите отсортированные или простые значения.
- GitHub отображает `README.md`, `README.rst` или `README.txt` на главной странице репозитория; Markdown на GitHub — это диалект GitHub Flavored Markdown (таблицы, списки задач `- [ ]`).
- Формат CHANGELOG часто ведут по соглашению «Keep a Changelog» (https://keepachangelog.com), а номера версий — по Semantic Versioning (`MAJOR.MINOR.PATCH`, https://semver.org).
- Документация: https://peps.python.org/pep-0257/ и https://docs.python.org/3/library/doctest.html
