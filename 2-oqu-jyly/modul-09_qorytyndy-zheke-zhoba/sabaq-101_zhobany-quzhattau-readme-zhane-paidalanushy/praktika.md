# Сабақ 101. Практикалық тапсырмалар: README және пайдаланушы нұсқаулығы

## Базалық деңгей

### 1-тапсырма. 30 секундтық сынақ (жылулық, 5 мин)
Құрбыңыздың репозиторийін ашып, тек 30 секунд қараңыз. Содан кейін қағазға жазыңыз: (1) бұл жоба не істейді? (2) кімге арналған? (3) қалай іске қосылады? Авторға беріңіз — ол README-нің не айтатынын, ал сіз не түсінгеніңізді салыстырсын.

### 2-тапсырма. Толық README (міндетті)
Теориядағы 3-бөлімнің 11 бөлімі бойынша README.md жазыңыз. Міндетті талаптар:
- бір сөйлемдік сипаттама және кемінде **1 скриншот** жоғарыда;
- «Мәселе және шешім» — нақты пайдаланушы мен мәселе;
- технологиялар кестесі (кемінде 3 технология және не үшін қолданылғаны);
- орнату командалары `bash` код блогында;
- жоба құрылымы, тесттерді іске қосу командасы, автор.

Тексеру: VS Code-та `Ctrl+Shift+V`, кейін GitHub-та көрініс (суреттер, кестелер, код блоктары).

### 3-тапсырма. Пайдаланушы нұсқаулығы (міндетті)
`docs/user_guide.md` файлын жазыңыз:
- бағдарлама не істейді (2–3 сөйлем);
- нөмірлері бар «Тереземен танысу» скриншоты (суретке 1, 2, 3... белгілерін кез келген сурет редакторында қойыңыз);
- кемінде **3 негізгі тапсырма** («Қалай ...?»), әрқайсысы нөмірленген қадамдармен және «Нәтиже:» жолымен;
- кемінде **4 сұрақ** «Жиі қойылатын сұрақтар» бөлімінде (99-сабақтағы тест-кейстер мен 98-сабақтағы пікірлер көмектеседі).

### 4-тапсырма. Нұсқаулықты тексеру (айқас)
Құрбыңыздың нұсқаулығын алып, бағдарламаны **тек нұсқаулық бойынша** (автордан сұрамай) қолданып көріңіз. Әр кедергіні жазыңыз: «3-қадамда “Қосу” батырмасы делінген, бірақ терезеде “Сақтау” деп тұр». Автор түзетулерді енгізеді.

## Кеңейтілген деңгей

### 5-тапсырма. Нашар нұсқаулықты түзету
Мәтінді жазу ережелері бойынша қайта жазыңыз:

> Бағдарламаны қосқанда пайда болған окноның сол жақ бөлігіндегі entry-ге username-ды енгізіп, сосын пароль да енгізілу керек және кнопканы басса кіресіз, егер қате шықса тағы бір рет енгізіңіз ал егер бәрібір болмаса онда database файлын тексеру керек.

### 6-тапсырма. Docstring-дерді толықтыру
Жобаңыздың логика және деректер модульдеріндегі **барлық** ашық функциялар мен кластарға docstring жазыңыз (не істейді, параметрлер, не қайтарады, қандай қате). Кемінде бір функцияға `>>>` мысалын қосып, `python -m doctest <файл> -v` арқылы тексеріңіз. `python -m pydoc <модуль>` нәтижесін қараңыз.

### 7-тапсырма. CHANGELOG және LICENSE
Git тарихын (`git log --oneline`) және жабылған Issues-ті қарап, `CHANGELOG.md` жазыңыз: `0.1-mvp` және `1.0` нұсқалары, «Қосылды / Түзетілді» бөлімдері. GitHub арқылы MIT лицензиясын қосыңыз.

## ★ Олимпиадалық / шығармашылық тапсырма

### 8-тапсырма. README тексерушісі
README.md-ні тексеретін `tools/check_readme.py` скриптін жазыңыз:
- міндетті бөлімдер бар ма («Орнату», «Қолдану», «Технологиялар», «Автор»);
- `![...](жол)` суреттерінің файлдары шынымен бар ма;
- `[...](жол)` жергілікті сілтемелері (http емес) бар файлдарға апара ма;
- код блоктарының (үш backtick) саны жұп па.

Шығару мысалы:
```text
[OK]   «Орнату» бөлімі бар
[ЖОҚ]  «Автор» бөлімі табылмады
[ЖОҚ]  сурет табылмады: docs/screenshots/Main.png
[OK]   код блоктары жабылған (6)
```

### 9-тапсырма. Бейне-нұсқаулық
1–2 минуттық экран бейнесін жазыңыз (OBS Studio немесе Windows-тағы `Win+Alt+R`): бағдарламаны іске қосу және ең маңызды сценарий. Бейнені README-ге сілтеме ретінде қосыңыз (GitHub-қа 10 МБ-тан үлкен бейнені жүктемеңіз — сілтеме немесе GIF).

## Үй тапсырмасы
1. README мен нұсқаулықты 4-тапсырманың пікірлері бойынша аяқтаңыз. `push`.
2. Таза папкаға `git clone` жасап, README-дегі командаларды сөзбе-сөз орындаңыз — бәрі жұмыс істей ме?
3. Келесі сабаққа: жобаңыз туралы 5 минуттық баяндаманың жоспарын ойлаңыз (Мәселе → Шешім → Демо → Техника → Нәтиже).

## Бағалау критерийлері
| Критерий | Үлес | Не тексеріледі |
|---|---|---|
| README толықтығы мен дұрыстығы | 40% | 11 бөлімнің негізгілері бар, командалар жұмыс істейді, скриншот көрінеді |
| Пайдаланушы нұсқаулығының сапасы | 25% | қадамдар нақты, нәтиже көрсетілген, FAQ ≥ 4, құрбы нұсқаулық бойынша жұмыс істей алды |
| Ресімдеу және тіл | 20% | Markdown дұрыс, сауатты қазақ тілі, біркелкі терминдер; docstring-дер |
| Өз бетінше жұмыс, айқас тексеруге қатысу | 15% | құрбысының нұсқаулығын тексерді, уақытында `push` |

**6-тапсырма.** Тексеру: `python -m doctest` нәтижесінде `Test passed`; `pydoc` шығысында әр ашық функцияның сипаттамасы бар.

**8-тапсырма.**
```python
import re
import sys
from pathlib import Path

REQUIRED = ["Орнату", "Қолдану", "Технологиялар", "Автор"]
FENCE = "`" * 3


def check_readme(path="README.md"):
    readme = Path(path)
    text = readme.read_text(encoding="utf-8")
    base = readme.parent
    ok = True

    headings = [h.strip() for h in re.findall(r"^#{1,6}\s+(.+)$", text, re.M)]
    for name in REQUIRED:
        if any(name.lower() in h.lower() for h in headings):
            print(f"[OK]   «{name}» бөлімі бар")
        else:
            print(f"[ЖОҚ]  «{name}» бөлімі табылмады")
            ok = False

    for is_image, target in re.findall(r"(!?)\[[^\]]*\]\(([^)\s]+)\)", text):
        if target.startswith(("http://", "https://", "#", "mailto:")):
            continue
        if not (base / target).exists():
            kind = "сурет" if is_image else "сілтеме"
            print(f"[ЖОҚ]  {kind} табылмады: {target}")
            ok = False

    fences = sum(1 for line in text.splitlines() if line.strip().startswith(FENCE))
    if fences % 2 == 0:
        print(f"[OK]   код блоктары жабылған ({fences // 2})")
    else:
        print(f"[ЖОҚ]  жабылмаған код блогы бар ({fences} белгі)")
        ok = False
    return ok


if __name__ == "__main__":
    sys.exit(0 if check_readme(*sys.argv[1:]) else 1)
```
Ескерту: ``FENCE = "`" * 3`` — скрипттің өз мәтінінде үш backtick-ті тікелей жазбау үшін (әйтпесе бұл markdown файлдағы код блогы бұзылады) — оқушылармен талқылауға жақсы мысал.

**7, 9-тапсырмалар** — шығармашылық; CHANGELOG-та нұсқалар жаңасынан ескісіне қарай, «Қосылды/Түзетілді» бөлімдері, issue нөмірлері болса жеткілікті.
