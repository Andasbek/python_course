## 2. Markdown: қысқаша шпаргалка

| Не керек | Markdown | Нәтиже |
|---|---|---|
| Тақырыптар | `# Үлкен`, `## Орта`, `### Кіші` | 1–3 деңгей тақырып |
| Қалың / көлбеу | `**қалың**`, `*көлбеу*` | **қалың**, *көлбеу* |
| Тізім | `- пункт` немесе `1. пункт` | маркерлі / нөмірлі тізім |
| Тапсырма тізімі | `- [x] дайын`, `- [ ] жоқ` | белгі қойылатын тізім |
| Код (жолда) | `` `python main.py` `` | `python main.py` |
| Код блогы | үш backtick + тіл атауы | түсті код блогы |
| Сілтеме | `[мәтін](https://...)` | басылатын сілтеме |
| Сурет | `![сипаттама](docs/screenshots/main.png)` | сурет |
| Кесте | `\| А \| Б \|` + `\|---\|---\|` | кесте |
| Ескерту | `> мәтін` | дәйексөз блогы |

**Маңызды:** суреттерге **салыстырмалы жол** (`docs/screenshots/main.png`) қолданыңыз — сонда олар GitHub-та да, жергілікті компьютерде де көрінеді. `C:\Users\...` жолдары GitHub-та жұмыс істемейді.

## 3. README құрылымы

1. **Атауы және бір сөйлемдік сипаттама** — «30 секундтық сынақтан» өтуі керек: бейтаныс адам жарты минут оқып, бұл қандай бағдарлама екенін және оны қалай іске қосуды түсінеді.
2. **Скриншот** — бірден көрінетін жерде (сөзден гөрі сурет тез түсіндіреді).
3. **Мәселе және шешім** — кімге, не үшін керек.
4. **Мүмкіндіктер** — маркерлі тізім.
5. **Технологиялар** — негізгілерін атап, неге таңдалғанын қысқаша.
6. **Орнату және іске қосу** — нақты командалар, көшіріп қоюға болатындай.
7. **Қолдану** — 3–5 қадам немесе нұсқаулыққа сілтеме.
8. **Жоба құрылымы** — папкалар ағашы.
9. **Тестілеу** — тесттерді қалай іске қосу, нәтижесі.
10. **Болашақтағы жоспарлар** — feature freeze-ге ілікпеген идеялар.
11. **Автор және лицензия**; көмек алынған дереккөздер (кітапханалар, API, ЖИ-көмекші қолданылса — қай жерде).

## 4. Пайдаланушы нұсқаулығы

README — «жоба туралы», нұсқаулық — «қалай қолдану керек». Оның оқырманы бағдарламалауды білмейтін адам болуы мүмкін (мысалы, сіздің әжеңіз немесе 5-сынып оқушысы).

### Құрылымы
1. **Бағдарлама не істейді** — 2–3 сөйлем.
2. **Жүйелік талаптар және орнату** (немесе `.exe` іске қосу).
3. **Тереземен танысу** — нөмірленген бөліктері бар скриншот: «1 — баланс, 2 — енгізу формасы, 3 — кесте, 4 — диаграмма».
4. **Негізгі тапсырмалар** — әр сценарий жеке бөлім: «Шығысты қалай қосамын?», «Операцияны қалай жоямын?», «Есепті қалай сақтаймын?».
5. **Жиі қойылатын сұрақтар және ақауларды жою** — «Не істеу керек, егер...».
6. **Байланыс** — қате тапсаңыз, кімге жазу (GitHub Issues).

### Жазу ережелері
| Ереже | Жаман | Жақсы |
|---|---|---|
| Бір қадам — бір әрекет | «Соманы енгізіп, санатты таңдап, сақтаңыз» | 1. Соманы енгізіңіз. 2. Санатты таңдаңыз. 3. «Сақтау» басыңыз. |
| Бұйрық рай, «сіз» | «Сома енгізілу қажет» | «Соманы енгізіңіз» |
| Интерфейс элементтерін дәл атау | «сақтау түймешігін басыңыз» | **«Сақтау»** батырмасын басыңыз |
| Нәтижені айту | — | «Операция кестеде пайда болады, баланс жаңарады.» |
| Техникалық терминсіз | «ValueError шықса» | «“Соманы сан түрінде енгізіңіз” хабары шықса» |
| Скриншот | ұзақ сипаттама | әрекет болатын жері белгіленген сурет |

## Жиі қойылатын сұрақтар

**«Соманы сан түрінде енгізіңіз» деген хабар шықты.**
Сома өрісінде әріп, нүкте немесе минус белгісі бар. Тек цифрларды жазыңыз: `1500`.

**Доллардағы сома көрсетілмейді.**
Интернет байланысын тексеріңіз. Интернет жоқ кезде бағдарлама соңғы сақталған
бағамды қолданады; бағдарлама алғаш рет интернетсіз ашылса, тек теңге көрсетіледі.

**Деректерім қайда сақталады? Басқа компьютерге қалай көшіремін?**
Барлық дерек бағдарлама папкасындағы `qalta.db` файлында. Осы файлды басқа
компьютердегі бағдарлама папкасына көшіріңіз.

## 5. Әзірлеуші құжаттамасы: docstring-дер

Кодты оқитын адамға (және сізге) әр модуль, класс және ашық функция үшін docstring жазамыз. Жақсы docstring: **не істейді**, **параметрлері**, **не қайтарады**, **қандай қате көтереді**.

```python
def forecast_goal_date(goal, balance, net_per_month, today):
    """Мақсатқа жететін күнді болжайды.

    Параметрлер:
        goal (int): мақсат сомасы, теңге.
        balance (int): ағымдағы баланс, теңге.
        net_per_month (int): айына таза жинақ (кіріс - шығыс).
        today (datetime.date): есептеу басталатын күн.

    Қайтарады:
        datetime.date | None: болжамды күн; жинақ жоқ болса None.

    Мысал:
        >>> import datetime
        >>> forecast_goal_date(1000, 400, 300, datetime.date(2027, 5, 1))
        datetime.date(2027, 6, 30)
    """
    import datetime
    import math
    if balance >= goal:
        return today
    if net_per_month <= 0:
        return None
    days = math.ceil((goal - balance) / (net_per_month / 30))
    return today + datetime.timedelta(days=days)


help(forecast_goal_date)
```

`help()` немесе терминалда `python -m pydoc qalta.logic` — docstring-дерден автоматты құжаттама көрсетеді. Ал `>>>` мысалдарын `python -m doctest qalta/logic.py -v` тексере алады — құжаттама мен код бір-біріне сәйкес келетініне кепіл.

## Жиі кездесетін қателер

**1. README тек атаудан тұрады** немесе «Бұл менің жобам» деп жазылған. 30 секундтық сынақтан өтпейді.

**2. Орнату командалары тексерілмеген.** README-де `python app.py`, ал файл `main.py`. Дұрысы: командаларды таза папкада README бойынша **сөзбе-сөз** орындап көру (таза орта тесті: `git clone` → жаңа `venv` → `pip install -r requirements.txt`).

**3. Сурет көрінбейді.** Себептері: абсолют жол; файл атауында бас әріп (`Main.PNG` ≠ `main.png` — GitHub регистрді ажыратады); сурет репозиторийге жүктелмеген.

**4. Код блогын жаппау.** Жабылмаған үш backtick-тен кейінгі бүкіл README код болып көрінеді. VS Code-та `Ctrl+Shift+V` арқылы алдын ала қарап шығыңыз.

**5. Нұсқаулық — әзірлеуші тілінде.** «Combobox-тан item-ді select жасаңыз». Дұрысы: «Тізімнен санатты таңдаңыз».

**6. Docstring кодпен сәйкес емес.** Функция өзгерді, docstring — ескі. `doctest` мұны табады.

## Ескерту

- Docstring стилі PEP 257-де сипатталған: бірінші жол — қысқаша сипаттама, одан кейін бос жол және толығырақ мәлімет; жабатын `"""` — жеке жолда.
- Docstring бөлімдерінің екі пішімі кең тараған: Google style (`Args:`, `Returns:`, `Raises:`) және NumPy style; Sphinx сияқты құралдар оларды HTML-құжаттамаға айналдыра алады.
- `doctest` шығысты **таңба бойынша** салыстырады: артық бос орын немесе сөздік кілттерінің басқа реті мысалды «құлатады» — мысалдарда сұрыпталған немесе қарапайым мәндерді шығарыңыз.
- GitHub репозиторийдің басты бетінде `README.md`, `README.rst` немесе `README.txt` көрсетеді; GitHub-тағы Markdown — GitHub Flavored Markdown диалектісі (кестелер, `- [ ]` тапсырмалар тізімі).
- CHANGELOG пішімін көбіне «Keep a Changelog» келісімі бойынша (https://keepachangelog.com), ал нұсқа нөмірлерін Semantic Versioning бойынша (`MAJOR.MINOR.PATCH`, https://semver.org) жүргізеді.
