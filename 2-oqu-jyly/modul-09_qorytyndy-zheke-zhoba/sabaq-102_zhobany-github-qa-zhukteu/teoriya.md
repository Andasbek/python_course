## 1. Соңғы репозиторий чек-парағы

Жариялау алдында репозиторийді «бейтаныс адамның көзімен» тексереміз:

| № | Тексеру | Қалай |
|---|---|---|
| 1 | Құпия деректер жоқ (кілттер, құпия сөздер, жеке деректер) | `git log -p | findstr /i "key password"` (Windows) немесе `git log -p | grep -i -E "key|password"` |
| 2 | Артық файлдар жоқ: `venv/`, `__pycache__/`, `.db`, `.log`, `build/`, `dist/` | GitHub бетін қарау, `.gitignore` |
| 3 | `requirements.txt` толық | таза ортада `pip install -r requirements.txt` |
| 4 | README бойынша іске қосылады | таза орта тесті: `git clone` → жаңа `venv` → орнату → іске қосу |
| 5 | Барлық тест өтеді | `python -m unittest discover -s tests` |
| 6 | Скриншоттар көрінеді, сілтемелер жұмыс істейді | GitHub-та README-ді ашу |
| 7 | Өлі код, `test2.py` сияқты файлдар жоқ | файлдар ағашын қарау, `git ls-files` |
| 8 | Репозиторий **ашық** (Public) | Settings → Danger Zone → Change visibility |
| 9 | LICENSE, CHANGELOG бар | репозиторий түбірі |

> Құпия дерек тарихта табылса: файлдан өшіру **жеткіліксіз** — кілтті қызметте жаңасына ауыстырыңыз (ескісін өшіріңіз): Git тарихы файлдардың барлық бұрынғы нұсқаларын сақтайды.

## 2. Нұсқа тегі және GitHub Release

**Семантикалық нұсқалау** (`MAJOR.MINOR.PATCH`): `1.0.0` — бірінші толық нұсқа; `1.0.1` — қате түзету; `1.1.0` — жаңа мүмкіндік; `2.0.0` — үлкен өзгеріс.

```bash
git status                       # бәрі коммиттелген бе?
git tag -a v1.0 -m "Қалта ақшасы 1.0 — бірінші толық нұсқа"
git push origin main --tags
```

**Release** — GitHub-тағы тегтің «бетi»: сипаттамасы және жүктелетін файлдары бар.
1. Репозиторийде: **Releases → Draft a new release**.
2. **Choose a tag** → `v1.0`.
3. Атауы: `Қалта ақшасы 1.0`. Сипаттамасы — CHANGELOG-тағы `1.0` бөлімі.
4. Қаласаңыз, `.exe` файлын тіркеңіз (PyInstaller арқылы жиналған).
5. **Publish release**.

Енді кез келген адам дәл осы тұрақты нұсқаны жүктей алады, ал `main`-дегі әзірлеу әрі қарай жалғасады.

## 3. Репозиторий — портфолио бөлігі

Бірнеше ұқыпты безендірілген жобасы бар GitHub профилі — әзірлеушінің **портфолиосы**: оны жоба байқауларында, оқуға түскенде, сұхбатта көрсетеді.

| Не істейміз | Қайда |
|---|---|
| Қысқа сипаттама (About) және сайт/бейне сілтемесі | репозиторий беті → About (тісті доңғалақ белгісі) |
| Тақырыптар (topics): `python`, `tkinter`, `sqlite`, `matplotlib` | About → Topics |
| Профильде бекіту (Pin) — 4–6 үздік жоба | профиль → Customize your pins |
| Профиль README (өзіңіз туралы 3–5 жол) | `<логин>/<логин>` атты арнайы репозиторий |

Профиль README үлгісі:
~~~markdown
# Сәлем, мен — Әлихан
Алматыдағы жаңадан бастаған Python-әзірлеуші.

**Жобаларым:** Қалта ақшасы (Tkinter + SQLite + API), «Дала жүгірісі» ойыны (Pygame),
Алматы ауа сапасын талдау (Pandas + Matplotlib).

**Қызығушылықтарым:** деректерді талдау, ойын әзірлеу. Келесі мақсат — веб-әзірлеу (Flask).
~~~

## 4. Жобаның техникалық презентациясының құрылымы

| № | Бөлім | Мазмұны |
|---|---|---|
| 1 | Таныстыру | жоба атауы, ол туралы бір сөйлем |
| 2 | **Мәселе** | кімнің, қандай мәселесі? Дерек/мысал |
| 3 | **Шешім** | жоба мәселені қалай шешеді, ұқсастарынан айырмашылығы |
| 4 | **Демо** | 2–3 негізгі сценарийдің тірі көрсетілімі |
| 5 | **Техника** | архитектура (қабаттар), технологиялар, ДҚ моделі, бір қызықты код үзіндісі |
| 6 | **Сапа** | тесттер саны, табылған және түзетілген қателер, code review |
| 7 | **Болашақ** | ағымдағы нұсқаның шектеулері, келесі нұсқа жоспары |

**Тарих айтыңыз:** «Ай сайын ақшам қайда кететінін білмейтінмін...» — фактілер тізімінен әлдеқайда есте қалады.

## 5. Слайд ережелері

| Ереже | Түсіндірме |
|---|---|
| 7–10 слайд | әр бөлімге 1–2 слайд |
| Бір слайд — бір ой | слайд тақырыбы — сол ойдың өзі: «Тесттер: 24/24 өтті» |
| Аз мәтін | 3–4 жолдан аспайды, әр жол — 6–8 сөз; толық сөйлемдерді **айтасыз**, жазбайсыз |
| Ірі қаріп | кемінде 24 pt (код үшін 18 pt), соңғы қатардан оқылуы керек |
| Сурет > мәтін | скриншот, архитектура сызбасы, ER-сызба, диаграмма |
| Код — тек үзінді | 8–12 жол, ең қызықты жері, түсті белгілеумен |
| Бір стиль | 2–3 түс, бір қаріп, жобаның түстерімен бірдей болса — тамаша |
| Соңғы слайд | «Рақмет!» + репозиторий сілтемесі/QR-коды |

Жаман слайд: «Менің бағдарламам Python тілінде жазылған және ол Tkinter кітапханасын қолданады, сонымен қатар SQLite деректер қоры...» (6 жол мәтін).
Жақсы слайд: үш технологияның белгішесі + архитектура сызбасы + бір жол: «Үш қабат: интерфейс → логика → деректер».

## 6. Демо: ең тәуекелді бөлім

Тірі көрсетілім — баяндаманың ең әсерлі, бірақ ең қауіпті бөлігі. «Демо әсері» деген сөз бар: әзірлеушіде мінсіз жұмыс істеген бағдарлама аудитория алдында құлайды. Сондықтан:

**Демо сценарийі** — алдын ала жазылған қадамдар (не басамын, не айтамын):
```text
1. Бағдарлама ашық, ДҚ-да 2 апталық дайын деректер бар.     "Бұл — басты терезе..."
2. Шығыс қосу: 800, Тамақ, "Түскі ас" -> Сақтау.             "Енгізу 5 секунд алады..."
3. Диаграмма жаңарды -> назар аударту.                        "Тамақ — шығыстың 45%-ы..."
4. Қате енгізу: "абв" -> хабарлама.                           "Бағдарлама қатеге төзімді..."
5. Мақсат болжамы: велосипед 60 000 тг -> күні.               "Ең ұнайтын мүмкіндігім..."
```

**Демо деректері:** бос ДҚ-мен демо — әсерсіз. Алдын ала шынайы деректер дайындаңыз (бөлек `demo.db` файлы немесе толтыру скрипті):

```python
"""tools/make_demo_db.py — демо үшін шынайы деректер жасайды."""
import datetime
import random
import sqlite3

rnd = random.Random(2027)            # әр жолы бірдей деректер
conn = sqlite3.connect(":memory:")   # нағыз жобада: "demo.db"
conn.executescript("""
CREATE TABLE operation (id INTEGER PRIMARY KEY, category TEXT,
                        amount INTEGER, op_date TEXT);
""")
start = datetime.date(2027, 4, 1)
categories = {"Тамақ": (300, 1200), "Көлік": (100, 200), "Ойын-сауық": (500, 2500)}
rows = []
for day in range(40):
    d = (start + datetime.timedelta(days=day)).isoformat()
    for cat, (low, high) in categories.items():
        if rnd.random() < 0.6:
            rows.append((cat, rnd.randrange(low, high, 50), d))
with conn:
    conn.executemany("INSERT INTO operation (category, amount, op_date) VALUES (?, ?, ?)", rows)
total = conn.execute("SELECT COUNT(*), SUM(amount) FROM operation").fetchone()
print(f"Демо деректер: {total[0]} операция, барлығы {total[1]} тг")
```

Нәтижесі (сандар `seed` бойынша әрдайым бірдей):
```text
Демо деректер: 78 операция, барлығы 54950 тг
```

**Сақтық жоспары (Plan B):**
| Не болуы мүмкін | Алдын ала дайындық |
|---|---|
| Бағдарлама құлады | демо бейнесі (1–2 мин) немесе скриншоттар слайдта |
| Интернет жоқ (API) | кэш жұмыс істейтінін тексеру; оны «офлайн режим» ретінде көрсету |
| Бөгде компьютерде Python/кітапхана жоқ | өз ноутбугы немесе `.exe`; көрсетілім болатын компьютерде алдын ала тексеру |
| Экран кішкене, проектор ажыратымдылығы басқа | терезе өлшемін, қаріпті үлкейту |
| Демо деректер бұзылды | `make_demo_db.py` скрипті оларды бір секундта қайта жасайды |

## Жиі кездесетін қателер

**1. Тегті коммиттелмеген өзгерістермен қою.** `v1.0` ескі нұсқаны көрсетеді. Дұрысы: алдымен `git status` — «nothing to commit».

**2. Репозиторий жеке (Private) күйде қалды** — сілтеме бойынша оны сізден басқа ешкім ашалмайды. Сілтемені басқа аккаунттан немесе жасырын терезеден тексеріңіз.

**3. Слайдтағы мәтінді оқу.** Аудитория сізден жылдам оқиды да, тыңдамайды. Слайд — сурет пен кілт сөздер, мәтін — сіздің аузыңызда.

**4. Демоны бос деректермен көрсету** немесе демо кезінде деректерді «енді толтырайын» деп уақыт жоғалту.

**5. Техникалық бөлімде барлық кодты көрсету.** 200 жол кодты проекторда ешкім оқымайды. Бір қызықты 10 жолдық үзінді + архитектура сызбасы.

**6. Тег GitHub-қа жіберілмеген.** `git push` әдепкі бойынша тегтерді жібермейді. Дұрысы: `git push origin v1.0` немесе `git push --tags`.

## Негізгі ұғымдар
| Ұғым | Түсіндірме |
|---|---|
| Тег (tag) | коммитке берілген тұрақты атау (`v1.0`) |
| Release | тегке негізделген, сипаттамасы мен файлдары бар GitHub жарияланымы |
| Семантикалық нұсқалау | `MAJOR.MINOR.PATCH` нұсқа нөмірлеу жүйесі |
| Портфолио | үздік жұмыстар жинағы (GitHub профилі) |
| Демо сценарийі | көрсетілімнің алдын ала жазылған қадамдары |
| Сақтық жоспары (Plan B) | бір нәрсе бұзылса не істейтінің |

## Ескерту

- Аннотацияланған тег (`git tag -a`) авторды, күнді және хабарламаны сақтайды, ал жеңіл тег (`git tag v1.0`) — тек коммитке нұсқағыш; релиздер үшін аннотацияланған тегті қолданыңыз.
- `random.Random(seed)` жеке генератор жасайды: бірдей дән бірдей тізбек береді, әрі бағдарламаның қалған бөлігіндегі ғаламдық `random`-ға әсер етпейді.
- Нұсқа нөмірін кодтың бір жерінде сақтаған ыңғайлы (`qalta/__init__.py` ішінде `__version__ = "1.0.0"`) және оны «Бағдарлама туралы» терезесі мен тақырыпта көрсету.
- Бүкіл тарихтан құпияларды іздеуге арнайы құралдар бар (мысалы, `git log -S "кілт"` жол пайда болған немесе жоғалған коммиттерді табады).
- Тарихта құпиялар қалып қойса, оларды `git filter-repo` құралымен тазартуға болады, бірақ кілтті бәрібір ауыстыру керек — репозиторий көшірмелері таралып кеткен болуы мүмкін.
- Құжаттама: https://docs.github.com/ru/repositories/releasing-projects-on-github және https://git-scm.com/book/ru/v2/Основы-Git-Работа-с-метками
