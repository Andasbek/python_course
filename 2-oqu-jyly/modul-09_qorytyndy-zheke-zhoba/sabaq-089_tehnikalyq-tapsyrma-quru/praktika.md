# Сабақ 89. Практикалық тапсырмалар: техникалық тапсырма құру

## Базалық деңгей

**1-тапсырма. Бұлдыр талапты нақтыла.** Әр талапты нақты, тексерілетін түрге келтіріңіз және оны функционалдық (Ф) немесе функционалдық емес (ФЕ) деп белгілеңіз:
1. «Ойын қызық болуы керек.»
2. «Бағдарлама деректерді сақтайды.»
3. «Пайдаланушы ақпаратты іздей алады.»
4. «Бағдарлама тез ашылады.»
5. «Бағдарлама қауіпсіз.»
6. «Барлық қателер өңделеді.»
7. «Графиктер бар.»
8. «Бағдарлама кез келген компьютерде жұмыс істейді.»

**2-тапсырма. User story жаз.** Төмендегі жобаларға 3 user story-ден жазыңыз (рөл — әрекет — себебі):
- а) «Отбасы бюджеті» (рөлдер: ата-ана, бала);
- ә) «Бастауыш сыныпқа арналған математикалық ойын» (рөлдер: оқушы, мұғалім).

**3-тапсырма. MoSCoW.** «Мектеп кітапханасы» жобасының мүмкіндіктерін 4 топқа бөліңіз және таңдауыңызды бір сөйлеммен негіздеңіз: кітап қосу; кітапты іздеу; оқушыға кітап беру; кітапты қайтару; мерзімі өткен кітаптар тізімі; кітап мұқабасының суреті; SMS арқылы еске салу; CSV-ге экспорт; ең көп оқылатын кітаптар графигі; кітапханашы паролі; түнгі тақырып; онлайн каталог сайты.

**4-тапсырма. Қабылдау критерийлері.** «Мен оқушы ретінде сөздікке жаңа сөз (қазақша — ағылшынша) қосқым келеді, себебі оны кейін жаттағым келеді» деген user story-ге кемінде 4 қабылдау критерийін «Берілгені — Әрекет — Нәтиже» форматында жазыңыз (қалыпты жағдай, бос өріс, қайталанған сөз, сақталуы).

## Кеңейтілген деңгей

**5-тапсырма. Өз жобаңыздың ТТ-сы.** Репозиторийіңізде `docs/TT.md` файлын жасап, шаблон бойынша толтырыңыз. Талаптар:
- кемінде 5 user story, әрқайсысы MoSCoW басымдығымен; Must — 3–6;
- әр Must user story-ге кемінде 2 қабылдау критерийі;
- кемінде 4 функционалдық емес талап (сенімділік, қауіпсіздік, платформа, тесттер);
- кемінде 3 технология және әрқайсысының рөлі;
- «Шектеулер» және «Won't» тізімдері.

## ★ Олимпиадалық / шығармашылық тапсырма

**7-тапсырма. Талаптар трассировкасы.** `requirements.json` файлына ТТ-дағы user story-лерді (`id`, `matin`, `basymdyq`, `kriteriler`) жазыңыз. Бағдарлама жазыңыз: ол (а) басымдықтар бойынша статистика (неше Must/Should/Could/Won't) шығарсын; (ә) критерийі жоқ Must user story-лерді ескертсін; (б) `docs/TT_kesteh.md` түрінде Markdown кестесін генерациялап, оған «Күйі» бағанын (`[ ]` — орындалмады) қоссын. Жоба барысында бұл кесте прогресс бақылауына қолданылады.

**8-тапсырма. Критерийден тестке.** Өз ТТ-ңыздағы бір Must user story-дің қабылдау критерийлерін `tests/test_<атау>.py` файлында `unittest` тесттерінің қаңқасына айналдырыңыз: әр критерий — бір тест әдісі, ішінде әзірше `self.skipTest("әлі жүзеге асырылмаған")`. Іске қосқанда тесттер «skipped» болып көрінеді — әзірлеу кезінде оларды бірте-бірте толтырасыз (TDD).

## Үй тапсырмасы

1. ТТ-ны өзара тексерудегі пікірлер бойынша аяқтап, `docs/TT.md` ретінде GitHub-қа жүктеңіз (`git commit -m "ТТ 1.0"`).
2. ТТ-дағы барлық «зат есімдерді» (оқушы, сұрақ, тест, нәтиже...) және «етістіктерді» (тапсыру, сақтау, көрсету...) бөлек тізімге жазып келіңіз — келесі сабақта олардан кластар мен әдістерді табамыз.

## Бағалау критерийлері

ТТ формативті бағаланады; қорытынды жобада «Техникалық орындалу деңгейі» (25%) және «Тұрақты жұмыс, тестілеу» (20%) критерийлері ТТ-мен салыстырылып тексеріледі.

| Көрсеткіш | Ұпай | Толық ұпай үшін |
|---|---|---|
| Құрылымы толық (шаблонның барлық бөлімі) | 0–4 | 11 бөлім толтырылған |
| User story сапасы және басымдықтары | 0–6 | ≥ 5 story, формула бойынша, MoSCoW негізделген |
| Қабылдау критерийлері | 0–6 | Әр Must-та ≥ 2 тексерілетін критерий |
| Функционалдық емес талаптар | 0–4 | ≥ 4, нақты және тексерілетін |
| Ауқымның шынайылығы | 0–3 | Уақытқа сай, Won't және шектеулер бар |
| Өзара тексеруге қатысу | 0–2 | Жұбына ≥ 3 сындарлы пікір жазды |
| **Барлығы** | **25** | |

**2-тапсырма — үлгі:**
- а) «Мен ата-ана ретінде әр шығынды санатымен енгізгім келеді, себебі ақша неге жұмсалатынын білгім келеді.» «Мен ата-ана ретінде айлық шығындар графигін көргім келеді, себебі бюджетті жоспарлағым келеді.» «Мен бала ретінде өз қалта ақшамды бөлек есептегім келеді, себебі велосипедке жинап жүрмін.»

**3-тапсырма — үлгі:** Must: кітап қосу, іздеу, беру, қайтару (кітапхананың негізгі жұмысы). Should: мерзімі өткендер тізімі, кітапханашы паролі, CSV экспорт. Could: танымал кітаптар графигі, мұқаба суреті, түнгі тақырып. Won't: SMS еске салу (ақылы қызмет, интернет), онлайн каталог сайты (веб-әзірлеу курста жоқ). Оқушылардың негіздемесі әртүрлі болуы мүмкін — маңыздысы дәлел.

```python
import json
from collections import Counter

ULGI = [
    {"id": "US-1", "matin": "Тақырыпты таңдап, тест тапсыру", "basymdyq": "M",
     "kriteriler": ["10 сұрақ көрсетіледі", "Жауапты таңдауға болады"]},
    {"id": "US-2", "matin": "Нәтиже мен қателерді көру", "basymdyq": "M",
     "kriteriler": ["7/10 (70%) түрінде", "Қателер тізімі"]},
    {"id": "US-3", "matin": "Тақырыптар графигі", "basymdyq": "M", "kriteriler": []},
    {"id": "US-4", "matin": "CSV-ден импорт", "basymdyq": "S", "kriteriler": []},
    {"id": "US-5", "matin": "Таймер", "basymdyq": "C", "kriteriler": []},
]
ATAULAR = {"M": "Must", "S": "Should", "C": "Could", "W": "Won't"}


def zhukteu(path="requirements.json"):
    """Талаптарды JSON-нан оқиды; файл жоқ болса үлгіні сақтайды."""
    try:
        with open(path, encoding="utf-8") as f:
            return json.load(f)
    except FileNotFoundError:
        with open(path, "w", encoding="utf-8") as f:
            json.dump(ULGI, f, ensure_ascii=False, indent=2)
        return ULGI


def taldau(talaptar):
    """Басымдық статистикасы және критерийсіз Must ескертулері."""
    sanau = Counter(t["basymdyq"] for t in talaptar)
    for kod, atau in ATAULAR.items():
        print(f"{atau:<7} {sanau.get(kod, 0)}")
    for t in talaptar:
        if t["basymdyq"] == "M" and not t["kriteriler"]:
            print(f"Ескерту: {t['id']} (Must) — қабылдау критерийлері жоқ")


def kesteh_zhasau(talaptar, path="TT_kesteh.md"):
    """Прогресті бақылауға арналған Markdown кесте жасайды."""
    zholdar = ["| ID | Талап | Басымдық | Критерий саны | Күйі |", "|---|---|---|---|---|"]
    for t in talaptar:
        zholdar.append(f"| {t['id']} | {t['matin']} | {ATAULAR[t['basymdyq']]} "
                       f"| {len(t['kriteriler'])} | [ ] |")
    with open(path, "w", encoding="utf-8") as f:
        f.write("\n".join(zholdar) + "\n")
    print(f"{path} жасалды")


talaptar = zhukteu()
taldau(talaptar)
kesteh_zhasau(talaptar)
```
