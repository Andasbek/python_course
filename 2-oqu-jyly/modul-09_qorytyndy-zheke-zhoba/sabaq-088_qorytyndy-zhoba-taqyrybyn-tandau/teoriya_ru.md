## 1. Из чего состоит законченный Python-проект

Законченный проект — это не один файл со скриптом, а приложение, в котором объединены несколько технологий и соблюдены инженерные практики.

**Типичные сочетания технологий Python:**

| Тип проекта | Технологии | Пример |
|---|---|---|
| Оконное приложение с данными | ООП + Tkinter + SQLite | Учёт книг библиотеки |
| Игра | ООП + Pygame + JSON | Игра с таблицей рекордов |
| Аналитическое приложение | API (`requests`) + Pandas + Matplotlib | Мониторинг качества воздуха с графиками |
| Учебный тренажёр | Tkinter + SQLite + Pandas/Matplotlib | Тесты со статистикой слабых тем |
| Бот/консольный сервис | API + JSON/SQLite + `logging` | Telegram-бот с напоминаниями |

**Признаки качественного проекта:**
1. Код разделён на модули и классы, соблюдён PEP 8, у функций и классов есть docstring.
2. Данные хранятся постоянно: файл (CSV/JSON) или база данных (SQLite).
3. Основная логика покрыта тестами (`unittest`), ошибки обрабатываются (`try/except`) и записываются в лог (`logging`).
4. Репозиторий на GitHub: регулярные коммиты, README, руководство пользователя, `requirements.txt`.
5. Секреты (ключи API, пароли) вынесены в переменные окружения.

## 2. Откуда берутся идеи

### Начинать с «проблемы»

Хороший проект решает конкретную проблему конкретного человека. Оглянитесь вокруг:

| Сфера | Примеры проблем |
|---|---|
| Школа | Забытое домашнее задание; изменения в расписании; трудно найти книгу в библиотеке; график дежурств |
| Кружок/спорт | Отслеживание результатов тренировок; расписание соревнований; честное деление на команды |
| Семья | Учёт расходов; время приёма лекарств; список продуктов; семейная библиотека |
| Город | Качество воздуха (смог в Алматы!); общественный транспорт; погода; свободные парковки |
| Учёба | Заучивание слов (английский, казахские термины); тесты для подготовки к ЕНТ; тренажёр формул |
| Хобби | Игра; статистика прослушивания музыки; список фильмов/книг; рецепты |
| Экология/общество | Сортировка мусора; волонтёры; приют для животных |

### Формула идеи

```text
[ПОЛЬЗОВАТЕЛЬ]  ...  [ПРОБЛЕМА]  ...  поэтому я создаю  [РЕШЕНИЕ],
которое с помощью  [ОСНОВНОЙ ВОЗМОЖНОСТИ]  даёт  [ПОЛЬЗУ].
```

**Пример:** «*Ученики 9-го класса* при подготовке к ЕНТ *не знают, по каким темам они слабы*, поэтому я создаю *тестовый тренажёр*, который *показывает слабые темы* с помощью *хранения результатов в SQLite и графиков по темам*.»

Технологии: Tkinter (интерфейс) + SQLite (вопросы и результаты) + Pandas/Matplotlib (статистика) + ООП → 4 технологии.

### Способы генерации идей

- **5 проблем — 3 идеи — 1 выбор.** Сначала запишите только проблемы (без решений!), затем придумайте решения для трёх самых интересных.
- **Улучшить существующее.** Адаптировать небольшую часть известного приложения (Kundelik, Kaspi, 2GIS, Duolingo) под свою школу/кружок.
- **Комбинировать технологии.** «API + анализ + GUI»: например, калькулятор накоплений по курсу валют, с графиком.
- **Интервью.** Спросите у будущих пользователей (родителей, друзей, знакомых): «Что вам мешает каждый день?»

## 3. Критерии хорошей идеи

| Критерий | Вопрос | Красный флаг |
|---|---|---|
| **Актуальность** | Существует ли эта проблема на самом деле? Кому это полезно? | «Никому не нужно, но интересно» |
| **Самостоятельность** | Это моя собственная идея? Чем она отличается от существующих решений? | Копирование готового проекта из интернета |
| **Реализуемость** | Смогу ли я сделать это за отведённое время (например, ≈ 25 часов)? Хватит ли моих знаний? | «Соцсеть как Instagram», «ИИ-ассистент», «игра как GTA» |
| **Технологии** | Объединяет ли она естественным образом не менее 3 технологий? | Консольная программа только с `print`/`input` |
| **Интерес** | Интересно ли мне самому? Смогу ли я заниматься этим целый месяц? | «Потому что так сказали» |
| **Демонстрируемость** | Можно ли показать результат работы за 3 минуты? | Результат не виден глазу |

### Правильный выбор масштаба: MVP

**MVP** (Minimum Viable Product — минимально жизнеспособный продукт) — **самая простая работающая версия**, которая решает основную проблему, но не содержит ничего лишнего.

```text
     ┌───────────────────────────────────┐
     │  Версия мечты (если есть время)   │  ← онлайн-синхронизация, мобильная версия
     │  ┌─────────────────────────────┐  │
     │  │  Хорошая версия             │  │  ← графики, экспорт, темы
     │  │  ┌───────────────────────┐  │  │
     │  │  │  MVP (обязательно)    │  │  │  ← прохождение теста + сохранение результата
     │  │  └───────────────────────┘  │  │
     │  └─────────────────────────────┘  │
     └───────────────────────────────────┘
```

**Правило:** сначала полностью завершите MVP, затем добавляйте слои. **Завершённый** MVP намного лучше наполовину сделанного проекта «мечты».

### Оценка реализуемости: «бюджет времени»

Из общего времени на проект значительная часть уходит на планирование, тестирование и документирование: например, из 28 часов на чистую разработку остаётся около **15–18 часов**. Перечислите основные возможности идеи и оцените каждую в часах. Если в сумме больше 15 часов — уменьшите масштаб.

## 4. Матрица оценки идей

Оцениваем каждую идею по каждому критерию от 1 до 5 баллов; у некоторых критериев вес больше:

| Критерий | Вес | Идея А: тренажёр ЕНТ | Идея Б: монитор качества воздуха | Идея В: 3D-шутер |
|---|---|---|---|---|
| Актуальность | ×2 | 5 → 10 | 5 → 10 | 2 → 4 |
| Самостоятельность | ×1 | 3 → 3 | 4 → 4 | 2 → 2 |
| Реализуемость | ×2 | 5 → 10 | 4 → 8 | 1 → 2 |
| Технологии (≥ 3) | ×1 | 5 → 5 | 5 → 5 | 2 → 2 |
| Интерес для меня | ×2 | 4 → 8 | 5 → 10 | 5 → 10 |
| **Итого** | | **36** | **37** | **20** |

Идея Б (API + Pandas + Matplotlib + Tkinter + SQLite — сбор данных о качестве воздуха в Алматы, показ графиков и предупреждений) немного выше. А «3D-шутер», хоть и очень интересен, имеет низкую реализуемость — его нужно упростить до 2D.

## 5. Представление идеи: питч

**Питч** (pitch) — краткое и убедительное представление идеи. «Лифтовый питч» — заинтересовать инвестора, пока едешь в лифте (≈ 1 минута).

**Структура питча (1 минута):**
1. **Крючок** (10 сек) — вопрос или факт: «Вы замечали, что зимой качество воздуха в Алматы часто достигает «вредного» уровня, но никто не проверяет его ежедневно?»
2. **Проблема и пользователь** (15 сек) — кто и от чего страдает.
3. **Решение** (20 сек) — что делает программа; 2–3 основные возможности.
4. **Технологии** (10 сек) — какие 3+ технологии.
5. **Почему я** (5 сек) — почему мне это интересно, что я знаю.

### Вопросы для проверки идеи

- Кто конкретно будет пользоваться этой программой?
- Какие именно 3 возможности войдут в MVP?
- Откуда будут взяты данные?
- Какая часть самая сложная технически? Что можно убрать, если не хватит времени?
- Чем программа отличается от существующих приложений?

## Частые ошибки

**1. Слишком большая идея.** «Полноценный электронный журнал для школы» — годовая работа для целой команды. Уменьшить: «Приложение для отслеживания домашних заданий одного класса».

**2. Слишком маленькая идея.** «Калькулятор» — типичное учебное упражнение. Нет трёх технологий, низкая самостоятельность.

**3. Начинать с технологии.** «Я люблю Pygame, сделаю что-нибудь» — нет ни пользователя, ни проблемы. Лучше: «игра, помогающая ученикам начальных классов выучить таблицу умножения» (Pygame + рекорды в JSON + ООП + график прогресса в Matplotlib).

**4. Копирование готового проекта.** Выдавать чужой проект с GitHub под своим именем — нарушение академической честности. На чужом коде можно **учиться**, но проект должен быть вашим; использованные источники укажите в README.

**5. Не продумать источник данных.** «Буду анализировать оценки всех учеников школы» — кто даст эти данные? Есть ли разрешение на использование персональных данных?

## Основные понятия

| Понятие | Объяснение |
|---|---|
| Итоговый проект | Индивидуальный проект, объединяющий несколько технологий Python |
| Актуальность | Реальное существование проблемы и полезность решения |
| Самостоятельность | Идея принадлежит самому автору и отличается от существующих решений |
| MVP | Минимальная работающая версия, решающая основную проблему |
| Питч | Краткое и убедительное представление идеи |
| Матрица оценки | Таблица сравнения идей по взвешенным критериям |
| Масштаб (scope) | Граница возможностей, входящих в проект |

## Примечание

- Перед выбором технологии проверьте, есть ли у неё нужные возможности и поддерживает ли она вашу версию Python: например, страница пакета на [pypi.org](https://pypi.org) указывает поддерживаемые версии (`Requires: Python >=3.9`).
- Если проект использует внешний API, заранее проверьте лимиты бесплатного тарифа и формат ответа (JSON) — от этого зависит, получится ли собрать нужные данные.
- Tkinter и SQLite входят в стандартную библиотеку Python и не требуют установки; Pygame, Pandas, Matplotlib, `requests` устанавливаются через `pip`.
- Для оценки объёма удобно разбить каждую возможность на функции/классы: если возможность не удаётся описать 3–5 функциями, её стоит упростить.
- Чужой код с открытой лицензией (MIT, Apache 2.0 и др.) можно использовать только с соблюдением её условий — как минимум с указанием автора и лицензии в README.
- Документация: [Python Standard Library](https://docs.python.org/3/library/index.html), [Python Packaging User Guide](https://packaging.python.org/).
