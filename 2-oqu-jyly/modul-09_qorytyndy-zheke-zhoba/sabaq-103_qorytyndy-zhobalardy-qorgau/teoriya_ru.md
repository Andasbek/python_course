## 1. Проверка проекта перед показом

Проект показывают на чужом компьютере, поэтому сначала проверяем, что он **запускается не только у автора**. Технический чек-лист:

| № | Проверка | Как |
|---|---|---|
| 1 | Версия Python подходит | `python --version` ≥ версии из README |
| 2 | Все библиотеки установлены | `pip install -r requirements.txt` в чистом `venv` |
| 3 | Нет абсолютных путей вида `C:\Users\...` | пути строятся от `Path(__file__).resolve().parent` |
| 4 | Демо-данные отдельно от настоящих | `demo.db` или скрипт заполнения |
| 5 | Окно помещается на экран проектора | проверка при разрешении 1280×720 |
| 6 | Работа без интернета | кэш/офлайн-режим для API |

Часть проверок удобно автоматизировать небольшим скриптом:

```python
"""tools/check_env.py — проверяет окружение перед запуском проекта."""
import sys
from importlib import metadata

MIN_PYTHON = (3, 10)
REQUIRED = ["matplotlib", "requests"]


def check():
    ok = True
    if sys.version_info < MIN_PYTHON:
        print(f"Нужен Python {MIN_PYTHON[0]}.{MIN_PYTHON[1]}+, а запущен {sys.version.split()[0]}")
        ok = False
    for name in REQUIRED:
        try:
            print(f"{name:12} {metadata.version(name)}")
        except metadata.PackageNotFoundError:
            print(f"{name:12} НЕ УСТАНОВЛЕН -> pip install {name}")
            ok = False
    return ok


if __name__ == "__main__":
    print("Окружение в порядке" if check() else "Есть проблемы")
```

Пример результата:
```text
matplotlib   3.9.2
requests     2.32.3
Окружение в порядке
```

`importlib.metadata.version()` возвращает версию установленного пакета, не импортируя его.

## 2. Как объяснить архитектуру проекта

Архитектуру проще всего показать схемой: какие модули есть и кто кого вызывает.

```text
main.py ──> gui.py ──> logic.py ──> database.py ──> SQLite (qalta.db)
                           └──────> currency.py ──> API курса валют (+ кэш JSON)
```

Схему зависимостей можно получить автоматически: модуль `ast` разбирает исходный код и находит все `import`:

```python
import ast

SOURCE = '''
import datetime
from qalta.database import Database
from qalta.currency import get_kzt_rate
'''


def imports_of(source):
    """Возвращает отсортированный список модулей, импортируемых в коде."""
    found = set()
    for node in ast.walk(ast.parse(source)):
        if isinstance(node, ast.Import):
            found.update(alias.name for alias in node.names)
        elif isinstance(node, ast.ImportFrom) and node.module:
            found.add(node.module)
    return sorted(found)


print(imports_of(SOURCE))
```

Результат:
```text
['datetime', 'qalta.currency', 'qalta.database']
```

В настоящем проекте `SOURCE` читают из файла: `Path("qalta/logic.py").read_text(encoding="utf-8")`. Если оказалось, что `database.py` импортирует `gui.py`, — слои перепутаны.

## 3. Обоснование технического решения: структура «Т–А–П»

На вопрос «Почему вы сделали так?» отвечают по схеме:

| Часть | Значение | Пример |
|---|---|---|
| **Т**езис | ваше решение | «Я хранил данные в SQLite.» |
| **А**ргумент | почему это правильно | «Потому что операции и категории связаны, а для отчётов нужна фильтрация по месяцу и категории.» |
| **П**ример | конкретное доказательство | «Например, месячный отчёт — это один запрос с `JOIN` и `GROUP BY`, `database.py`, строка 45. В JSON это был бы цикл на 20 строк.» |

Признать альтернативу — признак понимания: «JSON был бы проще, но...». Типичные технические выборы и аргументы:

| Выбор | Когда оправдан | Альтернатива |
|---|---|---|
| SQLite | связанные таблицы, фильтры, отчёты | JSON — для настроек и небольших списков |
| Tkinter | оконное приложение с формами, входит в стандартную библиотеку | Pygame — для игр с анимацией |
| Классы (ООП) | у сущности есть состояние и поведение | функции — для простых вычислений без состояния |
| `unittest` | стандартная библиотека, не нужна установка | `pytest` — короче синтаксис, нужна установка |
| Кэш для API | сервис может быть недоступен | запрос при каждом запуске — медленно и ненадёжно |

## 4. Технические вопросы о проекте и ответы на них

Вопросы о коде обычно касаются нескольких ключевых понятий. Ответ должен опираться на конкретное место в коде:

| Вопрос | Понятие | Короткий ответ |
|---|---|---|
| Зачем `with conn:`? | транзакция | при успехе — `commit`, при ошибке — `rollback`, данные не записываются наполовину |
| Почему `?`, а не f-строка в SQL? | SQL-инъекция | значение передаётся отдельно и не может изменить смысл запроса |
| Что будет без интернета? | обработка исключений, кэш | `requests.RequestException` перехватывается, показывается последний сохранённый курс |
| Зачем `if __name__ == "__main__":`? | модуль и скрипт | код внутри выполняется только при прямом запуске файла, а не при импорте |
| Как проверяется ввод? | валидация | `parse_amount()` выбрасывает `ValueError` с понятным сообщением, интерфейс его показывает |
| Как вы тестировали? | модульные тесты, mock | `python -m unittest discover`, БД `:memory:`, `mock.patch` для API |

Если ответа нет — честно сказать «этот случай я не проверял» лучше, чем выдумывать: любое утверждение о коде можно сразу проверить, запустив программу.

## 5. Подготовка программы к демонстрации

Удобно предусмотреть **режим демонстрации** — запуск с демо-базой и крупным шрифтом через аргумент командной строки:

```python
"""main.py — запуск с аргументами командной строки."""
import argparse
from pathlib import Path

BASE_DIR = Path(__file__).resolve().parent


def parse_args(argv=None):
    parser = argparse.ArgumentParser(description="Карманные деньги")
    parser.add_argument("--demo", action="store_true", help="использовать demo.db")
    parser.add_argument("--scale", type=float, default=1.0, help="масштаб интерфейса")
    return parser.parse_args(argv)


args = parse_args(["--demo", "--scale", "1.5"])      # в проекте: parse_args()
db_path = BASE_DIR / ("demo.db" if args.demo else "qalta.db")
print(db_path.name, args.scale)
```

Результат:
```text
demo.db 1.5
```

Полезные настройки Tkinter для показа на проекторе:
- `root.tk.call("tk", "scaling", 1.5 * root.tk.call("tk", "scaling"))` — увеличивает все шрифты и отступы, заданные в пунктах;
- `root.attributes("-fullscreen", True)` — полноэкранный режим (выход — `root.attributes("-fullscreen", False)`, удобно повесить на `<Escape>`);
- `root.minsize(...)` и `weight` в `grid` — окно корректно растягивается при другом разрешении.

## 6. Выставка проектов: краткое описание и QR-код

На выставке проект представляют за одну минуту («презентация в лифте»): **что это, для кого, чем особенный, на чём сделан**. Тот же текст подходит для поля About на GitHub и первого абзаца README:

> «“Карманные деньги” помогают видеть, куда уходят деньги. Расход вводится за 5 секунд, программа строит диаграмму по категориям и прогнозирует, когда вы накопите на цель. Внутри — Tkinter, SQLite, Matplotlib и API курса валют.»

Чтобы посетители могли открыть репозиторий с телефона, рядом с проектом размещают QR-код. Его можно сгенерировать на Python сторонней библиотекой `qrcode` (`pip install "qrcode[pil]"`):

```python
import qrcode

url = "https://github.com/<логин>/qalta-aqshasy"
image = qrcode.make(url)
image.save("docs/qr_repo.png")
```

## Частые ошибки

**1. Не проверить компьютер заранее.** На другом компьютере нет `matplotlib` или другая версия Python. Правильно: `tools/check_env.py`, свой ноутбук или `.exe`.

**2. Абсолютный путь к базе.** `sqlite3.connect("C:/Users/Alikhan/qalta.db")` на чужом компьютере создаст пустую базу или упадёт. Правильно: путь от `Path(__file__).resolve().parent`.

**3. Показ на настоящей базе.** Демо-операции смешиваются с реальными, случайное удаление портит данные. Правильно: отдельная `demo.db` (флаг `--demo`).

**4. Фиксированный размер окна.** `root.geometry("1920x1080")` не помещается на экран 1280×720. Правильно: `minsize` + растягивание через `weight`.

**5. Утверждать о коде то, что не проверено.** «Программа не падает ни при каком вводе» опровергается первым же нестандартным вводом. Правильно: говорить о том, что покрыто тестами и тест-кейсами.

## Основные понятия
| Понятие | Объяснение |
|---|---|
| Чистое окружение | новый `venv`, в котором установлены только зависимости из `requirements.txt` |
| `importlib.metadata` | модуль для получения сведений об установленных пакетах |
| `ast` | модуль разбора исходного кода Python в синтаксическое дерево |
| Т–А–П | тезис — аргумент — пример: структура обоснования решения |
| `argparse` | модуль разбора аргументов командной строки |
| Презентация в лифте | представление проекта за 1 минуту |
| QR-код | двумерный штрихкод со ссылкой, читаемый камерой телефона |

## Примечание

- `importlib.metadata` входит в стандартную библиотеку с Python 3.8; для старых версий существовал отдельный пакет `importlib_metadata`.
- `argparse` автоматически создаёт справку: `python main.py --help` покажет все аргументы с описаниями из `help=`.
- `tk scaling` задаётся в пикселях на пункт; на мониторах с высоким DPI в Windows дополнительно может понадобиться `ctypes.windll.shcore.SetProcessDpiAwareness(1)`, иначе интерфейс выглядит размытым.
- `qrcode` и `Pillow` — сторонние пакеты; если QR-код нужен только один раз, сгенерируйте картинку заранее и не добавляйте эти пакеты в `requirements.txt` основного приложения.
- Документация: https://docs.python.org/3/library/argparse.html, https://docs.python.org/3/library/ast.html, https://docs.python.org/3/library/importlib.metadata.html
