## 1. Көрсетер алдында жобаны тексеру

Жоба бөгде компьютерде көрсетіледі, сондықтан алдымен оның **тек автордың компьютерінде ғана емес** іске қосылатынын тексереміз. Техникалық чек-парақ:

| № | Тексеру | Қалай |
|---|---|---|
| 1 | Python нұсқасы сәйкес | `python --version` ≥ README-дегі нұсқа |
| 2 | Барлық кітапхана орнатылған | таза `venv`-те `pip install -r requirements.txt` |
| 3 | `C:\Users\...` сияқты абсолют жолдар жоқ | жолдар `Path(__file__).resolve().parent`-тен құрылады |
| 4 | Демо деректер нағыз деректерден бөлек | `demo.db` немесе толтыру скрипті |
| 5 | Терезе проектор экранына сыяды | 1280×720 ажыратымдылықта тексеру |
| 6 | Интернетсіз жұмыс | API үшін кэш/офлайн режим |

Тексерудің бір бөлігін шағын скриптпен автоматтандыруға болады:

```python
"""tools/check_env.py — жобаны іске қосар алдында ортаны тексереді."""
import sys
from importlib import metadata

MIN_PYTHON = (3, 10)
REQUIRED = ["matplotlib", "requests"]


def check():
    ok = True
    if sys.version_info < MIN_PYTHON:
        print(f"Python {MIN_PYTHON[0]}.{MIN_PYTHON[1]}+ керек, ал іске қосылғаны {sys.version.split()[0]}")
        ok = False
    for name in REQUIRED:
        try:
            print(f"{name:12} {metadata.version(name)}")
        except metadata.PackageNotFoundError:
            print(f"{name:12} ОРНАТЫЛМАҒАН -> pip install {name}")
            ok = False
    return ok


if __name__ == "__main__":
    print("Орта дұрыс" if check() else "Мәселелер бар")
```

Нәтиже мысалы:
```text
matplotlib   3.9.2
requests     2.32.3
Орта дұрыс
```

`importlib.metadata.version()` орнатылған пакеттің нұсқасын оны импорттамай-ақ қайтарады.

## 2. Жоба архитектурасын қалай түсіндіреміз

Архитектураны сызбамен көрсету оңай: қандай модульдер бар және қайсысы қайсысын шақырады.

```text
main.py ──> gui.py ──> logic.py ──> database.py ──> SQLite (qalta.db)
                           └──────> currency.py ──> валюта бағамы API-і (+ JSON кэш)
```

Тәуелділік сызбасын автоматты түрде алуға болады: `ast` модулі бастапқы кодты талдап, барлық `import`-ты табады:

```python
import ast

SOURCE = '''
import datetime
from qalta.database import Database
from qalta.currency import get_kzt_rate
'''


def imports_of(source):
    """Кодта импортталатын модульдердің сұрыпталған тізімін қайтарады."""
    found = set()
    for node in ast.walk(ast.parse(source)):
        if isinstance(node, ast.Import):
            found.update(alias.name for alias in node.names)
        elif isinstance(node, ast.ImportFrom) and node.module:
            found.add(node.module)
    return sorted(found)


print(imports_of(SOURCE))
```

Нәтижесі:
```text
['datetime', 'qalta.currency', 'qalta.database']
```

Нағыз жобада `SOURCE` файлдан оқылады: `Path("qalta/logic.py").read_text(encoding="utf-8")`. Егер `database.py` `gui.py`-ді импорттайтыны анықталса — қабаттар шатасқан.

## 3. Техникалық шешімді дәлелдеу: «Т–Д–М» құрылымы

«Неге осылай жасадыңыз?» деген сұраққа мына сызба бойынша жауап береді:

| Бөлік | Мағынасы | Мысал |
|---|---|---|
| **Т**ұжырым | шешіміңіз | «Мен деректерді SQLite-та сақтадым.» |
| **Д**әлел | неге бұл дұрыс | «Себебі операциялар мен санаттар байланысқан, ал есептер ай мен санат бойынша сүзуді қажет етеді.» |
| **М**ысал | нақты дәлел | «Мысалы, айлық есеп — бір `JOIN` және `GROUP BY` сұранысы, `database.py`, 45-жол. JSON-да бұл 20 жол цикл болар еді.» |

Баламаны мойындау — түсінудің белгісі: «JSON қарапайымырақ еді, бірақ...». Әдеттегі техникалық таңдаулар мен дәлелдер:

| Таңдау | Қашан орынды | Балама |
|---|---|---|
| SQLite | байланысқан кестелер, сүзгілер, есептер | JSON — баптаулар мен шағын тізімдер үшін |
| Tkinter | пішіндері бар терезелік қосымша, стандартты кітапханаға кіреді | Pygame — анимациясы бар ойындар үшін |
| Кластар (ОБП) | мәннің күйі мен мінез-құлқы бар | функциялар — күйсіз қарапайым есептеулер үшін |
| `unittest` | стандартты кітапхана, орнату қажет емес | `pytest` — синтаксисі қысқа, орнату керек |
| API үшін кэш | қызмет қолжетімсіз болуы мүмкін | әр іске қосуда сұраныс — баяу әрі сенімсіз |

## 4. Жоба туралы техникалық сұрақтар және оларға жауаптар

Код туралы сұрақтар әдетте бірнеше негізгі ұғымға қатысты. Жауап кодтағы нақты орынға сүйенуі керек:

| Сұрақ | Ұғым | Қысқа жауап |
|---|---|---|
| `with conn:` не үшін? | транзакция | сәтті болса — `commit`, қате болса — `rollback`, деректер жартылай жазылмайды |
| SQL-да неге f-жол емес, `?`? | SQL-инъекция | мән бөлек беріледі және сұраныстың мағынасын өзгерте алмайды |
| Интернет болмаса не болады? | ерекшеліктерді өңдеу, кэш | `requests.RequestException` ұсталады, соңғы сақталған бағам көрсетіледі |
| `if __name__ == "__main__":` не үшін? | модуль және скрипт | ішіндегі код файл импортталғанда емес, тікелей іске қосылғанда ғана орындалады |
| Енгізу қалай тексеріледі? | валидация | `parse_amount()` түсінікті хабарламамен `ValueError` көтереді, интерфейс оны көрсетеді |
| Қалай тестіледіңіз? | модульдік тесттер, mock | `python -m unittest discover`, `:memory:` ДҚ, API үшін `mock.patch` |

Жауап білмесеңіз — ойдан шығарғаннан гөрі «бұл жағдайды тексермеппін» деп шынын айтқан дұрыс: код туралы кез келген тұжырымды бағдарламаны іске қосып бірден тексеруге болады.

## 5. Бағдарламаны көрсетілімге дайындау

**Демонстрация режимін** алдын ала қарастырған ыңғайлы — пәрмен жолы аргументі арқылы демо базамен және ірі қаріппен іске қосу:

```python
"""main.py — пәрмен жолы аргументтерімен іске қосу."""
import argparse
from pathlib import Path

BASE_DIR = Path(__file__).resolve().parent


def parse_args(argv=None):
    parser = argparse.ArgumentParser(description="Қалта ақшасы")
    parser.add_argument("--demo", action="store_true", help="demo.db қолдану")
    parser.add_argument("--scale", type=float, default=1.0, help="интерфейс масштабы")
    return parser.parse_args(argv)


args = parse_args(["--demo", "--scale", "1.5"])      # жобада: parse_args()
db_path = BASE_DIR / ("demo.db" if args.demo else "qalta.db")
print(db_path.name, args.scale)
```

Нәтижесі:
```text
demo.db 1.5
```

Проекторда көрсетуге пайдалы Tkinter баптаулары:
- `root.tk.call("tk", "scaling", 1.5 * root.tk.call("tk", "scaling"))` — пункттермен берілген барлық қаріп пен шегіністі үлкейтеді;
- `root.attributes("-fullscreen", True)` — толық экран режимі (шығу — `root.attributes("-fullscreen", False)`, оны `<Escape>`-ке байлау ыңғайлы);
- `root.minsize(...)` және `grid`-тегі `weight` — басқа ажыратымдылықта терезе дұрыс созылады.

## 6. Жобалар көрмесі: қысқа сипаттама және QR-код

Көрмеде жоба бір минутта таныстырылады («лифттегі презентация»): **бұл не, кімге арналған, ерекшелігі неде, неден жасалған**. Дәл осы мәтін GitHub-тағы About өрісіне және README-нің бірінші абзацына жарайды:

> «“Қалта ақшасы” ақшаның қайда кететінін көруге көмектеседі. Шығыс 5 секундта енгізіледі, бағдарлама санаттар бойынша диаграмма салып, мақсатқа қашан жинайтыныңызды болжайды. Ішінде — Tkinter, SQLite, Matplotlib және валюта бағамы API-і.»

Келушілер репозиторийді телефоннан аша алуы үшін жобаның қасына QR-код қойылады. Оны Python-да `qrcode` бөгде кітапханасымен жасауға болады (`pip install "qrcode[pil]"`):

```python
import qrcode

url = "https://github.com/<логин>/qalta-aqshasy"
image = qrcode.make(url)
image.save("docs/qr_repo.png")
```

## Жиі кездесетін қателер

**1. Компьютерді алдын ала тексермеу.** Басқа компьютерде `matplotlib` жоқ немесе Python нұсқасы басқа. Дұрысы: `tools/check_env.py`, өз ноутбугы немесе `.exe`.

**2. Базаға абсолют жол.** `sqlite3.connect("C:/Users/Alikhan/qalta.db")` бөгде компьютерде бос база жасайды немесе құлайды. Дұрысы: `Path(__file__).resolve().parent`-тен жол.

**3. Нағыз базада көрсету.** Демо операциялар нағыз деректермен араласады, кездейсоқ өшіру деректерді бүлдіреді. Дұрысы: бөлек `demo.db` (`--demo` жалаушасы).

**4. Терезенің тұрақты өлшемі.** `root.geometry("1920x1080")` 1280×720 экранға сыймайды. Дұрысы: `minsize` + `weight` арқылы созылу.

**5. Код туралы тексерілмеген нәрсені айту.** «Бағдарлама кез келген енгізуде құламайды» деген сөзді бірінші ерекше енгізу жоққа шығарады. Дұрысы: тесттер мен тест-кейстер қамтыған нәрсе туралы айту.

## Ескерту

- `importlib.metadata` Python 3.8-ден бастап стандартты кітапханаға кіреді; ескі нұсқалар үшін бөлек `importlib_metadata` пакеті болған.
- `argparse` анықтаманы автоматты түрде жасайды: `python main.py --help` барлық аргументті `help=` сипаттамаларымен көрсетеді.
- `tk scaling` бір пунктке келетін пиксельмен беріледі; Windows-тағы жоғары DPI мониторларда интерфейс бұлыңғыр көрінбеуі үшін қосымша `ctypes.windll.shcore.SetProcessDpiAwareness(1)` керек болуы мүмкін.
- `qrcode` пен `Pillow` — бөгде пакеттер; QR-код бір рет қана керек болса, суретті алдын ала жасап, бұл пакеттерді негізгі қосымшаның `requirements.txt`-іне қоспаңыз.
- Құжаттама: https://docs.python.org/3/library/argparse.html, https://docs.python.org/3/library/ast.html, https://docs.python.org/3/library/importlib.metadata.html
