## 1. UI и UX: в чём разница?

| | **UI** (User Interface, пользовательский интерфейс) | **UX** (User Experience, пользовательский опыт) |
|---|---|---|
| Вопрос | **Как выглядит** программа? | **Насколько легко и приятно** пользоваться программой? |
| Содержание | цвета, шрифты, кнопки, расположение | сценарии, количество шагов, понятность, защита от ошибок |
| Аналогия | Цвет и форма дверной ручки | Сразу ли понятно, толкать дверь или тянуть |

Красивая, но непонятная программа — плохой UX. Простая, но понятная программа — хороший UX. Мы учитываем и то и другое, но **сначала UX**.

## 2. Определение пользователя и его цели

Интерфейс проектируем не «для себя», а для **конкретного пользователя**. Для этого пишем короткую **персону**:

> **Персона:** Даулет, 13 лет, 7-й класс. Получает 3000 тг карманных денег в неделю. Чаще пользуется компьютером, чем телефоном. Цель — понять, почему к концу месяца деньги заканчиваются, и накопить на велосипед.

Требования, вытекающие из персоны: крупные, понятные кнопки; ввод должен занимать не более 10 секунд; диаграмма должна быть видна сразу.

## 3. Пользовательский сценарий (user flow)

**Сценарий** — последовательность шагов, которые пользователь выполняет для достижения цели. Для каждой основной возможности из ТЗ пишем один сценарий.

**Сценарий «Добавить расход»:**
1. Открывает программу → главный экран (виден баланс).
2. Нажимает кнопку «+ Расход» → открывается окно ввода.
3. Вводит сумму, выбирает категорию из списка, дата автоматически сегодняшняя.
4. Нажимает «Сохранить» → окно закрывается, баланс и таблица обновляются.
5. Если ошибка (сумма пустая) → красное сообщение рядом с полем.

Сценарий удобно рисовать в виде блок-схемы:

```text
[Главный экран] --(+ Расход)--> [Окно ввода] --(Сохранить)--> <Данные верны?>
      ^                                                         |да          |нет
      |                                                         v            v
      +---------------------(обновлённый баланс)-------- [Запись в БД]  [Сообщение об ошибке]
```

**Правило:** для часто используемого действия должно быть **минимум шагов**. Расход добавляется несколько раз в день — поэтому кнопка находится на главном экране, а не в глубине меню.

## 4. Карта экранов (screen map)

Все экраны и переходы между ними:

```text
                ┌───────────────┐
                │ Главный экран │
                └──────┬────────┘
       ┌───────────┬───┴────────┬─────────────┐
       v           v            v             v
 [Добавить операцию] [История] [Статистика] [Настройки]
                   │            │
                   v            v
          [Редактировать операцию] [Диаграмма]
```

Карта экранов для игры: `Меню → Игра → Пауза → Игра окончена → Рекорды → Меню`.

> Если экранов больше 5–7, нужно пересмотреть объём проекта: за ограниченное время сделать всё невозможно.

## 5. Виды прототипов

**Прототип (prototype)** — не до конца сделанная версия программы, которая показывает, как она будет выглядеть и как будет работать. Он позволяет находить ошибки на **дешёвом** этапе: передвинуть кнопку на бумаге — 5 секунд, переписать готовый код — несколько часов.

| Вид | Детализация | Инструмент | Время | Когда используем |
|---|---|---|---|---|
| **Бумажный эскиз** | очень низкая | карандаш, стикер | 5–10 мин | быстро сравнить идеи |
| **Каркасная схема** (wireframe) | низкая | draw.io, Penpot, даже текст | 15–30 мин | зафиксировать расположение (без цвета, серые прямоугольники) |
| **Макет** (mockup) | высокая | Figma, Penpot | 1–2 ч | цвета, шрифты, иконки |
| **Интерактивный прототип** | средняя/высокая | Figma или код Tkinter без логики | 30–60 мин | проверить сценарий, реально «нажимая» |

Самый эффективный путь для небольших проектов: **бумажный эскиз → каркасная схема → каркас на Tkinter**. Каркас на Tkinter потом станет началом настоящего интерфейса, то есть время не пропадёт зря.

### Пример текстовой каркасной схемы
```text
┌─────────────────────────────────────────────────┐
│  Карманные деньги                  [Настройки]  │
├─────────────────────────────────────────────────┤
│  Баланс:  12 450 тг        ≈ 24.9 $             │
│  [ + Доход ]   [ + Расход ]                     │
├───────────────────────────┬─────────────────────┤
│  Последние операции       │   Расходы за апрель │
│  15.04  Еда       -800    │     ( круговая      │
│  14.04  Транспорт -200    │      диаграмма )    │
│  14.04  Родители  +3000   │                     │
├───────────────────────────┴─────────────────────┤
│  [История]  [Статистика]  [Экспорт CSV]         │
└─────────────────────────────────────────────────┘
```

## 6. 8 правил удобного интерфейса

Список, основанный на 10 эвристиках юзабилити Якоба Нильсена (в сокращённом виде):

| № | Правило | Хороший пример | Плохой пример |
|---|---|---|---|
| 1 | **Состояние системы должно быть видно** | сообщение «Сохранено ✓» | кнопка нажата, ничего не произошло |
| 2 | **Говори на языке пользователя** | «Сумма не введена» | `ValueError: invalid literal for int()` |
| 3 | **Предотвращай ошибки** | категория выбирается только из списка (Combobox) | ввод категории вручную → «еда», «Еда », «Ееда» |
| 4 | **Дай возможность отменить** | вопрос перед «Удалить», кнопка «Отмена» | одним нажатием всё удаляется |
| 5 | **Единообразие** | во всех окнах «Сохранить» справа внизу | в одном месте «OK», в другом «Готово», в третьем «Отправить» |
| 6 | **Не заставляй запоминать** | последняя выбранная категория сохраняется | каждый раз вводить всё заново |
| 7 | **Минимализм** | на главном экране только нужное | 20 кнопок в одном окне |
| 8 | **Помощь и справка** | в пустом списке «Пока нет операций. Нажмите "+ Расход"» | пустое белое окно |

### Визуальные правила
- **Выравнивание и сетка:** выравнивайте элементы в одну линию по `grid`; отступы (`padx`, `pady`) должны быть одинаковыми (например, 8 или 10 пикселей).
- **Иерархия:** самая важная информация (баланс) — крупный шрифт, вверху; второстепенная — мельче.
- **Цвета:** 1 основной цвет + 1 акцентный + оттенки серого. Красный — ошибка/расход, зелёный — успех/доход. Не полагайтесь только на цвет: пусть будет и знак «−800» (для людей, не различающих цвета).
- **Контраст и размер:** текст не меньше 11–12 pt, на светлом фоне — тёмный текст.
- **Название кнопки — глагол:** «Сохранить», «Удалить», «Экспортировать» (одним словом понятно, что произойдёт).

## 7. Каркасный прототип на Tkinter

Программа без логики, но со всеми экранами и кнопками. Для ещё не реализованного действия выводим через `messagebox` «Это действие будет сделано позже». Вместо данных используем **фиктивные данные** (заглушки, mock data).

```python
import tkinter as tk
from tkinter import ttk, messagebox

# Фиктивные данные (для прототипа)
FAKE_OPERATIONS = [
    ("15.04", "Еда", -800),
    ("14.04", "Транспорт", -200),
    ("14.04", "Родители", 3000),
]


def not_ready():
    messagebox.showinfo("Прототип", "Это действие будет сделано позже.")


def open_add_window(kind):
    """Прототип окна добавления операции."""
    win = tk.Toplevel(root)
    win.title(f"Новый {kind}")
    win.resizable(False, False)
    ttk.Label(win, text="Сумма (тг):").grid(row=0, column=0, sticky="w", padx=10, pady=5)
    ttk.Entry(win, width=20).grid(row=0, column=1, padx=10, pady=5)
    ttk.Label(win, text="Категория:").grid(row=1, column=0, sticky="w", padx=10, pady=5)
    ttk.Combobox(win, values=["Еда", "Транспорт", "Развлечения"],
                 state="readonly", width=18).grid(row=1, column=1, padx=10, pady=5)
    ttk.Label(win, text="Комментарий:").grid(row=2, column=0, sticky="w", padx=10, pady=5)
    ttk.Entry(win, width=20).grid(row=2, column=1, padx=10, pady=5)
    buttons = ttk.Frame(win)
    buttons.grid(row=3, column=0, columnspan=2, pady=10)
    ttk.Button(buttons, text="Отмена", command=win.destroy).pack(side="left", padx=5)
    ttk.Button(buttons, text="Сохранить", command=not_ready).pack(side="left", padx=5)


root = tk.Tk()
root.title("Карманные деньги — прототип")
root.geometry("560x360")

# 1. Верхняя часть: баланс
top = ttk.Frame(root, padding=10)
top.pack(fill="x")
ttk.Label(top, text="Баланс: 12 450 тг", font=("Arial", 18, "bold")).pack(side="left")
ttk.Button(top, text="Настройки", command=not_ready).pack(side="right")

# 2. Кнопки действий
actions = ttk.Frame(root, padding=(10, 0))
actions.pack(fill="x")
ttk.Button(actions, text="+ Доход", command=lambda: open_add_window("доход")).pack(side="left")
ttk.Button(actions, text="+ Расход", command=lambda: open_add_window("расход")).pack(side="left", padx=8)

# 3. Таблица операций (Treeview)
table = ttk.Treeview(root, columns=("date", "cat", "sum"), show="headings", height=8)
for col, title in (("date", "Дата"), ("cat", "Категория"), ("sum", "Сумма")):
    table.heading(col, text=title)
    table.column(col, width=150)
for row in FAKE_OPERATIONS:
    table.insert("", "end", values=row)
table.pack(fill="both", expand=True, padx=10, pady=10)

# 4. Нижнее меню
bottom = ttk.Frame(root, padding=10)
bottom.pack(fill="x")
for text in ("История", "Статистика", "Экспорт CSV"):
    ttk.Button(bottom, text=text, command=not_ready).pack(side="left", padx=4)

root.mainloop()
```

Здесь `ttk.Treeview` — виджет списка в виде таблицы (многоколоночный вариант `Listbox`). В готовом приложении в нём показывают операции, полученные из базы данных.

### Прототип для проекта на Pygame
В игровом проекте прототип — это **серые прямоугольники** («грейбоксинг»): персонаж — синий квадрат, препятствие — серый прямоугольник. Сначала проверяем, интересно ли играть, а картинки добавляем потом.

```python
import pygame

pygame.init()
screen = pygame.display.set_mode((640, 400))
pygame.display.set_caption("Прототип: экраны")
font = pygame.font.SysFont("arial", 28)
state = "menu"          # menu -> game -> over -> menu
clock = pygame.time.Clock()
running = True
while running:
    for event in pygame.event.get():
        if event.type == pygame.QUIT:
            running = False
        elif event.type == pygame.KEYDOWN and event.key == pygame.K_SPACE:
            state = {"menu": "game", "game": "over", "over": "menu"}[state]
    screen.fill((40, 40, 40))
    if state == "game":
        pygame.draw.rect(screen, (60, 120, 220), (300, 300, 40, 40))   # персонаж
        pygame.draw.rect(screen, (150, 150, 150), (100, 340, 440, 20))  # платформа
    labels = {"menu": "МЕНЮ: SPACE - начать", "game": "ИГРА: SPACE - закончить",
              "over": "ИГРА ОКОНЧЕНА: SPACE - меню"}
    screen.blit(font.render(labels[state], True, (255, 255, 255)), (20, 20))
    pygame.display.flip()
    clock.tick(30)
pygame.quit()
```

## 8. Тестирование прототипа (5-минутный тест)

1. Дайте прототип другому человеку и скажите **задание**: «Попробуй добавить расход на еду в 800 тенге». **Не говорите**, куда нажимать.
2. Пусть он думает вслух: «Я нажимаю сюда, потому что...».
3. Вы молча наблюдаете и записываете, где он **задержался**, **ошибся**, **задал вопрос**.
4. После 2–3 заданий анализируете результат и исправляете прототип.

> Тест с пятью людьми выявляет большую часть неудобств — так показывает опыт профессиональных UX-исследователей.

## Частые ошибки

**1. Показывать пользователю техническую ошибку.**
```python
amount = int("")        # ValueError — пользователь этого не поймёт
```
Объяснение: программа падает, окно закрывается или выводится ошибка на английском. Правильно — проверить и дать понятное сообщение:
```python
from tkinter import messagebox

text = ""
if not text.strip().isdigit():
    messagebox.showwarning("Ошибка", "Введите сумму в виде целого положительного числа.")
```

**2. Ввод категории свободным текстом** (`Entry`) — «Еда», «еда», «Еда » превращаются в три разные категории. Правильно: `ttk.Combobox(..., state="readonly")`.

**3. Удаление без подтверждения.** Правильно:
```python
from tkinter import messagebox

if messagebox.askyesno("Подтверждение", "Вы действительно хотите удалить операцию?"):
    print("Удалено")
```

**4. Сразу браться за «красивый» макет.** Потратить много времени на выбор цвета и шрифта и не проверить сценарий. Правильно: сначала серая каркасная схема, потом оформление.

**5. Смешивать `pack` и `grid` в одном контейнере** — Tkinter зависает. Правильно: внутри каждого `Frame` — один менеджер.

## Основные понятия
| Понятие | Объяснение |
|---|---|
| UI | внешний вид программы: виджеты, цвета, расположение |
| UX | лёгкость и приятность использования программы |
| Персона | краткое описание целевого пользователя |
| Пользовательский сценарий | последовательность шагов для достижения цели |
| Карта экранов | схема всех экранов и переходов |
| Каркасная схема (wireframe) | схема без цвета, показывающая только расположение |
| Макет (mockup) | статичное изображение с цветами и шрифтами |
| Прототип | первая версия интерфейса, которую можно проверить |
| Фиктивные данные (mock data) | образцы значений, используемые в прототипе вместо настоящих данных |

## Примечание

- `ttk`-виджеты выглядят как родные элементы ОС; их внешний вид меняют через `ttk.Style()` и темы (`style.theme_use("clam")`), а не параметрами `bg`/`fg`, как у классических `tk`-виджетов.
- `Combobox(state="readonly")` не даёт вводить произвольный текст; выбранное значение читается через `.get()`, а событие выбора — `"<<ComboboxSelected>>"`.
- `messagebox.askyesno()` возвращает `True`/`False`, а `askokcancel()` — тоже логическое значение; `showinfo()` и `showwarning()` возвращают строку `"ok"`.
- Задавайте `minsize` и `weight` через `columnconfigure`/`rowconfigure`, чтобы окно корректно растягивалось; `root.geometry()` фиксирует лишь начальный размер.
- Для Pygame-прототипа ограничивайте частоту кадров `clock.tick(fps)` — без этого цикл занимает 100% одного ядра процессора.
- Документация: https://docs.python.org/3/library/tkinter.ttk.html и https://docs.python.org/3/library/tkinter.messagebox.html
