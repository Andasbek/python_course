## 1. Жоба репозиторийінің құрылымы

Барлық жобаға ортақ ұсынылатын құрылым («Қалта ақшасы» мысалында):

```text
qalta-aqshasy/
├── .gitignore            # Git бақыламайтын файлдар
├── README.md             # жоба сипаттамасы
├── requirements.txt      # тәуелділіктер тізімі
├── main.py               # іске қосу нүктесі
├── qalta/                # негізгі код (пакет)
│   ├── __init__.py
│   ├── models.py         # кластар: Operation, Category
│   ├── database.py       # SQLite-пен жұмыс
│   ├── logic.py          # есептеулер, бизнес-логика

├── tests/                # unittest тесттері
│   └── test_logic.py
├── data/                 # үлгі деректер (нағыз ДҚ емес!)
│   └── sample.csv

    └── prototype.png
```

Ойын жобасында `qalta/` орнына `game/` (sprites.py, levels.py, scenes.py) және `assets/` (images, sounds) папкалары болады.

**Неге мұндай құрылым?**
- Кез келген адам жобаны ашқанда бірден түсінеді: код қайда, тест қайда, құжат қайда.
- `main.py` қысқа: тек қосымшаны іске қосады. Логика модульдерде — оны тестілеу оңай.

## 3. Жобаны кезеңдерге бөлу (декомпозиция)

**Декомпозиция** — үлкен міндетті кіші, нақты, тексерілетін бөліктерге бөлу. Пілді бір-ақ рет жей алмайсыз — оны бөліп-бөліп жейсіз.

Үш деңгей:
```text
Жоба
 └── Кезең (эпик): «Деректермен жұмыс»
      └── Тапсырма: «database.py: add_operation() функциясы»
           └── Тексеру белгісі: «Жаңа операция кестеде пайда болады»
```

**Жақсы тапсырманың белгілері** (SMART-қа ұқсас):
- **Нақты:** «Интерфейсті жасау» емес → «Операция қосу терезесі: сома, санат, күн өрістері».
- **Тексерілетін:** қашан дайын болғанын қалай білемін?
- **Шағын:** 30 минуттан 2 сағатқа дейін. Ұзағырақ болса — бөліңіз.
- **Мерзімі бар:** қай күнге дейін аяқталады.

## 4. MVP және MoSCoW әдісі

**MVP (Minimum Viable Product, ең аз жарамды өнім)** — негізгі мәселені шешетін ең қарапайым жұмыс істейтін нұсқа. Алдымен MVP-ді аяқтаймыз, қосымша мүмкіндіктер — кейін.

**MoSCoW** — мүмкіндіктерді төрт топқа бөлу:

| Топ | Мағынасы | «Қалта ақшасы» мысалы |
|---|---|---|
| **M**ust (міндетті) | онсыз жоба жұмыс істемейді | операция қосу, ДҚ-ға сақтау, баланс, тарих |
| **S**hould (керек) | маңызды, бірақ онсыз да болады | санаттар бойынша диаграмма, CSV экспорт |
| **C**ould (болса жақсы) | уақыт қалса | долларға аудару (API), түнгі режим |
| **W**on't (бұл жолы жоқ) | келесі нұсқаға | телефон қосымшасы, бірнеше пайдаланушы |

> **Ереже:** Must тізімі жалпы жұмыстың 60%-ынан аспасын. Әйтпесе тәуекел тым жоғары.

## 6. GitHub құралдарымен жоспарлау

| Құрал | Не үшін | Қалай |
|---|---|---|
| **Issues** | әр тапсырма немесе қате — бір issue | Issues → New issue; атауы + сипаттамасы + тексеру белгісі |
| **Labels** (белгілер) | түрін белгілеу | `must`, `should`, `could`, `bug`, `docs` |
| **Milestones** (кезеңдер) | issue-лерді кезеңге топтау, мерзім қою | Issues → Milestones → «MVP (29.04)», «v1.0 (11.05)» |
| **Projects** (Kanban тақтасы) | прогресті көру | бағандар: *Жоспарда → Жұмыста → Тексеруде → Дайын* |

Issue сипаттамасының үлгісі (markdown-да тапсырма тізімі қолданылады):
```text
Атауы: Операция қосу терезесі

Не істеу керек:
- [ ] сома, санат, күн, түсініктеме өрістері
- [ ] соманы тексеру (оң бүтін сан)
- [ ] «Сақтау» -> database.add_operation()

Дайын болды деп есептеледі, егер: жаңа операция кестеде және балансқа әсер етсе.
Кезең: MVP (29.04) · Белгі: must
```

Коммитте issue нөмірін жазсаңыз, GitHub оларды байланыстырады: `git commit -m "Операция қосу терезесі (#7)"`. Ал `Closes #7` деп жазсаңыз, коммит `main`-ге түскенде issue автоматты жабылады.

> GitHub қолжетімсіз болса, дәл осы тақтаны `docs/plan.md` файлында markdown кесте түрінде немесе қағаз стикерлермен жүргізуге болады.

## 7. Жоспарды Python-мен бақылау (қосымша)

Тапсырмалар тізімін `docs/plan.csv` ретінде сақтап, прогресті есептейтін шағын скрипт — `csv` модулін қолдану:

```python
import csv
import io

# Нағыз жобада: open("docs/plan.csv", encoding="utf-8")
PLAN = """task,stage,deadline,status
models.py кластар,2,22.04,done
logic.py баланс,2,22.04,done
logic.py айлық есеп,3,26.04,doing
database.py CRUD,4,27.04,todo
gui.py басты терезе,5,29.04,todo
"""

rows = list(csv.DictReader(io.StringIO(PLAN)))
done = sum(1 for r in rows if r["status"] == "done")
percent = done * 100 // len(rows)
print(f"Орындалды: {done}/{len(rows)} ({percent}%)")
print("[" + "#" * (percent // 10) + "-" * (10 - percent // 10) + "]")
for r in rows:
    if r["status"] != "done":
        print(f"  {r['deadline']} дейін: {r['task']} ({r['status']})")
```

Нәтижесі:
```text
Орындалды: 2/5 (40%)
[####------]
  26.04 дейін: logic.py айлық есеп (doing)
  27.04 дейін: database.py CRUD (todo)
  29.04 дейін: gui.py басты терезе (todo)
```

## 8. Тәуекелдерді алдын ала ойлау

| Тәуекел | Белгісі | Не істейміз |
|---|---|---|
| Жаңа кітапхана күткеннен қиын | бір тапсырмаға екі есе көп уақыт кетті | құжаттаманы оқу, тәжірибелі әзірлеушіден сұрау, қарапайым балама |
| API жұмыс істемей қалады | интернет жоқ / сервер қатесі | соңғы жауапты кэште сақтау, офлайн режим |
| Компьютер бұзылды / файл жоғалды | — | **әр жұмыс күнінің соңында `git push`** |
| Бірнеше күн жұмыс істеу мүмкін емес | жоспардан қалу | буфер уақыт, кез келген компьютерден жұмыс істеу (репозиторий GitHub-та) |
| Мүмкіндіктер тым көп | Must тізімі ұзын | MoSCoW-ты қайта қарау |

## Жиі кездесетін қателер

**1. `venv` папкасын GitHub-қа жүктеу.** Репозиторий мыңдаған файлға толады. Түзету:
```bash
echo venv/ >> .gitignore
git rm -r --cached venv
git commit -m "venv папкасын репозиторийден алып тастау"
```

**2. `.gitignore`-ды файлдарды қосқаннан кейін жасау.** Git бұрын бақыланған файлдарды елемеуді бастамайды — жоғарыдағыдай `git rm --cached` қажет.

**3. Құрамында құпия сөз немесе API кілті бар файлды коммиттеу.** Кейін өшірсеңіз де, ол тарихта қалады. Кілтті жаңасына ауыстыру керек және енді `.env` + `.gitignore` қолдану керек.

**4. Тым үлкен тапсырма.** «Ойынды жасау» — бұл тапсырма емес, бүкіл жоба. Бөліңіз: «Кейіпкер солға-оңға қозғалады», «Кедергімен соқтығысу», «Ұпай санауыш».

**5. `requirements.txt`-ті жаңартуды ұмыту.** Жаңа кітапхана орнатқан сайын `pip freeze > requirements.txt`. Әйтпесе басқа компьютерде `ModuleNotFoundError` шығады.

**6. `main.py` ішінде барлық код (500 жол).** Архитектура қабаттары бойынша (деректер, логика, интерфейс) модульдерге бөліңіз.

## Ескерту

- `pip freeze` ортадағы **барлық** пакетті, соның ішінде тәуелділіктердің тәуелділіктерін жазады; шағын жобада `requirements.txt`-те тек тікелей тәуелділіктерді нұсқасымен қалдыруға болады (`requests>=2.31`).
- `.venv` атты виртуалды ортаны VS Code пен PyCharm автоматты түрде таниды; Python 3.13-тен бастап `venv` орта бумасының ішінде `.gitignore` файлын өзі жасайды.
- Git 2.28 нұсқасынан бастап әдепкі тармақты бір рет орнатуға болады: `git config --global init.defaultBranch main` — сонда `git branch -M main` қажет емес.
- Пакет атауын (`__init__.py` бар буманы) сызықшасыз кіші әріппен жазыңыз (`qalta-aqshasy` емес, `qalta`) — PEP 8 бойынша және `import` жұмыс істеуі үшін.
- Python үшін `.gitignore` үлгісі: https://github.com/github/gitignore/blob/main/Python.gitignore; venv құжаттамасы: https://docs.python.org/3/library/venv.html
