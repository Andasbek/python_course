## 1. Разбиение сложной задачи: «сверху вниз»

Сложную задачу не кодируем сразу. Сначала формулируем её **одним предложением**, затем делим на шаги; каждый шаг — отдельная функция. Этот метод называется **нисходящим проектированием** (top-down design).

Пример: «Отчёт в конце месяца: сколько пришло, сколько ушло, категория с наибольшими расходами, средний расход в день, категории, превысившие лимит».

```text
monthly_report(year, month)
├── operations_in_month(year, month)      -> операции за месяц
├── sum_by_kind(ops)                      -> {'доход': ..., 'расход': ...}
├── total_by_category(ops)                -> {'Еда': ...}
│   └── top_category(totals)              -> ('Еда', 2300)
├── average_per_day(total, year, month)   -> в среднем за день
└── check_limits(totals)                  -> превысившие категории
```

Каждая функция — **5–15 строк**, выполняет только одну работу, и её можно проверить отдельно.

## 2. Псевдокод

**Псевдокод** — запись алгоритма на человеческом языке, но со структурой кода. Позволяет думать о логике, не отвлекаясь на синтаксис.

```text
ФУНКЦИЯ спрогнозировать_дату_накопления(цель, текущий_баланс, операции):
    ЕСЛИ текущий_баланс >= цель: ВЕРНУТЬ "сегодня"
    взять операции за последние 30 дней
    чистые_накопления = доходы - расходы
    ЕСЛИ чистые_накопления <= 0: ВЕРНУТЬ "при таком темпе накопить невозможно"
    в_день = чистые_накопления / 30
    осталось_дней = округлить_вверх((цель - текущий_баланс) / в_день)
    ВЕРНУТЬ сегодня + осталось_дней
```

Когда псевдокод готов, перевести его в код легко:

```python
import datetime
import math


def forecast_goal_date(goal, balance, ops_last_30_days, today):
    """Прогнозирует дату достижения цели. ops: список (сумма_со_знаком, дата)."""
    if balance >= goal:
        return today
    net = sum(amount for amount, _ in ops_last_30_days)
    if net <= 0:
        return None                     # при таком темпе накопить невозможно
    per_day = net / 30
    days_left = math.ceil((goal - balance) / per_day)
    return today + datetime.timedelta(days=days_left)


today = datetime.date(2027, 4, 26)
ops = [(3000, today), (-800, today), (-200, today), (3000, today), (-1000, today)]
result = forecast_goal_date(60000, 12000, ops, today)
print("Дата накопления на велосипед:", result)
print(forecast_goal_date(60000, 12000, [(-500, today)], today))
```

Результат:
```text
Дата накопления на велосипед: 2028-04-20
None
```

(В месяц накапливается 4000 тг → в день ≈133,3 тг → на оставшиеся 48 000 тг нужно 360 дней, то есть примерно год. Такой прогноз наводит пользователя на мысль «если сократить расходы, накоплю раньше» — это полезная возможность проекта.)

## 3. Основные приёмы обработки данных

### 3.1. Фильтрация
Выбор из списка элементов, удовлетворяющих условию, — с помощью генератора списков (list comprehension):

```python
import datetime

ops = [
    {"amount": 800, "cat": "Еда", "date": datetime.date(2027, 4, 1), "note": "обед"},
    {"amount": 200, "cat": "Транспорт", "date": datetime.date(2027, 4, 2), "note": "автобус"},
    {"amount": 1500, "cat": "Развлечения", "date": datetime.date(2027, 4, 20), "note": "кино"},
    {"amount": 600, "cat": "Еда", "date": datetime.date(2027, 3, 30), "note": "мороженое"},
]


def filter_ops(ops, start=None, end=None, category=None, text=""):
    """Фильтрация по нескольким условиям; незаданное условие не проверяется."""
    result = []
    for op in ops:
        if start and op["date"] < start:
            continue
        if end and op["date"] > end:
            continue
        if category and op["cat"] != category:
            continue
        if text and text.lower() not in op["note"].lower():
            continue
        result.append(op)
    return result


april = filter_ops(ops, datetime.date(2027, 4, 1), datetime.date(2027, 4, 30))
print(len(april), [o["note"] for o in april])
print([o["note"] for o in filter_ops(ops, category="Еда")])
print([o["note"] for o in filter_ops(ops, text="КИН")])
```

Результат:
```text
3 ['обед', 'автобус', 'кино']
['обед', 'мороженое']
['кино']
```

### 3.2. Сортировка: `key` и `lambda`
```python

by_amount = sorted(ops, key=lambda op: op[1], reverse=True)
print(by_amount)

```

### 3.3. Группировка и агрегация
`collections.defaultdict` — словарь, который даёт значение по умолчанию для отсутствующего ключа. Избавляет от необходимости каждый раз писать `get(..., 0)`:

```python
from collections import defaultdict
import datetime

ops = [
    (800, datetime.date(2027, 3, 30)),
    (200, datetime.date(2027, 4, 2)),
    (1500, datetime.date(2027, 4, 20)),
    (400, datetime.date(2027, 5, 1)),
]
by_month = defaultdict(int)
for amount, d in ops:
    by_month[d.strftime("%Y-%m")] += amount

for month in sorted(by_month):
    print(month, by_month[month])
best = max(by_month, key=by_month.get)
print("Месяц с наибольшими расходами:", best)
```

Результат:
```text
2027-03 800
2027-04 1700
2027-05 400
Месяц с наибольшими расходами: 2027-04
```

### 3.4. Работа с датами
| Задача | Код |
|---|---|
| Сегодня | `datetime.date.today()` |
| Через N дней | `d + datetime.timedelta(days=N)` |
| Разница между датами | `(d2 - d1).days` |
| Дата из текста | `datetime.date.fromisoformat("2027-04-26")` |
| Текст из даты | `d.strftime("%d.%m.%Y")` → `'26.04.2027'` |
| Количество дней в месяце | `calendar.monthrange(2027, 2)[1]` → `28` |

## 4. Конечный автомат (state machine)

В играх, викторинах, системах заказов объект переходит из одного **состояния** в другое. Описывать это **таблицей переходов**, а не запутанной цепочкой `if`, — понятнее и надёжнее.

```text
           start            pause
  [menu] --------> [game] --------> [paused]
     ^               |   <--------     |
     |          lose |     resume      | quit
     |               v                 |
     +--- restart [over] <-------------+
```

```python
TRANSITIONS = {
    ("menu", "start"): "game",
    ("game", "pause"): "paused",
    ("paused", "resume"): "game",
    ("paused", "quit"): "over",
    ("game", "lose"): "over",
    ("over", "restart"): "menu",
}


class GameState:
    def __init__(self):
        self.state = "menu"

    def send(self, event):
        """Меняет состояние по событию; если переход не разрешён — ValueError."""
        key = (self.state, event)
        if key not in TRANSITIONS:
            raise ValueError(f"В состоянии '{self.state}' событие '{event}' невозможно")
        self.state = TRANSITIONS[key]
        return self.state


g = GameState()
for e in ["start", "pause", "resume", "lose", "restart"]:
    print(e, "->", g.send(e))
try:
    g.send("pause")
except ValueError as err:
    print("Ошибка:", err)
```

Результат:
```text
start -> game
pause -> paused
resume -> game
lose -> over
restart -> menu
Ошибка: В состоянии 'menu' событие 'pause' невозможно
```

В цикле Pygame при нажатии клавиши вызывается лишь `g.send("pause")`, а что рисовать на экране, определяет `g.state`.

## 5. Быстрая проверка: `assert`

`assert условие, "сообщение"` — если условие ложно, выбрасывает `AssertionError`. После написания логики удобно поставить в конце файла несколько `assert` и проверить особые случаи (полноценные тесты пишут с помощью модуля `unittest`).

```python
def average(values):
    """Среднее значение; для пустого списка 0."""
    if not values:
        return 0
    return sum(values) / len(values)


assert average([2, 4, 6]) == 4
assert average([]) == 0, "пустой список должен возвращать 0"
assert average([5]) == 5
print("Все проверки пройдены")
```

Результат:
```text
Все проверки пройдены
```

**Список особых случаев (граничных значений)** — продумайте их для каждой функции:
- пустой список / пустая строка;
- только один элемент;
- ноль, отрицательное число, очень большое число;
- последний день месяца, 28/29 февраля, смена года (31.12 → 01.01);
- одинаковые значения (равные суммы при сортировке);
- казахские буквы и пробелы (`"Еда "` ≠ `"Еда"`).

## 6. Рефакторинг: улучшение кода

**Рефакторинг** — улучшение структуры кода **без изменения того, что делает программа**. На этапе 2, по мере роста логики, появляется повторяющийся код.

**Правило DRY** (Don't Repeat Yourself — «Не повторяйся»):

До рефакторинга:
```python
def total_food(ops):
    s = 0
    for op in ops:
        if op["cat"] == "Еда":
            s += op["amount"]
    return s


def total_transport(ops):
    s = 0
    for op in ops:
        if op["cat"] == "Транспорт":
            s += op["amount"]
    return s
```

После рефакторинга:
```python
def total_for(ops, category):
    """Сумма по заданной категории."""
    return sum(op["amount"] for op in ops if op["cat"] == category)


ops = [{"cat": "Еда", "amount": 800}, {"cat": "Транспорт", "amount": 200},
       {"cat": "Еда", "amount": 500}]
print(total_for(ops, "Еда"), total_for(ops, "Транспорт"))
```

Результат:
```text
1300 200
```

«Запахи кода» (code smells) — признаки того, что нужен рефакторинг:

| Признак | Что делаем |
|---|---|
| Функция длиннее 30 строк | делим на несколько функций |
| Один и тот же код повторяется в 2–3 местах | общая функция/метод |
| Магические числа (`if score > 37`) | именованная константа: `WIN_SCORE = 37` |
| Вложенные `if` на 4–5 уровней | ранний `return`/`continue`, словарь-таблица |
| Имена `a`, `x1`, `tmp2` | осмысленные имена (PEP 8) |

> **Важно:** после рефакторинга обязательно перезапустите программу и выполните проверки `assert` — ничего не сломалось?

## Частые ошибки

**1. Изменение списка в цикле.**
```python
nums = [1, 2, 2, 3]
for n in nums:
    if n == 2:
        nums.remove(n)
print(nums)     # [1, 2, 3] — одна «2» осталась!
```
Объяснение: при удалении элемента индексы сдвигаются, и цикл пропускает один элемент. Правильно — создать новый список:
```python
nums = [1, 2, 2, 3]
nums = [n for n in nums if n != 2]
print(nums)     # [1, 3]
```

**2. `max()` на пустом списке или деление на ноль.** `max([])` → `ValueError`, `sum([]) / len([])` → `ZeroDivisionError`. Правильно: `max(values, default=0)` и предварительная проверка `if not values`.

**3. Сравнение дат как строк.** `"9.04.2027" > "10.04.2027"` → `True` (по тексту «9» > «1»). Правильно: сравнивать объекты `datetime.date` или формат ISO (`2027-04-09`).

**4. Магические числа.** `if len(ops) > 50` — непонятно, что такое «50». Правильно: `MAX_HISTORY = 50`.

**5. Одна функция делает всё** — вычисляет, фильтрует и форматирует. Правильно: вычисления отдельно, форматирование (составление текста) — в слое интерфейса.

## Основные понятия
| Понятие | Объяснение |
|---|---|
| Нисходящее проектирование | постепенное разбиение большой задачи на небольшие функции |
| Псевдокод | запись алгоритма на человеческом языке со структурой кода |
| `lambda` | безымянная короткая функция, часто для `key=` |
| `defaultdict` | словарь, дающий значение по умолчанию для отсутствующего ключа |
| Конечный автомат | описание состояний и переходов таблицей |
| `assert` | быстрая проверка, вызывающая ошибку, если условие ложно |
| Рефакторинг | улучшение кода без изменения поведения |
| DRY | правило «не повторяйся» |
| Граничное значение | особые входные данные: пустые, ноль, максимальные и т.п. |

## Примечание

- `assert` отключается при запуске Python с флагом `-O`: не используйте его для проверки пользовательского ввода — для этого нужен `if ... raise ValueError(...)`.
- `sorted()` и `list.sort()` устойчивы: элементы с равным ключом сохраняют исходный порядок, поэтому можно сортировать в несколько проходов (сначала по вторичному ключу, потом по основному).
- Вместо `lambda op: op[1]` можно использовать `operator.itemgetter(1)`, а для объектов — `operator.attrgetter("amount")`: это короче и немного быстрее.
- `collections.Counter` удобен для подсчёта количества (`Counter(cats).most_common(3)`), а `defaultdict(list)` — для группировки элементов по ключу.
- В Python 3.10+ конечный автомат можно описать и через `match`/`case`, но таблица переходов в словаре проще расширять и проверять.
- Документация: https://docs.python.org/3/howto/sorting.html и https://docs.python.org/3/library/collections.html
