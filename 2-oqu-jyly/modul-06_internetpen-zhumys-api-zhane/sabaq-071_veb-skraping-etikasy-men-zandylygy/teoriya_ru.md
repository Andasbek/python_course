## 1. Законен ли скрапинг?

Короткий ответ: **зависит от ситуации**. Во многих странах мира сбор открыто опубликованных данных сам по себе не запрещён, но есть такие ограничения:

| Фактор | Вопрос | Риск |
|---|---|---|
| Правила сайта (Terms of Service) | Запрещает ли сайт автоматический сбор? | Блокировка аккаунта, судебное требование |
| Доступность | Данные открыты или доступны через логин/пароль? | Несанкционированный доступ — правонарушение |
| Авторское право | Являются ли текст, изображение, статья чьим-то произведением? | Копирование и публикация — нарушение авторского права |
| Персональные данные | Есть ли имена, телефоны, email, фото людей? | Нарушение закона о персональных данных |
| Нагрузка на сервер | Мешает ли работе сайта? | Может быть приравнено к DoS-атаке |

**В Казахстане** учитываются законы (на уровне знакомства):
- Закон РК «О персональных данных и их защите» (2013) — нельзя собирать, обрабатывать, распространять персональные данные человека без его согласия;
- Закон РК «Об авторском праве и смежных правах» — ограничивает использование произведений без разрешения автора;
- законодательство в сфере информатизации — несанкционированный доступ к информационным системам и нарушение их работы влекут ответственность.

В Европе действуют аналогичные правила GDPR. **Мы не юристы**, поэтому правило простое: если есть сомнения — не собираем или просим разрешения у владельца сайта.

## 2. Правила сайта (Terms of Service)

Внизу сайта обычно есть ссылка «Условия использования», «Terms of Use», «Пользовательское соглашение». Ищите в нём слова: *automated*, *scraping*, *crawl*, *robots*, «автоматизированный сбор». Если это запрещено — с этого сайта не скрапим.

## 3. robots.txt — «правила входа» на сайт

**robots.txt** — текстовый файл в корне сайта (`https://сайт/robots.txt`), в котором владелец сайта указывает роботам (поисковым системам, скраперам), в какие разделы можно заходить. Это **соглашение**, а не техническая защита: вежливый робот его соблюдает.

Пример:

```text
User-agent: *
Allow: /search/about
Disallow: /admin/
Disallow: /search
Crawl-delay: 5

User-agent: BadBot
Disallow: /

Sitemap: https://example.kz/sitemap.xml
```

| Директива | Значение |
|---|---|
| `User-agent: *` | Следующие правила относятся ко всем роботам |
| `User-agent: BadBot` | Только к роботу с этим именем |
| `Disallow: /admin/` | Нельзя заходить на страницы, начинающиеся с `/admin/` |
| `Disallow: /` | Запрет на весь сайт |
| `Disallow:` (пусто) | Разрешено всё |
| `Allow: /search/about` | Исключение внутри запрещённого раздела (поскольку некоторые роботы читают правила по порядку, строку `Allow` лучше писать перед `Disallow`) |
| `Crawl-delay: 5` | Не менее 5 секунд между запросами |
| `Sitemap:` | Адрес карты сайта |

Проверьте в браузере: `https://www.wikipedia.org/robots.txt`, `https://github.com/robots.txt`, `https://books.toscrape.com/robots.txt`.

## 4. Проверка robots.txt в Python

Есть стандартный модуль `urllib.robotparser`:

```python
from urllib.robotparser import RobotFileParser

rules = """
User-agent: *
Allow: /search/about
Disallow: /admin/
Disallow: /search
Crawl-delay: 5

User-agent: BadBot
Disallow: /
""".splitlines()

rp = RobotFileParser()
rp.parse(rules)

for path in ["/", "/news/1", "/admin/users", "/search?q=python", "/search/about"]:
    url = "https://example.kz" + path
    print(f"{path:18} → {'разрешено' if rp.can_fetch('PythonClubBot', url) else 'запрещено'}")
print("Для BadBot /news:", rp.can_fetch("BadBot", "https://example.kz/news"))
print("Crawl-delay:", rp.crawl_delay("PythonClubBot"))
```

Результат:
```text
/                  → разрешено
/news/1            → разрешено
/admin/users       → запрещено
/search?q=python   → запрещено
/search/about      → разрешено
Для BadBot /news: False
Crawl-delay: 5
```

Чтение файла реального сайта из интернета:

```python
from urllib.robotparser import RobotFileParser

rp = RobotFileParser("https://books.toscrape.com/robots.txt")
try:
    rp.read()                                   # загружает и разбирает файл
    print(rp.can_fetch("*", "https://books.toscrape.com/catalogue/page-2.html"))
except OSError:
    print("robots.txt не загружен — проверьте интернет")
```

**Примечание:** если `robots.txt` не найден (404), `robotparser` считает, что разрешено всё. Но это не заменяет проверку правил сайта (ToS).

## 5. Частота запросов: уважение к серверу

Человек в браузере с трудом открывает 1 страницу в секунду. А скрипт может отправлять сотни запросов в секунду — для маленького сайта это похоже на **DoS-атаку**.

**Правила вежливого скрапера:**

| Правило | Как реализуем |
|---|---|
| Делать паузы | `time.sleep(1)` или значение `Crawl-delay` (что больше) |
| Не отправлять параллельные запросы | В один момент — один запрос |
| Представляться | `User-Agent: PythonClubBot/1.0 (+email или сайт)` |
| Загружать только нужное | Не весь сайт, а конкретные страницы |
| Не загружать повторно (кэш) | Сохранять однажды загруженную страницу в файле |
| Уважать коды 429/503 | Остановиться, подождать (заголовок `Retry-After`) |
| Выбирать ночное время | Когда нагрузка на сайт мала |

## 6. Класс «вежливый скрапер»

```python
import time
from urllib.parse import urlparse
from urllib.robotparser import RobotFileParser

import requests


class PoliteScraper:
    """Скрапер, соблюдающий robots.txt и ограничивающий частоту запросов."""

    def __init__(self, base_url, user_agent="PythonClubBot/1.0 (educational)", min_delay=1.0):
        self.user_agent = user_agent
        self.session = requests.Session()
        self.session.headers["User-Agent"] = user_agent
        self.robots = RobotFileParser(base_url.rstrip("/") + "/robots.txt")
        try:
            self.robots.read()
        except OSError:
            pass
        crawl_delay = self.robots.crawl_delay(user_agent) or 0
        self.delay = max(min_delay, crawl_delay)
        self.last_request = 0.0
        self.cache = {}

    def get(self, url):
        if not self.robots.can_fetch(self.user_agent, url):
            print("robots.txt запрещает:", url)
            return None
        if url in self.cache:                         # повторно не загружаем
            return self.cache[url]
        wait = self.delay - (time.monotonic() - self.last_request)
        if wait > 0:
            time.sleep(wait)
        r = self.session.get(url, timeout=10)
        self.last_request = time.monotonic()
        if r.status_code in (429, 503):
            print("Сервер перегружен, попробуйте позже. Код:", r.status_code)
            return None
        r.raise_for_status()
        self.cache[url] = r.text
        return r.text

# scraper = PoliteScraper("https://books.toscrape.com")
# html = scraper.get("https://books.toscrape.com/catalogue/page-1.html")
```

`requests.Session()` — при нескольких запросах к одному сайту повторно использует соединение (быстрее и легче для сервера) и позволяет задать заголовки один раз.

## 7. Защита персональных данных

**Персональные (личные) данные** — любая информация, позволяющая прямо или косвенно определить человека:

| Вид | Примеры |
|---|---|
| Прямо идентифицирующие | ФИО, ИИН, номер паспорта, фото |
| Контактные | Телефон, email, адрес |
| Цифровой след | Логин, IP-адрес, геолокация |
| Особые категории | Здоровье, оценки, религиозные взгляды, биометрия |

**Правила:**
1. **Не собирайте**, если это не нужно для цели проекта (принцип минимизации данных).
2. Массовый сбор профилей, фотографий, контактов людей из социальных сетей — **не допускается**, даже если они открыты.
3. При необходимости — **анонимизация/маскирование**: вместо имени ID, вместо телефона `+7 701 *** ** 67`.
4. **Не распространяйте** собранные данные, не загружайте их на GitHub (добавьте в `.gitignore`).
5. После проекта — **удаляйте**.

Пример маскирования (модуль `re`):

```python
import re

text = "Контакты: aigerim.s@mail.kz, тел. +7 701 123 45 67, Нурлан: +77019876543"

email_re = re.compile(r"\b([\w.]{2})[\w.]*@([\w-]+\.[a-z]{2,})\b")
phone_re = re.compile(r"\+7[\s-]?(\d{3})[\s-]?\d{3}[\s-]?\d{2}[\s-]?(\d{2})")

masked = email_re.sub(r"\1***@\2", text)
masked = phone_re.sub(r"+7 \1 *** ** \2", masked)
print(masked)
```

Результат:
```text
Контакты: ai***@mail.kz, тел. +7 701 *** ** 67, Нурлан: +7 701 *** ** 43
```

## 8. Алгоритм принятия решения

```text
Нужны данные
   │
   ├─ Есть официальный API? ── да ──► Используй API (ключ храни безопасно)
   │        нет
   ├─ Запрещают ли правила сайта (ToS)? ── да ──► Не собирай / попроси разрешения
   │        нет
   ├─ Разрешает ли robots.txt эту страницу? ── нет ──► Не собирай
   │        да
   ├─ Есть персональные данные? ── да ──► Не собирай или только в анонимизированном виде
   │        нет
   ├─ Авторский контент? ── да ──► Только для личного анализа, без публикации, с указанием источника
   │        нет
   └─► Вежливый скрапер: паузы, User-Agent, кэш, только нужные страницы
```

## 9. «Кодекс этики скрапера»

1. Сначала ищу API.
2. Читаю и соблюдаю правила сайта и robots.txt.
3. Не перегружаю сервер: паузы, один запрос в один момент.
4. Представляюсь (`User-Agent`).
5. Не собираю и не публикую персональные данные.
6. Не выдаю чужой контент за свой, указываю источник.
7. Если владелец сайта попросит — прекращаю.

## Частые ошибки

**1. «Данные открыты — значит, можно собирать всё».** Открытость не означает разрешения использовать данные для любой цели (особенно персональные данные и авторский контент).

**2. Цикл без `time.sleep()`:**
```python
import time
pages = ["/page-1", "/page-2", "/page-3"]
for p in pages:
    # requests.get(base + p)   ← сотни запросов без паузы — неправильно
    time.sleep(1)              # правильно: пауза после каждого запроса
print("Готово")
```

**3. «Маскировка» под браузер** — подменять User-Agent строкой фальшивого браузера, чтобы обойти блокировку, неэтично. Если сайт вас заблокировал — это ответ «нет».

**4. Чтение robots.txt только один раз и вручную** — он может измениться; программа должна проверять его при каждом запуске.

**5. Загрузка результатов скрапинга (с персональными данными) на GitHub** — добавьте папку с данными в `.gitignore`.

**6. Игнорировать код 429 и повторять запросы снова и снова** — сервер может заблокировать IP навсегда.

## Основные понятия

| Понятие | Объяснение |
|---|---|
| Terms of Service (ToS) | Условия использования сайта |
| robots.txt | Файл правил доступа для роботов |
| `User-agent` / `Disallow` / `Allow` | Директивы robots.txt: для кого / запрет / исключение |
| `Crawl-delay` | Рекомендуемая пауза между запросами |
| `RobotFileParser` | Класс Python для разбора robots.txt |
| Rate limiting | Ограничение частоты запросов |
| DoS | Вывод сервера из строя чрезмерным числом запросов |
| Персональные данные | Информация, позволяющая определить человека |
| Анонимизация / маскирование | Приведение персональных данных к неопознаваемому виду |
| Авторское право | Охраняемые законом права автора произведения |

## Примечание

- `urllib.robotparser.RobotFileParser` входит в стандартную библиотеку: `can_fetch(useragent, url)`, а в Python 3.6+ также `crawl_delay(useragent)` и `request_rate(useragent)` (https://docs.python.org/3/library/urllib.robotparser.html).
- Если `robots.txt` не найден (404), `RobotFileParser` считает, что разрешено всё; при ответе 401/403 — что запрещено всё.
- Фиксированную паузу можно дополнить случайной составляющей (`random.uniform(1, 2)`); при ответе `429` учитывайте заголовок `Retry-After`.
- Для кэширования повторных запросов в рамках одного запуска подойдёт словарь `{url: html}` или `functools.lru_cache`.
- Отсутствие запрета в `robots.txt` не отменяет правил сайта (Terms of Service) и законов о персональных данных.
