## 1. Модель клиент–сервер

**Аналогия: ресторан.** Вы (клиент) делаете заказ (запрос) официанту (сеть), кухня (сервер) готовит и отправляет блюдо (ответ).

```text
 ┌──────────┐   1. Запрос (request)      ┌──────────┐
 │  Клиент  │ ─────────────────────────▶ │  Сервер  │
 │(браузер, │                            │ (сайт,   │
 │ Python)  │ ◀───────────────────────── │  API)    │
 └──────────┘   2. Ответ (response)      └──────────┘
```

- **Клиент** — программа, отправляющая запрос: браузер, мобильное приложение, наш Python-скрипт.
- **Сервер** — постоянно включённый компьютер/программа, который ждёт запросы и отвечает на них.
- Взаимодействие всегда **начинает клиент**.

## 2. IP-адрес, DNS и порт

**IP-адрес** — «почтовый адрес» устройства в сети. Пример IPv4: `142.250.74.46` (4 числа, каждое 0–255). IPv6 длиннее: `2a00:1450:4001:82a::200e`.

**DNS (Domain Name System)** — «телефонная книга» интернета. Человеку легко запомнить `google.kz`, а компьютеру нужен IP. DNS превращает домен в IP.

```bash
nslookup google.kz
ping -c 3 google.kz      # в Windows: ping google.kz
```

DNS-запрос можно выполнить и в Python:

```python
import socket

for domain in ["google.kz", "wikipedia.org"]:
    try:
        print(domain, "→", socket.gethostbyname(domain))
    except socket.gaierror:
        print(domain, "→ не найден (нет интернета?)")
```

Результат (IP со временем может меняться):
```text
google.kz → 142.250.74.67
wikipedia.org → 185.15.59.224
```

**Порт** — «номер квартиры» конкретной службы на одном компьютере. IP — адрес дома, порт — квартира.

| Порт | Служба |
|---|---|
| 80 | HTTP |
| 443 | HTTPS |
| 22 | SSH |
| 5432 | PostgreSQL |

## 3. Что происходит, когда вводишь адрес в браузере?

1. Браузер разбирает URL: `https://kundelik.kz/login`.
2. Через **DNS** определяется `kundelik.kz` → IP-адрес.
3. С сервером устанавливается **TCP-соединение** (порт 443).
4. **TLS**-«рукопожатие» — создаётся зашифрованный канал (HTTPS).
5. Браузер отправляет **HTTP-запрос**: `GET /login`.
6. Сервер возвращает **HTTP-ответ**: код состояния 200 и HTML.
7. Браузер читает HTML и отправляет **дополнительные запросы** за CSS, картинками, JS.
8. Страница отрисовывается на экране (рендеринг).

Чтобы открыть одну страницу, отправляются десятки, а иногда и сотни запросов!

## 4. Структура URL

```text
https://api.open-meteo.com:443/v1/forecast?latitude=43.25&longitude=76.95#top
└─┬─┘   └───────┬────────┘└┬┘└────┬─────┘ └────────────┬──────────────┘└┬┘
схема        домен       порт   путь (path)      параметры (query)     фрагмент
```

В Python разбираем модулем `urllib.parse`:

```python
from urllib.parse import urlparse, parse_qs

url = "https://api.open-meteo.com/v1/forecast?latitude=43.25&longitude=76.95&current_weather=true"
parts = urlparse(url)
print("Схема:", parts.scheme)
print("Домен:", parts.netloc)
print("Путь:", parts.path)
print("Параметры:", parse_qs(parts.query))
```

Результат:
```text
Схема: https
Домен: api.open-meteo.com
Путь: /v1/forecast
Параметры: {'latitude': ['43.25'], 'longitude': ['76.95'], 'current_weather': ['true']}
```

Обратная операция — построение строки параметров из словаря. Кириллица и пробелы автоматически **кодируются** (URL encoding):

```python
from urllib.parse import urlencode

params = {"q": "погода Алматы", "page": 2}
print("https://example.com/search?" + urlencode(params))
```

Результат:
```text
https://example.com/search?q=%D0%BF%D0%BE%D0%B3%D0%BE%D0%B4%D0%B0+%D0%90%D0%BB%D0%BC%D0%B0%D1%82%D1%8B&page=2
```

## 5. Протокол HTTP

**HTTP (HyperText Transfer Protocol)** — текстовый «договор» между клиентом и сервером, определяющий, в каком формате будут запрос и ответ.

### HTTP-запрос (request)

```text
GET /v1/forecast?latitude=43.25&longitude=76.95 HTTP/1.1      ← начальная строка: метод, путь, версия
Host: api.open-meteo.com                                     ← заголовки (headers)
User-Agent: Mozilla/5.0
Accept: application/json
                                                             ← пустая строка
(тело — в GET обычно пустое)                                  ← тело (body)
```

### Методы HTTP

| Метод | Значение | Соответствие CRUD | Пример |
|---|---|---|---|
| `GET` | Получение данных | Read | Открыть страницу, запросить погоду |
| `POST` | Отправка новых данных | Create | Форма регистрации, публикация поста |
| `PUT` / `PATCH` | Изменение (полное / частичное) | Update | Редактирование профиля |
| `DELETE` | Удаление | Delete | Удаление сообщения |

Это знакомые операции CRUD — «сетевой» аналог SQL-команд `SELECT`, `INSERT`, `UPDATE`, `DELETE`.

### HTTP-ответ (response)

```text
HTTP/1.1 200 OK                                  ← строка состояния: версия, код, описание
Content-Type: application/json; charset=utf-8    ← заголовки
Content-Length: 312
Date: Thu, 04 Feb 2027 09:15:00 GMT

{"latitude":43.25,"current_weather":{"temperature":-3.2, ...}}   ← тело
```

### Коды состояния (status codes)

| Группа | Значение | Частые коды |
|---|---|---|
| 1xx | Информационные | 101 |
| **2xx** | **Успех** | **200 OK**, 201 Created, 204 No Content |
| 3xx | Перенаправление | 301 Moved Permanently, 302 Found, 304 Not Modified |
| **4xx** | **Ошибка клиента** | 400 Bad Request, 401 Unauthorized, 403 Forbidden, **404 Not Found**, 429 Too Many Requests |
| **5xx** | **Ошибка сервера** | **500 Internal Server Error**, 502 Bad Gateway, 503 Service Unavailable |

**Способ запомнить:** 4xx — «ты ошибся» (клиент), 5xx — «я ошибся» (сервер).

### Важные заголовки (headers)

| Заголовок | Где | Значение |
|---|---|---|
| `Host` | запрос | На какой сайт |
| `User-Agent` | запрос | Кто клиент (браузер, Python) |
| `Accept` | запрос | Какой формат ожидаем |
| `Content-Type` | в обоих | Формат тела: `text/html`, `application/json` |
| `Set-Cookie` / `Cookie` | ответ / запрос | Сайт «запоминает» клиента |
| `Authorization` | запрос | Ключ или токен |

## 6. HTTP и HTTPS

**HTTP** — данные передаются открытым текстом: злоумышленник в сети Wi-Fi может прочитать ваш пароль.
**HTTPS** = HTTP + шифрование TLS. Значок 🔒 в браузере означает именно это.

**Правило:** вводите пароль и номер карты только на HTTPS-сайтах. В наших программах тоже всегда используем `https://`.

## 7. Первый HTTP-запрос в Python

В Python HTTP-запрос можно отправить стандартным модулем `urllib.request` (более удобная внешняя альтернатива — библиотека `requests`). Например, посмотрим код состояния и заголовки ответа через стандартный `urllib.request`:

```python
from urllib.request import urlopen
from urllib.error import URLError

try:
    with urlopen("https://example.com", timeout=10) as resp:
        print("Код состояния:", resp.status)
        print("Content-Type:", resp.headers["Content-Type"])
        html = resp.read().decode("utf-8")
        print("Длина HTML:", len(html), "символов")
        print(html[:60])
except URLError as e:
    print("Ошибка подключения:", e.reason)
```

Результат:
```text
Код состояния: 200
Content-Type: text/html
Длина HTML: 1256 символов
<!doctype html>
<html>
<head>
    <title>Example Domain</title>
```

## 8. Инструмент браузера DevTools

1. Откройте любой сайт и нажмите **F12** → вкладка **Network** (Сеть).
2. Обновите страницу (F5).
3. Каждая строка — один HTTP-запрос. Столбцы: **Name**, **Status**, **Type**, **Size**, **Time**.
4. Щёлкните по запросу и посмотрите разделы **Headers** (заголовки) и **Response** (тело ответа).
5. Если выбрать в фильтре **Fetch/XHR** — останутся только запросы сайта к API. Большинство из них возвращает JSON!

## Частые ошибки

**1. Забыта схема в URL:**
```python
from urllib.parse import urlparse
print(urlparse("example.com/page").netloc)          # пустая строка! домен попал в path
print(urlparse("https://example.com/page").netloc)  # example.com
```

**2. Добавление кириллицы в URL без кодирования** — сервер может не понять. Используйте `urlencode()` или `quote()`.

**3. Думать «404 — интернет не работает».** 404 — сервер ответил, значит, интернет есть, просто страница не найдена. Если интернета нет — кода состояния не будет вообще, возникнет `URLError` / ошибка подключения.

**4. Путать 401 и 403:** 401 — «вы не подтвердили, кто вы» (нет ключа), 403 — «я вас знаю, но доступа нет».

**5. Не задан `timeout`** — если сервер не отвечает, программа ждёт бесконечно и «зависает».

## Основные понятия

| Понятие | Объяснение |
|---|---|
| Клиент / сервер | Программа, отправляющая запрос / отвечающая на него |
| IP-адрес | Числовой адрес устройства в сети |
| DNS | Система, превращающая доменное имя в IP |
| Порт | Номер службы на компьютере (80, 443) |
| URL | Полный адрес ресурса |
| HTTP / HTTPS | Протокол передачи гипертекста / его зашифрованная версия |
| Запрос (request) | Метод + путь + заголовки + тело |
| Ответ (response) | Код состояния + заголовки + тело |
| Код состояния | Трёхзначное число, обозначающее результат запроса |
| Header (заголовок) | Дополнительная информация в виде «ключ: значение» |

## Примечание

- `urllib.request.urlopen()` выбрасывает `HTTPError` для кодов 4xx/5xx и `URLError` при проблемах с сетью/DNS — оба класса из модуля `urllib.error` (https://docs.python.org/3/library/urllib.request.html).
- `http.HTTPStatus` содержит все коды состояния с названиями: `HTTPStatus.NOT_FOUND == 404`, `HTTPStatus(404).phrase` → `'Not Found'`.
- Разбор URL — `urllib.parse.urlparse()`, правильная сборка параметров (с кодированием пробелов и кириллицы) — `urllib.parse.urlencode()`.
- Имена HTTP-заголовков нечувствительны к регистру: `Content-Type` и `content-type` — один и тот же заголовок.
- `socket.gethostbyname("python.org")` возвращает IP-адрес по имени — это и есть DNS-запрос.
