## 1. API кілті деген не?

**API кілті (API key)** — сервис сізді тану үшін беретін ұзын құпия жол, мысалы: `3f9a7c1e5b2d48a0b6e1c9f2d7a4b8e3`.

**Аналогия:** кілт — пәтеріңіздің кілті немесе банк картасының PIN-коды. Кімде кілт болса, сол «сіздің атыңыздан» сервисті пайдаланады.

| Ұғым | Мағынасы |
|---|---|
| API key | Бағдарламаны/пайдаланушыны анықтайтын тұрақты кілт |
| Token (токен) | Уақытша рұқсат белгісі (мысалы, 1 сағатқа) |
| Secret (құпия) | Жалпы атау: кілттер, құпия сөздер, токендер, қорға қосылу жолдары |

### Кілт жария болса, не болады?

- Біреу сіздің лимитіңізді жұмсайды → сервис сізді бұғаттайды.
- Ақылы сервис болса → карточкаңыздан ақша кетеді.
- Бот-токен (Telegram) → бөтен адам ботыңыздың атынан хабар жібереді.
- Қор құпия сөзі → барлық деректер ұрланады.

## 2. Кілтті қайда САҚТАМАЙМЫЗ

```python
import requests

# ❌ ЕШҚАШАН ОСЫЛАЙ ЖАЗБАҢЫЗ — кілт кодтың ішінде!
API_KEY = "мұнда-кілт-жазылмайды"
url = "https://api.openweathermap.org/data/2.5/weather"
# requests.get(url, params={"q": "Almaty", "appid": API_KEY}, timeout=10)
```

Тыйым салынған орындар:
- код ішінде (жоғарыдағыдай);
- репозиторийге түсетін конфигурация файлында (`config.json`, `settings.py`);
- скриншоттарда, бейнесабақтарда, чаттарда, форумда сұрақ қойғанда;
- коммит хабарламасында немесе README-де.

**Маңызды:** Git **бүкіл тарихты** сақтайды. Кілтті коммиттеп, келесі коммитте өшірсеңіз де, ол тарихта қалады: `git log -p` арқылы кез келген адам көре алады.

## 3. 1-тәсіл: орта айнымалылары (environment variables)

**Орта айнымалысы** — операциялық жүйе бағдарламаға беретін «атау = мән» жұбы. Код ішінде тек айнымалының **атауы** болады, мәні — компьютерде.

Орнату (терминалда):

```bash
# Windows (PowerShell) — ағымдағы терминал үшін:
$env:WEATHER_API_KEY = "сіздің_кілтіңіз"
# Windows — тұрақты (жаңа терминалдарда):
setx WEATHER_API_KEY "сіздің_кілтіңіз"
# macOS / Linux:
export WEATHER_API_KEY="сіздің_кілтіңіз"
```

Python-да оқу:

```python
import os

api_key = os.getenv("WEATHER_API_KEY")       # жоқ болса — None
if api_key is None:
    print("Қате: WEATHER_API_KEY орта айнымалысы орнатылмаған")
else:
    print("Кілт жүктелді, ұзындығы:", len(api_key))   # кілттің өзін ешқашан басып шығармаймыз!
```

Нәтижесі (айнымалы орнатылмаса):
```text
Қате: WEATHER_API_KEY орта айнымалысы орнатылмаған
```

| Әдіс | Айнымалы жоқ болса |
|---|---|
| `os.environ["NAME"]` | `KeyError` |
| `os.getenv("NAME")` | `None` |
| `os.getenv("NAME", "әдепкі")` | `"әдепкі"` |

## 4. 2-тәсіл: `.env` файлы және `python-dotenv`

Орта айнымалыларын әр рет терминалда орнату ыңғайсыз. Сондықтан жоба папкасында **`.env`** файлын жасаймыз:

```text
# .env — ЕШҚАШАН Git-ке жүктелмейді!
WEATHER_API_KEY=3f9a7c1e5b2d48a0b6e1c9f2d7a4b8e3
TELEGRAM_TOKEN=123456:ABC-DEF
DEBUG=true
```

Орнату:
```bash
pip install python-dotenv
```

Оқу:
```python
import os
from dotenv import load_dotenv

load_dotenv()                       # .env файлындағы мәндерді os.environ-ға жүктейді
api_key = os.getenv("WEATHER_API_KEY")
debug = os.getenv("DEBUG", "false").lower() == "true"

if not api_key:
    raise SystemExit("WEATHER_API_KEY табылмады. .env.example файлын қараңыз.")
print("Кілт сәтті жүктелді. DEBUG =", debug)
```

### `.env.example` — басқаларға нұсқау

Әріптесіңіз жобаны клондағанда қандай кілттер керек екенін білуі тиіс. Сондықтан репозиторийге **мәнсіз** үлгі файлды жүктейміз:

```text
# .env.example — осы файлды .env деп көшіріп, өз кілттеріңізді жазыңыз
WEATHER_API_KEY=your_key_here
TELEGRAM_TOKEN=your_token_here
DEBUG=false
```

| Файл | Ішінде | Git-ке |
|---|---|---|
| `.env` | Нақты кілттер | ❌ жоқ |
| `.env.example` | Атаулар + бос/жалған мәндер | ✅ иә |
| `config.py` | `os.getenv(...)` коды | ✅ иә |

## 5. Конфигурацияны бір модульге жинау

Құпиялар мен баптауларды бір жерге жинаған дұрыс:

```python
# config.py
import os

try:
    from dotenv import load_dotenv
    load_dotenv()
except ImportError:          # dotenv орнатылмаса — тек орта айнымалылары
    pass

WEATHER_API_KEY = os.getenv("WEATHER_API_KEY", "")
BASE_URL = "https://api.openweathermap.org/data/2.5/weather"
TIMEOUT = int(os.getenv("TIMEOUT", "10"))


def check():
    missing = [name for name, value in {"WEATHER_API_KEY": WEATHER_API_KEY}.items() if not value]
    if missing:
        raise RuntimeError("Орнатылмаған айнымалылар: " + ", ".join(missing))
```

```python
# main.py
# import requests
# import config
# config.check()
# r = requests.get(config.BASE_URL, params={"q": "Almaty", "appid": config.WEATHER_API_KEY,
#                                         "units": "metric"}, timeout=config.TIMEOUT)
```

**Кілтті қалай жібереміз?** Кейбір API кілтті URL параметрінде (`?appid=...`), кейбірі тақырыпта (`headers={"Authorization": "Bearer ..."}`) күтеді. Тақырыптағы кілт қауіпсіздеу — URL серверлердің логтарына жазылып қалуы мүмкін. Құжаттамада қалай жазылса, солай істейміз.

## 6. `.gitignore` — Git-ке «көрмейтін» файлдар

`.gitignore` — жоба түбіріндегі мәтіндік файл; онда Git назардан тыс қалдыратын файлдардың үлгілері жазылады.

```text
# --- Құпиялар ---
.env
*.key
secrets.json

# --- Python ---
__pycache__/
*.pyc
.venv/
venv/

# --- Деректер ---
*.db
backups/

# --- Редакторлар ---
.vscode/
.idea/

# --- Ерекшелік: үлгі файлды жүктейміз ---
!.env.example
```

### Үлгілер синтаксисі

| Үлгі | Мағынасы | Мысал |
|---|---|---|
| `file.txt` | Кез келген папкадағы осы атаулы файл | `.env` |
| `*.db` | Кеңейтімі `.db` барлық файл | `students.db` |
| `folder/` | Бүкіл папка | `.venv/` |
| `/todo.txt` | Тек жоба түбіріндегі файл | |
| `**/logs` | Кез келген деңгейдегі `logs` | `src/app/logs` |
| `!file` | Ерекшелік: бұрын сәйкес келсе де қосу | `!.env.example` |
| `#` | Түсініктеме | |

### Тексеру

```bash
git status                     # .env тізімде болмауы керек
git check-ignore -v .env       # қай ереже бойынша елемейтінін көрсетеді
```

### Файл бұрын коммиттелген болса

`.gitignore` тек **әлі бақыланбаған** файлдарға әсер етеді. Егер `.env` бұрын коммиттелсе:

```bash
git rm --cached .env           # Git бақылауынан алып тастау (дискте қалады)
git commit -m ".env бақылаудан алынды"
```

Бірақ кілт тарихта қалды — сондықтан келесі қадам міндетті!

## 7. Кілт жария болып қалса: әрекет жоспары

1. **Дереу кілтті жою/ауыстыру (revoke/rotate)** — сервистің сайтында ескі кілтті өшіріп, жаңасын жасау. Бұл — ең маңызды қадам; тарихты тазалау кілтті «құтқармайды», себебі оны біреу көшіріп үлгерген болуы мүмкін.
2. Жаңа кілтті `.env`-ке жазу, `.env`-ті `.gitignore`-ға қосу.
3. Сервистегі пайдалану статистикасын тексеру (бөтен сұраныстар болды ма).
4. Қажет болса — репозиторий тарихын тазалау (`git filter-repo` құралы) немесе репозиторийді жеке (private) ету.
5. Қорытынды жасау: келесі жобаларда `.gitignore`-ды **бірінші коммитте** жасау.

GitHub-тың өзі де көмектеседі: **Secret scanning** және **Push protection** белгілі сервистердің кілттерін тауып, push-ты бұғаттайды немесе ескертеді. Бірақ оған толық сенуге болмайды.

## 8. Ақпараттық қауіпсіздік мәдениеті

- **Ең аз құқық қағидасы:** кілтке тек қажетті рұқсаттарды беріңіз (мысалы, «тек оқу»).
- **Әр жобаға — жеке кілт:** біреуі жария болса, қалғандары қауіпсіз.
- **Шектеу қою:** сервисте лимит немесе бюджет шегін орнатыңыз.
- **Құпиялармен бөліспеу:** досыңызға да өз кілтіңізді бермеңіз — ол өзіне тіркелсін.
- **Логтарда құпия жоқ:** `print(api_key)` немесе қате хабарында кілтті шығармаңыз.
- **Жеке деректер де құпия:** оқушылардың телефондары бар `students.db` — сондықтан да ол `.gitignore`-да.

## Жиі кездесетін қателер

**1. `.gitignore`-ды `git add .` орындағаннан кейін жасау** — `.env` коммитке түсіп үлгереді. Алдымен `.gitignore`, сосын `git add`.

**2. Файл атауындағы қате:** `.env.txt` (Windows кеңейтімді жасырып қояды) немесе `env` (нүктесіз). Тексеру: `dir /a` немесе `ls -a`.

**3. `load_dotenv()` шақырылмаған** — `os.getenv` `None` қайтарады.
```python
import os
# Қате: load_dotenv() шақырылмай тұрып оқу
key = os.getenv("WEATHER_API_KEY")
print(key)   # None
```

**4. `.env` файлында бос орын немесе тырнақша:** `KEY = "abc"` — кейбір құралдар бос орынды мәннің бөлігі деп қабылдауы мүмкін. Дұрысы: `KEY=abc`.

**5. Кілтті тексеру үшін басып шығару:** `print(api_key)` терминал скриншотымен бірге жария болады. Тек ұзындығын немесе алғашқы 3 таңбасын: `api_key[:3] + "***"`.

**6. «Жеке (private) репозиторий — қауіпсіз» деп ойлау.** Жеке репозиторийді кейін ашық етуге, басқаларды қосуға болады. Құпияларды онда да сақтамаймыз.

## Негізгі ұғымдар

| Ұғым | Түсіндірме |
|---|---|
| API кілті | Сервиске қол жеткізуге арналған құпия жол |
| Токен | Уақытша рұқсат белгісі |
| Орта айнымалысы | ОЖ деңгейіндегі «атау = мән» баптауы |
| `os.getenv()` | Орта айнымалысын оқу функциясы |
| `.env` | Жергілікті құпиялар файлы (Git-ке жүктелмейді) |
| `.env.example` | Қажетті айнымалылардың мәнсіз үлгісі |
| `python-dotenv` | `.env` файлын оқитын кітапхана |
| `.gitignore` | Git елемейтін файлдар үлгілерінің тізімі |
| `git rm --cached` | Файлды Git бақылауынан алу (дискте қалдырып) |
| Revoke / rotate | Кілтті жою / жаңасымен ауыстыру |

## Ескерту

- `os.environ["KEY"]` айнымалы жоқ болса `KeyError` шығарады, ал `os.getenv("KEY")` `None` қайтарады — мәнді тексеріп, түсінікті қате хабарын шығарыңыз (https://docs.python.org/3/library/os.html#os.environ).
- `load_dotenv()` әдепкі бойынша бар орта айнымалыларын **қайта жазбайды**; қайта жазу үшін — `load_dotenv(override=True)`.
- `export`/`set` арқылы берілген орта айнымалылары тек сол терминалда және оның еншілес процестерінде әрекет етеді; IDE оларды қайта іске қосылғанша көрмеуі мүмкін.
- `.gitignore` бұрыннан бақыланып жүрген файлдарға әсер етпейді — алдымен `git rm --cached .env` орындау керек.
- Токен, құпиясөз сияқты құпияларды генерациялау үшін `random` емес, `secrets` модулін қолданыңыз: `secrets.token_hex(16)`.
