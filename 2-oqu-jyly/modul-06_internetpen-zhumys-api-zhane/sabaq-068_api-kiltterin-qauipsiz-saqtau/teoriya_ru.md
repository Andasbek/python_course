## 1. Что такое API-ключ?

**API-ключ (API key)** — длинная секретная строка, которую сервис выдаёт, чтобы узнавать вас, например: `3f9a7c1e5b2d48a0b6e1c9f2d7a4b8e3`.

**Аналогия:** ключ — это ключ от вашей квартиры или PIN-код банковской карты. У кого ключ, тот и пользуется сервисом «от вашего имени».

| Понятие | Значение |
|---|---|
| API key | Постоянный ключ, идентифицирующий программу/пользователя |
| Token (токен) | Временный знак доступа (например, на 1 час) |
| Secret (секрет) | Общее название: ключи, пароли, токены, строки подключения к базе |

### Что будет, если ключ утечёт?

- Кто-то израсходует ваш лимит → сервис вас заблокирует.
- Если сервис платный → с вашей карты уйдут деньги.
- Бот-токен (Telegram) → посторонний будет отправлять сообщения от имени вашего бота.
- Пароль от базы → все данные будут украдены.

## 2. Где ключ НЕ ХРАНИМ

```python
import requests

# ❌ НИКОГДА ТАК НЕ ПИШИТЕ — ключ внутри кода!
API_KEY = "здесь-ключ-не-пишется"
url = "https://api.openweathermap.org/data/2.5/weather"
# requests.get(url, params={"q": "Almaty", "appid": API_KEY}, timeout=10)
```

Запрещённые места:
- внутри кода (как выше);
- в конфигурационном файле, попадающем в репозиторий (`config.json`, `settings.py`);
- на скриншотах, в видеоуроках, в чатах, в вопросе на форуме;
- в сообщении коммита или в README.

**Важно:** Git хранит **всю историю**. Даже если закоммитить ключ и удалить его следующим коммитом, он останется в истории: любой может увидеть его через `git log -p`.

## 3. Способ 1: переменные окружения (environment variables)

**Переменная окружения** — пара «имя = значение», которую операционная система передаёт программе. В коде есть только **имя** переменной, а значение — на компьютере.

Установка (в терминале):

```bash
# Windows (PowerShell) — для текущего терминала:
$env:WEATHER_API_KEY = "ваш_ключ"
# Windows — постоянно (в новых терминалах):
setx WEATHER_API_KEY "ваш_ключ"
# macOS / Linux:
export WEATHER_API_KEY="ваш_ключ"
```

Чтение в Python:

```python
import os

api_key = os.getenv("WEATHER_API_KEY")       # если нет — None
if api_key is None:
    print("Ошибка: переменная окружения WEATHER_API_KEY не установлена")
else:
    print("Ключ загружен, длина:", len(api_key))   # сам ключ никогда не выводим!
```

Результат (если переменная не установлена):
```text
Ошибка: переменная окружения WEATHER_API_KEY не установлена
```

| Способ | Если переменной нет |
|---|---|
| `os.environ["NAME"]` | `KeyError` |
| `os.getenv("NAME")` | `None` |
| `os.getenv("NAME", "по умолчанию")` | `"по умолчанию"` |

## 4. Способ 2: файл `.env` и `python-dotenv`

Устанавливать переменные окружения в терминале каждый раз неудобно. Поэтому в папке проекта создаём файл **`.env`**:

```text
# .env — НИКОГДА не загружается в Git!
WEATHER_API_KEY=3f9a7c1e5b2d48a0b6e1c9f2d7a4b8e3
TELEGRAM_TOKEN=123456:ABC-DEF
DEBUG=true
```

Установка:
```bash
pip install python-dotenv
```

Чтение:
```python
import os
from dotenv import load_dotenv

load_dotenv()                       # загружает значения из файла .env в os.environ
api_key = os.getenv("WEATHER_API_KEY")
debug = os.getenv("DEBUG", "false").lower() == "true"

if not api_key:
    raise SystemExit("WEATHER_API_KEY не найден. Смотрите файл .env.example.")
print("Ключ успешно загружен. DEBUG =", debug)
```

### `.env.example` — инструкция для других

Коллега, клонировав проект, должен знать, какие ключи нужны. Поэтому в репозиторий загружаем файл-шаблон **без значений**:

```text
# .env.example — скопируйте этот файл как .env и впишите свои ключи
WEATHER_API_KEY=your_key_here
TELEGRAM_TOKEN=your_token_here
DEBUG=false
```

| Файл | Содержимое | В Git |
|---|---|---|
| `.env` | Реальные ключи | ❌ нет |
| `.env.example` | Имена + пустые/фиктивные значения | ✅ да |
| `config.py` | Код `os.getenv(...)` | ✅ да |

## 5. Сбор конфигурации в одном модуле

Секреты и настройки лучше собирать в одном месте:

```python
# config.py
import os

try:
    from dotenv import load_dotenv
    load_dotenv()
except ImportError:          # если dotenv не установлен — только переменные окружения
    pass

WEATHER_API_KEY = os.getenv("WEATHER_API_KEY", "")
BASE_URL = "https://api.openweathermap.org/data/2.5/weather"
TIMEOUT = int(os.getenv("TIMEOUT", "10"))


def check():
    missing = [name for name, value in {"WEATHER_API_KEY": WEATHER_API_KEY}.items() if not value]
    if missing:
        raise RuntimeError("Не установлены переменные: " + ", ".join(missing))
```

```python
# main.py
# import requests
# import config
# config.check()
# r = requests.get(config.BASE_URL, params={"q": "Almaty", "appid": config.WEATHER_API_KEY,
#                                         "units": "metric"}, timeout=config.TIMEOUT)
```

**Как передавать ключ?** Одни API ожидают ключ в параметре URL (`?appid=...`), другие — в заголовке (`headers={"Authorization": "Bearer ..."}`). Ключ в заголовке безопаснее — URL может записываться в логи серверов. Делаем так, как написано в документации.

## 6. `.gitignore` — файлы, которые Git «не видит»

`.gitignore` — текстовый файл в корне проекта; в нём записаны шаблоны файлов, которые Git игнорирует.

```text
# --- Секреты ---
.env
*.key
secrets.json

# --- Python ---
__pycache__/
*.pyc
.venv/
venv/

# --- Данные ---
*.db
backups/

# --- Редакторы ---
.vscode/
.idea/

# --- Исключение: файл-шаблон загружаем ---
!.env.example
```

### Синтаксис шаблонов

| Шаблон | Значение | Пример |
|---|---|---|
| `file.txt` | Файл с таким именем в любой папке | `.env` |
| `*.db` | Все файлы с расширением `.db` | `students.db` |
| `folder/` | Вся папка | `.venv/` |
| `/todo.txt` | Файл только в корне проекта | |
| `**/logs` | `logs` на любом уровне | `src/app/logs` |
| `!file` | Исключение: добавить, даже если подходит под правило выше | `!.env.example` |
| `#` | Комментарий | |

### Проверка

```bash
git status                     # .env не должно быть в списке
git check-ignore -v .env       # показывает, по какому правилу файл игнорируется
```

### Если файл уже был закоммичен

`.gitignore` действует только на **ещё не отслеживаемые** файлы. Если `.env` уже был закоммичен:

```bash
git rm --cached .env           # убрать из-под контроля Git (на диске останется)
git commit -m ".env убран из отслеживания"
```

Но ключ остался в истории — поэтому следующий шаг обязателен!

## 7. Если ключ утёк: план действий

1. **Немедленно отозвать/заменить ключ (revoke/rotate)** — на сайте сервиса удалить старый ключ и создать новый. Это самый важный шаг; очистка истории ключ «не спасёт», потому что кто-то мог уже его скопировать.
2. Записать новый ключ в `.env`, добавить `.env` в `.gitignore`.
3. Проверить статистику использования в сервисе (были ли чужие запросы).
4. При необходимости — очистить историю репозитория (инструмент `git filter-repo`) или сделать репозиторий закрытым (private).
5. Сделать выводы: в следующих проектах создавать `.gitignore` **в первом коммите**.

GitHub тоже помогает: **Secret scanning** и **Push protection** находят ключи известных сервисов и блокируют push или предупреждают. Но полностью на это полагаться нельзя.

## 8. Культура информационной безопасности

- **Принцип минимальных прав:** давайте ключу только необходимые разрешения (например, «только чтение»).
- **Каждому проекту — отдельный ключ:** если один утечёт, остальные в безопасности.
- **Установка ограничений:** задайте в сервисе лимит или предел бюджета.
- **Не делиться секретами:** не давайте свой ключ даже другу — пусть зарегистрируется сам.
- **Никаких секретов в логах:** не выводите ключ через `print(api_key)` или в сообщении об ошибке.
- **Личные данные — тоже секрет:** `students.db` с телефонами учеников — поэтому он и в `.gitignore`.

## Частые ошибки

**1. Создание `.gitignore` после выполнения `git add .`** — `.env` успевает попасть в коммит. Сначала `.gitignore`, затем `git add`.

**2. Ошибка в имени файла:** `.env.txt` (Windows скрывает расширение) или `env` (без точки). Проверка: `dir /a` или `ls -a`.

**3. Не вызван `load_dotenv()`** — `os.getenv` возвращает `None`.
```python
import os
# Неправильно: чтение до вызова load_dotenv()
key = os.getenv("WEATHER_API_KEY")
print(key)   # None
```

**4. Пробелы или кавычки в файле `.env`:** `KEY = "abc"` — некоторые инструменты могут принять пробел за часть значения. Правильно: `KEY=abc`.

**5. Вывод ключа для проверки:** `print(api_key)` утечёт вместе со скриншотом терминала. Выводите только длину или первые 3 символа: `api_key[:3] + "***"`.

**6. Думать, что «закрытый (private) репозиторий — безопасен».** Закрытый репозиторий позже можно сделать открытым, добавить в него других людей. Секреты не храним и там.

## Основные понятия

| Понятие | Объяснение |
|---|---|
| API-ключ | Секретная строка для доступа к сервису |
| Токен | Временный знак доступа |
| Переменная окружения | Настройка «имя = значение» на уровне ОС |
| `os.getenv()` | Функция чтения переменной окружения |
| `.env` | Файл локальных секретов (не загружается в Git) |
| `.env.example` | Шаблон необходимых переменных без значений |
| `python-dotenv` | Библиотека для чтения файла `.env` |
| `.gitignore` | Список шаблонов файлов, игнорируемых Git |
| `git rm --cached` | Убрать файл из-под контроля Git (оставив на диске) |
| Revoke / rotate | Отозвать ключ / заменить новым |

## Примечание

- `os.environ["KEY"]` выбрасывает `KeyError`, если переменной нет, а `os.getenv("KEY")` возвращает `None` — проверяйте значение и выводите понятное сообщение об ошибке (https://docs.python.org/3/library/os.html#os.environ).
- `load_dotenv()` по умолчанию **не перезаписывает** уже существующие переменные окружения; для перезаписи — `load_dotenv(override=True)`.
- Переменные окружения, заданные через `export`/`set`, действуют только в текущем терминале и его дочерних процессах; IDE может не видеть их до перезапуска.
- `.gitignore` не действует на уже отслеживаемые файлы — сначала нужно выполнить `git rm --cached .env`.
- Для генерации секретов (токенов, паролей) используйте модуль `secrets`, а не `random`: `secrets.token_hex(16)`.
