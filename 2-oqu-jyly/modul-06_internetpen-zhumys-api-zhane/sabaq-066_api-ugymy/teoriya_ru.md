## 1. Что такое API?

**API (Application Programming Interface)** — правила, по которым программы общаются друг с другом, то есть «программный интерфейс».

**Аналогия: меню ресторана.** Вы не заходите на кухню готовить сами. Вы выбираете из меню (документация API), говорите официанту (HTTP-запрос), и приходит готовое блюдо (JSON-ответ). Знать, что происходит внутри кухни, не нужно.

| Вид интерфейса | Для кого | Пример |
|---|---|---|
| GUI (графический) | Для человека | Окно Tkinter, страница сайта |
| API (программный) | Для программы | `https://api.open-meteo.com/v1/forecast` |

Мы уже работали с API: методы `connect()`, `execute()` модуля `sqlite3` — это Python API для SQLite. Сегодня — **Web API**: API, вызываемый через интернет с помощью HTTP.

### Зачем нужен API?

- Приложение Kaspi не рассчитывает курс валют само — берёт его из API банка.
- 2GIS, Яндекс Такси — используют API карт.
- Виджеты погоды — метеорологический API.
- И наша программа получит доступ к мировым данным с помощью 10 строк кода!

## 2. Основы REST API

Многие Web API созданы в стиле **REST**. Основные принципы:

- У каждого **ресурса** свой URL (эндпоинт): `/users`, `/users/5`, `/forecast`.
- Действие определяется **методом HTTP**: GET — получить, POST — создать, PUT — изменить, DELETE — удалить.
- Ответ — чаще всего **JSON**.
- Сервер «не помнит» предыдущие запросы клиента (stateless) — в каждом запросе есть вся необходимая информация.

```text
Базовый URL (base URL)           Эндпоинт        Параметры
https://api.open-meteo.com   +   /v1/forecast  + ?latitude=43.25&longitude=76.95
```

**Эндпоинт (endpoint)** — адрес, соответствующий конкретной возможности API.

## 3. Чтение документации API

Работа с любым API начинается с чтения **документации**. В ней указано:

| Раздел | Что пишется |
|---|---|
| Base URL | Общее начало всех эндпоинтов |
| Endpoints | Список доступных адресов |
| Parameters | Обязательные (required) и необязательные (optional) параметры, их типы |
| Response | Структура ответа, значение полей, единицы измерения |
| Authentication | Нужен ли ключ, как он передаётся |
| Rate limits | Сколько запросов можно отправлять |
| Errors | Коды ошибок и их значение |

Документация Open-Meteo: `https://open-meteo.com/en/docs`. В ней есть интерактивный конструктор — отметьте параметры, и он создаст готовый URL.

## 4. Виды API: ключ и ограничения

| Вид | Описание | Пример |
|---|---|---|
| Открытый (без ключа) | Без регистрации, можно сразу использовать | Open-Meteo, open.er-api.com |
| Бесплатный, с ключом | Регистрируетесь и получаете личный API-ключ (API key) | OpenWeatherMap, NewsAPI |
| Платный | Оплата в зависимости от числа запросов | Google Maps, OpenAI |

**Rate limit (ограничение запросов)** — допустимое число запросов за единицу времени. Например, Open-Meteo разрешает до 10 000 запросов в сутки для некоммерческого использования. При превышении — `429 Too Many Requests`.

**API-ключ** — ваш «личный пропуск». Хранить его внутри кода нельзя. В примерах ниже используются API без ключей.

## 5. Open-Meteo: API погоды

Эндпоинт: `https://api.open-meteo.com/v1/forecast`

| Параметр | Значение | Пример |
|---|---|---|
| `latitude`, `longitude` | Широта, долгота (обязательные) | `43.25`, `76.95` |
| `current` | Список текущих значений | `temperature_2m,wind_speed_10m,weather_code` |
| `daily` | Прогноз по дням | `temperature_2m_max,temperature_2m_min` |
| `timezone` | Часовой пояс | `Asia/Almaty` или `auto` |
| `forecast_days` | Дни прогноза (1–16) | `3` |

```python
import requests

URL = "https://api.open-meteo.com/v1/forecast"
params = {
    "latitude": 43.25,
    "longitude": 76.95,
    "current": "temperature_2m,relative_humidity_2m,wind_speed_10m,weather_code",
    "timezone": "auto",
}
r = requests.get(URL, params=params, timeout=10)
r.raise_for_status()
data = r.json()

cur = data["current"]
units = data["current_units"]
print("Время:", cur["time"])
print("Температура:", cur["temperature_2m"], units["temperature_2m"])
print("Влажность:", cur["relative_humidity_2m"], units["relative_humidity_2m"])
print("Ветер:", cur["wind_speed_10m"], units["wind_speed_10m"])
print("Код погоды:", cur["weather_code"])
```

Результат (значения каждый раз разные):
```text
Время: 2027-02-09T14:15
Температура: -1.8 °C
Влажность: 71 %
Ветер: 6.4 km/h
Код погоды: 3
```

### Коды погоды (WMO)

API передаёт погоду не словами, а **числовым кодом**. Переводим его с помощью словаря:

```python
WEATHER_CODES = {
    0: "Ясно ☀️", 1: "Преимущественно ясно 🌤", 2: "Переменная облачность ⛅", 3: "Облачно ☁️",
    45: "Туман 🌫", 48: "Изморозь, туман 🌫",
    51: "Слабая морось", 53: "Морось", 55: "Сильная морось",
    61: "Слабый дождь 🌦", 63: "Дождь 🌧", 65: "Ливень 🌧",
    71: "Слабый снег 🌨", 73: "Снег 🌨", 75: "Сильный снег ❄️",
    80: "Небольшие осадки", 81: "Осадки", 82: "Сильные осадки",
    95: "Гроза ⛈",
}

def describe(code):
    return WEATHER_CODES.get(code, f"Неизвестно ({code})")

print(describe(3))
print(describe(73))
```

Результат:
```text
Облачно ☁️
Снег 🌨
```

## 6. Геокодирование: название города → координаты

Пользователь не знает координат, он пишет «Караганда». **Геокодирование (geocoding)** — превращение названия в координаты.

```python
import requests

def find_city(name):
    r = requests.get(
        "https://geocoding-api.open-meteo.com/v1/search",
        params={"name": name, "count": 1, "language": "ru"},
        timeout=10,
    )
    r.raise_for_status()
    results = r.json().get("results")      # если не найдено, ключа "results" нет
    if not results:
        return None
    c = results[0]
    return c["name"], c.get("country", ""), c["latitude"], c["longitude"]

print(find_city("Караганда"))
print(find_city("Qwertyuiop"))
```

Результат:
```text
('Караганда', 'Казахстан', 49.80187, 73.10211)
None
```

Обратите внимание: `.get("results")` при отсутствии ключа возвращает не `KeyError`, а `None`. Структура ответа API не всегда такая, как мы ожидаем!

## 7. API курсов валют

Эндпоинт: `https://open.er-api.com/v6/latest/<БАЗОВАЯ_ВАЛЮТА>` — без ключа, обновляется раз в сутки.

```python
import requests

r = requests.get("https://open.er-api.com/v6/latest/USD", timeout=10)
r.raise_for_status()
data = r.json()

if data["result"] == "success":
    rates = data["rates"]
    print("Обновлено:", data["time_last_update_utc"])
    for code in ("KZT", "RUB", "EUR", "CNY"):
        print(f"1 USD = {rates[code]:.2f} {code}")
```

Результат (курс меняется каждый день):
```text
Обновлено: Tue, 09 Feb 2027 00:02:31 +0000
1 USD = 512.40 KZT
1 USD = 91.25 RUB
1 USD = 0.92 EUR
1 USD = 7.18 CNY
```

### Конвертер валют

Кросс-курс: если 1 USD = 512 KZT и 1 USD = 0.92 EUR, то 1 EUR = 512 / 0.92 KZT.

```python
def convert(amount, from_cur, to_cur, rates):
    """rates — словарь курсов относительно USD."""
    usd = amount / rates[from_cur]
    return usd * rates[to_cur]

rates = {"USD": 1, "KZT": 512.4, "EUR": 0.92, "RUB": 91.25}
print(f"100 EUR = {convert(100, 'EUR', 'KZT', rates):,.0f} KZT")
print(f"10000 KZT = {convert(10000, 'KZT', 'RUB', rates):.2f} RUB")
```

Результат:
```text
100 EUR = 55,696 KZT
10000 KZT = 1780.84 RUB
```

## 8. Золотые правила работы с API

1. **Читай документацию** — не выдумывай названия параметров.
2. **Сначала проверь в браузере** — открой URL в браузере и посмотри структуру JSON.
3. **`timeout` и `try/except`** — сеть ненадёжна.
4. **Проверяй ответ** — `status_code`, `result`, `.get()`.
5. **Соблюдай ограничения** — не отправляй в цикле сотни запросов; если данные меняются редко, сохраняй их (кэш).
6. **Указывай источник данных** — многие бесплатные API требуют ссылку «Data by Open-Meteo.com».

## Частые ошибки

**1. Неправильное название параметра** — нужен `latitude`, а не `lat`. API вернёт `400 Bad Request`, а в теле ответа будет указана причина:
```python
import requests
r = requests.get("https://api.open-meteo.com/v1/forecast", params={"lat": 43.25}, timeout=10)
print(r.status_code, r.json().get("reason"))
```

**2. `KeyError` — обращение к ключу без знания структуры ответа.** Сначала `print(data.keys())` или посмотрите в браузере; для необязательных полей — `.get()`.

**3. Обратное применение курса** — `rates["KZT"]` = «тенге за 1 USD». Чтобы перевести тенге в доллары, **делим**, а не умножаем.

**4. Перепутанные широта и долгота** — вместо Алматы получите погоду в какой-то точке Китая или в океане. Широта (latitude) — север/юг, для Казахстана ≈ 40–55.

**5. Запрос к API каждую секунду** — погода обновляется каждые 15 минут, курс — раз в сутки. Частые запросы — напрасная трата лимита.

## Основные понятия

| Понятие | Объяснение |
|---|---|
| API | Интерфейс взаимодействия программ |
| Web API | API, вызываемый через HTTP |
| REST | Стиль API, основанный на ресурсах и методах HTTP |
| Эндпоинт | URL, соответствующий конкретной возможности API |
| Base URL | Общая часть всех эндпоинтов |
| API-ключ | Секретная строка, идентифицирующая пользователя |
| Rate limit | Ограничение числа запросов |
| Геокодирование | Превращение адреса/названия в координаты |
| Код WMO | Международный числовой код погодных условий |
| Кросс-курс | Курс, рассчитанный через третью валюту |

## Примечание

- Параметры запроса передавайте через `params=` — `requests` сам закодирует пробелы и кириллицу в URL (`"Алматы"` → `%D0%90...`).
- Если не указан параметр `timezone`, Open-Meteo возвращает время в UTC (укажите, например, `timezone="auto"` или `"Asia/Almaty"`).
- Для денежных расчётов с курсами валют лучше `decimal.Decimal`, чем `float`: `0.1 + 0.2 != 0.3` (https://docs.python.org/3/library/decimal.html).
- Структура ответа API может меняться между версиями (`/v1/`, `/v2/`) — проверяйте версию в URL и документацию.
- Кэшируйте ответы (например, в словаре со временем запроса), чтобы не тратить лимит на одинаковые запросы.
