# Сабақ 107. Резервтік сағат. Қорытынды жобаны аяқтауға қосымша уақыт.

## Тақырыптар

1. Қалған жұмысты сұрыптау: шектеулі уақытқа жоспар
2. Тұрақты нұсқаға қойылатын ең аз талаптар
3. Ескертулерді түзету және `v1.0.1` патч-нұсқасы

## 1. Қалған жұмысты сұрыптау: шектеулі уақытқа жоспар

Мерзімге аз уақыт қалғанда (мысалы, 90 минут) алдымен **бәрін** тізімдеп, кейін **ең маңыздыларын** таңдаймыз:

1. Барлық ашық Issues + code review ескертулері + пайдаланушы пікірлері → бір тізім.
2. Әрқайсысына маңыздылық деңгейі: **[С]** сыни, **[М]** маңызды, **[Ұ]** ұсыныс, **[Т]** ұсақ-түйек.
3. Әрқайсысына уақыт бағасы (минутпен) — және оны **1,5-ке көбейтіңіз** (күтпеген жағдайға буфер).
4. Тізімнен уақыт қосындысы бюджеттің ≈80%-ынан (мұнда 70 минут) аспайтындай етіп [С] → [М] → [Ұ] ретімен таңдаңыз. Қалған уақыт — тексеру, README, релиз.

Мысал:
| № | Жұмыс | Деңгей | Бағасы | ×1,5 | Таңдалды |
|---|---|---|---|---|---|
| 1 | Бос ДҚ-да диаграмма қате береді | [С] | 10 | 15 | иә |
| 2 | README-де орнату командасы қате | [М] | 5 | 8 | иә |
| 3 | Ай бойынша сүзгі (рецензент ұсынысы) | [Ұ] | 30 | 45 | иә |
| 4 | Түнгі режим | [Т] | 40 | 60 | — (кейін) |
| | **Барлығы таңдалғаны** | | | **68 мин** | |

Таңдау тәсілін бағдарламаға айналдыруға болады (құрама кілт бойынша сұрыптау және ашкөз таңдау):

```python
WORK = [
    ("Бос ДҚ-да диаграмма қате береді", "С", 10),
    ("README-де орнату командасы қате", "М", 5),
    ("Ай бойынша сүзгі", "Ұ", 30),
    ("Түнгі режим", "Т", 40),
    ("Тестке шекаралық мәндер қосу", "М", 15),
]
PRIORITY = {"С": 0, "М": 1, "Ұ": 2, "Т": 3}
BUDGET = 70          # минут
BUFFER = 1.5


def plan(work, budget=BUDGET):
    """Маңыздылығы бойынша, бюджетке сыйғанынша таңдайды."""
    chosen, used, later = [], 0, []
    for title, level, minutes in sorted(work, key=lambda w: (PRIORITY[w[1]], w[2])):
        need = round(minutes * BUFFER)
        if used + need <= budget:
            chosen.append((title, need))
            used += need
        else:
            later.append(title)
    return chosen, used, later


chosen, used, later = plan(WORK)
for title, need in chosen:
    print(f"[ ] {title} — {need} мин")
print(f"Барлығы: {used} мин. Кейін: {', '.join(later)}")
```

Нәтижесі:
```text
[ ] Бос ДҚ-да диаграмма қате береді — 15 мин
[ ] README-де орнату командасы қате — 8 мин
[ ] Тестке шекаралық мәндер қосу — 22 мин
Барлығы: 45 мин. Кейін: Ай бойынша сүзгі, Түнгі режим
```

Назар аударыңыз: бағдарлама «Ай бойынша сүзгіні» (45 мин) таңдамады, себебі ол 45 + 45 = 90 > 70. Мұндай жағдайда мүмкіндікті **кішірейтуге** болады: «тек ағымдағы және өткен ай» — 15 минут.

Мұндай алгоритм **ашкөз** (жадный) деп аталады: әр қадамда әлі сыятын, басымдығы бойынша ең жақсы нұсқа алынады. Ол әрдайым оңтайлы нәтиже бермейді (бұл — рюкзак есебі), бірақ қарапайым әрі түсінікті.

## 2. Тұрақты нұсқаға қойылатын ең аз талаптар

Уақыт аз болса, MVP-ге оралып, барды тұрақты күйге жеткіземіз:
- бағдарлама таза ортада README бойынша іске қосылады;
- ТТ-дағы Must-мүмкіндіктер жұмыс істейді;
- қате енгізуде бағдарлама құламайды;
- деректер іске қосулар арасында сақталады;
- README-де: не, кімге, қалай іске қосу.

**Кеңес:** релиз алдында жаңа мүмкіндік қоспаңыз. «Аз, бірақ жұмыс істейтін» жоба «көп, бірақ құлайтын» жобадан пайдалырақ.

## 3. Ескертулерді түзету және `v1.0.1` патч-нұсқасы

1. Әр ескертуге Issue (`review` белгісімен), түзеткенде `Closes #N`.
2. Әр түзетуден кейін: тесттер (`python -m unittest discover -s tests`) + негізгі сценарийлер.
3. CHANGELOG-қа `[1.0.1]` бөлімі: «Түзетілді: ...».
4. Тег және релиз:
```bash
git tag -a v1.0.1 -m "Ескертулер бойынша түзетулер"
git push origin main --tags
```

## 4. Өтінімге арналған жоба сипаттамасы (байқау, хакатон, портфолио)

Жоба байқауларына, IT-жарыстарға және хакатондарға әдетте мыналар сұралады:

| Құжат | Мазмұны | Жобадағы дайын материал |
|---|---|---|
| **Аннотация** (150–250 сөз) | өзектілік, мақсат, әдістер (технологиялар), нәтиже, практикалық маңызы | README-дегі «Мәселе және шешім», «Мүмкіндіктер» |
| **Жоба сипаттамасы** | кіріспе, жобалау (ТТ, архитектура, ДҚ моделі), жүзеге асыру, тестілеу, қорытынды | `docs/` папкасы: ТТ, ER-сызба, тест-кейстер |
| **Презентация** | 7–10 слайд | архитектура сызбасы, скриншоттар |
| **Бейне** (кейде) | 2–3 минуттық демо | демо сценарийі бойынша экран жазбасы |
| **Код** | репозиторий сілтемесі | GitHub Release |

**Аннотацияның құрылымы (үлгі):**
> **Өзектілік.** Мектеп оқушыларының көбі қалта ақшасын жоспарлауды білмейді: сауалнамада 20 оқушының 14-і ай соңында ақшасы неге біткенін түсіндіре алмады.
> **Мақсаты:** шығыстарды бақылауға және жинақ мақсатына жетуге көмектесетін қосымша жасау.
> **Әдістер:** Python, Tkinter (интерфейс), SQLite (деректер қоры), Matplotlib (визуализация), ашық валюта API-ы; объектіге бағытталған архитектура, модульдік тестілеу (unittest, 24 тест).
> **Нәтиже:** операцияларды тіркеу, айлық есеп, санат бойынша диаграмма, мақсатқа жету күнін болжау мүмкіндіктері бар қосымша; 5 пайдаланушы 2 апта бойы сынақтан өткізді.
> **Практикалық маңызы:** қосымша қаржылық сауаттылық сабақтарында қолданыла алады.

Жоба тарихы туралы деректер (қанша коммит, қанша күн жұмыс істедіңіз) өтінімде және сұхбатта пайдалы. Оларды Git-тен алуға болады:

```bash
git log --pretty=format:"%ad;%s" --date=short > docs/history.csv
```

```python
import csv
import io
from collections import Counter

# Нағыз жобада: open("docs/history.csv", encoding="utf-8")
HISTORY = """2027-04-20;Жоба қаңқасы
2027-04-22;models.py: Category, Operation
2027-04-22;logic.py: баланс
2027-04-27;database.py: CRUD
2027-04-29;MVP: интерфейс біріктірілді
2027-05-04;Тесттер: 24 тест
2027-05-04;Түзету: бос сома (#12)
2027-05-11;Релиз 1.0
"""
rows = list(csv.reader(io.StringIO(HISTORY), delimiter=";"))
days = Counter(date for date, _ in rows)
print(f"Коммиттер: {len(rows)}, жұмыс күндері: {len(days)}")
print(f"Кезең: {rows[0][0]} — {rows[-1][0]}")
print("Ең белсенді күн:", days.most_common(1)[0])
```

Нәтижесі:
```text
Коммиттер: 8, жұмыс күндері: 6
Кезең: 2027-04-20 — 2027-05-11
Ең белсенді күн: ('2027-04-22', 2)
```

(`git log` жаңа коммиттерді бірінші шығарады; мысалда деректер ескісінен жаңасына қарай берілген.)

## 5. Жобаны әрі қарай дамыту

Жоба v1.0 релизімен аяқталмайды. Кейінге қалдырылған жұмыстарды Issues-те `enhancement` белгісімен (немесе `v1.1` milestone-ында) қалдырып, README-нің «Болашақтағы жоспарлар» бөлімінде сипаттаңыз. Терезелік қосымшаның табиғи жалғасы — Flask-тағы веб-нұсқа: логика (`logic.py`) мен деректер қабаты (`database.py`) өзгеріссіз қайта қолданылады, тек интерфейс өзгереді.

## Жиі кездесетін қателер

**1. Жоспарсыз бастау** — бүкіл уақыт бір ұсақ-түйекке (түстер) кетеді, сыни қате қалады. Дұрысы: алдымен бірнеше минут жоспарлау.

**2. Релиз алдында жаңа мүмкіндік қосу** — тұрақтылықты бұзады.

**3. Түзетулерді коммиттемеу/жүктемеу** — бәрі тек сіздің компьютеріңізде қалады. Әр 30 минут сайын `commit` + `push`.

**4. Тегті жаңартуға тырысу** (`v1.0`-ді жаңа коммитке жылжыту) — бұл тарихты шатастырады. Дұрысы: жаңа нұсқа — жаңа тег (`v1.0.1`).

**5. Аннотацияда тек технологияларды тізу.** Аннотация оқырманына алдымен **мәселе** мен **нәтиже** маңызды; технологиялар — құрал.

## Негізгі ұғымдар
| Ұғым | Түсіндірме |
|---|---|
| Ашкөз алгоритм | әр қадамда бұрынғы шешімдерді қайта қарамай, ең жақсы қолжетімді нұсқаны таңдайды |
| Патч-нұсқа | тек қате түзетулері бар нұсқа (`1.0.1`) |
| Аннотация | жобаның өзектілігі, мақсаты, әдістері мен нәтижесінің қысқаша сипаттамасы |
| Буфер | бағаланған уақытқа қосылатын қор (×1,5) |

## Ескерту

- `sorted(..., key=lambda w: (PRIORITY[w[1]], w[2]))` кортеж бойынша сұрыптайды: алдымен бірінші элемент, тең болса — екіншісі бойынша; бірнеше белгі бойынша сұрыптау осылай беріледі.
- Python-дағы `round()` «банктік» дөңгелектеуді қолданады: `round(2.5) == 2`, `round(3.5) == 4`; уақытты қормен бағалау үшін `math.ceil()` дұрысырақ.
- Тегті байқатпай «жылжытуға» болмайды: `git push`-тан кейін оны басқалар жүктеп алған болуы мүмкін. Тег жарияланғанға дейін қате болса — `git tag -d v1.0.1` және қайта жасау.
- `git log --pretty=format:"..."` `%h` (қысқа хеш), `%an` (автор), `%ad` (күн), `%s` (хабарлама) өрістерін қолдайды; `--reverse` коммиттерді ескісінен жаңасына қарай шығарады.
- Құжаттама: https://git-scm.com/docs/git-log және https://docs.python.org/3/howto/sorting.html
