# Сабақ 107. Практикалық тапсырмалар: жоба шеберханасы

## Базалық деңгей

### 1-тапсырма. 90 минуттық жоспар (барлығына міндетті, 10 мин)
Барлық ашық Issues, комиссия ескертулері мен көрермен карточкаларын бір кестеге жинаңыз да, теориядағы 1-бөлімнің тәсілімен жоспар құрыңыз. Жоспарды педагогке бекітіңіз.

| № | Жұмыс | Деңгей [С/М/Ұ/Т] | Бағасы (мин) | ×1,5 | Таңдалды | Орындалды |
|---|---|---|---|---|---|---|
| 1 | | | | | | |
| 2 | | | | | | |
| | **Барлығы (≤ 70 мин)** | | | | | |

### 2-тапсырма. 1-жол: «Аяқтау және қайта қорғау»
Ең аз талаптар чек-парағы бойынша жұмыс істеңіз:
- [ ] таза ортада README бойынша іске қосылады;
- [ ] барлық Must-мүмкіндіктер жұмыс істейді (ТТ бойынша тексеру);
- [ ] 5 «бұзып көру» енгізуінде құламайды (бос, әріп, теріс сан, ұзын мәтін, тырнақша);
- [ ] кемінде үш технология мағыналы қолданылған;
- [ ] README: не, кімге, қалай іске қосу, скриншот;
- [ ] `git push`, тег `v1.0` (немесе `v1.0.1`).

Сабақ соңында қысқартылған регламент бойынша қайта қорғау: баяндама + демо 4–5 мин, сұрақтар 3 мин. Тәлімгеріңізбен бір рет жаттығыңыз.

### 3-тапсырма. 2-жол: «Ескертулерді түзету»
1. Комиссия мен көрермендердің әр ескертуін Issue ретінде тіркеңіз (`review` белгісі).
2. Жоспар бойынша түзетіңіз; әр түзету — жеке коммит `Closes #N`; әр түзетуден кейін тесттер.
3. CHANGELOG-қа `[1.0.1]` бөлімін жазып, `v1.0.1` релизін жариялаңыз.
4. Сабақ соңында «Не өзгерді?» — 1 минуттық көрсетілім.

### 4-тапсырма. 3-жол: «Жетілдіру және байқауға дайындау»
1. Тәлімгер ретінде 1-жолдағы бір оқушыға кемінде 20 минут көмектесіңіз (бағыттаушы сұрақтармен, пернетақтаны ұстамай).
2. Жобаңызға аннотация жазыңыз (150–250 сөз; өзектілік, мақсат, әдістер, нәтиже, практикалық маңызы) — `docs/annotation.md`.
3. Қалған уақытта — комиссия ұсынған жетілдіруді жеке тармақта жасап, `v1.1` релизін жариялаңыз.

## Кеңейтілген деңгей

### 5-тапсырма. Пайдаланушылық сынақ
Жобаңызды үйірмеден тыс 2–3 адамға (басқа үйірме оқушылары, отбасы) 5 минутқа беріп, 92-сабақтағы «5 минуттық тест» әдісімен бақылаңыз. Нәтижелерді `docs/user_test.md`-ге жазыңыз — бұл аннотациядағы «нәтиже» бөлімі үшін шынайы дәлел болады.

### 6-тапсырма. Жазғы жоспар
GitHub-та `summer` белгісімен 3–5 issue ашып, жазғы демалысқа 2 SMART мақсат жазыңыз. Мысал: «Шілденің соңына дейін “Қалта ақшасына” ай бойынша сүзгі қосып, `v1.2` жариялау».

## ★ Олимпиадалық / шығармашылық тапсырма

### 7-тапсырма. CHANGELOG генераторы
`git log` шығысынан (`%ad;%s` форматы) CHANGELOG жобасын автоматты түрде жасайтын скрипт жазыңыз: «Түзету:» деп басталатын коммиттер «Түзетілді» бөліміне, «Тест:» — «Тесттер» бөліміне, қалғаны «Қосылды/Өзгертілді» бөліміне түссін; соңғы тегтен кейінгі коммиттер ғана алынсын (`git log v1.0..HEAD`).

### 8-тапсырма. Жоба байқауына толық өтінім
Аннотациядан басқа 3–5 беттік жоба сипаттамасын (кіріспе, жобалау, жүзеге асыру, тестілеу, қорытынды, пайдаланылған әдебиеттер) жазыңыз. `docs/` папкасындағы ТТ, ER-сызба, тест-кейстер және скриншоттарды пайдаланыңыз.

## Үй тапсырмасы
1. Жоспардағы аяқталмаған жұмыстарды аяқтаңыз немесе `summer` белгісімен қалдырыңыз.
2. Соңғы нұсқаны GitHub-қа жүктеп, Release-ті тексеріңіз.
3. Келесі (қорытынды) сабаққа: «Екінші жылдағы ең есте қалған сәтім» туралы бір сөйлем және үйірмені жақсарту бойынша бір ұсыныс ойлап келіңіз.

## Бағалау критерийлері
**1-жол (қайта қорғау)** — қорытынды жоба критерийлері бойынша (103-сабақ): өзектілік 20%, техникалық орындалу 25%, тұрақтылық және тестілеу 20%, код сапасы мен құжаттама 15%, таныстыру 20%.

**2–3-жолдар (сабақтағы жұмыс):**
| Критерий | Үлес | Не тексеріледі |
|---|---|---|
| Жоспардың орындалуы | 40% | таңдалған жұмыстар аяқталды, жаңа релиз (`v1.0.1`/`v1.1`) жарияланды |
| Басымдық берудің ұтымдылығы | 25% | алдымен сыни және маңызды ескертулер, буфер ескерілген |
| Ресімдеу | 20% | Issues, `Closes #N`, CHANGELOG, аннотация (3-жол) |
| Өз бетінше жұмыс және тәлімгерлік | 15% | тұрақты коммиттер; 3-жол — құрбысына көмектесті |

**Ұйымдастыру бойынша кеңестер.**
- Жолдарды қорғау нәтижесіне қарай алдын ала бөліп, тақтаға жазыңыз; 1-жолдағы әр оқушыға 3-жолдан тәлімгер бекітіңіз.
- 1-жолдағы оқушымен жоспарлау кезінде MoSCoW-ты бірге қайта қараңыз: «Қайта қорғау үшін не міндетті?» — көбіне 2–3 сыни түзету және README жеткілікті.
- Қайта қорғау қорытындысын журналдың «Ескерту» бағанына жазыңыз: «Қорытынды жоба 24.05.27 қайта қорғалды, нәтиже __%».
- 3-жолдағы оқушылардың аннотацияларын жинап, қалалық/республикалық жоба байқауларының мерзімдері туралы ақпарат беріңіз.

**7-тапсырма.**
```python
import io

SECTIONS = [("Түзету:", "Түзетілді"), ("Тест:", "Тесттер")]
DEFAULT = "Қосылды / Өзгертілді"


def build_changelog(log_lines, version, date):
    """git log (%ad;%s) жолдарынан CHANGELOG бөлімін құрады."""
    groups = {name: [] for _, name in SECTIONS}
    groups[DEFAULT] = []
    for line in log_lines:
        line = line.strip()
        if not line or ";" not in line:
            continue
        _, message = line.split(";", 1)
        for prefix, name in SECTIONS:
            if message.startswith(prefix):
                groups[name].append(message[len(prefix):].strip())
                break
        else:                                   # ешбір префикс сәйкес келмеді
            groups[DEFAULT].append(message)
    out = [f"## [{version}] — {date}"]
    for name, items in groups.items():
        if items:
            out.append(f"### {name}")
            out.extend(f"- {item}" for item in items)
    return "\n".join(out)


# Нағыз жобада: git log v1.0..HEAD --pretty=format:"%ad;%s" --date=short > new.txt
LOG = io.StringIO("""2027-05-24;Түзету: бос ДҚ-да диаграмма қатесі (#31)
2027-05-24;Тест: шекаралық мәндер parse_amount үшін
2027-05-24;README: орнату командасы түзетілді
2027-05-24;Түзету: ұзын түсініктемеде кесте ені (#21)
""")
print(build_changelog(LOG, "1.0.1", "2027-05-24"))
```
Нәтижесі:
```text
## [1.0.1] — 2027-05-24
### Түзетілді
- бос ДҚ-да диаграмма қатесі (#31)
- ұзын түсініктемеде кесте ені (#21)
### Тесттер
- шекаралық мәндер parse_amount үшін
### Қосылды / Өзгертілді
- README: орнату командасы түзетілді
```
`for ... else` құрылымы: `else` блогы цикл `break`-сіз аяқталғанда ғана орындалады — сирек қолданылатын, бірақ дәл осындай жағдайға ыңғайлы конструкция.

**8-тапсырма** — шығармашылық; құрылымның толықтығы, дәлелдердің (тест нәтижелері, пайдаланушылық сынақ) болуы, әдебиеттер тізімінің дұрыс ресімделуі бағаланады.
